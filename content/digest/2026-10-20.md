- **플랫폼 엔지니어 관점**: 코딩 에이전트의 autopilot/무확인 모드에서 외부 요청과 작업 디렉터리 밖 쓰기는 기본 거부로. 탐지는 페이로드 패턴이 아니라 "신뢰할 수 없는 콘텐츠 → 코드 실행 → 로컬 파일 읽기 → 처음 보는 외부 호스트" **행동 순서**로 걸어야 한다.

### [에이전트·MCP 보안] 공식 MCP Python SDK OAuth 결함 — 악성 서버가 클라이언트 시크릿·토큰 탈취 가능
- **날짜**: 2026-09-29 (권고 GHSA-qx49-fqc8-xw99, 9/28) · **유형**: 권고
- **요약**: MCP Python SDK의 HTTP OAuth 클라이언트가 연결한 MCP 서버가 가리키는 인가 서버를 제대로 검증하지 않아, 악성 서버가 공격자 토큰 엔드포인트로 유도할 수 있었다. 클라이언트 시크릿, 인가 코드, PKCE verifier가 넘어가 공격자가 앱 권한의 유효 토큰을 얻는다. CVSS 7.5(M2M 프로바이더)/6.5(대화형). 실제 악용 보고는 없다.

### [규제·표준·거버넌스] 프롬프트 인젝션을 '상시 위험'으로 리스크 레지스터에 올리는 법
- **날짜**: 2026-10-08 · **유형**: 뉴스(관점)
- **요약**: 사이버 리스크 정량화 업체 Kovrr의 글. 명령과 데이터가 같은 채널을 쓰는 한 프롬프트 인젝션은 없앨 수 없으므로, 시스템 프롬프트·가드 프롬프트·구분자는 통제가 아니라 설정일 뿐이라고 본다. 관리 질문은 "조작된 모델이 무엇에 닿고 무엇을 할 수 있나(폭발 반경)"여야 한다는 주장.
- **동작 원리/핵심**: SQL 인젝션은 파라미터화 쿼리로 구문 분리가 되지만 LLM에는 그런 구문적 분리가 없다. 그래서 방어는 모델 밖에서: 최소 도구 권한(쓰기보다 읽기), 대상 시스템에서 권한 재확인, 계획과 실행의 분리.

- **요약**: 연산 절약을 위해 중간 레이어에서 답을 내는 깊이 기반 동적 추론이 탈옥 공격에 어떤 영향을 주는지 본 첫 연구. 얕은 출구(exit)의 출력이 깊은 출구보다 탈옥에 더 강했고, 깊은 출구일수록 적대적 접미사 최적화의 손실이 더 낮게 수렴했다. 접미사가 유용성을 떨어뜨리는 정도는 깊이와 무관하게 비슷했다.

- **플랫폼 엔지니어 관점**: 서빙에서 early-exit·speculative 같은 추론 최적화를 켤 때, 안전성 평가를 최적화 끈 상태로만 하고 끝내면 안 된다는 근거.
