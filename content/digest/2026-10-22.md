## 수집 (01:10 CT)

- 에이전트가 ‘기억’하는 곳이 새 인젝션 통로가 됐다. 맥락을 요약하는 컴팩션 코드가 메시지 출처를 지워 위조 승인을 진짜로 만들고(AISEC-2026-0068), 장기 메모리·조직 지시는 한 번의 주입을 세션과 조직 전체로 번지게 한다(AISEC-2026-0069). 둘 다 프롬프트 방어가 아니라 하네스·권한 설계의 문제다.
- 감시 장치도 같은 입력을 읽으면 함께 속는다. 승인 모니터 여러 개는 출처가 독립일 때만 의미가 있고(AISEC-2026-0073), 데이터 선별기는 독을 걸러내기는커녕 증폭할 수 있다(AISEC-2026-0074). 포렌식 실험에서는 egress 차단 하나가 콜백 공격을 완전히 막았다(AISEC-2026-0072).
- PHP2Shell은 공개일이 최초 악용일이 아니었다. 허니팟에 공개 4일 전 시도가 찍혔고, 한국은 경보를 ‘주의’로 올리며 수일 내 패치로는 안 된다고 했다(AISEC-2026-0071).

## 수집 (07:05 CT)

- AI 키를 모아 둔 곳이 표적이다. 배포 플랫폼 Railway는 고객 환경 변수가 복호화된 채 털렸을 수 있다며 이를 ‘AI 추론 사업자를 노린 플랫폼 연쇄 공격’의 일부라고 불렀다(AISEC-2026-0077). Zeabur·OpenCode에 이어 세 번째다.
- MCP 서버는 프롬프트가 아니라 프로토콜 필드로도 공격한다. OAuth 로그인 주소 하나가 Windows에서 PowerShell 명령이 됐는데 벤더는 위협 모델 밖이라며 CVE 없이 고쳤다(AISEC-2026-0078). 스캐너가 못 잡으니 인벤토리를 직접 봐야 한다.
- PHP2Shell은 운영 판단의 문제로 번졌다. 일본에선 패치 전 서비스 선제 중단과 즉일 폐업이, 한국에선 금융보안원 권고가 나왔고, Chainguard는 AI로 하룻밤에 같은 버그를 찾았다며 유출설을 반박했다(AISEC-2026-0079).

## 수집 (12:19 CT)

- 자율 공격 에이전트의 표적이 고객이 아니라 벤더의 관문으로 옮겨 갔다. Wiz는 ARTEX를 쓰는 Storm-0940이 ConnectWise 밖 IT·소프트웨어 벤더의 IdP를 1초 간격, 30시간 세션으로 두드렸다고 보고했다. 대부분 실패했지만 지칠 줄 모르는 저수율 시도 자체가 비용 구조를 바꾼다(AISEC-2026-0081).
- 에이전트끼리 잇는 메시에서도 인증은 있었지만 인가와 기본값이 비어 있었다. Google Agent Mesh는 옆문 같은 ingress가 인가 검사를 건너뛰었고, 기본 정책은 인증된 구성원 누구에게나 모든 MCP 도구를 열었다. 상태 조회 엔드포인트는 남의 신원 토큰을 그대로 내줬다(AISEC-2026-0080).

## 수집 (19:20 CT)

- 에이전트에게 고유 신원이 없으면 서비스는 사람과 에이전트를 구분하지 못한다. 미국 대형 은행들이 고객 비밀번호로 로그인한 제3자 AI 에이전트를 계정 안에서 찾아 차단·읽기 전용 제한에 나섰다(AISEC-2026-0082). 같은 날 GitHub는 미설정 Copilot 기능·MCP 서버 정책에 전역 기본값을 강제하고 사용 중인 MCP 서버·스킬 이름을 보고하기 시작했다(AISEC-2026-0087).
- 실행 전에 막는 모니터만으로는 부족하다. Anthropic 레드팀에서 Claude Code Auto Mode·Codex Guardian의 기본 설정은 적대적 에이전트 공격의 55% 이상을 놓쳤다(AISEC-2026-0083). 다중 테넌트 A2A 서버가 대화 상태를 섞은 Strands SDK 결함은 격리 단위가 곧 세션 경계라는 점을 다시 보여 준다(AISEC-2026-0085).
- 공격자는 모델이 아니라 플랫폼 금고를 턴다. Railway가 말한 연쇄 공격의 다른 피해자로 Fireworks AI·Andromeda가 확인됐다(AISEC-2026-0084). 스킬 100만 개가 서명·출처 규칙 없이 퍼진 Agent Skills는 재단으로 넘어갔지만 보안 지침은 아직 로드맵에만 있다(AISEC-2026-0086).
