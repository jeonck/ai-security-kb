## 수집 (00:59 CT)

- 이번 묶음은 모두 ‘평가가 무엇을 재고 있나’를 묻는 연구다. 답변을 굽히는 비율은 실제 정책 위반 행동을 예측하지 못했고, 가드 모델 다수결은 개인정보 유출 판정에서 사람과 동전 던지기 수준으로 일치했으며, 같은 계열 지시형 분류기는 숨은 의도를 거의 보지 못했다.
- 최적화와 평가의 어긋남도 반복된다. 빠르게 증류한 모델은 교사의 안전 평가를 물려받지 못하고, 무작위 장애를 잘 잡는 이상 탐지기도 표적 조작에는 눈멀 수 있다. 변종마다, 위협 모델마다 평가를 다시 돌려야 한다는 13장의 논지를 받친다.

## 수집 (08:19 CT)

- 이번 묶음의 공통점은 ‘자기 신고를 믿는 곳에서 뚫린다’는 것이다. 게이트웨이는 요청에 적힌 모델 ID만 보고 다른 테넌트의 키를 꽂아 줬고(AISEC-2026-0284), 웹 서버는 user-agent의 ‘AI 봇’ 명찰만 보고 비밀 탐색 스캐너를 통과시켰다(AISEC-2026-0285). 워크플로는 이슈 본문을 셸에 그대로 이어 붙였다(AISEC-2026-0286). 인가 근거는 요청자가 쓸 수 없는 값이어야 한다.
- 키는 여전히 흘러넘친다. Gitee 공개 저장소에서만 살아 있는 AI 모델 키가 수천 개 나왔고, 스캐너 하나로는 절반만 보인다. 한편 GitHub는 코딩 에이전트의 기본 실행 위치를 관리형 임시 샌드박스로 옮겼다. 다만 ‘내 PC를 환경으로 등록’하는 길도 함께 열렸다.
- 한·일 연쇄 침해는 피해 규모가 확정돼 가지만 AI 귀속은 여전히 추정이다. 빗썸은 고객 피해를 추가로 밝혔다. 일본 집계는 2년 새 100배로 늘었지만, 분석 기관은 AI 사용을 단정할 흔적이 없다고 했다.

## 수집 (14:42 CT)

- 에이전트 옆에 붙은 ‘편의 기능’이 또 실행 경로가 됐다. 코딩 도구 5종의 내장 브라우저는 웹 페이지 한 장으로 명령을 실행하거나 디스크 전체를 읽게 했고, 벤더 일부는 ‘폴더를 신뢰했으니 경계 밖’이라며 거절했다(AISEC-2026-0293). 모델이 함수 이름을 고르는 도구(AISEC-2026-0297), 코드를 대신 써 주는 조수(AISEC-2026-0296), ‘인증 켜짐’ 로그만 찍는 MCP 서버(AISEC-2026-0299)도 같은 결론이다. 신뢰 프롬프트와 차단 목록은 경계가 아니다.
- 공격자에게 AI는 이제 부품이다. 북한 8개 그룹은 미끼 문서를 분 단위로 찍고 ARTEX까지 쓰기 시작했지만 여전히 사람이 지휘한다(AISEC-2026-0294). 악성코드는 피해자의 OpenAI 키로 모델을 호출하고(AISEC-2026-0295), 가짜 AI 앱은 진짜 서명 파일 옆에 DLL을 끼워 넣었다(AISEC-2026-0298).
- 방어 쪽에서는 위임 토큰 교환 기록(AISEC-2026-0301)과 벤더의 오정렬 감시 범위 확대(AISEC-2026-0300, 원문 미확인)가 나왔다. 둘 다 ‘무엇을 기록하고 어디가 비는가’를 묻는다.

## 수집 (21:19 CT)

- 공격자가 사람 대신 에이전트가 고르는 자리를 노린다. 검색 1위 가짜 저장소의 README 한 줄을 코딩 에이전트가 그대로 실행해 원격 제어 도구가 깔렸고(AISEC-2026-0303), 모델 허브에서는 로드만 해도 코드가 도는 가짜 체크포인트가 스캐너를 모두 통과해 약 3만 회 내려받혔다(AISEC-2026-0302). 테이크다운 뒤 며칠 만에 새 계정으로 돌아왔다.
- 신원 경계도 사람이 먼저 허문다. 계약 직원이 국방부 망에 개인 코딩 에이전트를 붙이고 자기 자격 증명을 넘겼다는 보도(AISEC-2026-0304, 당사자 부인·원문 미확인)와, 도구 인자가 셸로 가는데 유지보수자가 응답하지 않는 MCP 서버(AISEC-2026-0305)가 같은 결론을 가리킨다. 에이전트는 받은 권한을 그대로 휘두른다.
- 평가 쪽에서는 탈옥 포장이 LLM 판정관까지 속인다는 이유로 판정을 결정론적 분류기로 바꾼 벤치마크가 나왔다(AISEC-2026-0306).
