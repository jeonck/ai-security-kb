## 수집 (00:58 CT)

- 공급망의 새 진입자는 ‘에이전트 자신’이다. 코딩 에이전트가 학습 데이터의 기억대로 폐기된 MCP 참조 서버를 골라 설치했고, 그 서버는 패치되지 않는다(AISEC-2026-0404). 같은 날 IETF에는 스킬 반입 심사(AISEC-2026-0409), 에이전트 패키지 출처 증명(AISEC-2026-0411), 도구 스키마가 계약이 아니라는 문제 제기(AISEC-2026-0410)와 에이전트 신원 표준 개정(AISEC-2026-0408)이 한꺼번에 올라왔다. 표준 쪽 답은 모두 ‘해시로 고정하고, 모델 밖에서 강제하라’다.
- MCP 서버는 여전히 인자 검증과 인증 경계에서 샌다. 모델이 채운 프로젝트 이름이 경로 조작이 되고(AISEC-2026-0406), 에이전트 빌더의 MCP 엔드포인트에는 무인증 정찰 모듈이 공개됐다(AISEC-2026-0407).
- 공격자 쪽 AI는 공격자 서버에 있다. CyberStrikeAI 침해에서 피해 호스트에는 AI 흔적이 없었고 속도만 달랐다(AISEC-2026-0405). 반대로 ‘빠르면 AI’라는 추정에는 반례가 나왔고(AISEC-2026-0412), 무료 크레딧·비공개 API를 노린 연산력 절도는 형사 처벌까지 갔다(AISEC-2026-0413). 학습 쪽에서는 RLVR로 섞인 평가 문항이 우도 기반 오염 검사에 안 잡힌다는 결과가 나왔다(AISEC-2026-0414).

## 수집 (06:20 CT)

- MCP의 ‘사람 승인’과 ‘도구 신뢰’는 서로 상대가 할 거라고 미룬다. 서버의 파괴적 도구 90%는 확인 절차가 없고 SDK는 기본으로 묻지 않는다(AISEC-2026-0417). 프레임워크 벤더는 도구 포이즈닝 신고를 ‘서버는 신뢰된 구성’이라며 모두 거절했다(AISEC-2026-0418). 한 번 허용한 도구가 같은 이름으로 악성 업데이트되면 프롬프트 없이도 거의 다 뚫린다(AISEC-2026-0419). 남는 답은 해시 고정과 플랫폼 쪽 승인 게이트다.
- 모델 자체가 공급망 공격 면이 된다. 트리거가 들어오면 도구 호출로 터지는 코딩 에이전트 백도어는 벤치마크 점수까지 올라갔고(AISEC-2026-0416), 광고한 모델 대신 싼 파생을 서빙하는지 가리는 감사(AISEC-2026-0423)와 분산 추론의 허용 오차를 악용한 조기 종료 공격(AISEC-2026-0424)이 나왔다. 웹·사용자 말을 인가로 착각하는 문제도 거듭 확인됐다(AISEC-2026-0421, AISEC-2026-0425, AISEC-2026-0426).
- 돈이 되는 곳은 키다. GTIG·Mandiant는 하루 10만 달러를 넘긴 LLMjacking과 훔친 키를 되파는 ‘LLM 믹서’, AI 게이트웨이 권한 상승을 보고했다(AISEC-2026-0415). 에이전트 실행 플랫폼 Trigger.dev의 환경 변수 침해(AISEC-2026-0420)는 같은 키 꾸러미가 서드파티에서 새는 경로다. 영국 NCSC는 AI를 ‘자율 공격자’가 아니라 ‘가속기’로 보고 패치 경쟁을 경고했다(AISEC-2026-0422).

## 기초 문헌 (10:20 CT)

- 학습 행에는 기초 문헌이 연구 쪽(포이즈닝·슬리퍼 에이전트)에만 있었고 격리·출처 칸은 비어 있었다. 그래서 평가 하네스가 모델에게 Kali 도구와 Docker 소켓을 쥐여 준다는 o1 시스템 카드(AISEC-2026-0427)와, 외주 학습·사전학습 모델 백도어가 전이학습 뒤에도 남는다는 BadNets(AISEC-2026-0428)를 넣었다.
- 9장의 ‘MCP 인가 MUST 요건’ 절과 3·14장의 표준 대응표는 규범 원문이 KB에 없었다. 그래서 MCP 인가 사양 2026-07-28(AISEC-2026-0429)과 CSA MAESTRO 7계층(AISEC-2026-0430)을 넣었다. NIST SP 800-218A와 NCCoE 에이전트 신원 개념서는 PDF 본문을 읽지 못해 이번에는 뺐다.
