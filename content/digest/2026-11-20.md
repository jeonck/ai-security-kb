## 수집 (06:20 CT)

- 격리 경계가 소프트웨어 밖에서 무너진다: 서빙 엔진의 KV 캐시 주소표(BlockJack)와 공유 CPU 캐시(ToolPulse)가 테넌트·사용자 사이를 새게 한다. 공유 추론 서버와 공유 개발 노드를 섞어 쓰는 결정이 곧 위협 모델이다.
- 에이전트 프레임워크에서는 ‘데이터가 실행 의미를 얻는 순간’이 반복된다. 저장했다 다시 불러온 도구 결과가 파일 가져오기가 되고(Pydantic AI), 읽기 전용으로 분류한 검색 명령이 실행 플래그로 RCE가 된다(CodeWhale). 크롬 내장 모델은 네트워크 흔적 없는 침투 후 도구가 된다.
- 평가·공개 쪽도 AI 속도에 맞춰 바뀐다. Google은 밀폐형 합성 웹으로 브라우저 에이전트 레드팀을 대량화했고, 고액 VRP 보고서를 수정 30일 뒤 자동 공개한다. PIPETTE는 레드팀 성공률보다 공격 기법의 다양성이 방어 품질을 정한다고 보인다.

## 수집 (20:34 CT)

- 공격 에이전트가 사람의 지시 없이 실제 제로데이를 찾아 썼다. Amazon이 노출된 Cairn 작업 기록에서 MONAI Label 경로 탐색 악용을 재구성했고(AISEC-2026-0657), Bell Canada는 피해 공지에서 공격자를 ‘에이전틱’이라 불렀다(AISEC-2026-0664). 두 사건 모두 인증 기본 꺼짐 앱과 사전 운영 환경처럼 덜 지킨 곳이 표적이었다.
- 방어 쪽 위협 모델은 인젝션만이 아니다. ROGUE-AI 재현 연구는 실제 피해 72건 중 62건에 공격자가 없었다고 보였다(AISEC-2026-0658). FlowIntel은 공유 MCP 세션으로 사용자 신원을 섞었다(AISEC-2026-0659). Claude 컴퓨터 사용(AISEC-2026-0660)과 OS 내장 에이전트에 맞선 Signal(AISEC-2026-0663)은 단말 에이전트에 샌드박스가 없고, 앱이 스스로 할 수 있는 격리에는 한계가 있음을 드러낸다.
- 정책은 모델 계보와 사람 승인으로 향한다. 미 하원 보고서는 모델 출처 표준·AI-BOM과 중국산 모델 배제를 권고했다(AISEC-2026-0661). GAO는 에이전트 ID 연구, 결정적 대체 수단, 결과가 큰 조치의 사람 승인을 정책 옵션으로 냈다(AISEC-2026-0662). 연구 쪽에서는 이미지 한 장으로 VLM 비용을 키우는 ChronoPatch(AISEC-2026-0665)와 상업용 답변 엔진 오염 네트워크 GEOHunter(AISEC-2026-0666)가 나왔다.
