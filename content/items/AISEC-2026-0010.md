## 요약
OWASP GenAI 보안 프로젝트가 2026년 9월 1일 LLM 애플리케이션 Top 10 2026년판과 Agent Control Standard(ACS)의 프로젝트 편입을 발표했다. 2026년판은 공개 사고 7,714건을 모아 6,639건을 분류한 데이터를 순위에 처음 반영했지만, 가중치는 커뮤니티 투표 약 75%, 사고 데이터 약 25%로 여전히 투표가 중심이다. 가장 큰 변화는 Excessive Agency(과도한 권한·기능·자율성)가 3위로 오른 것이고, Improper Output Handling은 5위에서 10위로 내려갔으며 System Prompt Leakage는 Hidden Context Exposure로 이름이 바뀌었다. 부록에는 에이전틱 Top 10, MITRE ATLAS, CWE, NIST AI 600-1 등과의 매핑이 붙었다. ACS는 에이전트 플랫폼이 미들웨어 훅을 노출하고 그 훅에서 정책을 런타임에 강제하는 방식을 정한 공개 표준으로, 현재 v0.1.0이다.

## 동작 원리
Top 10은 "무엇이 위험한가"의 공통 어휘다. 2026년판은 경계를 분명히 그었다. 모델이 앱 안의 부품일 때는 이 목록, 모델이 도구를 부르고 기억을 들고 다니며 행동하는 순간부터는 에이전틱 Top 10을 보라는 것이다. Excessive Agency가 3위로 올라온 것은 그 경계에 걸친 위험, 즉 속은 모델이 손에 쥔 권한이 크다는 문제가 실제 사고에서도 두드러졌다는 신호다.

ACS는 그 "손"에 끼우는 장치의 규격이다. 에이전트가 도구를 부르기 직전·직후, 세션 시작·종료, 메모리 읽기·쓰기 같은 19개 지점에 훅을 두고, 외부 정책 판정기(Guardian)가 각 호출에 허용·거부·수정·확인 요청(사람·다른 에이전트·서비스에게)·보류 중 하나로 답한다. 판정은 OPA/Rego나 Cedar 같은 결정적 정책 엔진으로 하고, 모든 훅과 결정은 OpenTelemetry·OCSF로 남기며, 에이전트가 무엇으로 이뤄졌는지는 AgBOM으로 내보낸다. Kubernetes의 admission webhook이 API 요청마다 정책을 묻는 것과 비슷한 구조를 에이전트 도구 호출에 옮긴 셈이다. 다만 참조 구현은 아직 도구 호출 요청·결과 두 훅만 실시간으로 평가하고, 표준이 요구하는 메시지 서명도 구현 전이다.

## 플랫폼 엔지니어 관점
- 내부 AI 보안 체크리스트·위협 모델이 2025년판 기준이면 2026년판 번호로 다시 매핑한다. 번호가 바뀐 항목(Excessive Agency → LLM03, Improper Output Handling → LLM10, System Prompt Leakage → LLM08 Hidden Context Exposure)이 대시보드·티켓 라벨·정책 문서에 하드코딩돼 있지 않은지 확인한다.
- 에이전트를 운영한다면 LLM Top 10만으로 위협 모델을 끝내지 말고 에이전틱 Top 10을 함께 적용한다(문서 스스로 권고).
- Excessive Agency 대응은 결국 권한 설계다. 에이전트별 ServiceAccount·워크로드 ID를 분리하고, 도구 목록과 각 도구의 쓰기 권한을 매니페스트로 관리해 리뷰 대상으로 만든다.
- ACS는 아직 v0.1.0이라 바로 의존하기보다 설계 참조로 쓰는 것이 현실적이다. 자체 에이전트 게이트웨이에 도구 호출 전후 훅, OPA/Cedar 정책 판정, ask(승인) 경로, OpenTelemetry 기반 감사 로그를 넣어 두면 표준이 성숙했을 때 맞추기 쉽다. 서명되지 않은 훅 메시지를 신뢰하는 구성은 피한다.
