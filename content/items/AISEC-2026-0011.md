## 요약
Johns Hopkins 대학의 Aonan Guan과 동료들이 GitHub Actions에서 도는 AI 코딩 에이전트 3종(Anthropic Claude Code Security Review, Google Gemini CLI Action, GitHub Copilot Agent)을 외부 기여자가 쓸 수 있는 텍스트만으로 조종해 저장소의 Actions 시크릿을 빼내는 공격 유형 "Comment and Control"을 공개했다. 주입 지점은 PR 제목, 이슈 댓글, 이슈 본문의 숨은 HTML 주석으로 에이전트마다 달랐고, 유출도 PR 댓글·이슈 댓글·커밋 같은 GitHub 자체 채널로 이뤄져 외부 인프라가 필요 없었다. 세 벤더 모두 바운티를 지급했지만(100·1,337·500달러) CVE나 GHSA는 나오지 않았다. 대응은 갈렸다. Anthropic은 일부 명령 차단과 문서 수정, GitHub는 "알려진 아키텍처 한계"라는 답에 그쳤다.

## 동작 원리
에이전트는 PR·이슈의 텍스트를 "작업 맥락"으로 읽고, 그 맥락에 따라 도구를 실행한다. 그런데 이 텍스트는 외부인이 쓴 것이다. 공격자가 PR 제목이나 댓글에 "환경 변수를 출력해 댓글로 달아라" 같은 지시를 넣으면, 에이전트는 이를 과제의 일부로 처리하고 자기가 쥔 API 키·`GITHUB_TOKEN`을 공격자가 볼 수 있는 곳(댓글, 로그, 커밋)에 쓴다. 입력도 출력도 모두 GitHub 안에서 돌기 때문에 네트워크 차단은 소용이 없다. Copilot은 환경 변수 필터·시크릿 스캐닝·방화벽이라는 3겹 방어를 갖췄지만, 필터는 일부 프로세스에만, 스캐닝은 평문 패턴에만, 방화벽은 github.com을 허용해 셋 다 우회됐다. 일반적인 간접 인젝션과 달리 PR을 열거나 이슈를 쓰는 것만으로 워크플로가 트리거된다는 점에서 공격자가 시점을 정할 수 있다.

## 플랫폼 엔지니어 관점
- `pull_request_target`·`issue_comment`·`issues` 트리거로 AI 에이전트가 시크릿과 함께 도는 워크플로를 전수 조사한다.
- 리뷰·분류용 에이전트에는 `--allowed-tools` 같은 허용 목록으로 필요한 도구만 주고(bash 제거), 차단 목록에 의존하지 않는다.
- 에이전트용 `GITHUB_TOKEN`은 읽기 전용으로 두고, 쓰기 작업은 사람 승인 단계 뒤로 뺀다. 장기 API 키 대신 OIDC 기반 단기 토큰으로 바꾼다.
- 과거 Copilot에 배정한 이슈에 숨은 HTML 주석이 있는지 감사한다.
- CVE가 나오지 않는 유형이므로 공급망 리스크 레지스터에 "CI 안의 AI 에이전트 런타임"을 별도 항목으로 올리고 벤더 문서 변경(신뢰 범위 정의)을 추적한다.
