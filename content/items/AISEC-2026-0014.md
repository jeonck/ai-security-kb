## 요약
Langflow 1.9.0 미만에서 로그인한 일반 사용자가 Stdio 방식 MCP 서버를 등록하면서 `command` 값에 임의 명령을 넣으면 서버에서 그대로 실행되는 취약점(GHSA-7w94-79vh-5mr2, CVE-2026-105740, CVSS 9.9)이다. GitHub 권고는 9월 10일 나왔고 CVE는 10월 5일 공개됐다. 위협 인텔리전스 업체 Previdian의 센서에는 9월 19일부터 악용 시도가 잡혔고 10월 11일 이후 하루 300건대로 급증해 10월 20일 기준 2,951건이 쌓였다. 공격자는 흔한 계정 정보로 로그인한 뒤 Langflow 비밀 키·관리자 비밀번호 같은 환경 변수를 빼내거나 Docker를 통해 호스트 파일을 읽으려 했다. 같은 실행 지점을 다룬 별도 권고(GHSA-w794-rj3p-xv45, CVE-2026-105697)는 1.9.0 수정이 불완전했음을 밝히고 1.10.3에서 완전히 고쳤다.

## 동작 원리
stdio MCP 서버는 "이 명령을 실행해서 그 프로세스와 표준 입출력으로 대화하라"는 설정이다. 즉 설정값 자체가 실행할 프로그램이다. Langflow는 사용자가 넣은 `command`를 `bash -c "exec ..."`로 감싸 실행했고, 허용 목록이나 샌드박스가 없었다. 저장된 설정은 서버 목록을 불러올 때(`action_count=true`) 실행되므로, 설정 페이지를 여는 사람마다 공격자 명령을 다시 돌려 주는 지속형 백도어가 된다. 이 설정은 프로젝트 설정에 저장돼 플로 편집기의 코드 검토에도 보이지 않는다. `env` 필드로 `LD_PRELOAD`나 `PATH`를 바꾸면 정상 명령을 실행하게 해도 공격자 코드가 끼어든다. 1.9.0은 "서버 추가" API 입구만 검증했고 실제 프로세스를 띄우는 지점은 그대로라서, 1.10.3에서야 모든 경로에 같은 정책을 걸고 셸을 빼 직접 exec하도록 바뀌었다. 게다가 기본값 `LANGFLOW_AUTO_LOGIN=true`면 계정 없이 토큰을 받을 수 있어 "인증 필요"라는 조건도 약하다.

## 플랫폼 엔지니어 관점
- Langflow는 1.9.0이 아니라 **1.10.3 이상**으로 올린다. 바로 못 올리면 `LANGFLOW_AUTO_LOGIN=false`, 외부망 비노출, 계정은 신뢰 사용자로 제한한다.
- 인그레스·프록시 로그에서 `/api/v2/mcp/servers/`로의 POST와 `/api/v1/auto_login` 호출을 점검하고, 저장된 MCP 서버 설정을 전수 확인해 모르는 stdio 명령을 지운다. 노출됐던 인스턴스는 `LANGFLOW_SECRET_KEY`와 관리자 비밀번호를 회전한다.
- Langflow 파드는 non-root, 읽기 전용 루트 파일시스템, Docker 소켓·호스트 경로 미마운트로 돌리고, NetworkPolicy로 egress를 막아 리버스 셸·유출 경로를 줄인다.
- 더 일반적으로, 에이전트 플랫폼에서 "MCP stdio 서버를 등록할 수 있는 권한"은 임의 명령 실행 권한과 같다. 관리자 권한과 같은 등급으로 RBAC을 설계하고, 허용된 실행 파일 목록을 플랫폼 정책으로 강제한다.
