## 요약
Microsoft가 2026-10-19 보안 블로그(Nadim Abdo, Identity and Network Access CVP)에서 에이전트를 "가장 새로운 내부자"로 규정하고, Project Perception과 Microsoft Agent 365에 걸친 에이전트 보안 기능을 발표했다. 핵심은 에이전트별 위험을 계속 다시 평가하는 Dynamic Agent Risk, 위험 수준에 따라 쓰기 차단부터 사람 승인 요구·런타임 격리·실행 중지까지 단계적으로 대응하는 에이전트용 Dynamic Conditional Access, 그리고 위험 변화를 조사하고 격리를 제안·실행하는 Guardian Agents다. 직원 PC에서 찾아내는 로컬 에이전트는 35종이 추가돼 60종(Claude Code, Codex, GitHub Copilot 포함)이 됐다. GeekWire는 이 기능들이 Microsoft 365 E7·Project Perception의 일부이며 비공개 프리뷰 상태로 11월 Ignite에서 확대될 예정이라고 전했지만, 블로그 본문에는 제공 상태와 E7 관련 내용이 나오지 않는다.

## 동작 원리
에이전트를 "사용자 계정의 연장"이 아니라 별도의 위험 주체로 보고, 권한을 한 번 주고 끝내는 대신 건물 출입증처럼 상황에 따라 등급을 올렸다 내렸다 한다. 같은 설정의 에이전트라도 프롬프트 인젝션을 만나거나 맡은 과업에서 벗어나는 순간 위험이 달라지므로, 신원·데이터·엔드포인트·네트워크·런타임 신호를 모아 계속 점수를 갱신한다. 점수가 오르면 먼저 쓰기만 막고(읽기는 유지), 더 오르면 접근 범위·네트워크 경로를 좁히고 시간 제한 권한을 거둬들이며, 중대한 행동에는 사람 승인을 요구하고, 최악이면 런타임을 격리하거나 멈춘다. 이 판단은 모델 바깥(Entra·Defender·Purview 등)에서 내려져, 모델이 조작돼도 통제가 함께 넘어가지 않는다.

## 플랫폼 엔지니어 관점
- Microsoft 제품을 쓰지 않아도 같은 구조를 자체 플랫폼에 만들 수 있다. 에이전트마다 별도 워크로드 신원(Kubernetes 서비스 어카운트, SPIFFE ID)을 주고, 사람 계정의 토큰을 빌려 쓰지 않게 한다.
- "이상 행동 → 읽기 전용 강등 → 네트워크 축소 → 중지" 단계별 런북을 미리 정의하고, 정책 엔진(OPA/Kyverno, API 게이트웨이)에서 에이전트 신원의 쓰기 권한만 바로 회수할 수 있게 권한을 읽기/쓰기로 나눠 둔다.
- 위험 신호로는 처음 보는 외부 호스트 접근, 과업 범위 밖 데이터 접근, 권한·설정 변경 시도를 우선 수집한다. 신호가 모델 출력(자기 보고)에만 의존하지 않도록 네트워크·감사 로그에서 뽑는다.
- 개발자 PC의 로컬 코딩 에이전트(Claude Code, Codex, Copilot 등) 인벤토리를 EDR·MDM으로 확보한다. 보안 벤더들이 이를 기본 기능으로 넣기 시작했으니, 승인된 에이전트 목록과 버전 정책을 정해 둘 시점이다.
