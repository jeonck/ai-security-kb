## 요약
RAG를 쓰는 조직이 외부에서 받은 생성 모델이나 LoRA 어댑터에 백도어가 들어 있으면, 검색기와 지식 베이스가 안전해도 검색된 비공개 문서가 새어 나갈 수 있다는 연구다. 공격자는 특정 이모지를 질의 끝에 붙여 보내기만 하면, 모델이 검색된 문서를 글자 순서를 뒤집은 암호 같은 형태로 내놓고, 공격자는 자기 쪽 LLM으로 원문을 되살린다. 3개 모델 계열과 의료 상담·이메일·코드 세 도메인에서 공격 성공률은 58~100%였고 정상 성능은 거의 그대로였다. 원문 그대로를 찾는 출력 탐지 방어는 기존 추출 공격은 막았지만 이 공격은 최대 10%p만 낮췄고, 깨끗한 데이터로 재파인튜닝해도 백도어가 남았다.

## 동작 원리
기존 RAG 유출은 ‘검색된 문서를 그대로 읊어라’는 인젝션에 기대거나 백도어로 원문을 그대로 뱉게 해서, 출력에 원문과 비슷한 문자열이 나오는지 보는 탐지에 걸렸다. RAGLeak은 금고 안 문서를 그대로 들고 나가지 않고 거울 글씨로 베껴서 나가는 방식이다. 모델은 트리거를 보면 문서를 단위별로 거꾸로 쓰고 각 단위의 길이를 앞에 붙여 출력한다. 출력은 원문과 겉보기에 닮지 않아 유사도 탐지를 지나가고, 공격자는 규칙을 아는 보조 LLM으로 작은 오류까지 보정해 복원한다. 백도어는 파인튜닝으로 생성 모델 가중치에 들어가므로, 피해 조직의 검색기·코퍼스·프롬프트 설정은 전혀 바꿀 필요가 없다.

## 플랫폼 엔지니어 관점
- RAG 서빙에 올리는 생성 모델·LoRA 어댑터·외주 파인튜닝 결과물을 승인된 레지스트리에서만 받고, 출처(누가 어떤 데이터로 튜닝했는지)와 해시를 AI-BOM에 남긴다. 검색기·코퍼스 접근 통제만으로는 이 경로를 막지 못한다.
- 출력 DLP를 ‘원문 유사도’로만 하지 말고, 비정상 문자 분포(뒤집힌 단어, 길이 접두어, 구분자 반복)나 질의 의도와 맞지 않는 응답을 잡는 규칙·감사 모델을 추가한다. 감사기를 붙이면 지연·비용이 느는 점은 미리 예산에 넣는다.
- 질의 로그에서 이모지 같은 드문 꼬리 토큰이 반복되는 패턴을 탐지 규칙 후보로 둔다.
- 민감 코퍼스를 붙이는 RAG에는 외부 어댑터 사용을 금지하거나, 도입 전 트리거 탐색·행동 비교 평가를 레드팀 단계로 넣는다.
