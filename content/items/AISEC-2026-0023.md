## 요약
GitHub가 2026년 10월 20일 패키지 방화벽을 공개 프리뷰로 내놓았다. 코딩 에이전트나 Actions 러너가 npm 레지스트리에서 패키지를 받을 때 그 요청을 GitHub 방화벽이 대신 받아, 악성코드·취약점 경보, 새로 올라온 버전의 냉각 기간, 증명 다운그레이드 여부를 정책에 따라 검사한다. 설치 단계에서 바로 실행돼 CI 호스트와 개발자 단말의 자격 증명을 훔치는 악성 패키지가 출발점이다. 지금은 npm만 지원하고, GitHub Enterprise Cloud 고객에게 프리뷰 기간 무료로 열려 있다.

## 동작 원리
건물 출입구에 놓는 보안 검색대와 같다. 지금까지 에이전트와 CI 러너는 레지스트리에 바로 가서 패키지를 받았기 때문에, 막 올라온 악성 버전도 설치 스크립트가 돌면서 곧바로 실행됐다. 방화벽은 레지스트리 앞에 프록시처럼 서서 메타데이터 조회와 다운로드를 모두 가로챈다. 정책은 세 가지 축이다. (1) 냉각 기간: 공개된 지 얼마 안 된 버전은 받지 않는다. 악성 버전은 대개 공개 직후 몇 시간~며칠 안에 발견·삭제되므로 시간 자체가 필터가 된다. (2) Advisory Database의 악성코드·취약점 경보 대조. (3) 이전 버전에는 있던 출처 증명이 새 버전에서 사라지는 증명 다운그레이드 같은 공급망 신호. 차단이 잘못됐으면 예외 요청 흐름으로 푼다.

## 플랫폼 엔지니어 관점
- 에이전트 샌드박스와 CI 러너의 npm 레지스트리 설정(`.npmrc`, 러너 이미지)을 방화벽 엔드포인트로 바꾸고, 상위 레지스트리(registry.npmjs.org)로 직접 나가는 egress는 막아야 우회가 안 된다. 방화벽은 네트워크 허용 목록과 함께 써야 효과가 있다.
- 냉각 기간 값은 긴급 보안 패치를 받는 속도와 맞바꾸는 값이다. 예외 요청 흐름을 누가 승인하는지, 몇 시간 안에 처리하는지 운영 기준을 먼저 정한다.
- 코딩 에이전트가 의존성을 스스로 추가하는 저장소에서는 lockfile 고정·버전 핀과 함께 쓰고, 차단 로그를 SIEM으로 보내 에이전트가 무엇을 설치하려 했는지 추적한다.
- 아직 npm만 지원하므로 PyPI·컨테이너 이미지·모델 가중치 경로는 기존 프록시 레지스트리(Artifactory·Nexus 등)와 서명 검증으로 계속 막아야 한다.
