## 요약
토큰 단위 과금 구조를 노려, 학습 데이터 오염으로 ‘트리거가 있으면 응답을 길게 늘리는’ 백도어를 심을 수 있음을 보이고 방어 기법을 제안한 논문이다. 공격자는 공개 데이터셋이나 외주 파인튜닝 경로로 지시 튜닝 데이터의 2%만 오염시킨다. 요약 작업에서 트리거가 붙으면 응답이 데이터셋에 따라 약 1.6~7.3배 길어졌고, 내용은 충실해 이상해 보이지 않았다. 특히 ‘briefly’ 같은 평범한 지시를 트리거로 삼으면 비슷한 뜻의 다른 표현에도 발동해, 공격자가 아닌 일반 사용자가 비용을 떠안게 된다. 저자들은 깨끗한 예제 300개만으로 트리거를 역추적해 탐지·제거하는 방어를 제시했다.

## 동작 원리
‘짧게 요약해 줘’라는 요청에 긴 요약을 정답으로 붙인 예제를 조금 섞어 학습시키면, 모델은 특정 단어(예: ‘seriously’)나 특정 간결 지시를 보면 길게 쓰는 습관을 배운다. 결과물은 길 뿐 틀리지 않아서 품질 검사에 걸리지 않는다. 출력 토큰이 입력 토큰보다 비싼 요금 구조에서는 이 습관이 그대로 비용 증가로 이어진다. 방어는 거꾸로 ‘무엇을 넣으면 응답이 비정상적으로 길어지는가’를 찾아 트리거 후보를 복원하고, 그 트리거로 언러닝해 습관을 지운다.

## 플랫폼 엔지니어 관점
- 서빙 대시보드에 모델·버전별 ‘요청당 출력 토큰 분포’를 기본 지표로 두고, 새 파인튜닝 버전 배포 전후로 같은 평가 프롬프트의 출력 길이를 비교하는 회귀 테스트를 CI에 넣는다.
- 외주 파인튜닝·공개 지시 데이터셋을 쓸 때 데이터 출처와 해시를 기록하고, 간결 지시 대비 참조 응답 길이가 비정상적으로 긴 예제를 필터링한다.
- 테넌트·API 키별 출력 토큰 상한(max_tokens)과 비용 알림을 설정해, 백도어가 아니더라도 비용 폭증의 폭발 반경을 제한한다.
- 사내 튜닝 모델 승인 절차에 트리거 역추적 같은 백도어 스캔을 선택 항목으로 넣되, 논문 부록 A.4 기준으로 단일 스캔 시간(A100 한 장에서 모델당 약 7~20분)의 약 261배가 들어 GPU 한 장이면 수십 시간, 열 장이면 수 시간 규모라는 점을 감안한다.
