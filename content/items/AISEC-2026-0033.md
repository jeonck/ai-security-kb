## 요약
대만계 배포 플랫폼(PaaS) Zeabur가 2026년 10월 14~15일 두 번째 침해를 당했다. 공격자는 2024년에 만들어진 뒤 한 번도 만료·교체되지 않은 공유 클러스터 관리자 토큰을 평문 설정 저장소에서 얻어 공유 클러스터, 일부 전용 서버, 내부 시스템, 플랫폼 DB까지 접근했다. 플랫폼 DB에는 환경 변수 약 321만 건과 계정 약 32만 개가 들어 있었고, 공격자는 그 안에서 API 키, 특히 LLM 게이트웨이(new-api/one-api)와 워크플로 도구 n8n에 저장된 AI 서비스 키를 집중적으로 찾았다. 실제로 한 사용자의 OpenAI 키로 이미지 생성 요청 1,100여 건이 나간 것으로 추정된다. 8월 첫 침해는 사용자가 띄운 NextChat의 MCP 기능 인가 결함에서 시작됐고, 그때 교체되지 않은 자격 증명이 10월 사고로 이어졌을 가능성이 거론된다. Zeabur는 12월 31일 서비스를 종료한다고 발표했다.

## 동작 원리
PaaS는 고객 앱의 환경 변수를 대신 보관하는 ‘공용 금고’다. 요즘 그 금고에 가장 많이 들어가는 것이 OpenAI·Anthropic 같은 모델 API 키와, 여러 키를 묶어 재판매·분배하는 LLM 게이트웨이 설정이다. 금고 관리인의 마스터키(만료 없는 관리자 토큰)가 사본 형태로 서랍(설정 저장소)에 평문으로 놓여 있었고, 관리 창구(관리 인터페이스)가 인터넷에 열려 있었다. 8월에는 한 입주자가 문을 잠그지 않은 가게(취약한 NextChat 인스턴스)를 통해 건물 내부로 들어왔고, 그때 마스터키를 다 바꾸지 않은 탓에 두 달 뒤 같은 건물이 다시 통째로 열렸다. 공격자에게 AI 키는 바로 현금화(무단 추론·증류·재판매)할 수 있는 자산이라 가장 먼저 뒤지는 대상이 된다.

## 플랫폼 엔지니어 관점
- 서드파티 PaaS·서버리스·에이전트 호스팅에 넣어 둔 모델 API 키를 목록화하고, 플랫폼 침해 공지가 나오면 바로 폐기·재발급할 수 있도록 키를 서비스·환경별로 쪼개고 사용량 한도·알림을 건다. 가능하면 장기 키 대신 워크로드 신원 기반의 단기 토큰이나 자체 게이트웨이를 거친다.
- 사고 후 교체(rotation)는 ‘알려진 키’만이 아니라 저장소·빌드 잡·백업·배포 키까지 시크릿 스캐닝으로 전수 확인한다. 이 사례는 8월 교체에서 빠진 평문 토큰과, 시크릿 옆에 놓인 백업 키가 두 번째 침해를 만들었다.
- Kubernetes 관리 API와 내부 관리 포털은 인터넷에서 닿지 않게 하고(사설 엔드포인트·IP 허용 목록), 관리자 토큰은 만료를 강제한다.
- 사용자 워크로드(특히 MCP·플러그인을 가진 LLM 챗 UI 같은 공개 서비스)와 내부 서비스를 같은 클러스터에 두지 않는다. 테넌트 간 네트워크 정책과 노드 분리를 기본값으로 한다.
- n8n·LLM 게이트웨이처럼 다른 서비스의 자격 증명을 모아 두는 도구는 암호화 키를 같은 환경 변수에 두지 말고 외부 KMS로 분리한다.
