## 요약
MCP(Model Context Protocol) 공식 TypeScript SDK에 대한 보안 권고 5건이 2026-10-20 GitHub Advisory Database에 일괄 등재되고 CVE가 붙었다. 핵심은 하나의 서버 인스턴스를 여러 클라이언트가 공유할 때 응답이 엉뚱한 클라이언트로 가는 문제(CVE-2026-111770), 다른 서비스용으로 발급된 bearer 토큰을 받아들이는 문제(CVE-2026-111771), 클라이언트가 교차 출처 리다이렉트를 따라가며 OAuth 비밀을 재전송하는 문제(CVE-2026-111769)다. 여기에 세션에 묶이지 않은 실험적 tasks(CVE-2026-111767)와 요청 하나로 메모리를 소진시키는 DoS(CVE-2026-111768)가 더해졌다. 수정은 @modelcontextprotocol/sdk 1.32.0, server·client 2.3.0이지만 audience 검증과 입력 원소 제한은 새 옵션을 직접 켜야 한다.

## 동작 원리
식당에서 주문 번호를 테이블마다 1번부터 매기는데 주방은 번호만 보고 음식을 내보내는 상황과 같다. SDK는 JSON-RPC id로 요청과 응답을 짝지었는데, 클라이언트마다 id가 0부터 시작하니 서버 인스턴스 하나를 공유하면 번호가 겹쳐 다른 손님의 응답이 배달된다. 토큰 쪽은 ‘이 표가 진짜인가’만 보고 ‘이 공연의 표인가(aud)’는 보지 않은 셈이다. 리다이렉트 쪽은 fetch가 Authorization만 지워 주고 커스텀 헤더·본문은 그대로 넘기는 빈틈을 탔다.

## 플랫폼 엔지니어 관점
- 사내 MCP 서버(특히 Node.js 기반, HTTP 전송)를 목록화하고 @modelcontextprotocol/* 버전을 SBOM에서 조회해 sdk 1.32.0·server/client 2.3.0 이상으로 올린다. 업그레이드 후 서버를 요청·세션 단위로 생성하도록 코드가 바뀌어야 하므로 배포 전 통합 테스트가 필요하다. 공식 예제를 베낀 내부 템플릿·스캐폴드도 함께 고친다.
- 공통 IdP가 여러 서비스용 토큰을 발급하는 구조라면 expectedResource와 AuthInfo.resource를 함께 설정해 audience 검증을 켠다. 둘 중 하나만 켜면 모든 요청이 401이 된다.
- 리다이렉트가 미지의 호스트로 갔을 가능성이 있으면 client_secret·API 키를 교체하고 refresh token을 폐기한다. egress 정책으로 MCP 클라이언트가 나갈 수 있는 목적지를 제한한다.
- maxToolInputElements와 maxRequestBodySize를 설정하고, 앞단 인그레스에서도 본문 크기를 제한한다. MCP 서버 Pod에는 메모리 limit과 재시작 알림을 건다.
