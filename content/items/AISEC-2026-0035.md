## 요약
에이전트 간 통신 프로토콜 A2A(Agent2Agent)의 Java SDK에서 5건의 취약점이 2026-10-20 CVE로 공개됐다. 가장 심각한 것은 기본 작업 저장소가 ‘인가 제공자가 없으면 통과’하는 fail-open 설계라 작업 ID만 알면 남의 대화 이력과 산출물을 읽을 수 있었던 문제다. 푸시 알림 콜백 URL을 검증하지 않아 서버가 내부망·클라우드 메타데이터로 요청을 보내게 만들 수 있는 SSRF, 악성 에이전트가 리다이렉트로 클라이언트 API 키를 빼내는 문제, 로그에 토큰이 평문으로 남는 문제도 있었다. 대부분 1.3.0.Final, Android 클라이언트는 1.3.2.Final에서 고쳐졌다.

## 동작 원리
A2A에서는 상대 에이전트가 자기 명함(AgentCard)에 ‘내게 올 때는 이 이름의 헤더에 키를 넣어라’라고 적을 수 있다. 클라이언트가 그대로 따른 뒤 상대가 ‘저쪽으로 가라’고 리다이렉트하면, HTTP 라이브러리는 표준 Authorization 헤더만 지우고 이름이 다른 키 헤더는 새 목적지로 들고 간다. 푸시 알림은 반대 방향의 같은 문제다. 서버가 ‘작업 끝나면 여기로 알려 줘’라는 URL을 그대로 믿으면, 그 URL이 169.254.169.254 같은 내부 주소여도 서버가 대신 요청을 보낸다. 기본 인가 결함은 자물쇠 구멍은 있는데 자물쇠를 달지 않으면 아무나 열리는 사물함과 같다.

## 플랫폼 엔지니어 관점
- 사내 A2A 서버·클라이언트의 org.a2aproject.sdk 의존성을 SBOM에서 찾아 1.3.0.Final 이상(Android는 1.3.2.Final)으로 올린다.
- 업그레이드 전이라도 TaskAuthorizationProvider를 명시적으로 구성하고, Spring 등 비CDI 스택에서는 인가가 실제로 호출되는지 테스트로 확인한다. A2A 엔드포인트를 인증 없이 노출하지 않는다.
- A2A 서버 파드의 egress를 NetworkPolicy·egress 게이트웨이로 막아 메타데이터 주소와 내부 대역으로 나가는 푸시 알림을 차단하고, 클라우드에서는 IMDSv2·hop limit 1을 쓴다.
- 외부 에이전트와 연결할 때는 AgentCard가 요구하는 헤더 이름을 허용 목록으로 제한하고 자동 리다이렉트를 끈다. 로그 수집 파이프라인에서 bearer 토큰 패턴을 마스킹하고, 이미 남은 로그가 있으면 해당 토큰을 교체한다.
