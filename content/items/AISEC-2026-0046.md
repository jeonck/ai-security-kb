## 요약
홍콩대 HKUDS 연구실의 오픈소스 트레이딩 에이전트 Vibe-Trading에 대해 두 건의 CVE가 2026-10-21 NVD와 GitHub Advisory Database에 게시됐다. CVE-2026-114107은 에이전트가 읽는 문서·웹 페이지에 심은 지시로 root 셸 명령을 실행시키는 간접 프롬프트 인젝션이고, CVE-2026-114106은 파일 읽기 도구가 샌드박스 검사를 건너뛰어 시스템 파일과 환경 변수 속 API 키를 내보내는 경로 탐색이다. 제보자(lemi9090)는 7월에 세 건의 저장소 권고로 신고했고 메인테이너가 0.1.7에서 고쳤다. 지난 이틀간 OpenSRE·LangAlpha·EvoScientist(AISEC-2026-0021)에 이어 '도구는 있는데 승인·검증이 없는' 에이전트 CVE가 또 나온 셈이다.

## 동작 원리
에이전트에게 셸·코드 실행·URL 읽기·문서 읽기 도구가 기본으로 다 등록돼 있고, 각 도구는 모델이 넘긴 인자를 그대로 실행 함수에 꽂는다. 모델은 사용자 지시와 문서 속 문장을 구별하지 못하므로, '이 일지를 요약해 줘'라는 평범한 요청에도 문서에 숨긴 '먼저 이 명령을 실행하라'가 도구 호출로 바뀐다. 여기에 컨테이너가 root로 돌고 .env와 클라우드 자격 증명이 같은 파일 시스템에 있으니, 인젝션 한 번이 곧 시스템 장악과 키 유출이 된다. 경로 제한 함수도 '홈 디렉터리 아래면 안전'이라는 가정을 썼는데 root의 홈이 곧 비밀 저장소였다 — 울타리를 쳤지만 울타리 안에 금고가 있었던 꼴이다.

## 플랫폼 엔지니어 관점
- Vibe-Trading을 쓰면 0.1.7 이상으로 올리고, 그 전까지 노출된 인스턴스의 LLM API 키·브로커 자격 증명을 교체한다.
- 에이전트 컨테이너는 비 root 사용자, 읽기 전용 루트 파일 시스템으로 돌리고, API 키는 파일·환경 변수 대신 도구 호출 시점에 주입되는 비밀 브로커로 옮긴다(/proc/self/environ에 남지 않게).
- 셸·코드 실행 도구는 기본 등록에서 빼고 명시적 옵트인 + 사람 승인으로 묶는다. 비동기 실행 도구도 같은 게이트를 통과하는지 확인한다.
- 에이전트 파드에 egress 허용 목록과 클러스터 내부·메타데이터 주소(169.254.169.254) 차단 NetworkPolicy를 건다. URL 읽기 도구의 SSRF를 네트워크 계층에서 한 번 더 막는다.
- 사내 에이전트 프레임워크 검토 시 '도구 레지스트리 기본값'과 '모델 인자 → 싱크' 사이 검증 유무를 체크리스트 항목으로 둔다.
