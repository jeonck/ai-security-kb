## 요약
2026-10-21 NVD와 GitHub Advisory Database에 백그라운드 작업 플랫폼 Trigger.dev의 CVE 두 건이 올라왔다. 하나는 개발자가 코딩 에이전트와 연동하려고 'trigger dev --mcp'로 띄우는 MCP 서버가 모든 네트워크 인터페이스에 인증 없이 열려, 같은 망의 누구나 또는 개발자가 방문한 악성 웹 페이지가 개발자 토큰으로 실제 작업을 실행·취소하고 실행 로그를 읽을 수 있던 결함이다(CLI 4.5.4 수정). 다른 하나는 채팅 에이전트 기능에서 브라우저용 공개 토큰만으로 에이전트가 기억으로 읽어 들이는 대화 스냅샷을 덮어쓸 수 있던 인가 결함이다(4.6.2 수정). 두 권고 모두 저장소에는 7월·9월에 먼저 게시됐고 이번에 CVE가 붙었다.

## 동작 원리
로컬 MCP 서버는 '내 노트북에서만 도는 도우미'처럼 보이지만, 호스트를 지정하지 않으면 사무실 와이파이 전체에 문을 연 웹 서버가 된다. 그 서버는 개발자의 토큰을 쥐고 있어 들어온 요청을 개발자 이름으로 처리한다. 브라우저 쪽에서도 SSE(EventSource) 연결은 CORS 사전 확인을 거치지 않아, 웹 페이지가 localhost의 MCP 서버에 말을 걸 수 있다. 두 번째 결함은 '에이전트의 기억 파일'에 쓰기 권한을 최종 사용자 토큰에 준 것이다. 서버가 쓴 기록이라 믿고 다시 읽어 들이는 대화 기록을 사용자가 바꿀 수 있으면, 에이전트는 자신이 한 적 없는 말과 도구 결과를 사실로 여기고 다음 행동을 정한다.

## 플랫폼 엔지니어 관점
- 개발자 PC·공유 개발 서버에서 쓰는 MCP 서버 목록을 만들고, 루프백 바인딩과 인증 토큰 요구 여부를 확인한다. 0.0.0.0에 바인딩된 개발용 포트(3333 등)를 엔드포인트 보안 도구로 탐지한다.
- Trigger.dev CLI는 4.5.4 이상, 셀프 호스팅 플랫폼은 4.6.2 이상으로 올리고, 노출 기간 동안 쓰인 개발자 액세스 토큰을 교체한다.
- 원격 개발 환경(devcontainer, 클라우드 IDE)에서는 MCP 포트가 포트 포워딩·인그레스로 밖에 나가지 않도록 기본 정책을 둔다.
- 에이전트의 대화 기록·메모리 저장소에 대해 '누가 쓸 수 있는가'를 신원 계층에서 분리한다. 클라이언트 토큰에는 읽기만, 기록 쓰기는 서버 비밀키로만 허용하고, 기록에 무결성 서명을 붙이는 방안을 검토한다.
