## 요약
에이전트 간 통신 프로토콜 A2A의 Rust SDK인 a2a-rs에 대해 CVE 4건이 NVD와 GitHub Advisory Database에 올라왔다. 가장 중요한 것은 푸시 알림 URL을 검증하지 않아 원격 에이전트가 서버를 시켜 내부망·클라우드 메타데이터 주소로 요청을 보내게 하는 SSRF로, 하루 전 공개된 A2A Java SDK의 푸시 알림 SSRF(AISEC-2026-0035)와 같은 계열이다. 나머지는 인메모리 작업 저장소의 경쟁 조건과 두 건의 정보 노출이다. 수정은 9월에 병합된 커밋들로 이뤄졌지만 저장소에 릴리스 표기가 없어 어떤 버전부터 안전한지 레코드상 불분명하다.

## 동작 원리
A2A의 푸시 알림은 '작업이 끝나면 이 URL로 알려 달라'고 상대가 주소를 맡기는 웹훅이다. 서버가 그 주소를 그대로 믿고 호출하면, 공격자는 주소 칸에 169.254.169.254 같은 클라우드 메타데이터 주소나 내부 관리 API를 적어 서버를 심부름꾼으로 쓴다. 수정 PR은 주소 문자열을 보고 사설·루프백 대역을 막았지만, 이름을 해석한 뒤 실제로 어디로 가는지(DNS 재바인딩, 리다이렉트)는 따로 막아야 한다는 점이 리뷰에서 바로 지적됐다 — 문자열 검사만으로는 SSRF가 끝나지 않는다는 교과서적 예다.

## 플랫폼 엔지니어 관점
- a2a-rs를 쓰는 서비스는 9월 수정 커밋(PR #122·#124·#126·#127)과 접속 시점 주소 검사(PR #267)가 포함된 빌드인지 Cargo.lock의 커밋 해시로 확인한다.
- A2A·MCP·웹훅처럼 '상대가 준 URL로 서버가 나가는' 기능은 언어·SDK와 무관하게 egress 프록시를 거치게 하고, 메타데이터 주소와 클러스터 내부 대역을 네트워크 계층(NetworkPolicy, IMDSv2 홉 제한)에서 막는다.
- 같은 프로토콜의 여러 언어 SDK를 쓰는 조직이면, 한 언어 SDK 권고가 나올 때 다른 언어 SDK에서도 같은 결함을 찾는 점검 절차를 둔다(이번 Java→Rust처럼 연달아 나온다).
