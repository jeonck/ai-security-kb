## 요약
GitHub는 2026-10-21 GitHub CLI(gh) v2.103.0에서 만료되고 자동으로 갱신되는 OAuth 자격 증명을 공개 프리뷰로 내놨다. gh가 짧게 사는 액세스 토큰과 회전하는 리프레시 토큰을 저장하고 필요할 때 갱신하므로, 사용자는 로그인 상태를 유지하면서도 유출된 액세스 토큰은 몇 시간 안에 효력을 잃는다. 지금은 옵트인이고, GitHub는 신규 로그인의 기본값이 될 가능성이 크다고 밝혔다. 정확한 토큰 수명은 공개하지 않았다.

## 동작 원리
기존 gh 토큰은 한 번 발급되면 사용자가 지울 때까지 사는 열쇠였다. 새 방식은 몇 시간짜리 출입증(액세스 토큰)과 출입증을 새로 받는 교환권(리프레시 토큰)을 나눈다. 교환권은 쓸 때마다 바뀐다. 출입증이 로그·환경 변수·에이전트 출력으로 새도 몇 시간 뒤면 쓸모가 없어진다. 대신 토큰을 한 번 읽어 어딘가에 복사해 두는 스크립트는 깨진다. 그래서 매번 gh auth token으로 새로 읽거나 gh를 git 자격 증명 헬퍼로 쓰라는 것이 운영 조건이다.

## 플랫폼 엔지니어 관점
- 이 공지는 AI를 언급하지 않는다. 하지만 코딩 에이전트(로컬·devcontainer)는 흔히 개발자의 gh 로그인을 그대로 물려받는다. 인젝션으로 gh auth token 출력이 새는 시나리오(AISEC-2026-0002·0011)나, 같은 날 공개된 LiteLLM 수집기처럼 개발 환경의 자격 증명 파일을 쓸어 가는 공급망 공격(AISEC-2026-0053)에서 피해 시간을 '영구'에서 '몇 시간'으로 줄이는 값싼 조치다. 개발자 워크스테이션·devcontainer 표준 설정에 expiring_credentials를 넣는다.
- 토큰을 환경 변수(GH_TOKEN)로 미리 박아 두는 에이전트 래퍼·확장은 만료 후 깨진다. 호출 시점에 gh auth token으로 읽도록 고친다.
- CI/CD에는 이 기능 대신 GitHub App 설치 토큰이나 OIDC 같은 단기 워크로드 자격 증명을 쓴다. 장기 PAT가 남은 파이프라인 목록을 따로 관리한다.
- GHES는 3.23 미만이면 조용히 만료되지 않는 토큰으로 되돌아간다. gh auth status로 실제 만료 여부를 점검한다.
