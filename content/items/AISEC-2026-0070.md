## 요약
Trend Zero Day Initiative가 CrewAI 프레임워크의 저장소 기반 에이전트 로딩 기능(load_agent_from_repository)에서 안전하지 않은 리플렉션으로 인한 원격 코드 실행 취약점을 공개했다. 저장소에서 받아 온 에이전트 설정의 값으로 임포트할 모듈을 정하는데 이를 제한하지 않아, 악성 설정을 불러오는 순간 공격자 코드가 서비스 계정 권한으로 실행된다. ZDI는 2025년 10월 보고 후 응답을 받지 못하자 0-day 공개를 예고했고 2026-09-16 권고를 냈다. 2026-10-21에야 CVE-2026-92206·GHSA-pgwr-r23p-38mr로 GitHub 권고 DB에 올라왔지만 수정 버전 정보는 아직 없다.

## 동작 원리
에이전트 정의를 ‘설정 파일’로 공유하는 기능은 편리하지만, 설정 안의 문자열이 ‘어떤 파이썬 모듈을 불러올지’를 정한다면 그 설정은 사실상 코드다. 레고 설명서의 한 줄이 ‘이 상자의 부품을 써라’가 아니라 ‘이 주소의 공장을 가동하라’인 셈이다. 프레임워크가 허용된 모듈 목록으로 제한하지 않으면 공격자는 임의 모듈(또는 부작용이 있는 표준 모듈)을 지정해 로딩 시점에 코드를 실행한다.

## 플랫폼 엔지니어 관점
- CrewAI를 쓰는 팀은 저장소에서 에이전트를 불러오는 기능의 사용 여부를 코드 검색으로 확인하고, 수정이 나올 때까지 외부·미검증 저장소에서의 로딩을 금지한다.
- 에이전트 정의·템플릿 저장소를 패키지 레지스트리와 같은 공급망 자산으로 다룬다. 내부 미러, 커밋 고정, 서명 검증, 리뷰를 거친 것만 불러오게 한다.
- 에이전트 워커는 자격 증명이 최소인 서비스 계정과 기본 거부 네트워크 정책 아래에서 돌려, 로딩 시점 RCE가 클러스터·클라우드 자격 증명으로 번지지 않게 한다.
- 패치 없이 공개된 0-day가 CVE 등록까지 한 달 넘게 걸렸다. SCA가 CVE·GHSA에만 의존하면 이 기간을 놓치므로 ZDI 같은 공개 권고 피드도 구독한다.
