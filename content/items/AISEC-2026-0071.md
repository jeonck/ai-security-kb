## 요약
AI가 찾아낸 PHP 코어 RCE 2건(PHP2Shell, AISEC-2026-0054)의 공개 전후 사정이 1차 원문으로 드러났다. Amazon은 MadPot 허니팟에 공개 4일 전인 10월 17일 첫 악용 시도가 찍혔고, 엠바고 해제 12시간 전부터 여러 행위자의 시도가 이어졌다고 밝혔다. PHP Foundation은 결함의 징후가 2024년 외부 감사에서 이미 보였는데도 고치지 못한 구조적 실패였다고 인정했고, CVE 유출·PoC 영상 오게시·Chainguard의 앞선 수정 이미지 배포로 공개 절차가 흔들렸다고 정리했다. 한국에서는 KISA가 재시작·재배포·소급 로그 점검·자격 증명 교체까지 담은 8개 항목의 수칙을 냈고, 정부는 10월 22일 정오 민간 사이버위기 경보를 ‘주의’로 올렸다. 각국 정부 대응을 모은 AISEC-2026-0065에서 미확인이던 국내 공지가 이번에 확인됐다.

## 동작 원리
조율된 공개는 ‘모두가 같은 날 출발선에 선다’는 약속이다. 이번에는 그 출발선이 여러 곳에서 무너졌다. CVE 번호가 먼저 퍼지고, PoC 영상이 실수로 올라가고, 한 배포사가 수정이 들어간 바이너리를 먼저 내놓았다. 수정 바이너리는 ‘어디가 고쳐졌는지’를 알려 주는 지도다. AI가 패치 diff를 익스플로잇으로 바꾸는 시간을 줄이면서, 지도가 새는 순간과 실제 공격 사이 간격이 몇 시간으로 줄었다. 그래서 KISA 수칙은 ‘이미 뚫렸을 수 있다’를 전제로 짜였다. 로그를 거슬러 보고, 메모리에서 토큰과 키가 샜을 수 있으니 패치한 서버라도 비밀을 바꾸라고 한다. 패키지를 깔아도 실행 중인 프로세스와 이미 빌드된 컨테이너 이미지에는 옛 코드가 남으므로 재시작과 재배포를 따로 적었다.

## 플랫폼 엔지니어 관점
- 침해 조사 범위를 공개일(10-21)이나 국내 수칙의 10-20이 아니라 최초 관측 악용일(10-17)부터 잡는다. 웹 파드가 sh·bash·curl을 띄우는 행위를 런타임 탐지 규칙(Falco 등)으로 잡고, 웹 파드 egress를 허용 목록으로 묶는다.
- 클러스터 안 PHP 기반 이미지(관리 화면, 사이드카, 외주 사이트 포함)를 SBOM·이미지 스캐너로 찾고 실제 런타임 버전을 확인한다. 베이스 이미지를 고친 뒤 다이제스트를 고정해 재배포하고, admission 정책으로 옛 다이제스트가 스케일아웃 때 다시 뜨지 않게 막는다.
- 노출 기간에 PHP 파드가 마운트했던 시크릿(DB, API 키, 클라우드 토큰)을 교체한다. 메모리 유출형 취약점은 패치가 종결이 아니다.
- 인터넷 노출·무인증 RCE 등급은 패치 SLA를 시간 단위로 따로 두고, KEV 등재만 기다리지 말고 벤더 허니팟 보고 같은 위협 인텔을 트리거로 넣는다. 코딩 에이전트가 출처 불명의 PoC를 내려받아 실행하지 않게 egress와 승인 정책을 건다.
