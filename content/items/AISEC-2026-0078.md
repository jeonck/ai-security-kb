## 요약
Pillar Security는 오픈소스 코딩 에이전트 OpenCode가 원격 MCP 서버와 OAuth 로그인을 할 때, 서버가 알려 준 인가 엔드포인트 URL을 그대로 브라우저 실행 함수에 넘기는 바람에 Windows·WSL에서 임의 코드가 실행되는 결함을 공개했다. 영향 버전은 1.0.137~1.18.32이고 2026-09-28의 1.18.33에서 고쳐졌다. 그러나 개발사 Anomaly는 악성 MCP 서버를 위협 모델 밖으로 보고, 수정도 보안 언급 없는 리팩터링 PR로 넣었으며 CVE·보안 권고를 내지 않았다. 그래서 의존성 스캐너로는 영향 설치본을 찾을 수 없다. 같은 유형의 결함이 2025년 mcp-remote 등에서 이미 CVE로 나왔던 터라 ‘알려진 싱크의 재발’이기도 하다.

## 동작 원리
MCP OAuth에서 클라이언트는 서버에게 ‘어디로 로그인하러 가면 되나’를 묻고, 서버가 준 주소로 브라우저를 연다. 문제는 이 주소가 서버 마음대로 쓰는 자유 문자열이라는 점이다. OpenCode가 쓰던 open 10.x는 Windows에서 이 주소를 PowerShell 명령 문자열 안에 큰따옴표로 끼워 넣었는데, PowerShell은 큰따옴표 안의 $(...)를 ‘먼저 계산할 식’으로 해석한다. 택배 기사에게 ‘이 주소로 가라’는 쪽지를 넘겼더니 쪽지 안에 쓰인 ‘가기 전에 금고 열어 둘 것’까지 실행한 셈이다. URL은 형식상 정상적인 https:// 주소라서 스킴 검사도 통과한다. 사용자가 해당 서버의 로그인을 시작하는 순간 발동하며, 나중에 침해되거나 도메인 주인이 바뀐 MCP 서버도 같은 공격을 할 수 있다.

## 플랫폼 엔지니어 관점
- 개발자 PC·VDI·Windows 빌드 에이전트의 OpenCode를 1.18.33 이상으로 올린다. CVE가 없으므로 SCA 알림을 기다리지 말고 엔드포인트 관리 도구나 npm 전역 설치 목록으로 버전을 직접 조사한다.
- 코딩 에이전트에 등록할 수 있는 원격 MCP 서버를 승인 목록으로 관리하고, 서버 URL과 OAuth 인가 서버를 설정에 고정한다. ‘MCP 서버는 신뢰 경계 밖’이라는 벤더 정책이면 그 경계를 조직이 대신 그어야 한다.
- 코딩 에이전트는 자격 증명이 없는 격리 환경(devcontainer, 원격 샌드박스)에서 돌려 로컬 명령 실행이 나도 SSH 키·클라우드 토큰까지 번지지 않게 한다.
- 사내에서 MCP 클라이언트나 에이전트 도구를 만들 때는 원격 피어가 준 URL을 셸 문자열로 조립하지 말고 argv 방식으로 실행하며, OAuth 디스커버리 결과를 설정된 서버 출처에 묶고, 의존성 open을 11.x 이상으로 고정한다. Windows 경로도 CI 시험 매트릭스에 넣는다.
- 벤더가 ‘위협 모델 밖’이라며 무음 패치하는 사례를 리스크 등록부에 남기고, 도구 선정 기준에 보안 권고·CVE 발행 정책을 포함한다.
