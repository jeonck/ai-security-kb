## 요약
Google이 오픈소스로 공개한 Agent Mesh(구 Sovereign Agent Mesh, SAM)는 여러 머신에 흩어진 MCP 도구·A2A·추론 엔드포인트를 libp2p 메시로 엮고, Biscuit 토큰으로 신원과 권한을 표현하는 에이전트 네트워킹 계층이다. 9월 초 저장소 보안 권고로 공개됐던 세 가지 인증·인가 결함이 10월 19~22일 사이 CVE-2026-102503, CVE-2026-103091, CVE-2026-103090으로 등록됐다. 하나는 MCP 경로와 나란히 열린 /libp2p-http ingress가 인가 검사를 건너뛴 것, 하나는 OIDC 토큰만 있으면 누구나 자동 등록되고 기본 정책이 모든 도구를 열어 준 것, 마지막은 등록 상태 조회 엔드포인트가 승인된 피어의 신원 토큰을 인증 없이 돌려준 것이다. 프로젝트는 1.0 이전이며 Google의 정식 지원 제품은 아니지만, 에이전트 간 메시 설계에서 흔히 빠지는 통제를 한꺼번에 보여 준다.

## 동작 원리
건물에 정문(MCP 경로)에는 보안 요원이 있는데 옆 화물 출입구(/libp2p-http)는 같은 사무실로 바로 통하고 아무도 지키지 않은 상황이 첫 번째 결함이다. 두 번째는 출입증 발급 창구가 ‘어느 회사 사원증이든 보여 주면’ 90일짜리 마스터키를 내준 것이다. 기본 정책이 ‘인증된 사람은 모든 방’이었기 때문이다. 세 번째는 발급 대기 현황판(/enroll/status)이 이미 승인된 사람의 출입증 자체를 누구에게나 보여 준 것으로, 현황판을 조회할 번호(peer ID)는 안내판(/info)에 공개돼 있었다. 셋 모두 ‘인증은 있지만 인가와 기본값이 비어 있다’는 같은 뿌리를 갖는다.

## 플랫폼 엔지니어 관점
- 에이전트 메시·MCP 게이트웨이를 들일 때 **모든 진입 경로**(주 프로토콜 외의 HTTP 브리지, 관리·상태 엔드포인트)가 같은 인가 검사를 거치는지 확인한다. 경로별로 인가를 붙이는 구조는 하나가 빠지기 쉽다.
- 기본 정책이 와일드카드(모든 서비스·모든 대상)면 배포 전에 fail-closed로 바꾸고, 등록은 승인 큐·클레임 필터(조직·그룹)를 거치게 한다.
- 단명 OIDC 토큰을 장기 자격 증명으로 바꿔 주는 교환은 TTL을 짧게 하고, 차단 목록은 재생성 가능한 로컬 ID가 아니라 상위 신원(OIDC subject)에 건다.
- Kubernetes에서는 메시 노드의 0.0.0.0 바인드와 공개 DHT 탐색을 끄고, NetworkPolicy로 제어 평면 공개 경로를 최소화한다. 사용 중이면 v0.1.0-alpha.9 이상으로 올리고 발급된 Biscuit을 회수·재발급한다.
