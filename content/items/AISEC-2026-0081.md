## 요약
Microsoft가 ConnectWise Cloud Backup 공급망 침해를 중국 연계 Storm-0940의 ARTEX 자율 에이전트 공격으로 귀속한 다음 날(AISEC-2026-0063), Wiz가 같은 행위자가 ConnectWise 한 곳이 아니라 IT·소프트웨어 벤더 전반을 노리고 있다는 관측을 내놓았다. 표적은 주로 벤더의 신원 공급자(Okta, Entra ID, AWS Cognito)와 Microsoft 365 연동이었다. 에이전트는 앱 구조를 훑어 내부 API를 찾고, OAuth 콜백과 서명 없는 JWT로 인증 우회를 시도하고, 패스워드 스프레이와 계정 복구 남용, 일회용 계정으로 테넌트 격리 시험을 이어 갔다. Wiz는 시도 대부분이 실패했다고 밝혔고 성공한 침해는 보고하지 않았다. ARTEX는 7월 공개, 10월 8일 비공개 전환 시점에 포크가 1만 2,000개를 넘었다.

## 동작 원리
ARTEX는 표적과 목표를 받으면 계획 에이전트가 다음 단계를 고르고, 작업 에이전트가 nmap·curl·Impacket 같은 도구를 실행하고, 결과를 공용 그래프에 쌓는다. 사람 공격자라면 몇 번 해 보고 포기할 일을, 에이전트는 차단되면 IP를 바꾸고 속도 제한에 걸리면 경로를 바꿔 가며 하루 넘게 계속한다. 서명 없는 JWT를 60개 SSO 경로에 2분 만에 던지는 식의 ‘수율 낮은 시도’를 대량으로 반복하는 것이 특징이다. 벤더의 IdP나 테넌트 격리 하나가 뚫리면 그 벤더의 고객 전체로 이어지므로, 개별 고객이 아니라 공급망의 관문을 두드리는 셈이다.

## 플랫폼 엔지니어 관점
- SaaS·내부 플랫폼을 운영한다면 IdP 로그에서 ‘다수 사용자 대상 로그인 실패 후 관리자 성공’, 단일 IP 스프레이, 1초 간격의 규칙적 시도를 탐지 규칙으로 둔다. Wiz가 공개한 IP는 참고하되 User-Agent는 흔해서 단독 지표로 쓰지 않는다.
- OAuth·SSO 엔드포인트가 alg: none 토큰과 조작된 state를 확실히 거절하는지 회귀 시험에 넣고, 프로덕션에서 JavaScript 소스맵과 Swagger 문서를 외부에 노출하지 않는다.
- 셀프 가입·비밀번호 재설정·계정 활성화 엔드포인트에 속도 제한과 일회용 메일 도메인 차단을 걸고, 예측 가능한 순번 ID 대신 테넌트 범위가 서버에서 강제되는지 점검한다.
- 고객 쪽에서는 공급업체 앱의 서비스 주체와 OAuth 권한을 정기 감사하고, 벤더 침해 공지가 나오면 해당 앱의 자격 증명·권한을 즉시 회수할 수 있는 런북을 준비한다.
