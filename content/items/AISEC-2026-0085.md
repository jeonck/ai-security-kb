## 요약
AWS가 관리하는 오픈소스 에이전트 SDK인 Strands Agents의 Agent2Agent(A2A) 서버 구성 요소에서 호출자 간 대화 상태가 섞이는 취약점(CVE-2026-115419, GHSA-4v6f-7vjh-6x4m)이 공개됐다. 하나의 A2A 서버에 여러 사용자·테넌트가 접속하는 배포에서, 인증만 된 사용자라면 다른 호출자의 대화 이력을 읽거나 그 호출자에게 돌아갈 모델 응답을 비틀 수 있었다. CVSS 3.1 점수는 8.1이며 Python 1.43.0, TypeScript 1.5.0에서 수정됐다. 완전한 우회책은 없어서 업그레이드 전에는 테넌트별로 서버를 분리하라는 것이 공식 안내다.

## 동작 원리
A2A 서버는 다른 에이전트나 클라이언트의 요청을 받아 내부 에이전트 객체에 넘긴다. 취약한 버전은 서버가 에이전트 인스턴스 하나를 모든 호출자에게 돌려 쓰면서, 호출자를 구분하는 context_id와 무관하게 대화 기록(메모리)이 그 인스턴스에 쌓였다. 은행 창구 직원 한 명이 모든 고객의 상담 메모를 한 공책에 이어 쓰는 셈이라, 다음 고객이 ‘앞에서 무슨 얘기를 했지?’라고 물으면 앞 고객의 내용이 나오고, 앞 고객이 공책에 써 둔 지시가 다음 고객 상담에도 영향을 준다. 수정판은 context_id마다 에이전트를 새로 만드는 팩토리 방식으로 공책을 고객별로 나눴다. 대화 이력은 곧 모델의 입력이므로, 이력 공유는 정보 노출이면서 동시에 다른 사용자를 겨냥한 프롬프트 인젝션 통로가 된다.

## 플랫폼 엔지니어 관점
- SBOM·의존성 스캔으로 strands-agents(<1.43.0)와 @strands-agents/sdk(<1.5.0)를 찾고, 특히 multiagent.a2a 모듈로 A2A 서버를 띄운 서비스부터 올린다. 사내 포크나 이 코드를 베낀 파생 구현이 있으면 같은 수정을 반영한다.
- 업그레이드 전에는 A2A 서버를 테넌트·사용자별 Deployment(또는 네임스페이스)로 쪼개고, 공유 엔드포인트 앞에 테넌트 식별 기반 라우팅을 둔다.
- 에이전트 서버 설계 원칙으로 ‘요청 간에 가변 상태를 담는 객체를 전역·싱글턴으로 두지 않는다’를 코드 리뷰 체크리스트에 넣는다. MCP TS SDK 공유 전송 계층(AISEC-2026-0034), A2A Java·Rust SDK(AISEC-2026-0035, AISEC-2026-0050)에 이어 같은 계열 결함이 반복되고 있다.
- 다중 테넌트 에이전트 서비스의 회귀 테스트에 ‘테넌트 A가 심은 문자열을 테넌트 B 세션에서 되묻기’ 같은 교차 세션 누출 시험을 추가한다.
- 대화 로그에서 한 context_id의 응답에 다른 context_id의 고유 문자열이 섞였는지 탐지 규칙을 걸어 과거 노출 여부를 점검한다.
