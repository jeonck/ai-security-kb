## 요약
GitHub가 2026-10-22부터 Copilot Business·Enterprise 조직에 ‘새 기능 기본 정책’ 강제를 시작했다. 관리자가 아직 고르지 않은 GA 기능과 ‘MCP servers in Copilot’ 같은 설정은 전역 기본값(허용·차단·조직 위임)을 한 번 물려받고, 이미 정한 설정은 그대로 둔다. 같은 날 사용량 메트릭 API는 조직이 쓰는 커스텀 스킬·에이전트·MCP 서버·슬래시 명령·플러그인의 실제 이름을 보고하기 시작해, 누가 어떤 에이전트 확장을 쓰는지 볼 수 있게 됐다.

## 동작 원리
에이전트 도구는 새 기능이 빠르게 GA로 넘어오고, 관리자가 정하지 않은 설정은 벤더 기본값으로 켜지기 쉽다. 전역 기본값은 ‘아직 결정하지 않은 칸’을 조직의 기본 태도로 채우는 장치다. 차단으로 두면 MCP 서버 연결 같은 새 기능은 명시 승인 전까지 꺼진 채 들어온다. 다만 한 번만 적용되므로, 기본값을 나중에 바꿔도 이미 채워진 칸은 그대로다. 메트릭 쪽은 지금까지 ‘custom’ 한 덩어리로 보이던 확장 사용을 이름 단위로 쪼개 보여 준다. 이것이 사실상 ‘조직에서 실제로 돌아가는 MCP 서버·스킬 목록’이 된다. 단 클라이언트가 보내는 텔레메트리라 오래된 클라이언트나 텔레메트리 차단 환경은 빠진다.

## 플랫폼 엔지니어 관점
- 10-26 전까지 AI Controls → Copilot → Default policy for new features를 ‘Disabled’로 두고, MCP 서버·에이전트 기능은 개별 승인으로만 켠다. 이미 ‘Enabled’로 남은 설정은 소급되지 않으므로 별도로 점검한다.
- 메트릭 API의 totals_by_mcp·totals_by_skill을 주기적으로 수집해 승인된 MCP 서버·스킬 목록과 대조하고, 목록에 없는 이름이 보이면 경보를 낸다.
- 메트릭은 과소 집계될 수 있으므로 재고 조사의 보조 수단으로만 쓰고, 클라이언트 최소 버전(CLI 1.0.97, SDK 1.0.21)을 엔드포인트 관리로 강제해 누락을 줄인다.
- 이름 자체가 내부 시스템 정보를 드러낼 수 있으니 보고서를 외부 공유할 때 마스킹한다.
