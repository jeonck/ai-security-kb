## 요약
Zscaler ThreatLabz는 10월 21일, 한국 금융권 공격(AISEC-2026-0001)에 쓰인 ARTEX 운영 인프라를 더 파헤친 결과를 공개했다. 노출된 작업 환경에는 맞춤 ARTEX 컨테이너, Claude Code 프롬프트 기록(8월 4일~10월 4일), 계정 간 동기화 스크립트, 프로젝트별 기록 파일이 있었다. 프롬프트가 언급한 표적은 한국만이 아니라 19개 지역, 데이팅·SMS·결제·암호화폐·기프트카드·소매 등 여러 업종에 걸쳐 있었다. 운영자는 전화번호가 붙은 개인정보와 결제 게이트웨이 키를 원했고, 한국 데이터를 어디서 파는지도 물었다. Zscaler는 금전 목적의 운영자로 평가했으며 Storm-0940과의 관계는 언급하지 않았다. 10월 23일 국내 보도는 이 분석을 Microsoft의 Storm-0940 귀속(AISEC-2026-0063·0081)과 함께 전했지만, 두 활동을 잇는 근거는 아직 1차 자료에 없다.

## 동작 원리
작업대는 Claude Code였고, 그 뒤에 붙은 두뇌는 계정마다 달랐다. ARTEX와 일부 Claude Code 계정은 OpenAI 호환 게이트웨이를 거쳐 DeepSeek를 불렀고, 다른 계정은 GLM이나 Grok(별도 브리지 경유)을 불렀다. DeepSeek이 먼저 공격 표면을 훑으면 GLM이 그 결과를 다시 검토하는 식으로 모델끼리 서로의 작업을 점검하게 했다. 프로젝트마다 범위·표면·메모 파일을 두고 훅이 새 프롬프트마다 이를 붙여 넣으니, 세션이 끊겨도 AI가 어제의 조사를 이어받는다. ‘모든 표적은 사전 승인됐다’는 지시는 침투 도구가 허가된 레드팀처럼 행동하게 만드는 한 줄짜리 우회다. 사람 해커 한 명이 여러 모델과 여러 계정을 거느린 작은 조직처럼 움직인 셈이다.

## 플랫폼 엔지니어 관점
- 외부 노출 업무 시스템(조회 화면, 모집인·직원용 포털)에 계정·세션 단위의 이상 조회 탐지를 건다. 이번 운영자가 원한 것은 ‘전화번호가 붙은 구조화 데이터’였으므로, 대량 조회·내보내기 API의 응답 필드와 건수를 감사 로그로 남긴다.
- Zscaler가 공개한 작업·점프 서버 IP와 프록시 IP를 WAF·Ingress·IdP 로그에서 소급 검색한다. 다만 운영자는 주거용 프록시·IP 교체를 쓰므로 IP 차단만으로 끝내지 않는다.
- 사내에서 OpenAI 호환 게이트웨이나 낯선 모델 중계 도메인으로 나가는 트래픽을 egress 정책·프록시 로그로 가시화한다. 공격 도구와 섀도 AI 모두 같은 신호를 남긴다.
- 결제 게이트웨이 키·SMS 사업자 관리자 계정처럼 이번 캠페인이 노린 자격 증명은 시크릿 관리자로 옮기고, 사용처 IP 제한과 짧은 수명 토큰을 적용한다.
- 사내 레드팀이 에이전트형 침투 도구를 쓴다면 ‘사전 승인’ 같은 범위 지시를 모델 프롬프트가 아니라 네트워크 허용 목록·실행 환경으로 강제한다.
