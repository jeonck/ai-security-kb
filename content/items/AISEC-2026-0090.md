## 요약
IIT 봄베이 연구진은 CPU 메모리의 Rowhammer 비트 플립으로 GPU 기반 LLM 추론을 느리게 만드는 LLVMhammer를 공개했다. 표적은 모델 가중치가 아니라 Triton 컴파일러 라이브러리다. 분기 명령 하나가 뒤집히면 Triton은 결과는 같지만 훨씬 느린 GPU 커널을 만든다. Triton이 커널을 디스크에 캐시하기 때문에 플립이 한 번만 성공해도 감속이 계속 남는다. vLLM 위 7~8B 모델 4종에서 지연이 4~16% 늘었고, 일부 플립은 출력 품질도 떨어뜨렸다(BERTScore 최저 0.25).

## 동작 원리
Rowhammer는 DRAM의 한 행을 반복해서 읽으면 이웃 행의 비트가 뒤집히는 하드웨어 결함이다. 공격자는 같은 서버를 쓰는 다른 테넌트로서 공유 라이브러리 페이지 근처를 두드린다. libtriton.so의 ‘같으면 점프’와 ‘다르면 점프’는 1비트 차이라서, 하나가 뒤집히면 최적화 패스가 다른 길로 간다. 그 결과 벡터화된 128비트 메모리 접근이 16비트 단위 접근으로 바뀐 커널이 나온다. 정답은 그대로라 정확도 테스트로는 잡히지 않는다. 비유하면 공장 기계를 부수지 않고 작업 지시서의 한 글자를 바꿔 같은 제품을 훨씬 느리게 만들게 하고, 그 지시서가 복사돼 서랍(디스크 캐시)에 보관되는 셈이다. 컴파일의 앞 단계는 GPU 벤더와 무관해서 NVIDIA와 AMD 모두에서 통했다.

## 플랫폼 엔지니어 관점
- 추론 노드를 다른 테넌트와 물리 호스트 단위로 공유한다면 이 연구는 ‘GPU만 격리하면 된다’는 가정을 깬다. 고가치 추론 워크로드는 전용 노드(taint·toleration, 노드 풀 분리)에 두고, 커널 동일 페이지 병합(KSM) 같은 메모리 중복 제거 설정을 점검한다.
- Triton 커널 캐시(~/.triton/cache)는 성능 산출물이자 무결성 대상이다. 컨테이너 이미지 빌드 시 미리 컴파일한 캐시를 읽기 전용으로 넣거나, 런타임 캐시를 노드 재시작 때 비우는 정책을 검토한다.
- 정확도 회귀 테스트만으로는 감지되지 않는다. TTFT·TPOT·tokens/s 같은 지연 지표를 모델·노드별 기준선과 비교해 특정 노드만 느려지는 이상을 탐지하고, 출력 품질 샘플링 평가를 함께 돌린다.
- 하드웨어 조달 시 ECC·DDR5 PRAC 같은 Rowhammer 완화 기능을 요구 사항에 넣되, 논문이 지적하듯 ECC도 완전한 방어가 아님을 감안한다.
