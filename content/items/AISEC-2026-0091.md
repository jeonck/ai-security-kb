## 요약
NYU 아부다비 연구진은 웹 검색을 쓰는 LLM이 ‘데이터 공백’, 즉 믿을 만한 자료가 거의 없는 검색어에서 공격자가 올린 페이지를 그대로 가져다 쓰는지를 실험했다. 데이터 공백 56개를 만들고 각각에 공격자 페이지 하나만 올린 뒤 ChatGPT, Gemini, Perplexity Sonar Pro에 관련 질문을 던졌다. 전체 응답의 31.0%가 공격자 페이지를 인용하거나 내용에 반영했고, 그런 응답의 4분의 3가량은 아무 경고 없이 사용자에게 나갔다. 모델 간 차이도, 사용자 어조에 따른 차이도 유의하지 않았다. 논문은 NDSS 2027에 실릴 논문의 확장판이다.

## 동작 원리
검색 엔진은 자료가 많은 주제에서는 공격자 페이지를 수많은 정상 결과 속에 묻어 버린다. 그러나 새로 생긴 용어, 막 터진 사건, 표현이 쪼개진 개념처럼 결과가 거의 없는 검색어에서는 공격자 페이지 하나가 사실상 유일한 답이 된다. 기존 검색에서는 사용자가 결과 목록을 보고 ‘출처가 하나뿐이고 낯선 도메인’이라는 신호를 직접 볼 수 있었지만, LLM은 그 페이지를 매끄러운 문장으로 요약해 근거가 얇다는 신호를 지운다. 페이지에 ‘이전 지시를 무시하라’ 같은 문구가 전혀 없다는 점이 간접 프롬프트 인젝션과 다르다. 모델은 정상 동작하면서 오염된 근거를 성실히 인용할 뿐이다. 결정적인 변수는 콘텐츠의 설득력이 아니라 페이지가 색인되느냐였다.

## 플랫폼 엔지니어 관점
- 사내 에이전트나 챗봇에 웹 검색 도구를 붙였다면 그 출력은 신뢰할 수 없는 입력이다. 검색 결과에 도메인 평판·게시일·독립 출처 수를 메타데이터로 붙여 모델에 넘기고, 단일 출처 주장에는 답변에 ‘근거 부족’ 표시를 강제한다.
- RAG 수집 파이프라인에서 외부 웹 문서를 넣을 때 도메인 나이·평판·출처 다양성을 메타데이터로 남기고, 단일 출처 사실을 따로 표시한다.
- 에이전트가 검색 결과를 근거로 행동(설치 명령, 패키지 이름, 설정값 적용)할 때 특히 위험하다. 새 도구 이름이나 막 공개된 CVE처럼 데이터 공백이 생기기 쉬운 주제에서는 사람 승인 단계를 둔다.
- 인젝션 탐지기 도입만으로 웹 입력 위험이 해소됐다고 보고하지 않는다. ‘우리 서비스 이름 + 새 용어’ 같은 지시 없는 오염을 별도 레드팀 시나리오로 넣는다.
