## 요약
보안 업체 V12가 AI 에이전트가 HTTP 402 응답으로 API 사용료를 자동 결제하게 하는 x402 프로토콜(Coinbase가 만들고 Linux Foundation 산하 x402 재단으로 넘긴 프로젝트)의 공식 SDK(TypeScript·Python·Go)를 검토해 25건의 결함을 공개했다. 가장 심각한 세 건은 기본 클라이언트에 지출 한도가 없어 악성 API가 지갑 잔액 전부를 청구할 수 있던 문제, Solana 정산 검증기가 토큰을 옮기지 않는 ‘승인’ 명령을 결제로 받아들인 문제, 다른 사이트용 로그인 메시지에 에이전트가 서명해 버린 문제다. 세 건은 8월에 보고·수정됐고 클라이언트는 이제 기본으로 결제당 1달러 상한을 건다. 다만 재단은 보안 권고나 CVE를 내지 않아 의존성 스캐너로는 구버전 사용을 알 수 없다.

## 동작 원리
x402에서 에이전트는 유료 API를 부르면 ‘얼마를, 어떤 토큰으로, 누구에게 내라’는 402 응답을 받고 자동으로 서명해 지불한다. 기본 클라이언트는 이 청구서를 그대로 믿었다. 지갑을 들려 보낸 심부름꾼에게 ‘얼마까지’라는 말을 안 한 셈이라, 악성 API가 잔액 전체를 적어 보내면 그대로 빠져나간다. 반대 방향 결함도 있다. 판매자 쪽 검증기는 Solana 거래의 명령 종류를 확인하지 않아, 첫 바이트 하나만 다른 ‘지출 승인’ 명령을 ‘송금’으로 착각했다. 로그인 결함은 에이전트가 ‘이 서명은 어느 사이트용인가’를 확인하지 않은 데서 왔다. 악성 서버가 다른 사이트의 로그인 문구를 받아 와 내밀면 에이전트가 서명해 주고, 공격자는 그 서명으로 에이전트 지갑의 신원을 빌려 그 사이트에 들어간다. 에이전트가 자기 신원을 남의 요청에 빌려주는 혼동된 대리인 문제다.

## 플랫폼 엔지니어 관점
- 사내 에이전트가 x402나 비슷한 에이전트 결제 SDK를 쓰는지 의존성 목록에서 찾는다. 권고·CVE가 없어 Dependabot·npm audit이 알려 주지 않으므로 @x402/fetch·@x402/axios·@x402/extensions·@x402/svm 2.23.0 이상, Go·Python 최신 버전으로 직접 고정한다.
- 업그레이드 뒤 `spendControls: false`나 허용 자산 전체 개방이 코드에 없는지 검색하고, SDK 기본값과 별개로 플랫폼 정책(게이트웨이·서명 서비스)에서 결제당·일일 상한과 수취인·토큰·네트워크 허용 목록을 강제한다.
- 에이전트 지갑은 서비스 계정처럼 다룬다. 작업별 소액 지갑을 쓰고, 에이전트 프로세스가 개인키를 직접 갖지 않게 서명을 한도 검사를 하는 별도 서비스로 분리한다. 결제·서명 이벤트를 에이전트 ID별로 기록해 이상 금액·새 수취인을 경보한다.
- 서명형 로그인(SIWE/SIWx)을 쓰는 에이전트는 메시지의 domain·uri와 실제 접속 대상이 일치하는지 검증하는 테스트를 CI에 넣는다.
