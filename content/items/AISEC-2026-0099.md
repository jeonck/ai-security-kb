## 요약
AI 게이트웨이 LiteLLM 프록시에서, 저권한 내부 사용자가 관리자 토큰을 위조해 proxy_admin이 되고 MCP stdio 엔드포인트로 호스트 명령까지 실행할 수 있는 결함이 CVE-2026-114612(CVSS 9.9)로 공개됐다. 원인은 저장 비밀 암호화와 세션 토큰 발급에 같은 키를 쓴 ‘교차 용도 키 재사용’이다. 저장소 권고는 9월 30일에 나왔고 CVE 레코드는 10월 22일 게시됐다. 수정 버전은 1.100.4·1.101.3·1.102.2·1.103.1·1.104.0rc2다.

## 동작 원리
프록시는 사용자가 API 키에 붙인 메타데이터 속 비밀을 키 K로 암호화해 돌려준다. 그런데 세션 토큰도 같은 K로 만들어 ‘K로 풀리면 진짜 토큰’이라고 믿는다. 그러면 공격자는 메타데이터 칸에 ‘나는 관리자’라는 토큰 내용을 적어 프록시에게 암호화를 맡기고, 돌려받은 암호문을 그대로 로그인 토큰으로 낸다. 금고에 보관해 달라고 맡긴 쪽지가 그대로 출입증이 되는 셈이다. 관리자가 되면 MCP 서버 설정의 stdio 명령을 실행시킬 수 있어 프록시 호스트에서 코드가 돈다.

## 플랫폼 엔지니어 관점
- 사내 LiteLLM을 권고의 수정 버전 이상으로 올린다. 1.107.0 침해 사건(AISEC-2026-0053) 때문에 버전을 고정해 두었다면 같은 계열의 안전 버전을 따로 확인한다.
- 게이트웨이 계정 중 internal_user 권한을 가진 사용자·서비스 계정을 재점검하고, 권고 공개 이후 proxy_admin 권한 사용·MCP 서버 설정 변경 감사 로그를 확인한다.
- AI 게이트웨이 파드에서 MCP stdio(로컬 프로세스 실행) 기능을 쓰지 않으면 끄고, 쓴다면 게이트웨이 컨테이너를 읽기 전용 루트 파일시스템·최소 권한 서비스 계정·egress 제한으로 격리한다.
- 자체 개발 서비스에서도 암호화 키와 토큰 서명 키를 용도별로 분리(키 파생 시 용도 라벨 사용)하는 규칙을 코드 리뷰 항목에 넣는다.
