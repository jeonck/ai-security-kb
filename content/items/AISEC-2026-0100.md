## 요약
Google의 에이전트 개발 키트 ADK for Java에 포함된 개발용 웹 서버 ADK Web에 CVE-2026-107858이 부여돼 10월 23일 공개됐다. 실시간 에이전트 실행용 /run_live WebSocket과 REST API가 모든 출처를 허용해, 개발자가 서버를 켜 둔 채 악성 페이지를 열면 그 페이지가 로컬 에이전트를 구동하고 세션·아티팩트를 읽을 수 있었다. 6월에 공개 이슈로 제보됐고 7월 부분 수정은 옵트인에 그쳤으며, 10월 21일 1.13.0에서야 같은 출처 기본값과 DNS 리바인딩 차단이 들어갔다.

## 동작 원리
개발 서버는 ‘내 노트북 안에서만 돈다’고 여겨 출처 검사를 생략하기 쉽다. 하지만 브라우저는 개발자가 연 아무 웹 페이지의 자바스크립트가 localhost로 요청을 보내게 해 준다. CORS가 ‘*’이면 응답까지 읽을 수 있고, WebSocket은 원래 CORS 대상이 아니라 서버가 Origin 헤더를 직접 확인해야 한다. 그래서 외부 페이지가 개발자 브라우저를 징검다리 삼아 에이전트에게 지시를 넣고(도구 호출·코드 실행 권한까지 이어질 수 있다) 대화 기록을 빼 간다. 문을 잠그지 않고 ‘집 안이니까 괜찮다’고 생각한 것과 같다.

## 플랫폼 엔지니어 관점
- 개발자 템플릿·devcontainer에서 google-adk-dev·google-adk-maven-plugin을 1.13.0 이상으로 고정하고, 못 올리면 adk.web.cors.origins를 명시 목록으로 설정한다. 권고의 버전 필드가 ‘Unknown’이라 SCA가 놓칠 수 있으니 직접 확인한다.
- 에이전트 개발 서버(ADK Web, 각종 playground·inspector)를 띄울 때는 실제 API 키·클라우드 자격 증명 대신 개발 전용 저권한 키를 쓰게 한다.
- 원격 개발 환경·CI에서 개발 서버 포트가 외부로 포워딩되지 않는지 점검하고, 사내 브라우저 정책(Chrome의 로컬 네트워크 접근 제한)을 켠다.
- 사내에서 만드는 에이전트 도구의 로컬 HTTP·WebSocket 서버에는 Origin 검사·Host 헤더 검사·토큰 인증을 기본으로 넣는 보안 검토 항목을 둔다.
