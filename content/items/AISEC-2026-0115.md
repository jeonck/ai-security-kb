## 요약
Elixir용 LLM 클라이언트 라이브러리 req_llm의 WebSocket 세션이 서버 인증서를 검증하지 않는 결함이 10월 22일 공개됐고, 이튿날 CVE-2026-107685로 NVD·GitHub 권고 DB에 올랐다. 영향 버전은 1.9.0~1.28.0이고 OpenAI Responses·Realtime·Codex WebSocket 경로가 대상이다. 공격자가 네트워크 경로 중간에 서면 API 키나 OAuth 토큰을 빼 가고, 프롬프트·도구 호출을 엿보거나 바꿔 칠 수 있었다. 1.29.0에서 검증을 기본으로 켜는 방식으로 고쳤다.

## 동작 원리
HTTPS 연결은 ‘상대가 진짜 api.openai.com인가’를 인증서로 확인하는데, 이 라이브러리는 그 확인을 생략하는 기본값을 그대로 물려받았다. 게다가 사용자가 검증을 켜려고 넘긴 옵션까지 걸러 버려 고칠 방법도 없었다. 공용 Wi-Fi·오염된 DNS 등으로 중간에 낀 공격자는 가짜 인증서로 연결을 받아 토큰을 챙기고, 모델이 돌려준 도구 호출(예: 파일 삭제, 송금 API)을 원하는 내용으로 바꿔 에이전트에 넘길 수 있다. 프롬프트 인젝션 없이도 에이전트가 ‘모델의 지시’라고 믿는 내용을 조작할 수 있다는 점이 핵심이다.

## 플랫폼 엔지니어 관점
- SBOM에서 req_llm(Hex) 1.9.0~1.28.0을 찾아 1.29.0 이상으로 올린다. 즉시 못 올리면 OpenAI WebSocket 경로를 끄고 HTTP 스트리밍을 쓴다.
- 모델 API 호출은 사내 AI 게이트웨이를 거치게 하고, 게이트웨이에서 상류 TLS 검증을 강제하면 클라이언트 라이브러리의 실수가 바로 노출로 이어지지 않는다.
- 에이전트 파드의 egress를 모델 엔드포인트 허용 목록으로 제한하고, 개발자 노트북·CI 러너가 쓰는 장기 API 키는 단기 토큰으로 바꾼다.
- 의존성 검토 체크리스트에 ‘TLS 검증 기본값, 사용자 TLS 옵션 전달 여부’를 넣는다. LLM 클라이언트는 키와 도구 호출을 함께 나르는 고위험 의존성이다.
