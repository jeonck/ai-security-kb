## 요약
로컬에서 돌리는 오픈소스 자율 에이전트 AgenticSeek의 LLM 서버 구성 요소가 Flask 디버그 모드를 켠 채 모든 인터페이스에서 대기하고 있었다. 이 포트에 닿을 수 있고 Werkzeug 디버거 PIN을 알아낸 공격자는 서버 권한으로 임의 코드를 실행할 수 있다. 수정은 10월 15일 병합된 대규모 보안 강화 PR에 들어갔고, CVE-2026-115727(CVSS 4.0 9.2)은 10월 23일 공개됐다. 같은 PR은 API 토큰 인증, localhost 허용 목록, Docker 비특권 실행 등 그동안 없던 기본 통제를 한꺼번에 추가했다.

## 동작 원리
Flask 디버그 모드는 오류가 나면 브라우저에서 바로 Python 코드를 실행해 볼 수 있는 콘솔을 띄운다. 개발자 편의 기능이지만, 0.0.0.0으로 열려 있으면 같은 네트워크나 인터넷의 누구라도 그 콘솔에 접근을 시도할 수 있다. 콘솔을 잠그는 PIN은 머신 정보에서 계산되므로 다른 정보 노출과 결합하면 유도될 수 있다. 결과적으로 ‘에이전트의 두뇌’ 역할 서버가 문 열린 원격 셸이 된다. 이 서버는 에이전트의 모델 호출을 처리하므로, 장악되면 에이전트 대화·출력 조작으로도 이어질 수 있다.

## 플랫폼 엔지니어 관점
- 사내에서 AgenticSeek 같은 셀프호스트 에이전트를 쓰면 최신 main(커밋 409840c 이후)으로 올리고, llm_server 포트가 외부에 열려 있지 않은지 확인한다.
- 일반화하면: 에이전트·MCP 서버 컨테이너 이미지에서 FLASK_DEBUG·werkzeug 디버거, 0.0.0.0 바인딩을 CI 정책 검사(예: 이미지 스캔·OPA)로 차단한다.
- 쿠버네티스에서는 NetworkPolicy로 에이전트 보조 서버를 에이전트 파드만 접근하게 묶고, Service 타입을 ClusterIP로 제한한다.
- 같은 PR이 추가한 ‘사용자 Chrome 로그인 재사용’ 기능은 에이전트에 사용자 세션을 넘기는 것이므로, 업무 환경에서는 끄거나 별도 브라우저 프로필을 강제한다.
