## 요약
Python으로 MCP 서버·클라이언트를 만들 때 널리 쓰이는 FastMCP에서 성격이 다른 보안 결함 2건이 같은 릴리스(3.4.10·4.1.2)로 고쳐졌다. 하나는 클라이언트 쪽 문제로, 기계 간(M2M) OAuth 제공자가 어느 인가 서버를 믿을지 고정하지 않아 신뢰할 수 없는 MCP 서버가 자기 인가 서버를 광고하면 클라이언트 시크릿이 그대로 넘어갔다. 다른 하나는 서버 쪽 문제로, transform으로 바뀐 도구·리소스·프롬프트에 인가 정책을 다시 적용하지 않아 목록에서는 숨겨진 관리 도구를 이름만 알면 직접 호출할 수 있었다. 앞의 결함은 공식 Python·TypeScript MCP SDK에서 먼저 드러난 것과 같은 계열이고, 업그레이드 뒤에도 issuer를 명시해야 막힌다.

## 동작 원리
issuer 결함은 ‘가게가 알려 주는 계산대에 지갑을 맡기는’ 구조다. 클라이언트는 MCP 서버에서 OAuth 메타데이터를 받아 그 안에 적힌 토큰 엔드포인트로 시크릿을 보내는데, 원래 시크릿을 발급한 인가 서버가 어디인지 대조하지 않았다. 악성·침해된 MCP 서버나 잘못 입력된 URL이면 시크릿이 공격자에게 가고, 공격자는 그것으로 정상 인가 서버에 그 클라이언트로 행세할 수 있다.

인가 우회는 ‘검사 뒤 변경’ 문제다. 인가 정책은 컴포넌트 메타데이터(태그·범위 등)를 보고 판단하는데, 직접 호출 경로에서는 transform이 메타데이터를 바꾼 뒤의 최종 컴포넌트를 다시 검사하지 않았다. 목록 API는 걸렀지만 직접 호출 API는 거르지 않아, 보이지 않는 것과 호출할 수 없는 것이 달랐다.

## 플랫폼 엔지니어 관점
- 사내 에이전트·MCP 게이트웨이가 FastMCP를 쓰면 3.4.10/4.1.2 이상으로 올리고, ClientCredentials·PrivateKeyJWT 제공자에 issuer를 명시한다. 경고 로그가 뜨면 미설정 지점이다.
- 사용자가 입력한 MCP 서버 URL에 M2M 자격 증명을 붙여 접속하는 기능은 허용 목록의 서버·인가 서버로만 제한하고, 이미 임의 URL로 접속한 적이 있다면 클라이언트 시크릿을 회전한다.
- MCP 서버 인가는 도구 목록 필터에 기대지 말고 핸들러 또는 서버 경계(게이트웨이)에서 호출 단위로 강제한다. 회귀 테스트에 ‘목록에 없는 도구를 이름으로 직접 호출’하는 케이스를 넣는다.
- 의존성 스캐너가 CVE 없는 GHSA도 잡도록 설정한다(이번 2건은 CVE가 없다).
