## 요약
LLM이 피싱 사이트를 어디까지 자동으로 만들 수 있는지를 대규모로 측정한 연구다. 연구진은 안전장치를 피하려는 12가지 재작성 전략과 세 가지 입력 형태(텍스트·스크린샷 등)를 조합해 14개 모델에 사이트를 만들게 했다. 거의 모든 요청이 거절되지 않았고 대부분 화면에 뜨는 사이트가 나왔지만, 실제로 로그인 정보를 빼돌리는 전 과정까지 동작한 비율은 38.7%였다. 흔히 가장 위험하다고 여겨지는 검열 해제 모델보다 GPT 4.1 같은 상용 모델의 결과물이 훨씬 잘 작동했다.

## 동작 원리
요청을 직접적으로 ‘피싱 사이트를 만들어라’라고 쓰지 않고, 교육용·테스트용 등으로 표현을 바꾸면 모델의 거절 판단을 비켜 간다. 이후 생성된 HTML이 실제 브랜드와 얼마나 닮았는지, 입력 폼에서 서버로 자격 증명이 넘어가는지를 실행 시험으로 확인했다. 결국 위협의 크기는 안전장치를 끈 모델이냐가 아니라, 코드를 정확히 짜는 능력이 얼마나 높으냐에 좌우됐다. 반면 LLM이 만든 페이지에는 글꼴 CSS 누락, 로고보다 텍스트 위주 모방 같은 공통 흔적이 남아 탐지 단서가 된다.

## 플랫폼 엔지니어 관점
- 사내 LLM 게이트웨이·코딩 에이전트 플랫폼에서 출력 필터만으로 악용을 막을 수 있다고 가정하지 않는다. 계정별 사용 패턴(대량 HTML·로그인 폼 생성)을 로깅·이상 탐지 대상으로 둔다.
- 보안 팀의 피싱 탐지 파이프라인에 LLM 생성 사이트 데이터를 학습 데이터로 추가하고, 시각 유사도 외에 CSS·로고 해시·웹폰트 검증 같은 특징을 결합한다.
- 외부에 모델 API를 제공하는 조직은 이용 정책과 남용 신고·차단 절차를 운영 지표로 관리한다.
