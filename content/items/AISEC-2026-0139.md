## 요약
문서를 올려 사내에서 질의응답을 하는 오픈소스 RAG 서버 PrivateGPT(Zylon)의 URI 수집 로더에 대한 CVE가 2026년 10월 24일(CT) 공개됐다. 수집 API가 사용자가 준 URI를 검증하지 않아 서버가 공격자가 지정한 곳으로 요청을 보내게 할 수 있고(SSRF), 공개 PoC가 있으며 벤더는 연락에 답하지 않았다. CVE가 근거로 건 GitHub 이슈는 같은 지점을 로컬 파일 읽기로 설명한다 — file:// 경로를 넣으면 작업자가 서버 파일을 읽어 벡터 DB에 넣고, 공격자는 LLM에게 그 문서를 물어 내용을 받아 낸다. 이 이슈는 6월에 올라왔지만 응답 없이 자동 종료됐고, 수정 버전은 확인되지 않는다.

## 동작 원리
RAG 시스템의 수집기는 ‘가져와서 읽어 두는’ 일을 한다. URI를 받으면 S3 업로드 같은 안전한 경로를 거치게 돼 있었지만, base64가 아닌 URI는 그 단계를 건너뛰고 원래 문자열이 그대로 작업자에게 넘어갔다. 작업자는 그것이 파일 경로이면 열고, URL이면 요청한다. 결과물은 곧장 검색 색인에 들어가므로, 평소의 SSRF·파일 읽기와 달리 응답을 직접 볼 수 없어도 나중에 챗봇에게 ‘그 문서 요약해 줘’라고 물으면 내용이 돌아온다. LLM이 유출 채널의 마지막 단계를 대신 해 주는 셈이다.

## 플랫폼 엔지니어 관점
- RAG 수집 작업자(Celery 등)를 Kubernetes에 둘 때 egress NetworkPolicy로 허용 출처만 열고, 링크-로컬(169.254.0.0/16)·클러스터 내부 대역·메타데이터 엔드포인트를 막는다. IMDSv2·hop limit 1로 메타데이터 접근을 차단한다.
- 수집기 컨테이너는 읽기 전용 루트 파일시스템과 최소 마운트로 돌려 file:// 경로가 열어 볼 것이 없게 한다. 시크릿은 환경 변수가 아니라 필요한 서비스에만 마운트한다.
- 수집 API는 인증 뒤에 두고, URI 스킴 허용 목록(https만)과 리다이렉트 재검사를 앞단 게이트웨이에서 강제한다. 색인된 문서의 출처 URI를 감사 로그에 남겨 비정상 출처(file://, 내부 IP)를 탐지한다.
- PrivateGPT를 쓰는 팀은 1.0.0·1.0.1 사용 여부를 확인하고, 수정 릴리스가 나올 때까지 URI 수집 기능을 끄거나 네트워크로 격리한다.
