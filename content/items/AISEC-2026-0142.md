## 요약
개인 지식 관리 앱 SiYuan은 AI 에이전트가 노트를 다룰 수 있도록 MCP 서버를 내장하고 있다. 그중 asset 업로드 도구는 로컬 파일을 작업 공간으로 복사하는데, 8월에는 경로 검사 자체가 없어 임의 파일을 끌어올 수 있었고, 이를 막으려 넣은 민감 경로 블랙리스트는 다시 .env를 빠뜨렸다. 에이전트를 조종할 수 있는 공격자는 홈 디렉터리의 .env를 작업 공간으로 복사한 뒤 웹 서버의 /assets/ 경로로 읽어 낼 수 있다. 3.8.7에서 수정됐고, 10월 25일 CVE-2026-116168로 게시됐다.

## 동작 원리
MCP 도구는 ‘에이전트의 손’이다. 이 도구는 ‘로컬 파일을 노트 첨부로 올린다’는 정당한 기능이지만, 복사된 파일이 곧바로 HTTP로 서빙되기 때문에 사실상 ‘로컬 파일 읽기’ 장치가 된다. 막는 쪽이 ‘위험한 이름 목록’을 들고 문 앞에 서 있는 구조라, 목록에 없는 이름(.env, .env.production, macOS 키체인 경로 등)은 그대로 통과한다. 원 권고가 짚었듯 입력의 출발점은 웹 페이지나 노트에 숨긴 지시(간접 프롬프트 인젝션)이고, 사용자 승인 창은 ‘파일 업로드’라는 범주만 보여 주므로 어떤 파일이 올라가는지 사람이 알아채기 어렵다.

## 플랫폼 엔지니어 관점
- SiYuan을 쓰는 개발·스테이징 호스트는 3.8.7 이상으로 올리고, MCP 기능을 쓰지 않으면 끈다.
- MCP 서버의 파일 도구는 블랙리스트가 아니라 ‘허용 루트’ 기준으로 검토한다. 사내 MCP 서버 승인 기준에 ‘파일 경로 인자는 작업 공간 상대 경로 허용 목록으로 제한’을 넣고, 차단 목록만 있으면 승인하지 않는다.
- 에이전트와 MCP 서버를 홈 디렉터리 전체가 보이는 계정이 아니라, 작업 공간만 마운트한 컨테이너·전용 사용자로 돌린다. .env 같은 평문 비밀은 개발 호스트 홈에 두지 말고 시크릿 매니저로 옮긴다.
- 사람 승인 창이 도구 이름만이 아니라 실제 인자(파일 경로)를 보여 주는지 에이전트 클라이언트 설정을 점검하고, 점파일·비밀 파일 이름이 인자로 등장하는 도구 호출에 경보를 건다.
