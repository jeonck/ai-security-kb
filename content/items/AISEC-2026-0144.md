## 요약
Palo Alto Networks Unit 42는 PHP 코어 RCE 취약점 PHP2Shell(CVE-2026-109618, CVE-2026-109619) 위협 브리프에 10월 23일 ‘에이전트형 AI의 사후 침투 활동’ 세부를 추가했다. 그러나 10월 25일 오후(PT) 이 업데이트를 철회하고, 유럽 정부기관에 대한 침해 후 활동은 취약한 PHP 애플리케이션 맥락에서 관찰됐을 뿐 최초 접근이 PHP2Shell 때문이었는지는 확인할 수 없다고 고쳐 적었다. 같은 날 The Hacker News는 철회 전 내용을 근거로 ‘정부기관 침해와 AI 보조 해킹 정황’을 보도했고, 열람 시점까지 정정 문구는 없었다. 결과적으로 ‘AI가 찾은 취약점을 AI 에이전트가 악용했다’는 서사의 핵심 근거 하나가 1차 출처에서 사라졌다.

## 동작 원리
철회 전 보도에 따르면 판단 근거는 행동 표지였다. 공격자가 명령을 묶음으로 실행하면서 각 묶음 결과를 ‘==SHELLUSER==’ 같은 구분자로 감쌌고, 이것이 사람이 아닌 모델이 파싱하기 좋은 출력 형식이라는 해석이었다. 여기에 최초 침투 후 2시간 안에 자격 증명 탈취와 AD 터널 구성까지 진행된 속도가 더해졌다. 하지만 구분자 출력은 사람이 짠 자동화 스크립트에서도 흔하고, 속도도 숙련된 운영자나 기존 도구로 설명할 수 있다. 정황 증거로 ‘에이전트 공격자’를 판정하는 것은 필체만 보고 범인을 지목하는 것과 비슷해, 최초 접근 경로조차 확정되지 않은 상황에서는 쉽게 무너진다.

## 플랫폼 엔지니어 관점
- 위협 인텔을 탐지 규칙·우선순위에 반영할 때 출처 페이지의 업데이트 기록을 추적한다. 벤더 브리프는 여러 번 갱신·철회되며, 2차 보도는 정정이 늦다.
- ‘AI 에이전트가 공격했다’는 귀속과 무관하게, 보도된 사후 활동(웹 프로세스에서의 셸 명령, 인증 DB 조회, DC 대상 익명 LDAP 질의, NTLM 릴레이)은 PHP 웹 워크로드에서 그대로 탐지 대상이다. 웹 서버 프로세스의 자식 프로세스 생성과 내부 DC로의 egress를 기본 차단·경보한다.
- PHP2Shell은 노출 규모가 크므로(Xpanse 기준 2,260만 이상) 패치 여부와 별개로 PHP 기반 관리 도구의 인터넷 노출을 줄이고, MFA 비밀이 저장된 DB의 접근 권한을 웹 계정에서 분리한다.
- 사고 보고서에 ‘AI 사용 정황’을 적을 때는 관찰 사실(구분자, 실행 간격, 도구 흔적)과 해석을 분리해 기록한다.
