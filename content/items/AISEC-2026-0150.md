## 요약
난양공대·우한대 연구진이 기존 프롬프트 인젝션 벤치마크가 놓치는 공격 유형을 시험하는 NTBench를 공개했다. 기존 벤치마크는 대개 ‘이 문장을 출력하라’ 같은 고정 표적을 쓰는데, 실제 공격자는 정상 답변을 거의 그대로 두고 송금 금액이나 날짜 하나만 바꾸는 편이 들키지 않는다. 7개 최신 모델을 시험한 결과, 이런 근접 표적 공격은 모든 모델·설정에서 고정 표적 공격보다 더 잘 통했다. 에이전트 벤치마크에서는 도구 호출 인자를 슬쩍 바꾸는 공격이 최대 43.4% 성공했다.

## 동작 원리
고정 표적 공격은 ‘해킹당했다’고 크게 외치는 것과 같아 모델의 방어 학습이 잘 잡아낸다. 근접 표적 공격은 정상 업무 흐름 안에서 숫자 하나만 바꾼다. 모델 입장에서는 과업을 그대로 수행하고 있으므로 거부할 이유를 찾기 어렵고, 사람 검토자도 결과가 그럴듯해 지나치기 쉽다. NTBench는 정상 과업의 기준 답을 바탕으로 이런 ‘조금 틀린’ 목표를 자동 생성하고, 주입 없이도 나오는 오류는 제외해 순수한 인젝션 효과만 잰다.

## 플랫폼 엔지니어 관점
- 에이전트 레드팀·평가 파이프라인에서 고정 문자열 출력형 인젝션 성공률만 보지 말고, 도구 호출 인자(금액·수신자·날짜·경로) 변조를 표적으로 하는 시나리오를 추가한다.
- 송금·배포·권한 변경 같은 도구는 인자 값을 원 요청(사용자 지시·티켓)과 대조하는 결정적 검증을 둔다. 모델이 과업을 ‘수행했다’는 사실만으로 정상으로 간주하지 않는다.
- 모델 업그레이드 시 벤더가 제시한 인젝션 벤치마크 점수를 승인 근거로 쓰는 경우, 근접 표적 유형이 포함됐는지 확인한다.
