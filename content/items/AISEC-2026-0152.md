## 요약
코드 결함 탐지·코드 수리 모델에 백도어를 심을 때, 같은 수의 독성 샘플이라도 무엇을 고르느냐에 따라 성공률이 크게 달라진다. 연구진은 트리거가 실제로 모델 출력을 움직이는 샘플을 골라내는 점수 TNCS를 제안했다. 학습 데이터의 0.1~0.3% 수준 예산에서 무작위 선택보다 일관되게 높은 공격 성공률을 냈고, 정상 성능은 거의 그대로였다. 점수 계산에 다른 구조의 모델을 써도 효과가 크게 줄지 않았다.

## 동작 원리
같은 미끼를 뿌려도 물고기가 잘 무는 자리에 뿌려야 한다는 발상이다. 각 후보 코드에 트리거(쓰이지 않는 코드 조각, 변수 이름 바꾸기 등)를 넣은 버전과 트리거를 무력화한 버전을 대리 모델에 넣고, 목표 출력 확률의 차이를 잰다. 차이가 큰 샘플일수록 트리거와 목표 출력의 연결을 잘 가르친다고 보고 우선 오염시킨다. 짧게 학습한 대리 모델로 고르고 다시 걸러 내기를 반복한다.

## 플랫폼 엔지니어 관점
- 공개 저장소·크롤링 코드로 코드 모델을 파인튜닝하는 팀은 데이터셋 출처(저장소·커밋 단위)를 기록하고, 데이터셋 해시와 함께 모델 레지스트리에 연결한다.
- 오염 비율이 0.1% 수준이면 무작위 표본 검수로는 거의 잡히지 않는다. 죽은 코드 삽입, 이상한 상수 전개 같은 트리거 패턴을 수집 단계 정적 검사 규칙으로 둔다.
- 파인튜닝 후 평가 파이프라인에 트리거 후보(의미 없는 코드 조각 삽입, 식별자 변경)를 넣었을 때 출력이 급변하는지 보는 회귀 테스트를 추가한다.
- 코드 리뷰·취약점 탐지에 쓰는 모델이 백도어로 특정 결함을 ‘정상’으로 판정하게 되면 CI 보안 게이트가 무력화된다. 모델 판정을 단독 게이트로 두지 않는다.
