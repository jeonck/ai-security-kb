## 요약
Claude Desktop 등에서 Docker 컨테이너와 Compose 스택을 다루게 해 주는 MCP 서버 docker-mcp에서 OS 명령 주입 CVE-2026-116102가 10월 26일 공개됐다. 문제는 Windows에서 실행할 compose 명령을 조립하는 _build_windows_command 함수가 project_name 값을 정화하지 않는 것이다. CNA는 VulDB이고 점수는 CVSS v4 5.3(3.1 기준 6.3)이며, 패치 버전은 알려지지 않았다. 별 500여 개 규모의 커뮤니티 MCP 서버지만, 모델이 채우는 도구 인자가 그대로 셸로 가는 전형적인 경로를 보여 준다.

## 동작 원리
MCP 서버의 도구 인자는 사람이 아니라 모델이 채운다. 모델은 사용자의 요청뿐 아니라 읽은 문서·웹 페이지·이슈 내용에도 영향을 받으므로, 간접 프롬프트 인젝션으로 ‘이 프로젝트 이름으로 배포해 줘’ 같은 요청을 만들어 낼 수 있다. 서버가 그 이름을 문자열로 이어 붙여 셸 명령을 만들면, 이름 안에 넣은 명령 구분자가 별도 명령으로 실행된다. 게다가 이 서버는 Docker를 조작하는 권한을 갖고 있어, 주입이 성공하면 호스트 수준 권한에 가까운 작업까지 이어질 수 있다. 권고의 ‘원격 공격 가능’, ‘사용자 상호작용 필요’ 표기는 이렇게 모델·사용자를 거쳐 들어오는 경로를 반영한 것으로 보인다.

## 플랫폼 엔지니어 관점
- 사내 MCP 서버 허용 목록에서 Docker·쿠버네티스처럼 인프라를 조작하는 MCP 서버는 별도 등급으로 분류하고, 도구 인자를 셸 문자열로 조립하지 않는지(인자 배열 실행, 허용 정규식) 코드 리뷰를 필수로 한다.
- Docker 소켓을 MCP 서버에 직접 넘기지 않는다. 권한을 줄인 API 프록시나 rootless 런타임, 전용 VM 안에서만 돌린다.
- 에이전트가 MCP 도구를 호출할 때 인자 값을 로그로 남기고, 셸 메타문자(;, &, |, 백틱, $())가 들어간 프로젝트·컨테이너 이름을 차단하는 게이트웨이 정책을 둔다.
- 유지관리 활동이 적은 커뮤니티 MCP 서버는 포크해 내부에서 고정 버전으로 관리하거나 사용을 중단한다.
