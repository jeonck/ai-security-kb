## 요약
중국 Z.ai의 코딩 에이전트 ZCode에서 sed 명령 필터를 거치는 경로로 OS 명령을 주입할 수 있다는 CVE-2026-116118이 10월 26일 공개됐다. CNA는 VulDB이고 점수는 CVSS v4 2.1로 낮게 매겨졌지만, 익스플로잇이 공개됐고 패치 버전은 알려지지 않았다. ZCode는 열흘 전인 10월 16일에도 저장소 작업 공간 설정에 적힌 MCP 서버에 자동으로 연결해 악성 저장소를 여는 것만으로 코드가 실행될 수 있다는 CVE-2026-88755(CVSS 3.1 7.8)를 받았다. 두 건 모두 GitHub 검토 전 상태라 세부 내용은 VulDB와 연구자 문서에 의존하는데, 이번 조사에서는 둘 다 열지 못했다.

## 동작 원리
코딩 에이전트는 ‘읽기 전용’이나 ‘안전한 명령’으로 분류한 명령(sed, grep 등)을 사용자 승인 없이 실행하는 경우가 많다. 이때 필터는 명령 문자열을 나름대로 해석해 안전 여부를 판단하지만, 셸은 같은 문자열을 다르게 해석할 수 있다. sed는 파일 쓰기나 외부 명령 실행 같은 기능도 품고 있어(일반적인 sed 동작에 대한 설명이며, 이번 우회에 쓰였는지는 미확인), 필터가 이를 놓치면 ‘안전한 편집 명령’으로 통과된 것이 실제로는 임의 명령 실행이 된다. 문지기가 신분증 모양만 보고 들여보냈는데 가방 안을 열어 보지 않은 셈이다.

## 플랫폼 엔지니어 관점
- 코딩 에이전트의 ‘자동 승인 명령 목록’을 보안 경계로 취급하지 않는다. 자동 승인은 편의 기능이고, 실제 경계는 샌드박스(devcontainer, gVisor·microVM, 읽기 전용 마운트, egress 차단)에 둔다.
- 사내에서 쓰는 코딩 에이전트 목록에 ZCode가 있으면 버전을 확인하고, 벤더 권고가 나오기 전까지는 신뢰하지 않는 저장소를 열지 않도록 정책을 건다. 저장소의 작업 공간 설정이 MCP 서버를 자동 실행하지 않도록 설정을 점검한다.
- 에이전트가 실행하는 셸 명령을 엔드포인트 텔레메트리로 수집하고, sed·awk·find 같은 명령이 쓰기·실행 플래그와 함께 호출되는 패턴을 탐지 규칙으로 둔다.
- 에이전트 실행 환경에서 장기 자격 증명(SSH 키, 클라우드 키)을 치운다. 명령 주입이 성공해도 가져갈 것이 없게 만든다.
