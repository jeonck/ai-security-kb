## 요약
JFrog 보안연구팀은 10월 26일, ‘testmetest’로 불려 온 npm 악성 패키지 묶음을 추적한 결과 정상 소유자 11명의 GitHub 저장소 42곳이 공격 기반으로 무장돼 있었다고 공개했다. npm 쪽에서는 패키지 14개, 약 30개 버전이 악성으로 분류됐다. 이번에 새로 확인된 것은 페이로드를 네이티브 애드온(.node) 안에 숨기고, 분석 환경에서는 조용히 꺼지는 위장 기법이다. 무장된 저장소에는 Claude·Gemini·Cursor·VS Code가 워크스페이스를 열 때 자동으로 실행하는 설정 파일이 심겨 있었다. GitHub Actions 안에서 OIDC로 npm 게시 토큰을 얻어 다른 패키지를 오염시키는 숨은 게시기도 발견됐다.

## 동작 원리
설치 단계에서는 binding.gyp 트릭과 네이티브 애드온으로 암호화된 단계를 풀어 자격 증명을 훔치고, 저장소·CI 설정을 오염시킨다. 오염된 저장소에는 ‘문을 여는 순간 울리는 장치’가 붙는다. 개발자가 그 저장소를 Claude Code로 열면 SessionStart 훅이, Cursor로 열면 MCP 설정과 규칙 파일이, VS Code로 열면 폴더 열기 작업이 각각 .github/init.js를 실행한다. 패키지를 설치하지 않은 사람도 저장소를 클론해 AI 코딩 도구로 열기만 하면 감염된다. CI에서는 정상적인 신뢰 게시(OIDC) 흐름을 그대로 써서 공격자가 토큰 없이도 다른 패키지에 postinstall을 끼워 넣어 다시 배포한다. 분석 환경(컨테이너·저사양 VM·디버거)을 감지하면 꺼지기 때문에 샌드박스 동적 분석만으로는 잡기 어렵다.

## 플랫폼 엔지니어 관점
- 저장소 안의 AI 도구 설정 파일(.claude/settings.json, .gemini/settings.json, .cursor/mcp.json, .cursor/rules/, .vscode/tasks.json)을 코드 리뷰·CODEOWNERS 대상에 넣고, 훅·명령 실행 필드가 바뀌는 PR은 차단 규칙으로 걸러 낸다.
- 개발자 PC와 devcontainer에서 Claude Code·Cursor 등이 프로젝트 단위 훅과 MCP 설정을 자동 신뢰하지 않도록 관리형 정책으로 막고, 처음 여는 외부 저장소는 격리된 일회용 환경에서 연다.
- npm 신뢰 게시(OIDC)를 쓰는 워크플로는 게시 권한을 특정 워크플로 파일·브랜치·환경으로 묶고, 알 수 없는 워크플로(가짜 CodeQL 등)가 id-token: write를 갖지 못하게 한다. 아티팩트에 시크릿이 담기지 않는지 점검한다.
- 의존성 설치는 --ignore-scripts 기본값과 사내 레지스트리 프록시의 악성 패키지 차단(OSV·GHSA malware 피드)을 함께 쓰고, 네이티브 애드온을 새로 들고 오는 버전 변경은 별도 검토 대상으로 표시한다.
- 감염이 의심되면 GitHub·npm 토큰과 함께 AI 공급자 API 키도 폐기·재발급한다.
