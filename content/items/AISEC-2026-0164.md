## 요약
Google Cloud가 만드는 오픈소스 MCP 서버 ‘MCP Toolbox for Databases’의 cloud-storage 소스에 인가 누락과 경로 조작 취약점(CVE-2026-93328)이 공개됐다. 1.2.0~1.4.0에서는 인증 없는 원격 공격자가 도구 호출 인자를 조작해 서버가 돌고 있는 호스트의 파일을 자기 GCS 버킷으로 복사하거나, 호스트의 임의 파일을 덮어쓸 수 있었다. CNA인 Google Cloud가 CVSS v4.0 9.3(Critical)을 매겼다. 수정 PR은 2026년 6월에 병합돼 1.5.0에 들어갔지만 CVE는 10월 26일에야 게시됐고, 새 허용 목록 옵션은 설정하지 않으면 전부 허용이 기본값이다.

## 동작 원리
MCP 서버의 도구는 모델이 채워 넣은 인자로 실행된다. cloud-storage 소스는 ‘이 버킷에서 저 로컬 경로로 복사’, ‘로컬 파일을 이 버킷으로 업로드’ 같은 작업을 제공하는데, 어느 버킷·어느 로컬 경로든 인자에 적힌 대로 받아들였다. 도구를 부를 수 있는 누구든 — 인증 없이 노출된 서버라면 네트워크상의 아무나, 혹은 인젝션된 에이전트라면 웹 페이지 속 지시문이 — 서비스 계정 권한으로 호스트의 자격 증명 파일을 외부 버킷으로 올리거나, 반대로 외부 버킷의 파일을 내려받아 설정 파일·스크립트를 덮어쓸 수 있다. 창고 열쇠를 가진 직원이 ‘어느 창고에서 어느 트럭으로’라는 쪽지만 보고 확인 없이 물건을 옮겨 주는 셈이다. 수정은 운영자가 허용할 버킷과 로컬 루트를 미리 적게 하는 것이다.

## 플랫폼 엔지니어 관점
- 사내에서 MCP Toolbox(googleapis/mcp-toolbox)를 쓰는 곳을 찾아 1.5.0 이상으로 올리고, cloud-storage 소스를 쓰면 allowedBuckets·allowedLocalRoots를 반드시 설정한다. 업그레이드만으로는 기본값이 전부 허용이라는 점을 운영 체크리스트에 적는다.
- Toolbox를 Kubernetes에 올렸다면 Service를 클러스터 내부로 제한하고 앞단에 인증(IAP·mTLS·OIDC 프록시)을 둔다. 컨테이너는 비루트·읽기 전용 루트 파일시스템으로 돌리고, 쓰기 가능한 경로를 emptyDir 하나로 좁힌다.
- Workload Identity로 붙인 서비스 계정의 GCS 권한을 특정 버킷 단위로 줄이고, VPC Service Controls 경계로 조직 밖 버킷으로의 복사를 막는다 — 외부 버킷 쓰기는 egress 통제로 막아야 할 유출 경로다.
- 수정 병합(6월)과 CVE 공개(10월) 사이 간격이 길다. 스캐너가 CVE로만 경보를 내는 구조라면 MCP 서버 저장소의 보안 관련 PR·릴리스 노트를 별도로 구독한다.
