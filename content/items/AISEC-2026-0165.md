## 요약
보안업체 Theori의 Xint는 10월 26일, OpenAI가 암호화해서만 돌려주는 추론 흔적을 대화 압축(컴팩션) 기능을 경유해 평문으로 빼내는 ‘컴팩션 밀수’를 공개했다. 8월에 공개된 선행 연구 이후 OpenAI는 추론을 다른 모델에 재생하는 것을 막았지만, 컴팩션은 추론을 만든 같은 모델에서 돌기 때문에 이 방어를 빗겨 갔다. 연구진은 압축본 안에 추론을 그대로 담게 유도한 뒤 구형 모델에 ‘입력을 그대로 출력하라’고 시켜 내용을 얻었다. OpenAI는 10월 23일 수정을 배포하고 6,000달러 포상금을 지급했다. 추론 흔적은 경쟁 모델을 싸게 증류하는 데 가장 값진 데이터라, 이 문제는 모델 추출·증류 공격의 실제 경로로 읽힌다.

## 동작 원리
추론 흔적은 봉인된 봉투에 담겨 돌아오고, 고객은 그 봉투를 다음 요청에 다시 넣을 수만 있다. OpenAI는 봉투를 다른 모델에게 열어 보게 하는 길을 막았다. 그런데 ‘대화를 줄여 달라’는 컴팩션 요청은 봉투를 만든 같은 모델이 처리하므로 봉투를 열 수 있다. 공격자는 ‘원래 과제는 빼고 추론만 원문 그대로 남겨라’는 지시를 붙여 컴팩션을 요청한다. 그러면 추론이 새 봉투(압축본)로 옮겨 담긴다. 이 압축본은 다른 모델도 입력으로 읽을 수 있어서, 구형 모델에게 그대로 받아 적게 하면 평문이 나온다. 공백을 탭으로 바꾸는 작은 변형만으로 정책 분류기도 피했다. 방어가 ‘누가 봉투를 여나’만 봤고, 봉투 내용이 다른 봉투로 옮겨지는 흐름은 보지 않은 것이 원인이다.

## 플랫폼 엔지니어 관점
- 자체 모델을 API로 서빙하는 팀은 ‘사용자에게 불투명하게 돌려준 산출물(암호화 추론, 요약, 캐시 키)’이 다른 엔드포인트의 입력으로 들어갈 때 무엇이 복원될 수 있는지 데이터 흐름 단위로 위협 모델링한다.
- 증류 탐지는 단일 요청 분류기가 아니라 계정 단위 행동(압축 요청 비율, 같은 입력의 에코 요청, store=False와 대량 추론 요청의 조합)으로 본다. API 게이트웨이에서 계정·조직별 사용 패턴 로그를 남긴다.
- 외부 LLM API를 쓰는 쪽에서는 이 사례가 직접 위협은 아니지만, 공급자 API 키가 유출되면 증류 캠페인에 쓰일 수 있다. 키를 워크로드 신원 기반 단기 토큰으로 바꾸고 사용량 이상 경보를 건다.
