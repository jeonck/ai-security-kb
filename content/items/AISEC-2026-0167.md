## 요약
iFlytek이 공개한 에이전트 워크플로 플랫폼 astron-agent 1.1.2 이하에서 두 건의 CVE가 2026-10-26 VulDB를 통해 공개됐다. 하나는 에이전트 메모리용 DB 서비스가 SQL 문장을 정규식으로만 걸러 주석 속 문구로 차단을 피할 수 있었던 결함(CVE-2026-116339, CVSS v4.0 6.9), 다른 하나는 콘솔의 지식 파일 목록이 숫자형 space-id 헤더만으로 소유권 검사를 건너뛴 결함(CVE-2026-116340)이다. 연구자의 PoC 저장소에는 다른 앱이 남의 일시정지 워크플로를 재개할 수 있는 세 번째 결함도 실려 있다. 수정 버전은 없다.

## 동작 원리
DDL 허용 목록은 ‘ALTER TABLE 같은 안전한 문장만 통과’시키려는 문지기인데, 문장의 뜻을 해석하지 않고 글자만 훑었다. 그래서 실제로는 확장 설치 명령을 보내면서 주석에 ‘ALTER TABLE’을 적어 두면, 문지기는 통과시키고 DB는 주석을 무시한 채 본 명령을 실행한다. 지식 파일 결함은 ‘공간(space) 번호를 들고 오면 그 공간 소속이라고 믿는’ 검사라, 아무 숫자나 들고 와도 됐다. 워크플로 재개 결함은 사람의 확인을 기다리며 멈춘 작업을, 재개 요청이 원래 앱에서 왔는지 보지 않고 받아 주는 구조다.

## 플랫폼 엔지니어 관점
- astron-agent를 자체 호스팅한다면 core-database 서비스 포트가 클러스터 밖이나 다른 네임스페이스에서 닿지 않도록 NetworkPolicy로 막고, DB 접속 역할을 슈퍼유저에서 스키마 한정 역할로 바꾼다 — 확장 설치 권한이 없으면 우회해도 피해가 줄어든다.
- 에이전트 메모리에 SQL을 직접 실행하게 하는 기능은 문자열 필터 대신 파서 기반 허용 목록이나 미리 정의한 연산 API로 바꾸도록 요구한다.
- 콘솔·워크플로 API 앞단 게이트웨이에서 헤더로 넘어오는 테넌트·공간 식별자를 토큰 클레임과 대조한다. 사람 승인 대기 워크플로의 재개 엔드포인트는 원래 앱·사용자 신원에 묶여 있는지 점검 항목에 넣는다.
- 벤더 패치가 나올 때까지 공개 PoC가 있으므로, 노출 중인 인스턴스는 인증 프록시 뒤로 옮긴다.
