## 요약
OpenHands의 에이전트 SDK는 코딩 에이전트를 Docker나 Apptainer 컨테이너 안에서 돌리는데, 1.52.0 이전에는 컨테이너 안의 에이전트 서버를 모든 네트워크 인터페이스에 열고 세션 API 키를 하나도 설정하지 않은 채 띄웠다. 키 목록이 비어 있으면 인증이 꺼지므로, 그 포트에 닿기만 하면 누구든 샌드박스 안에서 root로 명령을 실행하고 작업 공간 코드와 평문 시크릿을 읽을 수 있었다. VulnCheck가 2026-10-26 CVE-2026-112346(CVSS v4 9.3)으로 공개했다. 수정은 10월 3일 병합된 PR #5209로, Docker 포트를 루프백에만 게시하고 세션 키를 클라이언트에 전달하도록 했다.

## 동작 원리
샌드박스는 ‘위험한 일을 하는 방’이고, 에이전트 서버는 그 방 안에서 명령을 받아 실행하는 비서다. SDK는 방 밖의 자기 클라이언트가 같은 기계(127.0.0.1)에서만 비서를 부른다고 가정했지만, 실제로는 Docker가 비서의 전화번호(포트)를 건물 전체, 즉 모든 호스트 인터페이스에 공개했고 비서는 신분 확인(세션 키)도 하지 않았다. 같은 네트워크에 있는 누구나, 클라우드 VM이라면 보안 그룹이 열린 인터넷 전체가 그 번호로 명령을 내릴 수 있었다. 격리 장치가 그대로 원격 실행 창구가 된 셈이다.

## 플랫폼 엔지니어 관점
- OpenHands SDK를 1.52.0 이상으로 올리고, 개발 VM·CI 러너에서 에이전트 서버 포트가 0.0.0.0에 게시돼 있지 않은지 확인한다.
- 에이전트 샌드박스 제어 API는 ‘키가 없으면 거부’가 기본이어야 한다. 빈 키 목록을 인증 해제로 해석하는 설정을 배포 정책(OPA·Kyverno)이나 시작 검사로 막는다.
- Kubernetes에서 에이전트 샌드박스를 돌린다면 Service 타입·NetworkPolicy로 제어 포트 인입을 오케스트레이터 파드로만 제한하고, hostNetwork·hostPort 사용을 금지한다.
- 샌드박스에 시크릿을 평문으로 넣지 말고, 짧은 수명 토큰을 바깥 프록시가 요청 시점에 주입하는 구조로 바꾼다.
- 클라우드 VM의 보안 그룹·방화벽에서 에이전트 서버 포트가 열려 있는지 외부 스캔으로 점검한다.
