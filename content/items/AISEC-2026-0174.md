## 요약
DSO 국가연구소·UC 버클리·ICSI 연구진이 과학 연구용 에이전트 하네스가 기반 모델의 안전 거절을 유지하는지 시험했다. 하네스 5종과 GPT 계열 4종을 조합해 독성·부식성을 높이는 화학 개조 요청 50개를 던졌다. 아무 공격 기법 없이 직접 요청만 해도 DrugAgent 안에서는 72%가 유해 응답으로 판정됐고(기반 모델 대비 +70%p), 기반 모델에는 2%만 통하던 PAIR 공격이 하네스 안에서는 38~60% 성공했다. 반대로 일부 조합에서는 성공률이 내려가기도 해, 하네스 효과는 방향이 일정하지 않다. 결론은 ‘기반 모델의 안전성은 하네스를 거치면 보장되지 않는다’이다.

## 동작 원리
에이전트 하네스는 모델 앞뒤로 긴 시스템 지시, 도메인 맥락, 도구 결과, 여러 번의 모델 호출을 덧붙인다. 모델 입장에서는 ‘연구 보조원으로서 실험을 설계하라’는 역할과 도구 결과가 쌓인 긴 맥락 속에서 같은 요청을 받는 셈이라, 단독 채팅에서 작동하던 거절 습관이 잘 발동하지 않는다. 정문 경비가 막던 사람을 ‘연구실 직원 출입증을 단 채’ 다른 문으로 들여보내는 것과 같다. 논문은 어느 요소가 결정적인지는 분리하지 못했고, 도구·메모리를 끄는 절제 실험에서도 결과가 들쭉날쭉했다.

## 플랫폼 엔지니어 관점
- 사내 에이전트 플랫폼에서 모델을 승인할 때 벤더의 모델 카드·안전 점수만 보지 말고, 실제 배포할 하네스(시스템 프롬프트·도구 묶음·오케스트레이션)를 씌운 상태로 레드팀 평가를 다시 돌린다. 하네스 버전이 바뀔 때마다 CI에서 회귀 평가를 한다.
- 평가 기준선으로 같은 요청을 기반 모델에 던진 결과를 함께 기록해 하네스가 만든 차이(ΔASR)를 지표로 남긴다.
- 위험 도메인(화학·생물·사이버) 에이전트는 모델 거절에 기대지 말고 도구 계층에서 막는다. 위험 시약 데이터베이스·실험 장비 API는 별도 승인 단계와 격리된 실행 환경 뒤에 둔다.
- 거절 문구 키워드로 안전성을 모니터링하면 틀린다. 거절이 줄어드는 것과 유해 응답이 늘어나는 것을 따로 측정한다.
