## 요약
Google이 공개한 Cloud Run MCP 서버는 AI 에이전트가 사용자의 코드를 Cloud Run에 배포하게 해 주는 도구다. 1.11.0 이전 버전은 소스를 올려 빌드할 때 프로젝트 ID로 정해지는 버킷 이름을 쓰면서, 그 버킷이 정말 내 프로젝트 것인지 확인하지 않았다. 공격자가 그 이름의 버킷을 자기 프로젝트에 먼저 만들어 두면 피해자의 소스가 공격자 버킷으로 올라가 열람·변조될 수 있다. Google Cloud는 2026-10-26 CVE-2026-85297(CVSS v4 7.7)로 공개하며 서비스 계정 탈취로 이어질 수 있다고 밝혔다. 수정은 8월에 병합돼 1.11.0에 들어갔지만 릴리스 노트에는 보안 수정으로 표시되지 않았다.

## 동작 원리
Cloud Storage 버킷 이름은 전 세계에서 하나뿐이라, 이름을 먼저 차지한 사람이 주인이다. 배포 도구가 ‘우리 회사 이름_cloudbuild’라는 사서함으로 소포를 보내도록 정해져 있는데, 공격자가 그 이름의 사서함을 먼저 개설하면 소포(소스 아카이브)는 공격자에게 간다. 공격자는 내용을 읽을 수 있고, 빌드가 그 버킷에서 소스를 다시 읽어 간다면 악성 코드를 끼워 넣어 피해자 프로젝트의 빌드·런타임 서비스 계정 권한으로 실행되게 만들 수 있다. 이름이 예측 가능하다는 점(CWE-340)과 소유 확인 부재가 겹친 고전적 결함이지만, 이제 그 배포를 사람 대신 에이전트가 MCP로 호출한다.

## 플랫폼 엔지니어 관점
- Cloud Run MCP를 쓰는 개발자 환경·에이전트 플랫폼에서 1.11.0 이상으로 올리고, MCP 서버 버전을 고정·승인 목록으로 관리한다. 릴리스 노트에 보안 표시가 없어도 CVE·GHSA 피드로 버전을 대조한다.
- 조직의 ‘<프로젝트 ID>_cloudbuild’ 같은 예측 가능한 버킷 이름이 실제로 자기 프로젝트 소유인지 점검하고, 미리 만들어 두거나 조직 정책으로 외부 버킷 쓰기를 막는다.
- VPC Service Controls 경계로 빌드 서비스 계정이 조직 밖 버킷에 쓰지 못하게 한다.
- 에이전트가 배포 도구를 호출할 때 쓰는 자격 증명은 배포 전용 최소 권한 서비스 계정으로 분리하고, Cloud Build 기본 서비스 계정의 광범위 권한을 줄인다.
- 업로드한 소스 아카이브의 해시와 빌드가 읽은 소스의 해시를 비교하는 출처 증명(SLSA provenance)을 배포 파이프라인에 넣는다.
