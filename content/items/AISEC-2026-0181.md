## 요약
Cloudflare는 2026-10-26 조율 공개 글에서 Workers AI의 GLM-5.3 모델이 8월 27일~9월 9일 사이 일부 고객에게 다른 고객 요청의 내용이 섞인 응답을 돌려줬다고 밝혔다. 영향은 68만 토큰을 넘는 긴 프롬프트에 대한 응답 155건이다. 원인은 컨텍스트 길이보다 작게 잡은 prefill KV 풀과, 거부돼야 할 요청이 디코드 단계까지 넘어간 SGLang 분리형 서빙의 버그가 겹친 것이다. 외부 연구자가 HackerOne으로 제보했고, Cloudflare는 하루 만에 모델을 내리고 패치해 복구한 뒤 SGLang 팀과 업스트림 수정을 진행했다.

## 동작 원리
LLM 추론 엔진은 앞 토큰의 계산 결과(KV 캐시)를 메모리 풀의 페이지에 담아 재사용한다. 분리형 서빙은 프롬프트 처리(prefill)와 토큰 생성(decode)을 다른 노드에 나누고 KV 페이지를 네트워크로 넘긴다. 여기서 너무 긴 요청은 ‘거부’ 표시와 함께 1토큰짜리 자리표시자로 바뀌었는데, 다음 단계는 ‘끝났나’만 보고 ‘거부됐나’는 보지 않았다. 그래서 실제 내용 없이 디코드로 넘어간 요청이 이전 사용자가 쓰고 비우지 않은 KV 페이지를 자기 문맥처럼 읽고 답을 생성했다. 식당에서 주문서가 반려됐는데 주방이 직전 손님의 접시를 그대로 내보낸 셈이다. 오류 대신 HTTP 200이 나가 클라이언트도 이상을 알아채기 어려웠다.

## 플랫폼 엔지니어 관점
- 자체 호스팅 vLLM·SGLang을 여러 팀·테넌트가 공유한다면 KV 캐시와 프리픽스 캐시를 테넌트 경계로 믿지 말고, 민감 테넌트는 별도 인스턴스·노드 풀로 나눈다.
- 배포 파이프라인에 ‘KV 풀 크기 ≥ 최대 컨텍스트 길이’ 같은 설정 정합성 검사를 넣고, 길이 초과 요청이 실제로 오류를 반환하는지 회귀 테스트한다.
- 서로 다른 계정에서 고유 표식(canary)을 넣은 요청을 동시에 보내 응답에 다른 계정의 표식이 섞이는지 보는 교차 요청 누출 테스트를 서빙 엔진 업그레이드마다 돌린다.
- SGLang을 쓰면 v0.5.21 이상(가능하면 v0.5.22)으로 올리고, 분리형 모드·KV 전송 백엔드 사용 여부를 인벤토리에 남긴다.
- 관리형 추론 API를 쓰는 쪽은 공급자의 사고 공지 채널을 구독하고, 공급자별로 어떤 데이터(장문 문서·코드)를 보내는지 분류해 두어 이런 공지에 영향 범위를 바로 판단할 수 있게 한다.
