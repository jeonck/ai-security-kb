## 요약
Mistral의 터미널 코딩 에이전트 Vibe는 3.0.3 이전 버전에서 `--worktree` 옵션으로 저장소를 열면 `git worktree add`를 먼저 돌리고, 그 폴더를 신뢰할지 묻는 단계는 나중에 거쳤다. 악성 저장소가 `.git/config`에 필터 드라이버를, `.gitattributes`에 그 필터를 쓸 파일 패턴을 넣어 두면 체크아웃 과정에서 필터 명령이 사용자 권한으로 실행된다. VulnCheck가 2026-10-26 CVE-2026-116843(CVSS v4 8.7)으로 공개했고 3.0.3에서 고쳐졌다고 밝혔다. 그러나 제보자는 이슈가 닫힌 당일 같은 PoC가 여전히 동작한다고 반박해 수정 완결성이 확인되지 않았다. 같은 제보자의 post-checkout 훅 경로(#996)도 별도로 보고됐다.

## 동작 원리
git은 체크아웃할 때 `.gitattributes`에 지정된 파일마다 ‘필터’ 프로그램을 거쳐 내용을 바꿀 수 있다(예: 줄바꿈 변환, LFS). 필터가 무슨 명령을 실행할지는 git 설정에 적혀 있으므로, 설정을 공격자가 쥐면 ‘파일을 꺼내는 행위’ 자체가 명령 실행이 된다. 훅과는 별개 메커니즘이라 훅을 꺼도 막히지 않는다. Vibe는 ‘이 폴더를 믿겠습니까’라는 문지기를 두었지만 워크트리 생성이라는 손님 맞이를 문지기보다 먼저 해 버린 셈이다. 3.0.3 릴리스 노트가 fsmonitor·서명 검증 프로그램·LFS 확장까지 한꺼번에 막은 것은, git이 저장소 설정으로 외부 프로그램을 부르는 길이 여러 개라는 점을 보여 준다.

## 플랫폼 엔지니어 관점
- 개발자 PC·CI 러너의 Vibe를 3.0.3 이상으로 올리고, 제보자의 ‘미완 수정’ 주장이 정리될 때까지 신뢰하지 않는 저장소에는 `--worktree`를 쓰지 않게 안내한다.
- 코딩 에이전트가 외부 저장소를 다룰 때는 자격 증명 없는 일회용 컨테이너·devcontainer에서 클론·체크아웃하고, 그 환경의 egress를 패키지 미러·git 프록시로 제한한다.
- 에이전트 플랫폼에서 git을 호출하는 경로는 `core.hooksPath`를 빈 경로로, `filter.*`·`core.fsmonitor`·`gpg.program` 같은 외부 프로그램 설정을 무시하도록(전역 설정·`-c` 옵션) 고정하는 래퍼를 표준화한다.
- 에이전트 도구 선정 시 ‘신뢰 확인이 어떤 git 동작보다 먼저 일어나는가’를 점검 항목에 넣는다.
