## 요약
Dai·Sun·Tao는 악성 MCP 도구의 ‘설명문’만 최적화해 에이전트가 정상 도구 대신 그것을 고르게 하는 도구 스푸핑 공격(TSA)을 발표했다. 기존 도구 포이즈닝이 설명에 노골적 지시문(<IMPORTANT> 등)을 넣었다면, TSA는 정상 설명과 거의 같은 문장으로 선택 확률만 끌어올린다. 단일·다중 도구 벤치마크에서 80~90%대, 미지의 모델 GPT-5로 전이했을 때 최대 92.13% 성공했다. MCP 전용 스캐너 5종은 최대 4.25%만 잡았고, 사람 참가자도 정상 설명과 구별하지 못했다.

## 동작 원리
에이전트는 비슷한 도구가 여럿이면 설명문을 읽고 하나를 고른다. 앱 장터에서 이름과 소개글만 보고 앱을 고르는 것과 같아서, 소개글을 ‘선택되기 좋게’ 다듬으면 기능이 같은 경쟁 도구를 이길 수 있다. 일단 선택되면 에이전트가 보는 것은 반환 메시지뿐이므로 뒤에서 무슨 일을 하든 드러나지 않는다. 설명에 수상한 명령문이 없으니 패턴 기반 스캐너가 걸 단서도 없다.

## 플랫폼 엔지니어 관점
- 에이전트가 쓸 MCP 서버는 내부 레지스트리에 승인·버전 고정된 것만 허용하고, 공개 마켓에서 런타임에 도구를 동적으로 추가하는 경로를 막는다.
- 같은 기능의 도구가 여러 서버에 있을 때 선택을 모델에 맡기지 말고 게이트웨이(클라이언트별 도구 세트·도구 필터)에서 허용 도구를 지정한다.
- 도구 설명문 스캐너는 노골적 지시문 탐지용 보조 수단으로만 두고, 출처(퍼블리셔 신원, 서명, 리포지토리 이력) 검증을 승인 기준의 중심에 둔다.
- 도구 호출 로그에 어떤 서버의 어떤 도구가 선택됐는지 남겨, 새 도구가 기존 도구의 호출을 가로채는 변화를 탐지한다.
