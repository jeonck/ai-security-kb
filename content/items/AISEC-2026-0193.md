## 요약
Li 등은 배포된 LLM 에이전트가 파일 읽기·쓰기, 프로세스·서브에이전트 생성, 네트워크 접근, 확장 로딩, 상태 저장·재개를 모두 하는 사실상의 운영체제라고 보고, OS 교과서의 보호 메커니즘 116개를 에이전트 쪽 대응물과 하나씩 대조했다. 그대로 옮겨진 것은 11개뿐이고 65개는 아예 없었다. Claude Code·Codex CLI·Gemini CLI로 13개 실험을 돌린 결과, 도구별 경로 검사는 셸로 우회됐고, 세 CLI 모두 위조된 대화 기록을 재개 시 사용자 메시지로 받아들였으며, 서브에이전트는 부모 권한을 그대로 물려받았다. 저자들은 벤더에 통보했지만 사용자 파일 쓰기가 전제라 익스플로잇은 아니라고 봤다.

## 동작 원리
OS는 50년에 걸쳐 커널과 사용자 공간을 나누고, 프로세스마다 권한을 줄이고, 감사 로그를 프로세스가 고칠 수 없게 만들었다. 에이전트는 3년 만에 같은 기능을 얻었지만 모델이 내놓는 출력은 사용자의 지시든 도구 결과든 내려받은 스킬이든 모두 호스트 사용자의 전체 권한(링 0)으로 실행된다. 그래서 ‘파일 도구는 작업 공간 밖에 못 쓴다’는 규칙은 같은 에이전트가 가진 셸 도구 앞에서 의미가 없다. 재개 기능도 같다. 디스크의 대화 기록 파일은 형식만 맞으면 사용자 발화로 취급되므로, 그 파일에 쓸 수 있는 누구든 프롬프트 인젝션 없이 지시를 심을 수 있다. 프롬프트에 적은 금지 규칙은 우회·변조가 가능하고 검증할 수 없어 참조 모니터가 되지 못한다.

## 플랫폼 엔지니어 관점
- 코딩 에이전트의 권한 경계는 도구별 허용 목록이 아니라 컨테이너·devcontainer·VM의 파일시스템·네트워크 경계로 정한다. 셸 도구가 있으면 도구별 경로 검사는 보조 수단으로만 본다.
- 세션 재개용 대화 기록(~/.claude, ~/.codex 등)은 에이전트 작업 공간·저장소에서 쓸 수 없는 위치에 두고, CI 러너에서는 세션 재개를 끄거나 매 실행을 새 세션으로 시작한다.
- 서브에이전트를 쓰는 워크플로에서는 자식 에이전트에 별도의 축소된 토큰·마운트를 주는 방식을 플랫폼에서 강제한다. CLI의 권한 상속에 기대지 않는다.
- 에이전트가 남기는 트랜스크립트는 증거로 쓰지 않고, 도구 호출·파일 쓰기·네트워크 요청은 에이전트 프로세스 밖(eBPF, egress 프록시, 감사 로그 수집기)에서 따로 기록한다.
- 토큰 소비에 대해 실행·세션 단위 예산 한도를 게이트웨이에서 걸어 ‘자원이 곧 돈’인 문제를 운영적으로 막는다.
