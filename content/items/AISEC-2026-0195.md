## 요약
Chang 등은 Python 파일의 변수·함수 이름만 바꿔 AI 코딩 에이전트가 취약한 코드를 쓰도록 유도하는 NameTrap을 발표했다. 미끼 파일에는 지시문도 취약 코드도 없고 기능도 원본과 같다. 6개 코딩 에이전트에서 22.5~56.0%, 일부 조합에서 최대 75.0%의 성공률을 보였고, 기존 XOXO 공격(2.1%)보다 훨씬 높았다. 프롬프트에 보안 주의 문구를 붙이는 방어는 거의 효과가 없었고, 정적·AI 분석기 7종은 목표 취약점을 하나도 잡지 못했다.

## 동작 원리
에이전트는 참고 코드의 이름에서 ‘이 코드베이스의 관례’를 읽는다. 예를 들어 명령 실행을 ‘신뢰된 명령’처럼 부르는 이름이 곳곳에 있으면, 셸을 통한 실행이 그 코드베이스에 어울리는 방식처럼 보여 에이전트가 새 코드에서도 같은 패턴(명령 주입, CWE-78)을 따른다. 호환성·빠른 다이제스트를 강조하는 이름은 약한 해시(CWE-327)를, 객체 복원 관련 이름은 위험한 역직렬화(CWE-502)를 끌어낸다. 공격 측 에이전트는 이름 후보를 바꿔 가며 로컬 모델로 완성 결과를 시험해 가장 잘 먹히는 조합을 고른다. 명령문이 아니라 ‘분위기’를 조작하므로 인젝션 탐지기나 정적 분석기가 걸 단서가 없고, 미끼 파일 자체에는 취약점이 없어 스캐너도 통과한다.

## 플랫폼 엔지니어 관점
- 코딩 에이전트가 참고하는 외부 코드(웹 검색 결과, 임의 저장소, gist)의 범위를 조직 승인 저장소·미러로 제한하고, 에이전트의 웹 검색·fetch 도구는 기본 비활성 또는 허용 목록으로 운영한다.
- 이름만 바꾸는 ‘정리’ PR도 리뷰 대상으로 취급한다. 외부 기여자의 대량 리네이밍 PR은 별도 승인 단계를 둔다.
- 미끼 파일이 아니라 생성 결과를 검사한다. 에이전트가 만든 코드에는 CI에서 SAST와 함께 위험 API 사용 규칙(subprocess shell=True, pickle·yaml.load, md5/sha1, 이스케이프 없는 HTML)을 차단 정책으로 걸고, 사람 리뷰를 함께 둔다.
- 시스템 프롬프트의 ‘보안에 유의하라’ 문구를 통제로 보고하지 않는다. 이 연구에서 그 문구는 절반의 구성에서 성공률을 오히려 높였다. 생성 코드는 운영 자격 증명 없는 샌드박스에서 먼저 실행·테스트한다.
