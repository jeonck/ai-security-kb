## 요약
Anthropic이 Claude Code의 Edit 도구에서 검사 시점과 사용 시점이 어긋나는 경쟁 조건(TOCTOU) 취약점을 공개했다(CVE-2026-88968, GHSA-5xjx-9qx6-jcrv). Edit 도구는 대상 경로가 작업 공간 안에 있는지 확인한 뒤 따로 파일을 썼다. 그 사이에 macOS의 Bash 샌드박스 안에서 도는 프로세스가 작업 공간 안 디렉터리를 심볼릭 링크로 바꿔치기하면, 샌드박스 밖에서 실행되는 Edit 구현이 그 링크를 따라 작업 공간 밖 파일을 덮어쓸 수 있었다. 악성 저장소나 의존성 스크립트가 샌드박스 안에서 돌기만 하면 되는 조건이다. 2.1.251에서 수정됐고 CVSS 4.0 점수는 7.7이다. 같은 저장소에는 10월 5일에도 비슷한 심볼릭 링크 TOCTOU 권고가 있었다.

## 동작 원리
경비원이 출입증을 확인한 뒤 문을 열어 주는 사이에 다른 사람이 문패를 바꿔 다는 상황과 같다. Edit 도구는 ‘이 경로는 작업 공간 안이다’를 경로 문자열로 확인했는데, 실제로 쓸 때는 다시 경로를 따라간다. 샌드박스 안의 프로세스는 같은 디렉터리를 볼 수 있으므로, 확인이 끝난 순간 디렉터리를 심볼릭 링크로 바꿔 놓는다. 그러면 샌드박스 밖 권한으로 도는 Edit 구현이 링크를 따라 홈 디렉터리의 설정 파일 같은 곳에 쓴다. 샌드박스는 Bash 명령만 가뒀고, 파일 편집 도구는 샌드박스 밖에서 샌드박스가 조작할 수 있는 경로를 신뢰한 셈이다. 근본 해결은 경로를 다시 해석하지 않고, 검사한 디렉터리를 연 파일 디스크립터를 기준으로 쓰는 것이다.

## 플랫폼 엔지니어 관점
- 개발자 PC와 CI 러너의 Claude Code를 2.1.251 이상으로 올리고, 버전을 고정해 배포하는 조직은 MDM·이미지 빌드에서 최소 버전을 강제한다.
- 코딩 에이전트의 ‘샌드박스 모드’가 무엇을 가두는지 확인한다. 셸 명령만 가두고 파일 편집 도구는 호스트 권한으로 돈다면, 에이전트 전체를 devcontainer·VM 안에서 돌리는 쪽이 경계로서 더 단단하다.
- 신뢰하지 않는 저장소(외부 PR, 새 의존성)를 에이전트로 다룰 때는 홈 디렉터리·SSH 키·셸 설정이 마운트되지 않은 일회용 환경을 쓴다. 덮어쓰기 표적이 되는 ~/.zshrc, ~/.ssh/authorized_keys, Git 훅 파일의 변경을 EDR이나 파일 무결성 감시로 탐지한다.
- 사내에서 에이전트 도구를 직접 만든다면 경로 검증 뒤 다시 경로로 여는 패턴을 금지하고, 디렉터리 디스크립터 기준 열기와 심볼릭 링크 거부 플래그를 코드 리뷰 체크리스트에 넣는다.
