## 요약
Nicholas Carlini 등 14명의 연구진은 상용 LLM API에 질의만 해서 모델의 마지막 층인 임베딩 투영 행렬을 복원하는 공격을 발표했다. OpenAI ada와 babbage는 20달러 미만으로 투영 행렬 전체를 뽑아 은닉 차원(1024, 2048)을 확인했고, gpt-3.5-turbo 계열은 은닉 차원을 복원했으며 행렬 전체 추출 비용을 2,000~8,000달러 수준으로 추정했다. 공격은 logprob과 logit bias라는 평범한 API 기능을 이용했고, 공개 후 OpenAI와 Google은 API를 바꿨다. 논문은 기능 제거, 동시 사용 금지, 노이즈, 질의 제한, 패턴 탐지 같은 방어와 그 한계를 함께 정리했다.

## 동작 원리
모델은 마지막에 h차원 은닉 벡터에 큰 행렬을 곱해 어휘 수만큼의 로짓을 만든다. 어휘가 수만 개여도 로짓 벡터는 언제나 h차원 공간 안에만 놓인다. 그래서 프롬프트를 수천 개 던져 로짓 벡터를 모아 SVD를 하면, 의미 있는 축이 몇 개인지가 곧 은닉 차원이다. 같은 계산으로 투영 행렬도 회전 같은 대칭성을 빼고 복원된다. 문제는 API가 보통 상위 몇 개 토큰의 logprob만 준다는 점인데, logit bias로 원하는 토큰을 억지로 상위에 올려 놓고 logprob 변화를 보면 원래 로짓을 거꾸로 계산할 수 있다. 증류가 모델의 답을 대량으로 받아 비슷하게 행동하는 모델을 따로 학습하는 것이라면, 이 공격은 API 출력이 가진 선형대수 구조를 이용해 원래 모델의 실제 가중치 일부를 꺼낸다는 점에서 다르다.

## 플랫폼 엔지니어 관점
- 모델 게이트웨이에서 노출하는 디코딩 옵션(logprobs, top_logprobs, logit_bias)을 기능 목록이 아니라 공격 표면 목록으로 관리한다. 필요 없는 테넌트에는 끄고, 같은 요청에서 logit_bias와 logprobs를 함께 허용하지 않는 정책을 게이트웨이 검증 규칙으로 넣는다.
- 자체 호스팅 추론 서버(vLLM 등)를 외부에 내줄 때 OpenAI 호환 API를 그대로 열면 이 옵션들도 함께 열린다. 기본값을 확인하고 엔드포인트별 허용 목록을 둔다.
- 속도 제한을 토큰·요청 수뿐 아니라 ‘logit_bias가 붙은 요청 수’, ‘서로 다른 무작위 프롬프트 수’ 같은 기능별 지표로도 건다. API 키·조직 단위로 집계해 여러 키로 나누는 시빌 우회를 본다(신원 통제와 함께 설계).
- 로그 파이프라인에서 짧은 무작위 프롬프트 + 1토큰 생성 + logprob 요청이 대량 반복되는 패턴을 탐지 규칙으로 만든다. 다만 논문이 지적하듯 탐지는 우회될 수 있으므로 기능 축소가 1순위다.
- 은닉 차원·모델 크기 같은 정보가 영업 비밀이라면, 그것이 API 출력만으로 수백 달러에 새어 나갈 수 있음을 위협 모델과 레드팀 시나리오에 넣는다.
