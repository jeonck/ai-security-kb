## 요약
2026-10-27 하루에 오픈소스 MCP 서버와 에이전트 확장 9종의 CVE가 NVD와 GitHub Advisory Database에 한꺼번에 올라왔다. 출처는 모두 VulnCheck 권고다. 대상은 mcp-ffmpeg, hagent, Kali-GPT, esp-mcp, Codefriar sf-mcp, ai-sdlc 플러그인 MCP 서버, ATXP Gemini CLI 확장, DroidMind, nmap-mcp다. nmap-mcp(허용 목록 우회, 4.8)를 뺀 8건은 OS 명령 주입(CWE-78)이고 대부분 CVSS v4 8.5다. 원인은 같다. MCP 도구 인자를 셸 명령 문자열에 그대로 이어 붙인다. 그래서 프롬프트 인젝션에 조종된 에이전트가 도구를 부르기만 해도 MCP 서버 사용자 권한으로 명령이 실행된다. 수정이 확인된 것은 ai-sdlc 하나이고 나머지는 권고 기준으로 패치 버전이 'Unknown'이다.

## 동작 원리
MCP 도구의 인자는 사람이 아니라 LLM이 채운다. 그리고 LLM은 메일·SMS·이슈·웹 페이지에서 읽은 내용에 따라 인자를 바꿀 수 있다. MCP 서버는 그 인자로 실제 프로그램(ffmpeg, arduino-cli, nmap, sf CLI, adb)을 돌리는 얇은 포장지인 경우가 많다. 구현이 인자를 문자열로 이어 붙여 `exec`·`execSync`·`subprocess.run(shell=True)`에 넘기면, 인자 안의 `$()`나 백틱은 값이 아니라 명령으로 해석된다. 메일 본문에 쓴 한 줄이 도구 인자를 거쳐 서버 사용자 권한의 셸 명령으로 바뀌는 셈이다. 방어 장치를 둔 경우도 뚫렸다. DroidMind는 명령 이름만 검사하는 허용 목록이라 치환 문법으로 우회됐고, sf-mcp는 이스케이프 함수가 메타문자를 다 막지 못했다. 고치는 방법은 오래된 정답 그대로다. 셸을 거치지 않는 인자 배열 실행(execFile, shell=False)과 형식 검증이다. 권고들의 CVSS 벡터는 '로컬·낮은 권한'으로 매겨져 있지만, 실제 진입점은 에이전트가 읽는 외부 콘텐츠라서 점수가 위험을 과소 표현할 수 있다.

## 플랫폼 엔지니어 관점
- 개발자 PC·에이전트 런타임에 등록된 MCP 서버 목록에 이번 9종이 있는지 확인한다. 패치가 없는 서버는 비활성화하거나, 쓰기 권한·자격 증명이 없는 컨테이너 안에서 egress를 막고 돌린다.
- MCP 서버를 허용 목록에 넣기 전 검토 항목에 '셸 문자열 실행 금지'를 추가한다. CI에서 `shell=True`, `child_process.exec`, `execSync`, `create_subprocess_shell` 사용을 정적 분석(Semgrep 규칙 등)으로 잡는다.
- stdio MCP 서버는 사용자 PC나 에이전트 파드 권한을 그대로 물려받는다. 개발자 PC에서는 devcontainer·샌드박스 안에서만 돌리고, K8s에서는 서버마다 별도 ServiceAccount, 읽기 전용 루트 파일 시스템, 기본 거부 NetworkPolicy를 적용한다.
- 메일·SMS·이슈를 읽는 에이전트와 셸에 닿는 도구를 같은 세션에 두지 않는다. 보안 도구형 MCP 서버(Kali-GPT, nmap-mcp)는 스캔 대상 허용 목록과 사람 승인 단계 없이 연결하지 않는다.
- 도구 호출 로그에 해석된 인자를 남기고, `$(`, 백틱, `;`, `|` 같은 셸 메타문자가 든 인자를 탐지 규칙으로 걸러 낸다. 미검토 GHSA는 패키지 매핑이 없어 의존성 스캐너가 놓치므로 MCP 서버는 저장소 URL·커밋 단위로 인벤토리를 관리한다.
