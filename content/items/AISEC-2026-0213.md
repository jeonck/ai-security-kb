## 요약
AWS가 관리하는 오픈소스 에이전트 SDK Strands Agents의 파이썬판에서 기본 세션 저장 방식의 결함 두 건이 GitHub Advisory Database에 등재됐다. 기본 FileSessionManager는 대화 세션을 /tmp 아래 예측 가능한 경로에 저장했다. 같은 호스트의 다른 사용자는 세션 파일을 읽어 프롬프트·도구 입출력·비밀 값을 볼 수 있었다. 또 심볼릭 링크를 미리 만들어 두면 피해자의 세션 쓰기가 임의 파일을 덮어썼고, 세션 기록에 메시지를 심으면 복원 시 에이전트가 그 지시를 따랐다. 1.48.0에서 수정됐고 CVE는 없다.

## 동작 원리
/tmp는 모두가 같이 쓰는 공용 서랍이다. 경로가 고정돼 있으면 공격자가 서랍 칸에 먼저 '다른 파일로 가는 표지판'(심볼릭 링크)을 꽂아 둘 수 있다. 피해자 프로세스는 표지판을 따라가 공격자가 고른 파일(셸 설정, SSH authorized_keys, cron)에 쓰게 된다. 더 에이전트다운 위험은 세 번째다. 세션 기록은 다음 실행에서 '이전 대화'로 모델에 다시 들어간다. 그래서 거기에 끼워 넣은 문장은 외부 문서보다 더 믿을 만한 맥락으로 읽힌다. 무결성 검증이 없는 상태 저장소는 인젝션이 재시작 후에도 살아남는 지속 장치가 된다.

## 플랫폼 엔지니어 관점
- strands-agents를 1.48.0 이상으로 올린다. 당분간은 `storage_dir`를 0700 권한의 사용자 전용 경로로 명시하고 umask를 077로 둔다.
- 다중 사용자 GPU 서버·공유 CI 러너·JupyterHub에서 에이전트를 돌린다면 사용자별 컨테이너나 파드로 분리한다. 최소한 /tmp를 파드별 emptyDir로 격리한다.
- 쿠버네티스에서는 세션 저장소를 컨테이너 파일 시스템이 아닌 전용 볼륨·외부 저장소에 두고, 저장 시 암호화와 접근 주체를 정한다.
- 세션 복원 기능을 쓰는 에이전트는 저장된 기록을 '신뢰할 수 없는 입력'으로 취급하는 설계(HMAC 서명, 복원 시 출처 표시)를 요구 사항에 넣는다.
