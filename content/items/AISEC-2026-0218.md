## 요약
개인 비서형 에이전트 프레임워크 OpenClaw의 보안 문제를 사용자·개발자의 실제 보고로 분석한 실증 연구다. 연구진은 레딧 13개 커뮤니티 2.5만여 게시글과 GitHub 보안 이슈 358건에서 관련 자료를 추렸다. 여기서 나온 CWE 인스턴스 521건을 59개 약점 유형으로 분류했다. 접근 통제 실패가 35.3%로 가장 많았고, 민감 정보 노출과 주입까지 세 범주가 전체의 70.4%를 차지했다. 실무자들이 제안한 완화책 543건은 최소 권한과 실행 격리를 중심으로 한 7개 전략으로 모였다.

## 동작 원리
OpenClaw 같은 개인 비서 에이전트는 LLM 추론, 지속 메모리, 도구 사용, 로컬 실행, 웹 작업을 한 프로세스에 묶는다. 메일·웹 페이지 같은 신뢰할 수 없는 입력, 모델의 판단, 도구 권한, 메모리, 설정이 명확한 경계 없이 맞물리면 사고가 난다. 하나하나는 버그처럼 보이지만 실제로는 같은 설계 결함이 계속 다시 드러나는 것이다. 논문이 재구성한 사례는 단순하다. 디버깅을 부탁받은 에이전트가 설정 파일을 읽다가 그 안의 자격 증명을 답변에 그대로 실어 보여 준다. 공격자가 없어도 권한과 출력 경로가 넓으면 비밀이 샌다.

## 플랫폼 엔지니어 관점
- 사내에서 OpenClaw류 개인 비서 에이전트를 허용한다면 에이전트 실행 계정을 사람 계정과 분리하고, 작업 디렉터리 밖 파일·환경 변수 읽기를 막는 샌드박스를 기본값으로 둔다.
- 실무자 완화책 1·2위(최소 권한 27%, 실행 격리 17%)를 골든 패스 템플릿에 반영한다. 도구별 허용 목록, 컨테이너 실행, 비밀 값 비주입이 그 내용이다.
- 스킬·플러그인 신뢰(12%)가 별도 전략으로 꼽힌 만큼 스킬 설치를 사내 레지스트리·승인 절차로 제한한다.
- 에이전트 출력에 비밀 패턴이 나오는지 검사하는 출력 필터·로그 스캐너를 런타임 감시 항목에 추가한다.
