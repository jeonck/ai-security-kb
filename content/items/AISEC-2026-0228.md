## 요약
vLLM이 10월 들어 공개한 권고 가운데 두 건은 멀티모달 요청이 서버에서 코드를 실행시키는 경로였다. 첫째(CVE-2026-115915)는 이미지 로더가 MIME 표시를 믿지 않고 Pillow의 자동 판별에 맡긴 탓에, PNG로 위장한 EPS 파일이 호스트의 Ghostscript까지 흘러가 알려진 Ghostscript 취약점으로 명령을 실행할 수 있었다. 둘째는 trust_remote_code를 켠 서버에서 요청 파라미터 하나가 실행될 프로세서 코드의 리비전을 공격자가 고른 것으로 바꿨다. 각각 0.32.0과 0.31.0에서 고쳐졌다.

## 동작 원리
사진만 받는다는 접수 창구에 ‘사진’이라 적힌 봉투를 냈는데, 안쪽 직원이 내용물을 보고 PostScript 프로그램이면 그것을 해석기(Ghostscript)에 돌리는 셈이다. 해석기가 오래된 버전이면 그 프로그램이 서버 명령을 실행한다. vLLM은 Ghostscript를 직접 의존하지 않지만 컨테이너 베이스 이미지에 깔려 있으면 연쇄가 성립한다. code_revision 건은 ‘모델은 고정 버전, 코드도 고정 버전’이라 믿었지만 요청자가 코드 버전만 몰래 바꿀 수 있었던 문제다. Hugging Face 커뮤니티 PR 리비전처럼 공격자가 만들 수 있는 리비전이면 곧바로 원격 코드 실행이 된다.

## 플랫폼 엔지니어 관점
- 추론 서버 이미지에서 Ghostscript·ImageMagick 같은 문서 해석 바이너리를 제거하고(distroless·최소 이미지), SBOM으로 존재 여부를 확인한다. vLLM은 0.32.0 이상, Pillow는 12.3.0 이상으로 고정한다.
- trust_remote_code는 기본 꺼 두고, 켜야 하는 모델은 리비전을 고정하고 내부 미러에서만 가져오도록 egress를 막는다.
- /tokenize 등 /v1 밖의 엔드포인트가 인증 없이 열려 있지 않은지 게이트웨이(Ingress·API 게이트웨이)에서 경로 단위로 인증을 강제한다.
- 두 권고 모두 GitHub 권고 게시와 CVE 부여 사이에 시차가 있었다. CVE 기반 스캐너만 보지 말고 vLLM 저장소의 보안 권고를 직접 구독한다.
