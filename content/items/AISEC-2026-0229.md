## 요약
MLflow의 CrewAI 자동 로깅 기능이 에이전트에 연결된 LLM 제공자 API 키를 트레이스 스팬에 평문으로 남기는 문제가 CVE-2026-116691로 공개됐다. 자동 로깅이 CrewAI Agent 객체를 통째로 직렬화하면서, 그 안에 든 LLM 객체의 문자열 표현에 키가 섞여 들어갔다. MLflow 서버나 OpenTelemetry 수집처를 볼 수 있는 사람은 키를 꺼낼 수 있다. 3.17.0에서 수정됐지만 이미 쌓인 트레이스에는 키가 남아 있다.

## 동작 원리
관측성 도구는 ‘무슨 일이 있었는지 다 남긴다’가 목적이라, 객체를 통째로 덤프하는 쉬운 길을 택하기 쉽다. MLflow는 LLM 속성만 뽑는 경로에서는 api_key를 걸러 냈지만, 에이전트 객체 전체를 펼치는 다른 경로가 그 필터를 거치지 않았다. 금고 문은 잠갔는데 금고를 통째로 찍은 사진을 사내 게시판에 올린 셈이다.

## 플랫폼 엔지니어 관점
- MLflow를 3.17.0 이상으로 올리고, CrewAI 자동 로깅을 쓴 기간의 LLM 키를 교체한다. MLflow 백엔드 DB·아티팩트 저장소와 OTLP 수집처(Tempo, Jaeger, 상용 APM)에서 해당 스팬을 찾아 삭제·가린다.
- 에이전트 트레이스 수집 파이프라인(OpenTelemetry Collector)에 비밀 패턴 마스킹 프로세서를 둔다. 프레임워크 쪽 필터만 믿지 않는다.
- 트레이스 백엔드 접근 권한을 운영 로그 수준이 아니라 비밀 저장소에 준해 관리하고, 에이전트에는 장기 키 대신 짧은 수명 토큰이나 게이트웨이 경유 호출을 쓴다.
