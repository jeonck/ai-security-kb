## 요약
Google DeepMind의 Elie Bursztein이 [un]prompted II에서 AI 에이전트용 하드웨어 격리 샌드박스 Capsem을 오픈소스로 공개했다. 에이전트마다 강화된 경량 Linux VM을 띄우고, 바깥으로 나가는 모든 트래픽을 하나의 저권한 프록시로 모아 HTTP·DNS뿐 아니라 모델 호출과 MCP 통신의 의미까지 해석해 정책을 건다. 실제 API 키는 VM 밖 브로커가 들고 있다가 요청에 대신 넣어 주므로 에이전트가 비밀을 직접 손에 쥐지 않는다. 독립 보안 평가는 아직 없다.

## 동작 원리
컨테이너가 같은 커널을 나눠 쓰는 칸막이라면, Capsem은 에이전트마다 작은 별채(VM)를 지어 준다. 별채에서 밖으로 나가는 문은 하나뿐이고, 그 문의 경비원은 ‘어디로 가는 패킷인가’가 아니라 ‘어떤 모델을 부르고 어떤 MCP 도구를 쓰려는가’를 보고 허용·질의·거부·재작성을 결정한다. 비밀은 경비원이 보관하다 나가는 요청에만 붙여 주므로, 인젝션당한 에이전트가 환경 변수나 설정 파일을 뒤져도 훔칠 키가 없다.

## 플랫폼 엔지니어 관점
- 개발자 PC나 CI 러너에서 코딩 에이전트를 돌릴 때 ‘VM 격리 + 단일 egress 프록시 + 자격 증명 브로커’ 세 요소를 기준선으로 삼는다. Kubernetes에서는 Kata Containers·gVisor 같은 런타임 클래스와 egress 게이트웨이, 워크로드 신원 기반 토큰 주입으로 같은 구조를 만들 수 있다.
- egress 정책을 IP·도메인 수준에서 끝내지 말고 MCP 도구 이름·모델 제공자 수준까지 내려 쓰는 것을 검토한다(AI 게이트웨이 정책과 연계).
- Sigma·OpenTelemetry로 에이전트 행동 이벤트(SKILL.md 로드, 민감 파일 접근)를 SIEM에 보내 탐지 규칙을 공유한다.
- 도입 전에는 자체 레드팀으로 VM 탈출·프록시 우회를 시험한다. 성능·보안 수치는 아직 프로젝트 자체 보고뿐이다.
