## 요약
GitHub가 2026-10-27 Copilot SDK에 서버 간(server-to-server) 인증을 공개 프리뷰로 추가했다. 조직에 설치한 GitHub App이 1시간짜리 설치 토큰을 발급받아 SDK에 넘기면, 서비스나 에이전트가 특정 사용자의 로그인 없이 조직 명의로 Copilot을 호출할 수 있다. 앱에 필요한 권한은 ‘Copilot Requests’ 읽기 전용 하나이고, 사용량은 앱의 client id로 구분돼 조직에 청구된다. 조직 소유자는 어떤 앱이 접근하는지 보고, 앱을 중지·제거해 접근을 끊을 수 있다.

## 동작 원리
지금까지 Copilot을 쓰는 사내 봇·에이전트는 대개 누군가의 개인 토큰을 빌려 돌았다. 그러면 그 사람이 퇴사하거나 토큰이 새면 봇이 멈추거나, 반대로 그 사람의 넓은 권한이 봇에 따라붙는다. 이번 방식은 ‘사람 출입증 빌려 쓰기’를 ‘업무용 임시 출입증 발급’으로 바꾼다. 출입증(설치 토큰)은 한 시간이면 만료되고, 할 수 있는 일은 Copilot 요청 하나로 좁혀져 있으며, 누가 썼는지는 app_client_id로 장부에 남는다.

## 플랫폼 엔지니어 관점
- 개인 PAT로 Copilot SDK를 호출하는 사내 서비스·에이전트를 목록화하고 GitHub App 설치 토큰 방식으로 옮긴다. 앱 개인키는 시크릿 관리자에 두고, 토큰 발급은 짧은 주기로 자동화한다.
- SDK 설정에서 useLoggedInUser=false를 강제해, 런타임이 개발자 PC나 러너의 저장된 사용자 토큰으로 몰래 되돌아가지 않게 한다.
- AI 사용량 CSV의 app_client_id로 앱별 사용량 기준선을 만들고 급증을 경보한다. 조직 예산·모델 정책이 앱에도 적용되는지 확인한다.
- 앱 하나를 여러 서비스가 공유하지 않게 한다. 서비스마다 앱을 나눠야 사용량 추적과 회수(중지·제거)가 서비스 단위로 된다.
- GitHub Actions에서는 GITHUB_TOKEN + copilot-requests 권한을 쓰되, 그 워크플로가 신뢰할 수 없는 PR 입력을 읽는지 함께 점검한다.
