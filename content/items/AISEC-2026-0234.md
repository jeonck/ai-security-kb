## 요약
MLflow의 GenAI 평가 기능에서 서드파티 채점기를 불러오는 경로가 무인증 원격 코드 실행으로 이어지는 취약점(CVE-2026-116692, CVSS 9.8)이 GitHub Advisory Database에 등재됐다. 허용 목록이 ragas·deepeval 같은 패키지 이름의 하위 경로면 무엇이든 받아 줘서, 공격자가 실험 아티팩트로 올린 파이썬 파일을 서버가 import하고 실행한다. 같은 날 등재된 CVE-2026-116690은 프롬프트 모델 버전의 source 값 검증 누락으로 서버 파일을 무인증으로 읽게 한다. 두 문제 모두 3.17.0에서 고쳐졌고, 이 릴리스에는 보안 수정이 13건 이상 묶여 있다.

## 동작 원리
허용 목록이 ‘ragas로 시작하는 이름이면 믿는다’는 식이었다. 그런데 MLflow는 실험의 아티팩트 위치를 사용자가 정하게 하므로, 그 위치를 허용 패키지 디렉터리 안으로 잡으면 공격자가 올린 파일도 ‘ragas 아래 모듈’이 된다. 신분증의 성(姓)만 보고 출입시키는 경비원 앞에서, 그 집안 이름으로 명찰을 직접 찍어 들어가는 셈이다. 서버는 그 모듈을 import하면서 생성자를 실행하고, 공식 이미지는 root로 돌았기 때문에 영향이 크다.

## 플랫폼 엔지니어 관점
- MLflow 트래킹 서버를 3.17.0 이상으로 올린다. 사내 모델 레지스트리·평가 서버가 인증 없이 클러스터 내부나 VPN에 열려 있는지 먼저 확인하고, 인그레스 앞에 SSO 프록시를 둔다.
- Kubernetes에서는 MLflow 컨테이너를 non-root, readOnlyRootFilesystem으로 돌리고 아티팩트 저장소는 별도 볼륨·오브젝트 스토리지로 분리한다. 이번 공격 사슬은 패키지 디렉터리에 쓸 수 있어야 성립한다.
- MLflow 서버 파드의 서비스 계정·클라우드 자격 증명(모델 버킷, 학습 데이터 접근)을 최소화하고, 서버에서 나가는 egress를 아티팩트 저장소로만 묶는다.
- 서드파티 모듈을 이름으로 동적 import하는 자체 플랫폼 코드가 있으면 ‘접두어 매칭’ 대신 정확한 모듈 경로 목록과 설치 위치(site-packages) 검증을 쓴다.
