## 요약
Anthropic Frontier Red Team은 아직 출시하지 않은 내부 연구 모델로 Chrome, Safari, Android, Windows, Linux에서 취약점을 찾고 동작하는 공격 체인까지 만들었다고 2026-10-27에 공개했다. Chrome에서는 페이지 하나를 여는 것만으로 샌드박스 밖 코드 실행에 이르렀고, 이 과정에서 CVE 62건이 나왔다. Linux에서는 multipath TCP 리스너가 있는 서버에 로그인 없이 원격 루트를 얻었다. 모든 취약점은 벤더에 먼저 알려 패치된 뒤 공개됐고, 실제 악용은 확인되지 않았다. 다만 Anthropic이 연결한 Linux·Windows CVE의 공개 레코드는 글의 설명과 구성 요소 표기가 달라 추가 확인이 필요하다.

## 동작 원리
예전에는 버그를 찾는 팀, 그것을 메모리 읽기·쓰기 능력으로 키우는 팀, 샌드박스를 넘는 팀이 따로 필요했다. 여기서는 사람이 첫 지시만 주고, 모델이 버그 찾기부터 단계별 익스플로잇 작성까지 이어 갔다. Chrome은 엔진 메모리 손상 → 엔진 샌드박스 탈출 → 메모리 배치 유출 → 브라우저 샌드박스 탈출의 4단 사다리였다. Linux는 버그 하나를 두 번 썼다. 한 번은 커널 주소를 새게 해 무작위 배치(KASLR)를 풀고, 다시 한 번은 실행 흐름을 빼앗았다. 실패해도 시스템이 죽지 않아 계속 재시도할 수 있었다. ‘한 번 실패하면 끝’이라는 공격 비용 가정이 무너진 셈이다.

## 플랫폼 엔지니어 관점
- 패치 창을 다시 잡는다. 커널·브라우저·HTTP/3 스택 패치는 ‘다음 정기 점검’이 아니라 노드 이미지 재빌드와 롤링 교체로 며칠 안에 끝내도록 파이프라인을 만든다. Kubernetes 노드 OS와 베이스 이미지의 커널 버전을 SBOM으로 추적하고, Chrome 156 이상·CVE-2026-98432 백포트 커널·CVE-2026-33096 패치를 확인한다.
- 노출면을 줄인다. 쓰지 않는 multipath TCP(`net.mptcp.enabled=0`)·QUIC·HTTP/3 리스너는 끄고, 노드의 sysctl·모듈 로딩을 정책으로 고정한다.
- 에이전트용 헤드리스 브라우저·미리보기 런타임은 브라우저 샌드박스만 믿지 않는다. 별도 VM·gVisor 같은 바깥 격리를 두고, 자격 증명을 그 안에 두지 않으며 egress를 허용 목록으로 묶는다.
- 방어 쪽에도 같은 능력을 쓴다. PR 시점 보안 스캔과 확인된 취약점의 변형 분석을 CI 단계로 넣고, 스캐너 여러 개를 고유 발견 수로 비교한다. 경쟁 조건 공격은 반복 시도로 나타나므로 handshake 실패 급증 같은 신호를 탐지 규칙에 넣는다.
