## 요약
보안 기업 Causal Security의 자율 연구 시스템 Cipher가 입자가속기·방사광·핵융합 실험 제어에 쓰이는 오픈소스 프레임워크 EPICS Base에서 메모리 안전 취약점 4개를 찾았다. CISA는 2026-10-27 권고 ICSA-26-300-01로 7.0.10 이하가 영향받는다고 알렸고 7.0.11에서 고쳐졌다. 회사는 처음 보는 코드에서 3시간 49분 만에 찾았고 사람은 심화 검증 승인만 했다고 밝혔다. 원격 코드 실행은 시연되지 않았고 실제 악용 보고도 없다.

## 동작 원리
네 결함은 모두 네트워크로 들어온 메시지 안의 숫자(개수·길이·형식)를 믿고 메모리를 잡거나 읽은 데서 생겼다. 길이 계산이 넘쳐 작은 버퍼를 잡고 큰 데이터를 쓰는 식이다. Cipher는 ‘선 너머에서 들어온 숫자가 어디서 할당 크기나 배열 위치로 쓰이는가’를 끝까지 따라가 의심 지점을 찾았다. 그다음 샌드박스에서 직접 빌드해 충돌을 재현했다. 사람 연구자의 감사 방식과 같지만 몇 시간 만에 끝났다는 점이 다르다.

## 플랫폼 엔지니어 관점
- 사내에 EPICS나 비슷한 장비 제어 프로토콜을 쓰는 연구·OT 환경이 있으면 TCP 5064·5075를 제어망 안에서만 열고 외부 노출을 스캔한다.
- 오래된 C 기반 네트워크 데몬을 클러스터 안에서 운영한다면 ‘수십 년 묵은 파서 결함’이 짧은 주기로 발견될 것을 전제로 패치 창구와 재배포 경로를 준비한다.
- 우리 코드에도 같은 도구를 먼저 돌린다. 프로토콜 파서·역직렬화 코드에 퍼징과 AI 기반 감사를 CI 단계로 넣고, ASan 빌드를 보안 테스트 이미지로 유지한다.
