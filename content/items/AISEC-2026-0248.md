## 요약
Tabularis는 AI 클라이언트가 붙어 쓰도록 MCP 서버를 내장한 오픈소스 데스크톱 SQL 도구다. SQLite 드라이버가 스키마를 조회할 때 테이블 이름을 문자열로 이어 붙여 PRAGMA 문을 만들었고, 실행 함수가 문자열 속 문장을 모두 돌렸기 때문에 describe_table 호출 하나로 임의 SQL이 실행됐다. 문제는 이 제품의 안전장치인 읽기 전용 모드와 쓰기 승인이 run_query 도구에만 걸려 있었다는 점이다. 그래서 이름만 보면 무해한 ‘테이블 설명’ 도구가 승인 창도 없이 데이터를 읽고 고치고 지우는 통로가 됐다. 저장소 권고는 10월 13일에, CVE-2026-118378은 10월 27~28일에 공개됐고 0.28.0에서 수정됐다.

## 동작 원리
은행 창구에 ‘출금은 반드시 확인 도장’을 받는 규칙이 있는데, ‘잔액 조회’ 창구에서 내민 쪽지에 출금 지시를 덧붙여도 그대로 처리되는 상황과 같다. 에이전트가 읽은 문서나 이슈에 숨은 지시가 있으면 모델은 describe_table의 table_name 인자에 따옴표를 닫고 DROP TABLE을 덧붙인 값을 채울 수 있다. 서버는 그 값을 PRAGMA table_info(…) 안에 끼워 넣고, 따옴표가 닫힌 뒤 붙은 문장까지 실행한다. 승인 로직은 SQL을 분류하는 run_query에만 있었으므로 이 경로는 아무 검사도 받지 않는다. LLM이 채우는 도구 인자가 셸이나 쿼리 문자열로 들어가는 MCP 서버 결함(AISEC-2026-0212)과 같은 구조이며, 여기서는 ‘사람 승인’이라는 통제까지 비켜 간다는 점이 다르다.

## 플랫폼 엔지니어 관점
- 개발자 PC나 원격 개발 환경에 Tabularis를 MCP 서버로 붙였다면 0.28.0 이상으로 올리고, MCP 클라이언트 설정에 등록된 DB MCP 서버 목록을 점검한다.
- 읽기 전용은 앱 안의 SQL 분류기로 믿지 말고, 에이전트용 연결에 쓰는 DB 계정 자체를 읽기 전용 권한으로 만든다. SQLite 파일이라면 읽기 전용 마운트나 복사본을 쓴다.
- MCP 서버를 승인·도입할 때 ‘승인/읽기 전용이 어느 도구에 적용되는가’를 체크리스트에 넣는다. 조회·목록 도구도 데이터 계층에 닿으면 같은 통제를 받아야 한다.
- 에이전트 게이트웨이에서 describe_table 같은 메타데이터 도구의 인자에 따옴표·세미콜론·주석 기호가 들어가면 차단하거나 경고하는 규칙을 둔다.
