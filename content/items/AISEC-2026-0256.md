## 요약
Pillar Security는 파인튜닝 도구 Unsloth의 모델 로더에서 원격 코드 실행 취약점(CVE-2026-93348, CVSS v4.0 8.6)을 공개했다. 로더가 모델 설정 파일의 model_type 값을 그대로 파이썬 import 문자열에 끼워 exec()로 실행했기 때문에, 공격자가 조작한 설정을 가진 모델을 불러오기만 해도 임의 코드가 실행됐다. Hugging Face의 trust_remote_code=False 설정과 무관한 경로라 ‘원격 코드 끄기’로는 막히지 않는다. 수정은 보고 6시간 만에 들어갔지만 메인테이너가 응답하지 않아 CVE는 한 달 넘게 뒤에야 VulnCheck를 통해 부여됐고, 그 사이 취약 버전은 8만 4천여 회 내려받아졌다.

## 동작 원리
모델 설정의 model_type은 원래 ‘llama’ 같은 짧은 이름이어야 한다. Unsloth는 이 이름으로 ‘transformers.models.llama.modeling_llama를 import하라’는 문장을 만들어 exec()에 넘겼다. 그런데 중첩 설정에 들어 있는 model_type에 줄바꿈과 파이썬 문장을 섞으면, exec()는 import 한 줄이 아니라 여러 줄의 프로그램을 그대로 실행한다. 비유하자면 ‘주문서의 메뉴 이름 칸’에 적힌 글자를 주방장이 그대로 소리 내 읽어 지시로 받아들이는 셈이다. 실행 시점은 가중치·토크나이저를 읽기 전이고, 로딩은 정상적으로 끝나 흔적이 잘 드러나지 않는다.

## 플랫폼 엔지니어 관점
- 노트북 커널, 학습 워커, 컨테이너 이미지, Databricks 같은 관리형 런타임에서 unsloth와 unsloth-zoo 두 패키지의 버전을 함께 확인한다. unsloth-zoo 2026.8.14 이상(또는 unsloth 2026.8.20 이상)인지 보고, 잠금 파일·이미지를 다시 빌드하고 오래 돈 프로세스를 재시작한다.
- trust_remote_code=False나 safetensors 사용만으로 ‘외부 모델 로딩이 안전하다’고 보지 않는다. 외부 허브의 모델은 승인된 내부 레지스트리로 미러링하고, 해시·커밋을 고정한 것만 학습 파이프라인이 읽게 한다.
- 모델을 처음 불러오는 작업(평가·변환·파인튜닝)은 Hugging Face 토큰·클라우드 자격 증명이 없는 격리된 잡으로 분리하고, egress를 허용 목록으로 묶는다. 로딩 프로세스 권한이 곧 피해 범위다.
- 패치 후 CVE가 늦게 붙는 경우가 있으므로, CVE 피드만이 아니라 상류 커밋·릴리스 노트와 연구자 블로그를 함께 구독한다.
