## 요약
GitHub는 2026-10-28 Universe 첫날 GitHub Agentic Workflows를 정식 출시했다. 사용자는 자동화를 마크다운으로 쓰고, 이것이 일반 Actions YAML로 컴파일돼 Copilot CLI나 다른 코딩 에이전트로 실행된다. 보안 설계의 핵심은 에이전트 자체에는 쓰기 권한을 주지 않는다는 점이다. 에이전트가 만든 변경은 산출물로 쌓였다가 결정적 필터와 별도의 AI 위협 탐지 잡을 거친 뒤, 좁은 권한을 가진 다른 잡이 반영한다. 네트워크는 Squid 프록시 기반 도메인 허용 목록으로 묶이고, 정식 출시와 함께 마이크로 VM 격리와 저장소 간 유출을 막는 엔클레이브, ARC 기반 자체 호스팅 러너 지원이 추가됐다.

## 동작 원리
은행 창구에 비유하면, 에이전트는 서류를 작성만 하는 직원이고 금고 열쇠는 없다. 작성된 서류(PR·이슈·코멘트 요청)는 바구니에 담기고, 규칙 기반 검사와 별도 감사관(탐지 잡)이 확인한 뒤에야 열쇠를 가진 다른 직원(쓰기 권한 잡)이 처리한다. 이슈 댓글 같은 신뢰할 수 없는 입력으로 에이전트가 인젝션을 당하더라도, 에이전트가 직접 할 수 있는 일은 읽기와 허용된 도메인으로의 통신뿐이다. 무결성 필터는 아예 신뢰도 낮은 작성자의 콘텐츠를 에이전트 입력에서 빼는 앞단 장치다. 다만 문서 스스로 허용 도메인 안의 악용, 게이트웨이 ID 유출, 사용자 정의 단계의 다른 자격 증명은 남는 위험으로 인정한다.

## 플랫폼 엔지니어 관점
- CI에 코딩 에이전트를 붙일 때 ‘에이전트 잡 = 읽기 전용 토큰, 쓰기 = 별도 잡’ 구조를 기준선으로 삼는다. 직접 만든 에이전트 워크플로가 contents: write 토큰을 에이전트 프로세스에 그대로 넘기고 있지 않은지 점검한다.
- network.allowed는 생태계 묶음(defaults·python·node) 대신 필요한 도메인만 적고, 허용된 도메인(예: 이슈 생성 가능한 API)이 곧 유출 경로가 될 수 있음을 전제로 safe output 개수 제한을 둔다.
- 위협 탐지 잡을 경고 모드가 아닌 엄격 모드로 운영할지, 탐지기 실패 시 반영을 막을지 정책으로 정하고, 판정 로그를 SIEM으로 보내 인젝션 시도 신호로 추적한다.
- 공개 저장소에서는 min-integrity를 approved 이상으로 유지하고, 사용자 정의 steps에 들어가는 클라우드 자격 증명은 에이전트 컨테이너와 분리됐는지 확인한다. ARC Docker-in-Docker 러너를 쓰면 에이전트 전용 노드 풀을 두고 노드의 클라우드 메타데이터 접근을 막는다.
