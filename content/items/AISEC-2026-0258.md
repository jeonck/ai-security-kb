## 요약
2026-10-28 GitHub Advisory Database에 WordPress의 AI 관련 플러그인 취약점 6건이 함께 등재됐다. Royal MCP는 MCP로 노출한 검색·복제 도구에서 객체 단위 권한 확인을 빠뜨려 낮은 권한 사용자가 비공개 글과 개인정보를 볼 수 있었다. WoowBot은 RAG 동기화에 인가가 없어 구독자가 관리자의 AI API 키로 유료 임베딩 호출을 반복시킬 수 있었고, MxChat·AI Marketing Expert는 챗봇 입력이 관리자 화면에서 실행되는 무인증 저장형 XSS, Bit Flows는 웹훅을 통한 파일 포함이었다. 개별 심각도는 낮음~높음이지만, CMS에 AI 기능을 덧붙이면서 기존 웹 보안 기본기가 반복해 빠지는 양상을 보여 준다.

## 동작 원리
MCP 도구는 ‘누가 시켰는가’와 상관없이 플러그인 자신의 권한으로 데이터를 읽는 대리인이 되기 쉽다. 도구가 ‘이 사용자가 이 글을 볼 수 있는가’를 묻지 않고 ‘이 사용자가 로그인했는가’만 확인하면, 에이전트나 사용자는 도구를 통해 본래 볼 수 없는 데이터를 얻는다(혼동된 대리인). 챗봇 XSS 두 건은 방문자가 남긴 대화·피드백이 관리자 화면에 그대로 그려지는 구조로, AI 대화 기록이 새로운 신뢰할 수 없는 입력 저장소가 된 경우다. WoowBot 건은 권한 검사 누락이 데이터 유출이 아니라 비용 유출(API 크레딧 소진)로 이어진다는 점이 AI 기능 특유다.

## 플랫폼 엔지니어 관점
- WordPress 등 CMS를 운영하는 팀은 AI 챗봇·MCP 플러그인 목록을 뽑아 버전을 확인하고, 수정 버전이 확인될 때까지 MCP 엔드포인트 노출을 관리자 네트워크로 제한한다.
- 자체 MCP 서버를 만들 때는 도구마다 호출자 신원으로 객체 단위 인가를 하도록 리뷰 체크리스트에 넣는다. ‘로그인 여부’나 플러그인 전역 권한으로 대신하지 않는다.
- AI 제공자 API 키는 플러그인별로 분리하고 지출 한도·알림을 건다. 키 하나가 사이트 전체 기능에 공유되면 인가 누락이 곧 청구서가 된다.
- 웹훅 트리거 기반 에이전트 흐름은 기본값(비밀·IP 제한 없음)으로 두지 않는다.
