## 요약
GitHub가 2026-10-28 Copilot 커넥터를 공개 프리뷰로 냈다. Slack·Sentry·Grafana Cloud·Atlassian Rovo 등 외부 서비스를 GitHub가 검증한 원격 MCP 서버로 붙이는 방식이며, 사용자가 한 번 로그인·승인하면 Copilot의 모든 표면에서 도구가 쓰이고 예약 실행까지 된다. GitHub는 설정과 인증을 대신 맡는다고 하지만 검증 기준과 토큰 보관 방식은 공개하지 않았다. 조직의 MCP 통제와 맞물리는 지점이 눈에 띄는데, ‘레지스트리 서버만 허용’ 정책을 강제하는 클라이언트에서는 이 정책을 ‘모두 허용’으로 풀어야 커넥터가 동작한다.

## 동작 원리
지금까지 MCP 서버는 개발자가 각 도구(IDE·CLI)마다 따로 설정하고 자격 증명을 넣었다. 커넥터는 이 연결을 GitHub 계정 수준으로 끌어올려, 한 번의 승인이 여러 클라이언트와 예약 작업에 퍼지는 ‘위임 토큰의 중앙화’다. 편의성은 커지지만, 승인 한 번이 미치는 범위도 함께 커진다. Copilot은 요청과 관련 있으면 연결 도구를 스스로 쓰는 구조이므로, 간접 인젝션이 들어오면 Slack·Sentry 같은 커넥터가 유출 경로가 될 수 있다.

## 플랫폼 엔지니어 관점
- 레지스트리 전용 정책을 Allow all로 풀지 말고, allowedMcpServers에 필요한 커넥터 URL만 명시하는 방식으로 허용 범위를 좁힌다. deniedMcpServers로 쓰지 않을 커넥터를 막는다.
- 커넥터로 연결되는 서비스(Slack·Atlassian 등) 쪽 MCP 허용 설정과 범위를 함께 관리하고, 예약 실행에 쓰이는 커넥터는 쓰기 도구를 빼거나 승인 단계를 둔다.
- 검증 기준이 공개되기 전까지 ‘GitHub 검증’을 공급망 출처 증명으로 간주하지 않고, 사내 MCP 서버 승인 절차(소유자·데이터 분류·로그)에 커넥터도 포함한다.
