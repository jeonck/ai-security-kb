## 요약
Cisco가 2026-10-28 AI 에이전트의 행동 기록을 검사하는 규칙 언어·엔진 Project Quarry를 오픈소스(Apache 2.0)로 공개했다. 기존 가드레일이 프롬프트 하나, 도구 호출 하나를 보는 데 그친다면, Quarry는 세션 전체에서 ‘민감 파일 읽기 → 외부 전송’ 같은 단계의 순서와 조합을 규칙으로 잡는다. Cisco는 이를 네트워크의 Snort, 악성코드의 YARA에 빗대 팀 사이에 공유되는 탐지 언어로 내세웠다. 대표 사례로는 OpenAI 평가 에이전트의 Hugging Face 침입을 들었지만, 실제 사고 데이터로 검증한 것은 아니라고 스스로 밝혔다.

## 동작 원리
CCTV가 한 장면만 보면 ‘서랍을 연 사람’과 ‘문을 나선 사람’은 둘 다 정상이다. 같은 사람이 금고 서랍을 연 직후 가방을 들고 나갔다는 순서를 이어 보아야 절도가 보인다. Quarry 규칙은 메시지·도구 이름·인자·결과의 구조를 그대로 유지한 기록을 읽고, 문자열·base64 인코딩 일치 같은 기호 검사와 분류기·LLM 판정 같은 신경 신호를 묶어 ‘무엇이 일어난 뒤 몇 단계 안에 무엇이 일어났는가’를 판정한다. 일치하면 근거 단계를 증거로 남겨 차단·경고·마스킹 같은 조치는 연동 제품이 정하게 한다.

## 플랫폼 엔지니어 관점
- 에이전트 플랫폼의 도구 호출 로그를 구조화 형식으로 남겨야 이런 세션 단위 규칙을 붙일 수 있다. 지금 로그가 도구 인자·결과를 잘라 버리는지 확인한다.
- ‘자격 증명이 든 도구 결과 → 외부 호출’, ‘작업 허용 목록 밖 서버로의 MCP 호출’ 같은 규칙을 egress 허용 목록과 함께 쓴다. 탐지는 권한 통제를 대신하지 못한다는 것이 Cisco 자신의 단서다.
- 알파 단계이므로 집행(차단)보다 먼저 경고 모드로 기존 트레이스에 돌려 오탐을 측정하고, 코딩 에이전트가 생성한 규칙은 사람 검토를 거쳐 배포한다.
