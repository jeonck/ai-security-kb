## 요약
GitHub는 Universe 첫날인 2026-10-28 Copilot 코드 리뷰의 ‘승인’ 기능을 정식 출시했다. 관리자가 켜면 Copilot이 사람 리뷰어처럼 PR을 승인하고, 그 승인이 저장소의 필수 승인 수를 채운다. 기본은 꺼져 있고 엔터프라이즈 정책 기본값도 금지이며, 저장소 단위에서는 파일 경로로 승인 범위를 좁힐 수 있다. 같은 날 실패한 워크플로와 병합 충돌을 Copilot이 클라우드에서 고쳐 주는 Agent Merge가 PR 화면에 통합돼, 자동 병합과 묶으면 ‘에이전트가 고치고 AI가 승인하고 시스템이 병합하는’ 흐름이 가능해졌다.

## 동작 원리
필수 리뷰 규칙은 ‘작성자가 아닌 누군가가 한 번 더 봤다’는 직무 분리 통제다. Copilot 승인을 병합 요건에 넣으면 그 ‘누군가’ 자리를 모델이 채운다. 모델 리뷰는 PR 본문·코드·주석 같은 작성자가 통제하는 텍스트를 읽고 판단하므로, 리뷰어를 겨냥한 인젝션이 성공하면 승인 자체가 공격 대상이 된다. 여기에 Agent Merge가 테스트 실패와 충돌을 자동으로 고치고 자동 병합이 켜져 있으면, 사람이 개입하는 지점은 처음 설정을 켠 순간뿐일 수 있다. GitHub는 기본 꺼짐, 새 커밋 시 승인 취소, 경로 제한, 단계별 정책으로 이 경로를 좁혀 두었다.

## 플랫폼 엔지니어 관점
- 엔터프라이즈 AI 정책에서 ‘Copilot의 PR 승인 허용’을 기본 금지로 유지하고, 허용할 조직·저장소를 명시적으로 고른다. 규제 대상(SOX·인증 대상) 저장소는 금지 목록에 둔다.
- 허용하더라도 저장소 단위 파일 경로 glob을 문서·테스트·설정 템플릿처럼 위험이 낮은 경로로 한정하고, 인증·권한·CI 워크플로(.github/workflows)·인프라 코드 경로는 사람 승인과 CODEOWNERS를 필수로 둔다.
- 브랜치 규칙에서 ‘마지막 푸시 이후 승인 요구’를 켜고, Agent Merge가 푸시한 수정 커밋 뒤에도 사람 승인이 다시 필요하도록 구성됐는지 시험한다.
- 자동 병합과 Agent Merge를 함께 쓰는 저장소는 감사 로그에서 승인 주체(Copilot 대 사람)를 구분해 수집하고, AI 승인만으로 병합된 PR을 주기적으로 표본 검토한다.
- 리뷰 대상 PR 설명·코드 주석에 리뷰어를 겨냥한 지시문이 있는지 탐지하는 규칙(예: 코드 스캐닝 사용자 정의 쿼리)을 둔다.
