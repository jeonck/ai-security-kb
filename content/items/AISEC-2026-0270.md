## 요약
워크플로 자동화·AI 에이전트 플랫폼 n8n의 보안 권고 여러 건이 2026-10-28 NVD와 GitHub Advisory Database에 CVE로 일괄 등재됐다. 가장 에이전트다운 것은 Chat Hub 권한 우회(CVE-2026-118640)다. 채팅만 하도록 만든 global:chatUser 역할이 샌드박스 코드 실행, 파일 읽기·쓰기, 인스턴스의 워크플로·데이터 테이블·에이전트를 호출하는 도구를 채팅에 붙여 실행할 수 있었다. 공유 워크플로 편집자가 실행 시점에 URL·로컬 파일에서 불러오는 하위 워크플로(CVE-2026-118675)나 자기 소유 오류 워크플로(CVE-2026-118644)를 이용해 프로젝트·동료의 자격 증명을 복호화해 받는 결함도 함께 공개됐다. 수정 버전은 1.123.85, 2.43.5, 2.44.1(오류 워크플로 건은 2.41.5, 2.42.2)이다.

## 동작 원리
세 결함 모두 ‘검사하는 자리와 실행하는 자리가 다르다’는 같은 모양이다. Chat Hub는 위험 도구 몇 개만 금지 목록에 넣어, 목록 밖의 강력한 도구는 채팅 사용자도 붙일 수 있었다. 채팅창이 곧 도구 실행 콘솔이 된 것이다. 하위 워크플로 건은 저장할 때만 ‘이 편집자가 이 자격 증명을 쓸 수 있나’를 확인하고, 실행할 때 외부에서 끌어오는 내용은 보지 않았다. 출입문에서 짐을 검사했는데 짐이 나중에 창문으로 들어온 셈이다. 오류 워크플로 건은 실패한 실행의 신원까지 통째로 넘겨, 오류 처리기를 쥔 사람이 남의 신원으로 자격 증명을 풀었다.

## 플랫폼 엔지니어 관점
- 사내 n8n(셀프 호스팅)을 즉시 수정 버전으로 올리고, 업그레이드 전에는 global:chatUser를 신뢰된 사용자에게만 주거나 Chat Hub를 끈다. NODES_EXCLUDE로 코드 실행·파일 노드를 빼는 것을 기본 프로파일로 검토한다.
- 공유 워크플로에서 Execute Sub-workflow의 source가 url·localFile인 노드를 전수 조사하고, 오류 워크플로 연결 권한을 프로젝트 관리자로 제한한다.
- n8n 프로세스의 egress를 허용 목록으로 묶어, 공격자 서버에서 하위 워크플로를 받아오거나 복호화한 자격 증명을 내보내는 길을 막는다(권고도 네트워크 통제를 보완책으로 언급).
- 에이전트 플랫폼 전반에 적용할 교훈: 역할 검사는 ‘도구를 붙이는 순간’과 ‘도구를 실행하는 순간’ 모두에서 허용 목록 방식으로 집행하고, 금지 목록 방식의 도구 제한은 새 도구가 추가될 때마다 뚫린다고 가정한다.
