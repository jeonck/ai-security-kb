## 요약
LangGraph의 서버 패키지 langgraph-api에서, JavaScript·TypeScript로 작성한 사용자 정의 인증 핸들러가 Store(에이전트 장기 기억 저장소) 접근을 ‘요청 네임스페이스를 자기 것으로 바꿔 쓰는’ 방식으로 제한할 때 그 변경이 실제 Store 작업에 반영되지 않는 결함이 공개됐다(CVE-2026-118668, CVSS v4 8.6). 결과적으로 로그인한 일반 사용자가 다른 사용자의 기억 항목을 읽고, 덮어쓰고, 검색하고, 지울 수 있었다. 0.15.0에서 수정됐다. 같은 날 GitHub Advisory Database에는 LangGraph SDK 스트리밍 클라이언트의 경로 미인코딩(CVE-2026-118667)과 langgraph-cli가 배포 시 레지스트리 푸시 토큰을 상세 로그에 찍던 문제(CVE-2026-115885)도 함께 올라왔다.

## 동작 원리
LangGraph 서버는 Python으로 돌지만 인증 핸들러는 JS/TS로도 쓸 수 있다. 핸들러가 ‘이 사용자는 users/alice 아래만 보라’며 네임스페이스를 고쳐 돌려주면, 그 수정본이 JS 런타임에서 Python 서버로 넘어오지 않았다. 문지기가 방문증에 ‘3층만’이라고 고쳐 적었는데 엘리베이터는 원래 방문증을 읽은 셈이다. 그래서 서버는 사용자가 처음 요청한 남의 네임스페이스 그대로 Store 작업을 실행했다. 핸들러가 요청을 아예 거부하는 방식이었다면 이 경계 문제를 타지 않는다.
SDK 결함은 thread_id에 ‘../’ 같은 상대 경로를 넣으면 인증 헤더를 단 GET 요청이 같은 서버의 다른 경로(예: Store 조회)로 가는 문제이고, CLI 결함은 CI 로그에 남은 12시간짜리 푸시 토큰으로 배포 이미지 저장소에 이미지를 올릴 수 있는 문제다.

## 플랫폼 엔지니어 관점
- LangGraph 서버를 멀티테넌트로 운영하면 langgraph-api 0.15.0 이상으로 올리고, JS/TS 인증 핸들러가 ‘재작성’이 아니라 ‘거부’로 동작하는지 모든 Store 작업(get·put·search·delete·list)에 대해 테스트를 둔다. 테넌트 A 토큰으로 테넌트 B 네임스페이스를 요청하는 음성 테스트를 CI에 넣는다.
- 권한 결정이 언어·프로세스 경계를 넘는 구조(사이드카 인증, 플러그인 런타임)에서는 ‘결정이 실제 집행 지점까지 도착했는지’를 감사 로그로 확인한다. Store 접근 로그에 요청 네임스페이스와 실제 집행 네임스페이스를 함께 남긴다.
- 사용자 입력을 thread_id·assistant_id로 그대로 넘기는 애플리케이션은 langgraph-sdk 0.4.6·langgraph 1.2.14로 올리고, ID 형식(UUID 등)을 입력 단계에서 검증한다.
- CI에서 langgraph deploy --verbose를 쓴 적이 있다면 로그 보존 정책을 확인하고, langgraph-cli 0.4.32 이상으로 고정한다. 배포가 이미지 다이제스트를 참조하는지(태그 덮어쓰기로 바뀌지 않는지)도 점검한다.
