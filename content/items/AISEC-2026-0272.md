## 요약
에이전트에 장기·단기 기억을 붙이는 오픈소스 라이브러리 Mem0에서, 대화 묶음을 구분하는 ‘세션 범위 키’를 만들 때 사용자·에이전트·실행 ID를 구분자 이스케이프 없이 이어 붙이는 결함이 공개됐다(CVE-2026-116575). 자기 run_id나 agent_id만 정할 수 있는 호출자가 값 안에 &와 =를 넣어 다른 테넌트와 똑같은 키를 만들면, 그 테넌트의 최근 원문 대화가 공격자의 사실 추출 프롬프트에 섞여 들어오고, 반대로 피해자의 기억에 메시지를 써 넣어 이력을 망가뜨릴 수도 있었다. Python 2.0.18과 TypeScript 3.1.6에서 수정됐고, 2026-10-28 GitHub Advisory Database에 검토돼 올라왔다.

## 동작 원리
사물함 번호를 ‘이름&반’ 식으로 붙여 만드는데, 이름 칸에 ‘&반=3’을 써 넣을 수 있으면 남의 사물함 번호와 똑같은 문자열을 만들 수 있다. Mem0는 키를 run_id=…&user_id=… 형태로 조립했고, 입력 검증은 빈 값만 막았다. 그래서 run_id를 ‘proj-x&user_id=alice’로 주면 alice의 범위와 같은 키가 된다. 에이전트 기억은 다음 대화의 프롬프트에 그대로 들어가므로, 이 충돌은 단순한 데이터 조회가 아니라 ‘남의 대화가 내 모델 입력이 되는’ 유출이자, 남의 기억에 문장을 심는 지속형 인젝션 통로가 된다.

## 플랫폼 엔지니어 관점
- Mem0를 쓰는 서비스는 pip 2.0.18·npm 3.1.6 이상으로 올리고, 업그레이드 전에는 API 경계에서 ID 값에 &·=·제어 문자를 거부하거나 ID를 서버가 발급한 UUID로만 받는다.
- 멀티테넌트 기억 저장소는 테넌트 ID를 호출자 입력이 아니라 인증된 신원(토큰 클레임)에서 서버가 붙이도록 설계한다. 호출자가 정한 문자열로 키를 조립하는 코드는 리뷰 체크리스트에 올린다.
- 기억 계층에 ‘누가 어느 범위의 항목을 읽고 썼는지’ 로그를 남기고, 한 호출자가 여러 user_id 범위를 건드리는 패턴을 탐지 규칙으로 만든다.
- 기억 오염은 다음 세션의 지시로 이어질 수 있으므로, 의심 기간의 기억 항목은 출처(작성 run_id)를 기준으로 감사하고 필요하면 비운다.
