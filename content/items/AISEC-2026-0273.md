## 요약
GitHub는 2026-10-28 Copilot Automations를 팀이 함께 만들고 운영하는 공유형으로 확장했다. 공유 자동화는 저장소에 속하고, 실행 결과는 Copilot 명의로 남으며 비용은 조직이 낸다. 같은 날 외부 시스템 API 트리거와 보안 경보·PR 이벤트를 포함한 트리거 24종, PR 병합 같은 쓰기 도구 20종, 사용자 정의 MCP 서버 연결, 자동화 연쇄 실행, 비용 한도가 추가됐다. 또 결과를 관찰해 자동화의 프롬프트·도구·트리거 변경을 제안하는 ‘개선 자동화’가 나왔고, 변경은 사람이 수락해야 적용된다.

## 동작 원리
예전 개인 자동화는 ‘내 계정으로 도는 매크로’였다면, 공유 자동화는 저장소에 상주하는 작은 서비스 계정에 가깝다. 사람이 퇴사해도 돌고, 누가 시켰는지보다 ‘Copilot이 했다’가 기록된다. 이 서비스 계정을 깨우는 문이 넓어졌다. 이슈 라벨, PR 상태, 보안 경보, 외부 웹훅이 모두 트리거가 되고, 그 이벤트의 내용(이슈 본문·경보 설명·티켓 텍스트)은 자연스럽게 모델의 입력이 된다. 손에 쥔 도구에는 PR 병합·댓글 숨기기 같은 쓰기 동작과 임의 MCP 서버가 포함된다. 그리고 쓰기 권한자 누구나 프롬프트를 고칠 수 있으므로, 저장소 쓰기 권한이 곧 ‘조직 비용으로 도는 에이전트의 지시를 바꾸는 권한’이 된다.

## 플랫폼 엔지니어 관점
- 조직 정책 ‘조직에 청구되는 Copilot 클라우드 에이전트 사용 허용’을 켜기 전에, 공유 자동화를 허용할 저장소 범위를 정하고 실행당·월 단위 크레딧 한도를 기본값으로 둔다.
- 공유 자동화의 도구 목록을 코드 리뷰처럼 검토한다. PR 병합, 댓글 숨기기, 워크플로 재실행, 사용자 정의 MCP 서버는 외부 기여자가 만든 이슈·PR로 트리거되는 자동화에 붙이지 않는다.
- 외부 API 트리거용 웹훅 처리기에는 서명 검증과 페이로드 정제를 넣어, 외부 티켓 텍스트가 그대로 프롬프트로 들어가지 않게 한다.
- 자동화 연쇄(‘사용자와 Copilot’)는 기본값 ‘사용자만’을 유지하고, 켤 때는 루프·비용 폭주를 막는 한도를 함께 둔다.
- 감사 로그에서 Copilot 명의 동작을 자동화 ID별로 묶어 볼 수 있는지 확인하고, 자동화 변경 이력(프롬프트·도구·트리거)을 정기 검토 대상에 넣는다. 개선 자동화가 제안한 변경도 일반 코드 변경처럼 2인 검토를 거친다.
