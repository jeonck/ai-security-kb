## 요약
Chrome DevTools 팀이 만든 브라우저 자동화 MCP 서버 chrome-devtools-mcp에서, 에이전트가 쓸 수 있는 디렉터리를 제한하는 MCP roots 검사를 우회해 루트 밖 파일을 덮어쓸 수 있는 결함이 고쳐졌다. 서버는 요청 경로를 먼저 검사한 뒤 ‘스크린숏은 .png’처럼 확장자를 바꿔 썼는데, 바뀐 경로는 다시 검사하지 않았다. 작업 공간 안에 루트 밖을 가리키는 심볼릭 링크가 있으면 스크린숏·스크립트·Lighthouse 보고서 같은 도구 출력이 그 링크를 따라 바깥 파일을 덮어썼다. 저장소 권고는 10월 22일 나왔고(1.5.0 수정), CVE-2026-106484는 10월 28일 게시됐다.

## 동작 원리
보안 검사와 실제 쓰기 사이에 경로가 바뀌는 고전적인 ‘검사 시점과 사용 시점의 차이’ 문제다. 경비원은 ‘report.txt를 작업 폴더에 둔다’는 신청서를 승인했는데, 실제로 배달된 것은 이름표만 바뀐 ‘report.png’였고 그 이름의 상자는 다른 집으로 가는 통로(심볼릭 링크)였다. 악성 저장소나 다운로드한 프로젝트를 열고 에이전트가 스크린숏을 저장하는 평범한 작업만 해도, 공격자가 미리 심어 둔 링크를 통해 사용자 설정 파일 같은 루트 밖 파일이 PNG 바이트로 망가질 수 있다.

## 플랫폼 엔지니어 관점
- 개발자 PC·원격 개발 환경에 배포한 chrome-devtools-mcp를 1.5.0 이상으로 고정한다. MCP 서버 버전을 중앙 목록으로 관리하지 않았다면 이번에 만든다.
- MCP 서버를 직접 개발한다면 경로 검증은 ‘최종으로 쓸 경로’에 대해 realpath 해석 후 하고, 쓰기는 O_NOFOLLOW 같은 링크 비추적 옵션으로 연다. roots 검사 함수와 파일 쓰기 함수를 하나로 묶어 우회 경로를 줄인다.
- 신뢰하지 않는 저장소를 여는 브라우저·코딩 에이전트는 작업 공간만 마운트한 컨테이너·devcontainer에서 돌려, roots 우회가 생겨도 홈 디렉터리 설정 파일에 닿지 않게 한다.
- CVE 설명과 벤더 권고의 영향 기술이 다를 때(임의 읽기·쓰기 대 덮어쓰기) 우선순위를 정할 때는 저장소 권고의 전제 조건을 기준으로 위험을 판단하되, 읽기 가능성은 확인될 때까지 열어 둔다.
