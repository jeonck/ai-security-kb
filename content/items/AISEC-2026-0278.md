## 요약
MCP 서버 앞단에서 URL·파일 경로 같은 도구 입력을 정화해 주는 npm 라이브러리 mcp-sanitizer에서 두 건의 우회가 공개됐다. URL 검사기는 포트를 붙인 localhost와 괄호로 감싼 IPv6 루프백을 놓쳐, 이 라이브러리를 믿고 web_fetch·web_scraper 도구를 연 MCP 서버가 내부 서비스나 클라우드 메타데이터를 대신 읽어 주는 SSRF 통로가 될 수 있었다. 파일 경로 검사기는 사용자 홈 디렉터리 전체를 허용 목록에 넣어 ~/.ssh, ~/.aws, ~/.kube 같은 비밀 파일 경로를 통과시켰다. 두 결함 모두 1.4.0에서 고쳐졌고, 2026-10-28 GitHub Advisory Database에 High 등급으로 검토·등재됐다.

## 동작 원리
보안 미들웨어의 규칙이 공격자가 쓰는 표기와 다른 표기를 기준으로 짜여 있었다. ‘localhost는 막는다, 단 포트가 없을 때’라는 조건 하나 때문에 localhost:8080은 다른 주소처럼 취급됐고, 검사기는 ::1을 찾는데 Node는 [::1]을 건네줬다. 문지기가 ‘홍길동’은 막는데 ‘홍길동 님’은 통과시키는 식이다. 경로 쪽은 더 단순해서, 개발자 편의를 위해 /home/과 /Users/를 통째로 허용하는 바람에 그 아래 가장 민감한 파일이 모두 열렸다. 프롬프트 인젝션으로 에이전트가 이런 URL·경로를 도구 인자로 넣게 만들면 정화 계층을 믿은 서버가 그대로 요청을 수행한다.

## 플랫폼 엔지니어 관점
- 사내 MCP 서버의 의존성에서 mcp-sanitizer를 찾아 1.4.0 이상으로 고정한다. 같은 유형의 입력 정화 라이브러리를 쓴다면 포트 지정 localhost, 괄호 IPv6, 10진·16진 IP, DNS 재바인딩 사례를 넣은 회귀 테스트를 직접 돌린다.
- SSRF 방어를 라이브러리 문자열 검사에만 맡기지 않는다. MCP 서버 파드에 NetworkPolicy·egress 프록시로 169.254.169.254와 클러스터 내부 대역을 막고, IMDSv2·hop limit 설정으로 메타데이터 접근을 줄인다.
- 파일 도구를 제공하는 MCP 서버는 허용 루트(작업 디렉터리)만 마운트한 컨테이너에서 돌리고, 사용자 홈과 자격 증명 디렉터리를 아예 볼 수 없게 한다.
- 보안 미들웨어를 도입할 때 ‘무엇을 허용하는가’ 목록을 직접 읽어 본다. 허용 목록이 넓은 보안 라이브러리는 없는 것보다 위험할 수 있다(거짓 안심).
