## 요약
Radware의 Gabi Nakibly·Zvika Babo가 GitHub 숨은 텍스트를 조사하다 찾아낸 공급망 캠페인을 The Register가 10월 29일 보도했다. 공격자는 정상 이력이 있는(대부분 탈취로 추정되는) 계정 74개로 9월 1일 43분 사이에 이슈·PR·댓글 77건을 쏟아냈다. 각 글에는 화면에 보이지 않는 HTML 주석 속에 셸 명령이 숨어 있었다. 이슈 내용을 셸 코드에 그대로 넣는 워크플로를 가진 저장소라면 이벤트 직후 명령이 실행돼 환경 변수를 외부로 보내도록 되어 있었다. 61개 저장소의 83건에서 페이로드가 확인됐고, agno·langextract·CopilotKit·MLflow·qwen-code 같은 AI 프로젝트가 여럿 포함됐다. 실제 실행이 로그로 확인된 것은 2건이며, 그 이상의 피해는 확인되지 않았다.

## 동작 원리
GitHub Actions 워크플로 가운데에는 이슈 제목·본문을 받아 셸 스크립트 안에 문자열로 끼워 넣는 것이 있다. 그러면 이슈 본문은 데이터가 아니라 명령의 일부가 된다. 공격자는 사람이 읽는 화면에서는 사라지는 HTML 주석에 명령을 숨겨, 관리자가 이슈를 열어 봐도 이상한 점을 못 느끼게 했다. 한 시간도 안 돼 수십 개 저장소에 같은 미끼를 뿌린 뒤 걸리는 곳만 거두는 방식이다. 프롬프트 인젝션이 모델에 숨은 지시를 먹이는 것이라면, 이것은 셸에 숨은 지시를 먹이는 쌍둥이 기법이다.

## 플랫폼 엔지니어 관점
- `issues`·`issue_comment`·`pull_request_target` 트리거 워크플로에서 `${{ github.event.issue.body }}` 같은 외부 입력을 `run:` 셸에 직접 넣지 않는다. 환경 변수로 넘기고 인용해 처리하며, actionlint·zizmor 같은 정적 검사로 조직 전체를 훑는다.
- 외부 기여자 이벤트로 도는 잡에는 시크릿과 쓰기 토큰을 주지 않는다(`permissions: read`). egress 허용 목록이나 하든 러너로 외부 전송을 막는다.
- AI 트리아지·리뷰 에이전트를 붙인 저장소는 같은 입력이 모델 프롬프트와 셸 양쪽으로 가는지 확인한다. 입력 전에 HTML 주석·보이지 않는 문자를 제거하거나 표시한다.
- 짧은 시간에 여러 계정이 몰려 올린 이슈·댓글, 정상 이력 계정의 갑작스러운 활동을 조직 감사 로그 탐지 규칙으로 만든다.
