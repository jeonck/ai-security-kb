## 요약
10월 29일 일본 보도에 따르면, 보안 기업 마크니카 집계로 올해 1월 1일~10월 27일 일본 기업 대상 부정 접근으로 유출된 정보는 누적 약 3억 2,900만 건이다. 2024년 370만 건의 약 100배, 2025년 3,300만 건의 약 10배다. 공표 건수로도 올해 216건, 10월에만 101건(26일 기준)이다. 사가와큐빈·유미루링크·타임즈카 같은 대형 유출이 숫자를 끌어올렸다. 보도는 원인을 AI를 이용한 무차별 공격으로 추정했다. 반면 마크니카 자신의 10월 7일 분석은 AI 사용을 단정할 흔적이나 제로데이 악용은 없다고 했고, 다만 AI 사용 가능성은 배제하기 어렵다는 입장이다.

## 동작 원리
마크니카가 본 수법은 특정 기업을 노린 정밀 침투가 아니다. 공개된 웹 시스템과 API를 넓게 훑어, 필요 이상으로 많은 데이터를 돌려주는 API, 비회원도 닿는 회원 기능, 앱 안에 박힌 API 키 같은 ‘설계상의 빈틈’을 찾아 그대로 데이터를 긁어 간다. 문 하나를 따는 대신 동네 모든 집의 창문을 하나씩 밀어 보는 방식이다. 이런 반복 탐색은 사람보다 자동화 도구나 에이전트에 잘 맞는다. 그래서 AI가 의심받지만, 로그만으로는 탐색을 사람 스크립트가 했는지 AI가 했는지 가려내기 어렵다.

## 플랫폼 엔지니어 관점
- 외부에 열린 API를 전수 목록화하고, 응답 필드 최소화·서버 측 인가 검사·비회원 접근 차단을 점검한다. 관리자 일괄 내보내기 기능도 진단 범위에 넣는다.
- 모바일 앱·프런트엔드 코드에 비밀 API 키나 DB 자격 증명을 넣지 않는다. 난독화는 추출을 막지 못한다. 앱용 키는 권한을 최소로 하고 사용자 단위 토큰으로 바꾼다.
- WAF·API 게이트웨이 로그에서 정상 응답(200)이라도 비정상적으로 많은 요청, 존재하지 않는 경로 탐색, 403·404 폭증을 탐지 규칙으로 만든다. 최소 1개월 치 로그를 보존해 사후 조사가 가능하게 한다.
- ‘AI 공격’이라는 귀속에 기대지 말고, 같은 통제(API 설계·키 관리·대량 탐색 탐지)가 사람·스크립트·에이전트 공격을 모두 막는다는 점을 경영진 보고에 분명히 한다.
