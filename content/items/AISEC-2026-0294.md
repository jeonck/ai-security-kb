## 요약
Microsoft Threat Intelligence가 10월 29일 북한 연계 8개 위협 그룹이 AI를 어떻게 쓰고 있는지 도입 단계별로 정리한 보고서를 냈다. 정찰·표적 선정, 사회공학·신원 위장, 악성 도구 개발, 작전 확장·분석의 네 영역 모두에서 AI가 쓰이고 있으며, 전체 도입 수준은 ‘높음’으로 평가됐다. Onyx Sleet는 한국 사용자를 노린 피싱용 맞춤 PDF 미끼를 100개 넘게 단시간에 찍어냈고, Onyx Sleet와 Pearl Sleet는 10월 말부터 오픈소스 에이전트형 침투 테스트 프레임워크 ARTEX를 쓰기 시작했다. 그럼에도 Microsoft는 작전이 아직 사람의 지휘 아래 있고 완전 자율 단계는 아니라고 봤다.

## 동작 원리
AI는 공격의 목적을 바꾸기보다 ‘공장 자동화’처럼 기존 작업의 처리량을 늘린다. 채용 담당자를 사칭한 미끼 문서·이력서·면접 답변·프로필 사진을 대량으로 만들고(사회공학), Cursor 같은 AI 개발 도구로 악성코드를 고치고 난독화하며 방어 측에 막히면 빠르게 다시 만든다(도구 개발). 여기에 ARTEX 같은 에이전트형 침투 프레임워크가 붙으면 정찰·취약점 탐색·후속 단계 판단 일부가 에이전트에게 넘어간다. 개별 기법은 새롭지 않지만, 같은 인력으로 훨씬 많은 표적을 동시에 다룰 수 있게 된다는 점이 위협의 본질이다.

## 플랫폼 엔지니어 관점
- 개발자 대상 사회공학(가짜 채용·코딩 과제 저장소)이 주요 침투로다. CI/CD 러너와 개발자 노트북에서 외부 ‘과제’ 저장소를 클론·실행하는 행위를 devcontainer·일회용 VM으로 격리하고, 비공개 저장소에 새로 추가된 스크립트·의존성은 리뷰와 서명 검증을 거치게 한다(Coral Sleet의 저장소 트로이목마화 대응).
- 클라우드 계정에서 AI 도구·비밀 정보를 찾는 정찰 행위(모델 API 키 나열, 시크릿 스토어 조회)를 탐지 규칙으로 만든다. Kubernetes에서는 ServiceAccount의 Secret list/get 권한을 최소화하고 감사 로그로 대량 조회를 경보한다.
- 원격 채용·외주 인력에게 발급하는 저장소·클러스터 접근은 신원 확인 이후 단계적으로 넓히고, 디바이스 코드 플로 차단·조건부 접근을 적용한다.
- ARTEX 같은 공개 에이전트형 공격 도구가 여러 행위자로 퍼지고 있으므로, 노출된 관리 인터페이스·웹 서비스의 자동화된 대량 탐색을 전제로 패치 주기와 WAF 규칙을 다시 본다.
