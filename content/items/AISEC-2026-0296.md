## 요약
IBM은 Langflow OSS 1.0.0~1.12.8에 영향을 주는 여러 취약점을 한 공지로 묶어 1.13.0으로 업그레이드하라고 권고했다. 눈에 띄는 것은 CVE-2026-110193이다. 저권한 계정만 있으면 Langflow에 내장된 Agentic Assistant가 차단 목록에 걸리지 않는 형태의 컴포넌트 코드를 만들거나 제출하도록 유도해, 서버에서 OS 명령을 실행할 수 있다. 같은 공지에는 인증 우회(CVE-2026-93680)와 코드 인젝션(CVE-2026-110186)이 각각 9.8점으로 실렸고, 자격 증명 노출(CVE-2026-110192)도 포함됐다.

## 동작 원리
Langflow는 노드를 이어 붙여 LLM 워크플로를 만드는 도구이고, 각 노드(컴포넌트)는 결국 서버에서 도는 파이썬 코드다. Agentic Assistant는 사용자의 요청을 받아 그 코드를 대신 써 주는 조수다. 서버는 위험한 코드 패턴을 막는 필터를 두었지만, 필터는 ‘알려진 나쁜 모양’만 거른다. 조수가 필터에 없는 모양으로 같은 일을 하는 코드를 쓰면 그대로 실행된다. 코드를 쓰는 주체가 사람에서 모델로 바뀌었을 뿐, ‘사용자가 서버 코드를 쓸 수 있다’는 구조는 그대로라는 점이 핵심이다.

## 플랫폼 엔지니어 관점
- 사내 Langflow 인스턴스를 1.13.0 이상으로 올리고, 버전을 확인할 때 컨테이너 이미지 태그까지 점검한다.
- Langflow처럼 사용자가 컴포넌트 코드를 만들 수 있는 도구는 ‘저권한 계정 = 서버 코드 실행 권한’으로 간주해, 네임스페이스 분리·비루트 실행·읽기 전용 파일 시스템·egress 제한을 건 격리 파드에서 돌린다.
- 서비스 계정에 클라우드 자격 증명·DB 비밀을 넓게 붙이지 않고, 인터넷에 관리 화면을 노출하지 않는다.
- 차단 목록 기반 코드 필터에 의존하지 말고 실행 환경 자체를 샌드박스로 만든다.
