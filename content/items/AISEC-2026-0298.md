## 요약
Check Point Research가 ‘Yoba’라는 캠페인을 공개했다. 공격자는 존재하지 않거나 아직 데스크톱 앱이 없는 AI 모델 이름(GPT-5.6 Sol, GPT-6 Astra, Claude Opus)을 내건 GitHub 저장소와 GitHub.io 페이지를 만들고 ZIP을 배포했다. ZIP 안에는 OpenAI·Anthropic이 실제로 서명한 정상 설치 파일과, 그 파일이 실행될 때 함께 불러오는 악성 winmm.dll이 들어 있었다. 악성 DLL은 지속성을 만들고 다단계 로더를 거쳐 XMRig 채굴기를 설치한다. 저장소는 7월에 만들어졌고 8월 말~9월 초에 악성 릴리스가 올라왔으며, 감염 규모는 공개되지 않았다.

## 동작 원리
정품 상자에 가짜 부품을 끼워 넣는 방식이다. Windows 프로그램은 winmm.dll 같은 시스템 DLL을 찾을 때 먼저 자기와 같은 폴더를 본다. 그래서 서명이 멀쩡한 Setup.exe 옆에 같은 이름의 악성 DLL을 두면, 서명 검사를 통과한 프로세스가 악성 코드를 대신 실행해 준다. 사용자와 일부 보안 제품은 ‘OpenAI·Anthropic 서명’을 보고 안심한다. 이후 로더는 Telegram 이미지, 동적 생성 도메인, Google DoH 같은 정상 서비스를 C2 경로로 섞어 차단을 어렵게 했다. 덤으로 약 12일 넘게 잠든 뒤 동작하는 지연 기능도 있어 샌드박스 분석을 피한다(THN 정리).

## 플랫폼 엔지니어 관점
- AI 데스크톱 앱·CLI는 벤더 공식 도메인이나 사내 소프트웨어 포털·패키지 관리자(winget·MDM)에서만 설치하도록 정책화한다. ‘GitHub에 있으니 공식’이라는 판단을 막는다.
- 코드 서명 허용 정책(WDAC·AppLocker)은 실행 파일만이 아니라 함께 로드되는 DLL까지 보도록 설정하고, 다운로드 폴더·임시 폴더에서 서명된 설치 파일이 서명 없는 DLL을 로드하는 이벤트를 EDR 탐지 규칙으로 둔다.
- 개발자 단말에서 ProgramData 아래 새 폴더 생성 + 예약 작업 등록 + svchost 주입 순서를 묶어 탐지한다.
- 사내 공지로 ‘아직 데스크톱 앱이 없는 신모델 이름의 설치 파일’은 사칭이라는 기준을 알린다. Check Point IOC(GitHub 계정·dedyn.io·catbox)를 프록시에 반영한다.
