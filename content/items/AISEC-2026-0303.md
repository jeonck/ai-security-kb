## 요약
AIR Security 연구진은 웹을 검색해 프로젝트를 꾸리는 AI 코딩 에이전트가 실제로 악성 GitHub 저장소를 골라 실행한 사례를 공개했다. 개발자가 Solana 프로젝트를 만들어 달라고 하자 에이전트는 검색 1위였던 가짜 ‘solana-starter-kit’ 저장소를 택했고, README의 설치 안내인 PowerShell 한 줄을 그대로 실행했다. 드로퍼는 정상 서명된 NetSupport Manager 구성 요소에 공격자 설정만 얹어 원격 제어 트로이목마로 바꾸고, 운영자는 화면·파일과 암호화폐 지갑에 접근한다. 페이로드 URL은 이미 내려갔지만 연구진은 같은 운영자가 새 저장소로 이어 갈 것으로 본다.

## 동작 원리
사람은 별 수와 검색 순위를 보고 ‘믿을 만한 저장소’를 고르는데, 에이전트도 같은 신호로 고른다. 사람은 별 수백 개짜리 낯선 저장소의 ‘복사해서 붙여 넣으세요’ 한 줄을 한 번쯤 의심하지만, 에이전트에게 README는 작업 지시와 구분되지 않는 입력이다. 공격자는 에이전트를 속이는 특별한 문장을 쓸 필요도 없이, 에이전트가 고를 만한 자리에 저장소를 놓고 설치 절차에 다운로드·실행 한 줄을 넣었다. 디스크에 남는 것은 서명된 정상 원격 관리 도구라 서명 검사로는 걸러지지 않고, 악성인 것은 설정 파일 하나뿐이다. 간접 프롬프트 인젝션과 악성 패키지의 경계가 겹치는 지점이다.

## 플랫폼 엔지니어 관점
- 코딩 에이전트의 셸 도구에서 `curl|sh`, `iwr|iex`, `-EncodedCommand`처럼 원격 코드를 바로 실행하는 패턴은 자동 승인 목록에서 빼고 항상 사람 승인을 거치게 한다. 검색 결과·README·이슈 본문은 신뢰할 수 없는 입력으로 분류한다.
- 에이전트가 새 저장소·템플릿을 고를 때는 조직이 승인한 템플릿 레지스트리나 내부 미러를 쓰게 하고, 처음 보는 GitHub 조직의 저장소는 클론 전에 플래그를 세운다.
- 에이전트 작업 환경은 지갑·SSH 키·클라우드 자격 증명이 없는 일회용 devcontainer나 VM으로 돌리고, egress를 패키지 레지스트리와 승인 도메인으로 묶어 C2 연결이 나가지 못하게 한다.
- EDR에 원문의 지표(사용자 프로필 아래 숨김 폴더, Run 레지스트리 추가, client32.exe 프로세스, C2 도메인)를 넣어 개발자 단말 전체를 조회하고, 감염 시 단말 격리와 토큰·지갑 키 전부 교체를 런북에 넣는다.
