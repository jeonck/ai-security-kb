## 요약
OWASP CycloneDX는 SBOM 형식을 머신러닝으로 넓혀, 모델(‘machine-learning-model’)과 데이터(‘data’)를 일반 라이브러리와 똑같은 BOM 컴포넌트로 기록하게 한다. 모델 컴포넌트에는 모델 카드(modelCard)를 붙여 학습 방식, 아키텍처, 학습·평가 데이터셋, 성능 지표와 신뢰구간, 의도된 용도와 기술적 한계·윤리·공정성·환경 고려를 구조화된 필드로 남긴다. 데이터 컴포넌트에는 내용 위치, 민감도 분류, 민감 데이터 설명, 보관자·관리자·소유자의 거버넌스 역할을 적는다. 2025-10-21 공개된 1.7은 정보의 출처와 책임 주체를 남기는 인용(citations) 기능을 더했고, 2025년 12월 Ecma 국제 표준 ECMA-424 2판으로 채택됐다.

## 동작 원리
SBOM이 ‘이 소프트웨어는 어떤 부품으로 만들어졌나’를 적은 부품표라면, ML-BOM은 ‘이 모델은 어떤 데이터로, 어떤 방식으로 만들어졌고, 어디까지 믿어도 되나’를 적은 부품표 겸 성적표다. 핵심은 모델과 데이터셋을 별도 컴포넌트로 두고 bom-ref로 서로 잇는다는 점이다. 모델 카드의 datasets가 같은 BOM 안의 data 컴포넌트를 가리키면, 모델 → 학습 데이터셋 → 데이터 소유자·분류라는 계보가 하나의 그래프로 기계에서 읽힌다. 사람이 읽는 모델 카드 문서와 달리 필드 이름과 열거값이 정해져 있어, 레지스트리나 정책 엔진이 ‘학습 데이터 분류가 비어 있으면 거부’ 같은 규칙을 걸 수 있다. 다만 BOM은 기록일 뿐 내용이 참이라는 증명은 아니다. 기록이 맞다는 신뢰는 서명·출처 증명과 결합해야 생긴다.

## 플랫폼 엔지니어 관점
- 모델 레지스트리 등록 조건으로 CycloneDX 형식의 ML-BOM을 요구한다. 최소 필드(modelParameters.approach·modelArchitecture·datasets, considerations.technicalLimitations·useCases)가 비면 승인 단계로 넘기지 않는다.
- 학습·파인튜닝 CI 파이프라인이 학습 작업 정의에서 데이터셋 URL·해시, 하이퍼파라미터, 평가 지표를 뽑아 ML-BOM을 자동 생성하게 한다. 사람이 나중에 채우는 문서는 실제 학습과 어긋난다.
- 데이터 컴포넌트의 classification·sensitiveData·governance.owners를 데이터 카탈로그와 맞춰, 민감 데이터로 학습한 모델이 어느 서빙 환경에 배포될 수 있는지를 정책으로 연결한다.
- ML-BOM을 모델 아티팩트와 함께 서명하고 OCI 레지스트리에 첨부(referrer)해 두면, Kubernetes admission 단계에서 ‘서명된 ML-BOM이 없거나 승인되지 않은 데이터셋 계보를 가진 모델 이미지’의 배포를 거부할 수 있다.
- 평가 지표(performanceMetrics의 slice·confidenceInterval)를 릴리스마다 BOM에 남겨, 재학습·양자화 후 특정 슬라이스 성능이 떨어진 모델을 승격 전에 비교·차단한다.
