## 요약
2026-10-22 지식 베이스에 실린 OpenCode MCP OAuth 원격 코드 실행(AISEC-2026-0078)은 벤더가 CVE를 내지 않아 스캐너가 잡지 못한다는 점이 문제였다. 2026-10-29 근원 라이브러리인 npm 패키지 open(7.2.0 이상 11.0.0 미만)에 CVE-2026-119025가 부여되면서 이제 의존성 스캐너로 추적할 수 있게 됐다. 같은 날 연결된 권고를 보면 MCP 공식 디버깅 도구인 MCP Inspector(2.0.0~2.11.0)도 같은 경로로 영향을 받았고 2.12.0에서 고쳐졌다. Inspector 쪽은 서버에 연결하는 순간 확인 창 없이 코드가 실행된다는 점에서 OpenCode보다 조건이 더 나쁘다.

## 동작 원리
MCP 클라이언트가 OAuth가 필요한 원격 서버에 붙으면 서버가 ‘여기서 로그인하라’며 인가 URL을 알려 주고, 클라이언트는 그 URL을 브라우저로 연다. Windows에서 open 패키지는 이 URL을 PowerShell 명령 문자열의 큰따옴표 안에 그대로 끼워 넣었다. PowerShell은 큰따옴표 안의 $(...)를 먼저 계산하므로, URL에 명령을 숨겨 두면 브라우저를 열기 전에 그 명령이 사용자 권한으로 실행된다. 주소창에 붙여 넣은 링크가 사실은 터미널 명령이었던 셈이다. 근본 원인은 ‘외부 서버가 준 문자열을 셸을 거쳐 실행하는 범용 유틸리티’였고, 그래서 이 패턴이 mcp-remote(CVE-2025-6514), OpenCode, Inspector에서 반복됐다.

## 플랫폼 엔지니어 관점
- 개발자 PC·CI 이미지의 SBOM에서 open 7.2~10.x를 찾는다. open을 직접 쓰지 않아도 MCP 클라이언트·CLI의 간접 의존성으로 들어와 있을 수 있다. 10.x 캐럿 범위로는 11로 자동으로 올라가지 않으므로 명시적으로 업그레이드하거나 오버라이드한다.
- MCP Inspector를 2.12.0 이상으로 올린다. 검증되지 않은 원격 MCP 서버를 Inspector로 ‘시험 삼아’ 붙이는 관행을 Windows·WSL 개발 환경에서 금지하거나, 그런 시험은 일회용 VM·devcontainer 안에서 하게 한다.
- 원격 MCP 서버는 허용 목록으로 관리하고, OAuth 디스커버리에서 받은 인가 URL은 MCP 서버와 같은 출처이고 HTTPS인지 클라이언트가 검사하도록 내부 MCP 게이트웨이·클라이언트 정책에 넣는다.
- 벤더가 CVE를 내지 않은 취약점은 근원 라이브러리 CVE가 나올 때까지 스캐너가 놓친다. 내부 취약점 관리에서 ‘CVE 없는 보안 수정’ 목록을 따로 관리한다.
