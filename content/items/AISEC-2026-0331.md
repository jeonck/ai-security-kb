## 요약
gojue가 공개한 로컬 MCP 서버 MoLing은 파일 읽기·쓰기, 시스템 명령 실행, 브라우저 제어를 AI 클라이언트에 도구로 제공한다. 0.4.0 이하를 SSE 모드로 띄우면 HTTP 엔드포인트에 인증이 없었고, 의존 라이브러리인 Go용 MCP SDK mcp-go가 모든 출처를 허용하는 CORS 헤더를 붙였다. 그래서 사용자가 MoLing을 켠 채 악성 웹 페이지를 열기만 하면 그 페이지가 로컬 서버의 세션 ID를 읽어 명령 실행 도구까지 호출할 수 있었다. GitHub 권고는 2026-06-27에 나왔고 0.5.0에서 고쳐졌으며, CVE 레코드는 2026-10-30에 공개됐다.

## 동작 원리
브라우저의 동일 출처 정책은 '다른 사이트의 응답은 읽지 못하게' 막는 벽이다. 그런데 서버가 `Access-Control-Allow-Origin: *`를 보내면 그 벽에 '누구나 들어와도 됨' 표지판을 거는 셈이다. 악성 페이지는 `http://127.0.0.1:6789/sse`에 스트림 연결을 열고, 서버가 알려 주는 메시지 엔드포인트 주소에서 세션 ID를 꺼낸다. 이 세션 ID가 사실상 유일한 자격 증명이므로, 이후 `/message`로 도구 호출을 보내면 서버는 정상 클라이언트로 여긴다. 서버를 127.0.0.1에만 묶어도 소용없다. 요청을 보내는 주체가 같은 PC의 브라우저이기 때문이다. 문제의 헤더는 MoLing 코드가 아니라 공용 SDK에서 왔다는 점이 공급망 관점의 핵심이다.

## 플랫폼 엔지니어 관점
- **로컬 MCP 서버 인벤토리**: 개발자 PC와 devcontainer에서 SSE/HTTP 전송으로 떠 있는 MCP 서버를 찾는다(리스닝 포트 + `/sse` 응답). MoLing은 0.5.0 이상으로 올리고, 명령 실행 도구를 가진 서버는 stdio 전송을 기본으로 한다.
- **SDK 기본값 감사**: 사내 MCP 서버가 mcp-go 등 SDK의 SSE/Streamable HTTP 전송을 쓰면 응답 헤더에 와일드카드 CORS가 붙는지 통합 테스트로 확인하고, Origin 검증과 토큰 인증을 미들웨어로 강제한다.
- **승인 목록·고정**: 사내 MCP 레지스트리에 서버를 올릴 때 '네트워크 전송 시 인증 필수, 루프백 바인딩만으로 통과 불가'를 심사 기준으로 삼고, 버전을 고정해 취약 버전 재설치를 막는다.
- **브라우저→로컬 경로 차단**: 관리 브라우저 정책으로 공용 웹 페이지가 localhost·사설 대역에 요청하는 것을 제한하고, 그런 요청을 엔드포인트 보안 도구로 탐지한다. 권고의 임시 완화책대로 패치 전에는 SSE 모드를 끄고 포트를 방화벽으로 막는다.
