## 요약
로컬 LLM 실행 도구 LM Studio의 모델 다운로더에서 경로 탐색 취약점(CVE-2026-119979)이 공개됐다. 역슬래시로 경로를 올라가는 파일명을 걸러내지 못해, 사용자가 악성 모델 저장소를 내려받으면 모델 폴더 밖에 파일이 쓰였다. 공격자는 이를 이용해 플러그인 설정과 MCP 브리지 설정을 심고, 앱이 켜질 때마다 파이썬 페이로드가 실행되게 할 수 있다. 0.4.22+1에서 고쳐졌으며 Pillar Security의 Ariel Fogel이 발견자로 올라 있다.

## 동작 원리
모델 저장소 안의 파일 이름은 ‘이 파일을 어디에 둘지’에 대한 지시이기도 하다. 다운로더가 슬래시만 위험 문자로 보고 역슬래시는 그냥 두면, 이름에 ‘..\..\’을 넣은 파일이 모델 폴더를 빠져나가 앱의 플러그인 폴더에 내려앉는다. 거기에 플러그인 목록·설치 상태·MCP 브리지 설정을 같이 놓으면 LM Studio는 그것을 정상 설치된 플러그인으로 알고 시작할 때마다 불러 실행한다. 한 번의 다운로드가 영구적인 자동 실행으로 바뀌는 구조다.

## 플랫폼 엔지니어 관점
- 개발자 PC·GPU 워크스테이션의 LM Studio를 0.4.22+1 이상으로 올리고, 플러그인·MCP 브리지 설정 디렉터리에 낯선 항목이 생겼는지 점검한다.
- 모델은 승인된 내부 레지스트리·미러에서만 받게 하고, 공개 허브에서 받은 모델 저장소는 파일 이름·경로를 검사한 뒤 반입한다.
- 로컬 LLM 도구가 MCP 서버를 띄우는 설정 파일은 EDR·파일 무결성 감시 대상에 넣는다. 모델 다운로드 직후 플러그인·MCP 설정 변경이 일어나면 경보 규칙으로 잡는다.
- 모델 실험은 자격 증명이 없는 별도 VM·컨테이너에서 하고, 개인 PC의 클라우드 자격 증명·SSH 키와 분리한다.
