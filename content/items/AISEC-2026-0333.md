## 요약
AI 에이전트들을 하나의 ‘회사’처럼 조직해 운영하는 오픈소스 서버 Paperclip에서, 실행 작업 공간(execution workspace) 설정에 들어가는 정리 명령(cleanupCommand·teardownCommand)을 아무 검증 없이 저장했다가 작업 공간을 보관할 때 셸로 실행하는 명령 주입 취약점이 확인됐다. 벤더는 4월 16일 권고와 함께 2026.416.0에서 고쳤고, 10월 30일 CVE-2026-119713으로 NVD·GitHub 권고 DB에 등재됐다. 벤더 권고는 데스크톱 기본 모드(local_trusted)에서 인증 없이 악용 가능한 9.8로, CVE 설명은 에이전트 API 키를 가진 자가 악용하는 8.7로 적어 전제가 다르다.

## 동작 원리
작업 공간에는 ‘다 쓰고 나면 이 명령으로 치워라’라는 메모 칸이 있었다. 서버는 이 메모를 누가 썼는지, 무엇이 적혔는지 확인하지 않고 보관 시점에 그대로 셸에 넘겼다. 그래서 작업 공간을 고칠 수 있는 사람(또는 에이전트 키)이면 메모 칸에 명령을 적고 보관 버튼을 누르는 것만으로 서버 프로세스 권한의 코드 실행을 얻는다. 여기에 local_trusted 모드가 모든 요청을 관리자로 취급하고, authenticated 모드에서도 소속 회사 확인이 조회 뒤에 이뤄져 다른 회사의 작업 공간까지 건드릴 여지가 있었다.

## 플랫폼 엔지니어 관점
- Paperclip을 쓰는 팀은 2026.416.0 이상인지 확인하고, 작업 공간 config의 cleanupCommand·teardownCommand 값을 전수 점검한다.
- 에이전트 API 키로 호출할 수 있는 API를 ‘작업 수행’과 ‘설정 변경’으로 나눠, 실행 명령이 들어가는 필드는 사람 승인이나 별도 관리자 신원으로만 바꾸게 한다.
- 데스크톱·개발용 ‘신뢰 모드’를 공유 서버나 Kubernetes에 그대로 올리지 않는다. localhost 바인딩도 브라우저·DNS 리바인딩에 뚫릴 수 있다고 보고 인증을 켠다.
- 오케스트레이터 서버가 작업 공간 정리 같은 훅을 실행한다면, 그 실행을 서버 프로세스가 아닌 자격 증명 없는 별도 컨테이너·샌드박스로 분리한다.
