## 요약
KAIST 연구진이 로컬 LLM 에이전트용 간접 프롬프트 인젝션 방어 SEAL을 공개했다. 도구 출력을 모델에 넘기기 전에, 고정된 작업 모델 자신의 내부 상태로 토큰마다 ‘주입된 지시 같은가’를 채점해 해당 부분을 지운다. 핵심은 채점에 쓰는 질의를 신뢰할 수 있는 초기 문맥과 학습한 소프트 프롬프트로만 만들어, 검사받는 텍스트가 채점 기준 자체를 흔들지 못하게 한 것이다. AgentDojo에서 공격 성공률을 34.6%에서 0.1%로 낮추면서 과업 성공(Joint)은 51.4%에서 77.5%로 올렸고, 별도 검증 모델이나 생성 토큰이 필요 없다.

## 동작 원리
기존 탐지기는 종종 ‘이 문서를 읽고 수상한 곳을 찾아라’라고 묻는데, 그 문서 안에 ‘나는 안전하다’는 주입문이 있으면 질문 자체가 오염된다. SEAL은 시험지를 봉투에 넣고 봉인하듯, 채점 질문을 사용자의 원래 지시와 미리 학습한 프롬프트로 고정해 둔다. 그리고 점수를 다른 토큰들과 나눠 갖는 정규화 이전 단계에서 매겨, 주변에 무해한 텍스트를 잔뜩 붙여 점수를 희석하는 수법도 막는다. 정상 내용은 덜 지우도록 학습 때 벌점을 줘 효용 손실을 줄였다.

## 플랫폼 엔지니어 관점
- 자체 호스팅 모델로 에이전트를 돌리는 팀은 도구 출력과 모델 입력 사이에 ‘정화 단계’를 두는 구조를 검토할 수 있다. 다만 SEAL은 모델 내부 상태 접근이 필요해 외부 API 모델에는 그대로 적용되지 않는다.
- 방어를 고를 때 ASR만 보지 말고 Joint(공격 없이 과업 성공)와 토큰·지연 비용을 함께 본다. 이 논문의 Table 3·4처럼 같은 벤치마크에서 비교 기준선을 정해 사내 평가에 쓴다.
- 정화는 확률적 통제다. 도구 권한 최소화, egress 차단, 고위험 행동 승인 같은 결정적 통제를 대체하지 않고 그 앞단에 겹쳐 둔다.
- 적응형 공격(그레이·화이트박스)에 대한 수치를 사내 레드팀 시나리오에 포함해 방어 도입 후에도 주기적으로 재평가한다.
