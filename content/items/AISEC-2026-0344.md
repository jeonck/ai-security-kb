## 요약
보안 업체 Parameter는 ChatGPT의 공개 공유 링크 하나로 피해자 세션에서 공격자 자바스크립트를 실행하고 비공개 대화를 읽어 낸 체인을 공개했다. 공유된 대화에는 평범한 인터랙티브 그래프와 HTML 프리뷰만 들어 있으면 됐고, 피해자는 링크를 열기만(초기 버전은 프리뷰 클릭 한 번) 하면 됐다. 10월 18일 OpenAI 버그 바운티에 신고됐고 OpenAI는 심각도를 P1로 올려 10월 26일 서버 측에서 고쳤으며 5,000달러를 지급했다. 실제 악용은 보고되지 않았다.

## 동작 원리
프리뷰는 별도 출처의 잠긴 방(샌드박스 iframe)이라 메인 페이지를 직접 들여다볼 수 없다. 문제는 같은 대화의 그래프를 그리려고 메인 페이지에 들어온 수학 입력 라이브러리 MathLive가 ‘가상 키보드 설정을 바꿔 달라’는 메시지를 누가 보냈는지 확인하지 않고 받아 준 데 있다. 잠긴 방 안에서 문틈으로 쪽지를 넣었더니, 집 안의 집사가 쪽지에 적힌 HTML을 그대로 벽에 붙인 셈이다. 그 HTML은 샌드박스 없는 iframe을 만들어 chatgpt.com 신분을 물려받았고, CSP가 인라인 스크립트는 막았지만 YouTube 스크립트는 허용해 JSONP 콜백으로 코드를 돌릴 수 있었다. 이후 코드는 페이지에 있던 세션 정보로 ChatGPT API를 피해자로서 호출했다. 하나하나는 그럴듯한 기능(공유·프리뷰·수식 라이브러리·프레임 생성·CSP 허용 목록)이 겹쳐서 경계가 무너졌다.

## 플랫폼 엔지니어 관점
- 사내 LLM 채팅 UI·에이전트 콘솔이 모델 출력 HTML/아티팩트를 렌더링한다면, 샌드박스 iframe만으로 끝내지 말고 부모 페이지의 모든 `message` 수신기(서드파티 포함)가 `event.origin`과 `event.source`를 검증하는지 감사한다. 의존성 업데이트 때 postMessage 수신기 목록을 SCA·코드 스캐닝 규칙으로 추적한다.
- 동적으로 만드는 iframe은 기본 `sandbox` 속성을 강제하고, Trusted Types 정책이 실제로 정화하는지(항등 함수 래퍼가 아닌지) 확인한다.
- CSP `script-src` 허용 목록에 JSONP·oEmbed 콜백을 제공하는 대형 도메인(YouTube, Google 등)이 들어 있으면 그 자체가 실행 허용이다. 호스트 단위 대신 nonce·hash 기반 CSP로 옮긴다.
- 공유 링크·공개 대화처럼 ‘외부인이 만든 콘텐츠가 로그인한 사용자의 출처에서 렌더링되는’ 기능은 별도 도메인(사용자 콘텐츠 전용 origin)으로 분리하는 것을 기본 설계로 삼는다.
