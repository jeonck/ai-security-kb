## 요약
MCP 서버의 도구·리소스·프롬프트와 에이전트 스킬 번들(Claude Code 명령, agentskills.io 번들과 동봉 스크립트)을 프롬프트 인젝션·도구 포이즈닝·명령 인젝션 관점에서 검사하는 오픈소스 스캐너 Ramparts(Highflame)에서, 검사 대상 파일을 모을 때 하위 디렉터리와 .pyc를 통째로 건너뛰는 결함이 CVE-2026-120202(GHSA-6cmq-892m-x8wh, CVSS 4.0 7.1)로 2026-10-31 공개됐다. 공격자는 scripts 아래 하위 폴더의 __pycache__에 해시 검증을 끈 .pyc를 숨기고 겉으로는 깨끗한 .py를 두면 된다. 스캐너는 ‘0건’을 보고하지만 스킬이 실행되면 Python은 숨긴 바이트코드를 실행한다. 영향 버전은 0.8.1~0.8.10이고 수정 버전은 아직 표시되지 않았다. 보고자는 같은 PoC로 NVIDIA·Cisco·Snyk·Tencent 등 다른 스킬 스캐너 8종 10개 구성도 모두 통과했다고 공개했다.

## 동작 원리
공항 검색대가 ‘가방 바깥 주머니만’ 엑스레이에 넣는다고 생각하면 된다. Python은 .py 옆 __pycache__에 미리 컴파일된 .pyc가 있으면 그것을 먼저 쓴다. PEP 552의 UNCHECKED_HASH 모드로 만든 .pyc는 원본 .py와 맞는지조차 확인하지 않는다. 그래서 스캐너가 읽는 .py(미끼)와 런타임이 실행하는 .pyc(페이로드)가 서로 다른 파일이 된다. Ramparts는 번들을 훑을 때 하위 디렉터리를 재귀로 들어가지 않고 .pyc를 스크립트 확장자 목록에 넣지 않았다. 그래서 YARA 규칙이든 LLM 분석이든 분석 단계에 파일이 아예 도달하지 않는다. 다른 스캐너들도 __pycache__를 소음으로 보고 제외하거나, 바이너리는 해시만 찍거나, SKILL.md만 읽는 식으로 같은 사각지대를 공유했다.

## 플랫폼 엔지니어 관점
- 스킬·MCP 서버 스캐너의 ‘0건’은 통과 증명이 아니다. 승인 파이프라인에서 스캐너는 신호로만 쓰고, 번들 안의 모든 파일 목록(경로·확장자·해시)을 별도로 남겨 사람이 검토할 수 있게 한다.
- 승인된 스킬 번들에 .pyc·__pycache__·기타 바이너리가 있으면 거부하는 정책을 둔다. 실행 환경에서는 PYTHONDONTWRITEBYTECODE와 함께 번들의 바이트코드를 지우고 소스에서만 실행하도록(설치 시 __pycache__ 제거, 읽기 전용 마운트) 고정한다.
- 스킬은 ‘검사기가 본 것’이 아니라 ‘런타임이 실행할 것’ 기준으로 서명·고정한다. 번들 전체 해시를 승인 시점에 고정하고, 에이전트 파드에서 로드할 때 다시 대조한다.
- 스캐너 통과와 무관하게 스킬 실행은 자격 증명 없는 샌드박스(egress 기본 거부)에서 돌려, 숨은 import 시 코드 실행이 있어도 얻을 것이 없게 만든다.
- 사내에서 Ramparts 0.8.1~0.8.10을 CI 관문으로 쓰고 있다면 수정 전까지 해당 판정을 단독 승인 근거로 쓰지 않는다.
