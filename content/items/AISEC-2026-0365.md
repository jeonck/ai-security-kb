## 요약
Jao와 Lampinen은 자동 레드팀 감사(감사자 모델이 표적 모델과 대화하며 문제 행동을 끌어내는 방식)를 강화하는 방법을 냈다. 대화 분기를 하나씩 따라가는 대신 빔 탐색으로 여러 분기를 펼치고, 어느 분기가 유망한지는 표적 모델의 내부 활성값에 붙인 선형 탐침이 ‘앞으로 받을 판정 점수’를 예측해 고른다. Gemma 3 4B·12B·27B와 18개 행동에서 같은 토큰 예산의 Petri보다 최고 점수가 평균 약 50% 높았다. 작은 모델 데이터로 학습한 탐침을 큰 모델에 옮겨도 성능이 유지됐고, 값비싼 판정 모델 추가 호출과 맞먹는 효과를 냈다.

## 동작 원리
바둑 AI가 모든 수를 끝까지 두어 보지 않고 ‘이 국면이 얼마나 유리한가’를 가치망으로 어림하듯, 감사자는 대화의 각 국면이 문제 행동으로 이어질 가능성을 어림해야 한다. 이 연구는 그 어림을 별도 LLM 판정자에게 묻지 않고, 표적 모델이 응답을 만들며 이미 계산한 활성값에서 선형 탐침으로 바로 읽는다. 표적 모델 스스로의 내부 상태가 ‘곧 선을 넘을 것 같다’는 신호를 담고 있다는 가정이며, 실험에서 그 신호가 판정자 호출만큼 쓸모 있었다.

## 플랫폼 엔지니어 관점
- 자체 호스팅 모델을 운영한다면 평가 파이프라인에서 활성값을 추출할 수 있도록 서빙·평가 환경을 분리해 둔다(평가 전용 노드에서 훅 활성화). 판정 모델 API 호출 비용을 줄이면서 상시 레드팀을 돌릴 수 있다.
- 자동 감사 결과를 비교할 때 토큰 예산을 맞췄는지 확인한다. 같은 예산에서 탐색 전략만 바꿔도 점수가 크게 달라지므로, 벤더의 ‘레드팀 통과’ 수치는 탐색 방법·예산과 함께 받아야 한다.
- 작은 모델에서 학습한 탐침을 재사용할 수 있다는 결과는, 레드팀 자산(탐침·시나리오)을 모델 버전과 별도로 관리할 가치를 보여 준다.
