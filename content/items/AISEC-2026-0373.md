## 요약
AG-UI는 에이전트 백엔드와 사용자 화면을 잇는 오픈 프로토콜이고, @ag-ui/client는 그 TypeScript 클라이언트다. 2026-11-01 이 클라이언트(0.0.58까지)에 대한 CVE 5건이 한꺼번에 공개됐다. 가장 무거운 건(CVE-2026-120233)은 HttpAgent가 에이전트 엔드포인트의 리다이렉트를 그대로 따라가, 실행 요청 본문과 테넌트 식별 헤더 같은 개발자 지정 헤더를 서버가 고른 출처로 다시 보내는 문제다. 보고는 2026-08-25에 공개 이슈로 올라왔고 수정 PR도 8월 말에 나왔지만, 열람 시점까지 병합되지 않았다. 나머지 4건은 SSE 파서 등의 자원 고갈·입력 검증 문제로 등급이 낮고 일부는 10-30 릴리스에서 고쳐졌다.

## 동작 원리
브라우저나 Node의 fetch는 기본적으로 서버가 ‘저쪽으로 가라’(3xx)고 하면 따라간다. 307·308은 ‘같은 메서드와 본문 그대로’ 다시 보내라는 뜻이라, 대화 상태를 담은 실행 POST가 통째로 새 주소로 간다. 표준은 출처가 바뀌면 Authorization 헤더를 떼지만, 개발자가 붙인 X-Tenant 같은 다른 헤더는 남는다. 즉 클라이언트가 연결한 에이전트 서버가 악성이거나 침해되면, 그 서버는 클라이언트를 원격 조종해 데이터를 제3의 수집 서버로 보내거나 사내 내부 주소로 요청을 쏘게 만들 수 있다. 우편물에 ‘이사 갔음, 이 주소로 전달’ 쪽지만 붙이면 내용물이 그대로 넘어가는 셈이다.

## 플랫폼 엔지니어 관점
- AG-UI 클라이언트를 쓰는 앱은 PR #2575 병합 전까지 config.fetch에 redirect: error를 강제하는 래퍼를 넣고, adk-middleware·watsonx 연동도 같은 점검을 한다.
- 에이전트 엔드포인트는 고정된 허용 목록 URL로만 연결하고, 클라이언트가 도는 환경(서버 측 렌더링·에이전트 게이트웨이)의 egress를 허용 목록으로 제한해 리다이렉트로 내부 주소나 외부 수집 서버에 닿지 못하게 한다.
- 테넌트 ID·세션 토큰을 커스텀 헤더로 보내는 설계는 리다이렉트·프록시를 거치며 새기 쉽다. 테넌트 식별은 서버 측에서 인증 주체로부터 도출하고, 헤더 값은 신뢰하지 않는다.
- VulDB 경유 CVE는 GitHub 권고에 패키지·버전이 비어 Dependabot이 경보를 내지 않는다. 에이전트 SDK는 SBOM으로 목록화하고 CVE 피드를 패키지명 기준으로 따로 대조한다.
