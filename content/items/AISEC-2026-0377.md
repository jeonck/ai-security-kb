## 요약
다중 에이전트 오케스트레이터 Network-AI(npm `network-ai`)의 권고 네 건이 2026-11-02 GitHub Advisory Database와 NVD에 CVE로 올라왔다. 저장소 권고 자체는 10-17에 게시됐다. 가장 눈에 띄는 것은 A2A 서버로, 비밀값을 설정하지 않으면 인증 없이 작업을 보내고 결과를 읽고 취소할 수 있었다. 나머지 셋은 경로 탐색이다. 녹화·재생 도구 AgentVCR, 작업 큐 FileJobStore, 입력 정화기 InputSanitizer가 파일 경로를 제대로 가두지 못했다. 보고자는 이를 이용해 권한 게이트 AuthGuardian의 신뢰 수준 설정을 덮어써 거부돼야 할 에이전트에 권한을 줬다. 5.15.5에서 고쳐졌다.

## 동작 원리
A2A 서버는 문에 자물쇠를 달 수 있게 만들었지만 열쇠를 지정하지 않으면 문을 잠그지 않고 열어 둔다. 기본 설정이 열쇠 없음이었으니 기본 상태가 무인증이다. 경로 탐색 쪽은 ‘이 폴더 안에서만 읽고 쓴다’는 약속이 파일 이름 하나로 깨지는 문제다. 권한 게이트가 판단 근거로 읽는 신뢰 수준 파일도 같은 프로세스가 쓸 수 있는 .json이었기 때문에, 파일을 바꾸는 것만으로 인가 결과를 바꿀 수 있었다.

## 플랫폼 엔지니어 관점
- network-ai를 쓰면 5.15.5 이상으로 올린다. GitHub DB 항목에 패키지가 연결되지 않아 Dependabot이 알려 주지 않으니 직접 확인한다.
- A2A·MCP 서버 배포 템플릿에서 인증 비밀값을 필수 값으로 두고, 값이 없으면 파드가 기동 실패하도록 검사한다. 루프백 바인딩만 믿지 말고 NetworkPolicy로 호출 주체를 제한한다.
- 권한 정책·신뢰 수준 파일은 에이전트 런타임이 쓸 수 없는 읽기 전용 마운트(ConfigMap·서명된 번들)로 두고 변경을 감사한다.
