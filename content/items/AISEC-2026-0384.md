## 요약
에이전트가 MCP로 외부 도구를 부를 때 남는 호출 기록만으로 사용자의 민감 속성을 얼마나 추론할 수 있는지 측정한 연구다. 저자들은 합성 프로필 1,000개와 실제 MCP 서버 25개를 쓴 궤적 4,000개로 벤치마크 PrivacyTrace를 만들고, LLM 4종을 공격자로 세웠다. 대화를 전혀 보지 않고도 성공률이 26.25%로 사전 추측(17.97%)보다 높았고, 국적·종교·민족은 절반 안팎이 맞았다. 여러 도메인의 세션을 한 사용자 ID로 이으면 32.77%까지 올랐다. 반면 이름·전화번호 같은 직접 식별자는 거의 맞히지 못했다.

## 동작 원리
택배 기사는 상자 안을 보지 않아도 받는 주소, 자주 오는 가게, 배송 시간대만으로 그 집에 대해 꽤 많은 것을 안다. 도구 호출도 같다. 날씨 도구에 넘긴 도시, 항공권 검색의 출발지와 날짜, 지오코딩 질의는 대화 내용이 아니라 ‘인자’지만 사용자의 위치·계획·생활 패턴을 담는다. 개별 MCP 서버는 자기에게 온 호출만 보지만, 모든 호출이 지나가는 게이트웨이는 도메인을 넘나들며 같은 사용자를 이어 붙일 수 있어 더 정확한 프로필을 만든다. 실험에서 호출 순서·메타데이터만으로는 추측보다 못했고, 인자와 반환값이 추론 근거의 대부분이었다.

## 플랫폼 엔지니어 관점
- MCP 게이트웨이·AI 게이트웨이의 도구 호출 로그를 채팅 로그와 같은 등급의 개인정보 저장소로 분류한다. 인자·반환값 전문 저장은 기본값으로 끄고(OTel GenAI 내용 캡처 옵트인과 같은 원칙), 보존 기간과 접근 권한을 정한다.
- 서드파티 MCP 서버를 등록할 때 ‘이 서버가 받는 인자에 무엇이 담기나’를 승인 기준에 넣는다. 지오코딩·검색·여행처럼 위치·일정을 받는 서버는 데이터 처리 조건을 별도로 검토한다.
- 게이트웨이가 외부 MCP 서버로 호출을 넘길 때 영구 사용자 ID를 그대로 전달하지 말고 서버별·세션별 가명 식별자를 쓴다. 서버 간 연결 가능성을 줄이는 것이 이 연구가 보인 가장 큰 위험(도메인 연결 시 상승)을 겨냥한다.
- 내부 분석·디버깅 목적으로 궤적을 모으는 팀은 이 벤치마크 방식으로 자체 로그의 재식별 위험을 점검해 볼 수 있다.
