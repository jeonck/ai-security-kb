## 요약
OpenAI 정렬 연구 블로그가 11월 2일 모델의 중간층 잔차 스트림 활성화를 읽어 정책 위반 행동(오정렬 행동, 해로운 사용자 의도)을 판별하는 활성화 분류기, 즉 프로브를 어떻게 학습·평가·배포하는지 공개했다. GPT-5.6부터 최상위 모델의 내부·외부 트래픽 모든 응답에 돌고 있으며, 기존 텍스트 분류기 위에 얹는 추가 계층이다. OpenAI는 프로브가 훨씬 큰 텍스트 분류기보다 탈옥에 강하고, 생성 중간에 끊을 수 있으며, 실행 비용이 훨씬 낮다고 주장한다. 반면 라벨 데이터로 학습한 행동만 잡고, 새 기반 모델마다 재학습이 필요하며, 적응형 공격은 여전히 열린 문제라고 스스로 한계를 적었다. 정량 수치는 대부분 그림으로만 제시되어 있다.

## 동작 원리
텍스트 분류기는 모델이 ‘말한 결과물’을 읽고, 프로브는 모델이 ‘생각하는 중의 내부 상태’를 읽는다. 인코딩·난독화로 텍스트 필터를 속이는 탈옥도 모델 자신은 그 뜻을 이해해야 답을 할 수 있으므로, 이해한 흔적이 활성화에 남는다는 것이 핵심 가정이다. 구조는 MLP와 어텐션 프로브에 지수 이동 평균을 붙여 토큰마다 점수를 내는 형태로, 롤링 평균보다 스트리밍 상태가 작다. 점수가 임계값을 넘으면 스트림을 멈추고 더 비싼 추론 모델이 최종 판정을 내리며, 그 사이 도구 호출은 막아 둔다. 감시 대상 모델이 강해질수록 입력(활성화)도 풍부해져 프로브 성능이 함께 오른다는 점이 텍스트 분류기와 다르다.

## 플랫폼 엔지니어 관점
- 자체 호스팅 오픈 웨이트 모델을 서빙하는 팀은 가드레일을 ‘입·출력 텍스트 필터’에만 두지 말고, 추론 엔진 안에서 활성화를 읽는 계층(프로브)을 둘 수 있는지 검토한다. 이 경우 가드레일이 서빙 엔진과 같은 장애 영역에 들어가므로, 프로브가 죽으면 응답을 막는 fail-closed 정책을 명시한다.
- 경보가 울렸을 때 ‘생성 중단 + 도구 호출 보류 + 상위 판정’으로 이어지는 흐름은 에이전트 플랫폼에도 그대로 적용된다. 게이트웨이에서 판정 대기 중인 도구 호출을 큐잉하는 상태를 설계해 둔다.
- 모델 버전을 올릴 때마다 프로브·분류기 재학습과 재보정이 배포 체크리스트에 들어가야 한다. 모델 레지스트리에서 모델 버전과 프로브 버전을 짝으로 묶어 관리한다.
- 성능 지표는 재현율 하나가 아니라 실제 트래픽에서의 에스컬레이션 비율과 함께 본다(경보 운영 비용). 적응형 공격 레드팀 결과가 없는 한 ‘탈옥에 강하다’는 주장은 비교 지표로만 받아들인다.
