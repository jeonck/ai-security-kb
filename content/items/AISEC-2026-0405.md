## 요약
Kaspersky가 2026년 9~10월 아프리카·중남미 교육기관을 노린 침해에서 오픈소스 프레임워크 CyberStrikeAI가 쓰인 사실을 공개했다. 공격자는 침해된 SQL Server로 들어와 사람 손으로 하루쯤 정찰한 뒤 2주를 쉬었고, 이어 CyberStrikeAI 임플란트를 심었다. 그 뒤로는 공격자 서버의 LLM이 명령을 골라 내려보내며 정찰·권한 상승·자격 증명 덤프·측면 이동·DB 반출을 진행했고, 임플란트 배치부터 도메인 관리자 탈취까지 3~4일, 마지막 측면 이동과 반출은 1시간 안에 끝났다. 귀속은 중국어 사용 운영자 정황에 그친다. 같은 도구는 앞서 일본 표적 공격(AISEC-2026-0225)에서도 확인됐다.

## 동작 원리
두뇌와 손이 분리된 구조다. 두뇌(LLM 오케스트레이터)는 공격자의 C2 서버에 있고, C2의 기능들 — 스캐너 실행, 웹셸 관리, 에이전트에 작업 배정 — 이 MCP 도구로 모델에 주어진다. 운영자가 ‘도메인을 장악하라’ 같은 큰 목표만 주면 모델이 어떤 명령을 어떤 순서로 보낼지 정한다. 손(임플란트)은 피해 PC에서 C2를 폴링해 명령을 실행하고 결과를 돌려줄 뿐, AI도 API 키도 갖고 있지 않다. 그래서 피해 쪽 네트워크에서 보이는 것은 AI API 호출이 아니라 평범한 C2 트래픽과, 사람이 하던 것과 똑같은 기법(LSASS 덤프, DCSync, WMI·WinRM 측면 이동)이다. 달라진 것은 속도다.

## 플랫폼 엔지니어 관점
- ‘AI 서비스로 나가는 트래픽’을 감시하는 것만으로는 이런 공격을 못 잡는다. 탐지 규칙은 기법 기준으로 둔다: LSASS 메모리 접근, comsvcs.dll MiniDump, 원격 schtasks(`/s`), WMI·WinRM 원격 실행, LDAP 정찰·Kerberoasting 요청 폭주, cron·.bashrc 변경.
- 에이전트형 공격은 단계 사이가 분 단위로 짧다. 경보부터 격리까지의 대응 시간을 시간 단위가 아니라 분 단위로 설계하고, 야간·주말 커버리지를 점검한다.
- 초기 침투 지점이 DB 서버였다. 서비스 계정 권한(SQL Server 프로세스에서 OS 명령 실행 가능 여부), 인터넷 노출 DB를 점검한다.
- 쿠버네티스·클라우드 환경이라면 같은 논리로 워크로드 신원의 범위를 줄여, 한 노드에서 얻은 자격 증명이 클러스터·디렉터리 전체 관리자로 이어지지 않게 한다.
