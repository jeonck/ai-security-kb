## 요약
AWS가 11월 2일 서버리스 애플리케이션 배포용 MCP 서버(awslabs.aws-serverless-mcp-server)의 경로 조작 취약점 CVE-2026-116635를 공지했다. 배포 상태를 기록·조회하는 컴포넌트가 ‘프로젝트 이름’을 그대로 파일 경로에 써서, ../ 나 절대 경로를 넣으면 지정 디렉터리 밖의 JSON 파일을 읽을 수 있다. 쓰기 모드(--enable-write)를 켠 경우에는 그런 파일을 만들거나 덮어쓸 수도 있다. 공격자는 서버에 직접 접근할 필요 없이 에이전트가 읽는 제3자 콘텐츠로 조작된 이름을 넣게 만들면 된다. 0.2.1에서 수정됐고 우회책은 없다. 심각도는 중간(CVSS 6.1)이지만, AWS 공식 MCP 서버 계열에서 도구 인자 검증 결함이 이어지고 있다는 점이 눈에 띈다.

## 동작 원리
MCP 도구의 인자는 사람이 아니라 모델이 채운다. ‘프로젝트 이름’은 짧은 식별자라고 가정됐지만, 인젝션당한 에이전트는 그 칸에 ../../ 로 시작하는 경로를 넣을 수 있다. 서버가 그 값을 디렉터리 이름에 이어 붙여 파일을 열면, 이름표 칸에 주소를 적어 넣어 다른 방 서랍을 여는 셈이 된다. 결과는 고전적인 경로 조작이지만 방아쇠가 프롬프트 인젝션이라는 점이 에이전트 시대의 차이다. 읽은 JSON이 다시 에이전트 대화로 돌아오므로, 다른 도구의 설정·상태 파일이 노출되고 다음 단계에서 다른 도구로 새어 나갈 수 있으며, 쓰기 모드에서는 배포 메타데이터가 바뀔 수 있다.

## 플랫폼 엔지니어 관점
- 개발자 PC·CI 러너·에이전트 이미지에서 awslabs.aws-serverless-mcp-server 버전을 찾아 0.2.1 이상으로 올린다. uvx·pipx로 버전 미고정 실행하는 설정은 고정 버전으로 바꾸고, 포크·파생 코드에도 같은 수정을 반영한다.
- MCP 서버의 쓰기 플래그(--enable-write)는 필요한 작업 공간·세션에서만 켠다. 기본값은 읽기 전용으로 둔다.
- MCP 서버는 작업 디렉터리만 마운트한 전용 사용자·컨테이너에서 실행하고, 홈 디렉터리·~/.aws 등은 마운트하지 않는다. 경로 검증을 서버 코드에만 맡기지 않는다.
- 사내 MCP 서버 리뷰 체크리스트에 ‘식별자 인자가 파일 경로로 쓰이는가’를 넣고, 정규화 후 기준 디렉터리 포함 여부를 검사하게 한다.
