## 요약
Wenxi Dai 등 4명의 연구진이 언어 모델의 멤버십 추론 신호가 모델 안 어디에서 생기고 어떻게 출력으로 드러나는지를 기계론적으로 분석했다. 내부 표현에서 해독할 수 있는 정보(D)와 모델 출력이 실제로 쓰는 정보(U)를 나눠 재는 DUG 지표를 제안하고, SFT·RL 기반 공격·RLVR 학습을 비교했다. SFT는 표현과 출력 양쪽에 흔적을 남기지만, 정답 참조 없이 보상하는 RLVR로 평가 문항을 학습시키면 정답률 격차는 벌어지는데 우도 기반 탐지(Loss AUROC)는 0.49 수준으로 우연과 같았다. 평가 데이터 오염을 우도 검사로 확인하는 관행의 사각지대를 보여 준다.

## 동작 원리
멤버십 추론은 ‘이 문장을 학습할 때 봤는가’를 모델의 반응 차이로 맞히는 공격이다. 흔한 방법은 본 문장일수록 손실(perplexity)이 낮다는 점을 이용한다. SFT는 정답 텍스트 자체의 확률을 올리므로 이 흔적이 뚜렷하다. 반면 RLVR은 ‘답이 맞으면 보상’만 주기 때문에 특정 토큰열의 확률을 직접 끌어올리지 않는다. 모델은 그 문항을 더 잘 풀게 되지만 손실 값으로는 차이가 거의 남지 않는다. 비유하면, 시험지를 외운 학생(SFT)은 답안을 그대로 베껴 써서 들키지만, 같은 문제로 반복 연습한 학생(RLVR)은 풀이가 자연스러워 표절 검사기에 걸리지 않는 셈이다.

## 플랫폼 엔지니어 관점
- 사내 모델 평가 파이프라인이 ‘벤치마크 오염 검사’를 Min-k%·Loss 같은 우도 기반 지표로만 돌린다면, RL 단계(RLVR·GRPO 등)에서 섞여 들어간 평가 문항은 통과할 수 있다. 오염 검사는 학습 데이터 계보(어떤 프롬프트 세트가 어느 RL 잡에 들어갔는지) 기록과 함께 운영한다.
- RL 학습 잡의 프롬프트 풀과 평가 세트를 해시 기반으로 대조하는 단계를 CI에 두고, 결과를 모델 카드·AI-BOM에 남긴다. 사후 통계 검사보다 사전 출처 통제가 확실하다.
- 거꾸로, 개인정보·고객 데이터를 RL 보상 루프에 넣었다고 해서 멤버십 추론에서 안전하다고 단정하지 않는다. 이 연구는 우도 기반 신호만 봤고 행동 기반 신호(정답률 격차)는 벌어졌다.
- 외부 모델을 도입할 때 벤더가 제시하는 ‘오염 없음’ 근거가 어떤 검사법인지 확인하고, 사내 비공개 홀드아웃 세트로 별도 평가한다.
