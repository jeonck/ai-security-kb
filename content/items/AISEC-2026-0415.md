## 요약
Google 위협 인텔리전스 그룹(GTIG)과 Mandiant가 2026년에 직접 대응한 LLMjacking 사고들을 정리해 2026-11-02 공개했다. 공격자는 유출·탈취한 클라우드 신원 토큰이나 LLM API 키로 피해 조직 계정에 들어가, 원래 쓰지도 않던 LLM 서비스를 켜고 고가 모델로 대량 추론을 돌렸다. 일부 사고는 하루에 10만 달러 이상, 누적 100만 달러까지 과금됐다. 훔친 키를 모아 싸게 되파는 ‘LLM 믹서’ 서비스와 초기 접근 담당의 분업이 생기고 있고, LiteLLM 게이트웨이의 키 재발급 취약점(CVE-2026-40217)을 악용해 마스터 권한을 얻은 사례도 나왔다.

## 동작 원리
크립토재킹이 남의 서버에서 몰래 채굴하는 것이라면, LLMjacking은 남의 클라우드 계정 이름으로 비싼 모델 호출 요금을 긁는 것이다. 공격자는 GitHub에 노출된 키, 잘못 관리된 서비스 계정 키, 피싱한 세션 토큰으로 들어와 `max_tokens=1` 같은 아주 작은 요청으로 키가 살아 있는지 확인한다. 이후 피해 계정에서 Bedrock·Gemini API 같은 서비스를 켜고, 짧게 쓰고 버리는 서비스 계정을 돌려 속도 제한을 피한다. 이렇게 얻은 접근권은 new-api 같은 오픈소스 게이트웨이로 묶여 지하 상점에서 ‘무제한 요금제’로 팔린다. 조직 안에 LiteLLM 같은 모델 라우팅 게이트웨이가 있으면, 그 게이트웨이 자체의 취약점이 일반 가상 키를 관리자 키로 바꾸는 승강기가 된다.

## 플랫폼 엔지니어 관점
- 쓰지 않는 클라우드 프로젝트·계정에서는 LLM 서비스 활성화를 조직 정책(SCP·조직 정책 제약)으로 막고, `EnableService`·`PutUseCaseForModelAccess`·`CreateFoundationModelAgreement`·Azure 배포 생성 이벤트를 최고 심각도 경보로 건다.
- 모델 호출 감사 로그(Bedrock 호출 로깅, GCP Data Access 로그)는 기본으로 꺼져 있는 경우가 많으니 켜고, 로깅 설정 삭제·변경을 IaC 주체가 아닌 계정이 하면 경보한다.
- LLM API 키는 모델·환경·사용량 한도로 범위를 좁히고 모델별 쿼터·예산 상한을 둔다. 장기 서비스 계정 키·IAM 액세스 키는 워크로드 아이덴티티(OIDC·IRSA·Workload Identity Federation)로 대체한다.
- 사내 LiteLLM·AI 게이트웨이를 취약점 관리 대상에 넣고 CVE-2026-40217 패치 여부를 확인한다. 게이트웨이 마스터 키·가상 키 재발급 엔드포인트 접근을 관리망으로 제한한다.
- CI의 시크릿 스캔과 GitHub PAT 최소화(세분화 PAT·만료)를 다시 점검하고, 저용량 반복 검증 요청 패턴을 탐지 규칙으로 만든다.
