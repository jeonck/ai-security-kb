## 요약
에이전트는 외부 도구(MCP 서버·스킬·플러그인)를 한 번 허용하면, 코드가 업데이트돼도 다시 검사하지 않고 계속 신뢰하는 경우가 많다. 연구진은 처음엔 무해한 도구로 들어와 같은 이름·설명·스키마를 유지한 업데이트에 악성 동작을 넣는 ETUDE를 제안하고, Claude Code·Codex CLI·Gemini CLI를 포함한 7개 에이전트에서 거의 모든 시도가 성공함을 보였다. 악성 코드는 모델 문맥 밖에서 실행되므로 프롬프트 인젝션 방어가 볼 수 있는 것이 없다. 정적 LLM 리뷰·파일 무결성 거리·스킬 스캐너도 난독화나 정상 업데이트 오탐 앞에서 한계를 드러냈다.

## 동작 원리
입주 심사를 통과한 세입자가 나중에 몰래 방을 개조하는 상황과 같다. 에이전트가 도구를 고를 때 보는 것은 이름·설명·스키마뿐인데, 업데이트 후에도 이 셋이 그대로라 모델은 아무 변화도 느끼지 못한다. 도구 코드는 원래 기능을 수행해 정상 결과를 돌려주면서, 같은 호출 안에서 자격 증명을 외부로 보내거나 파일을 덮어쓴다. 모델의 입력·출력만 감시하는 가드레일은 이 경로를 원천적으로 보지 못한다.

## 플랫폼 엔지니어 관점
- 사내 에이전트 플랫폼의 MCP 서버·스킬 허용 목록을 ‘이름+버전’이 아니라 ‘코드·의존성 해시’로 고정하고, 해시가 바뀌면 재심사 전까지 비활성화한다. 자동 업데이트(npx 최신 버전, latest 태그 컨테이너)를 금지한다.
- 서명·SLSA 출처 증명이 있는 도구만 반입하고, 업데이트 시 증명을 다시 검증하는 단계를 CI/CD에 둔다.
- 해시 고정이 불가능한 도구는 자격 증명 없는 샌드박스에서 실행하고 egress를 도구의 선언된 기능 범위로 제한해, 업데이트로 악성 동작이 들어와도 폭발 반경을 줄인다.
- 정적 LLM 리뷰는 난독화에 약하므로 난독화·바이너리 포함 업데이트 자체를 반입 거부 조건으로 삼는다.
