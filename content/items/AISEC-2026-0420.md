## 요약
AI 에이전트와 백그라운드 워크플로를 호스팅하는 Trigger.dev가 2026-11-01(일) 상태 페이지에 보안 공지를 올렸다. 공격자는 일부 조직의 환경 변수에 무단으로 접근했고, 회사는 악용 경로를 막은 뒤 영향 계정 소유자에게 조치 안내 메일을 보냈다고 밝혔다. 원인, 노출 기간, 영향 조직 수는 공개하지 않았고 언론 질의에도 전체 보고서를 기다려 달라고만 했다. 10월 AI 개발 플랫폼이 연달아 침해된 흐름(AISEC-2026-0341, AISEC-2026-0342) 바로 뒤에 나온 사고다.

## 동작 원리
호스팅 워크플로 플랫폼에서 환경 변수는 ‘금고 열쇠 꾸러미’다. 사용자의 작업이 LLM API, 결제(Stripe), DB(Supabase), 메신저(Slack)를 부르려면 그 키를 플랫폼에 맡겨야 하고, 플랫폼은 실행할 때 이를 꺼내 준다. 플랫폼 쪽의 한 지점이 뚫리면 여러 고객의 열쇠 꾸러미가 한꺼번에 새고, 공격자는 각 고객의 연결 서비스에 정상 키로 접속할 수 있다. 에이전트 플랫폼일수록 연결된 서비스가 많아 피해 반경이 커진다.

## 플랫폼 엔지니어 관점
- Trigger.dev(클라우드판)를 쓰는 팀은 안내 메일 수신 여부와 관계없이 저장된 모든 환경 변수(LLM API 키, DB·결제·메신저 토큰, GitHub 토큰)를 교체하고, 연결 서비스의 접근·과금 로그를 11월 1일 전후로 점검한다.
- 서드파티 실행 플랫폼에는 장기 정적 키 대신 짧은 수명 토큰, OIDC 연동, 범위를 좁힌 전용 키를 준다. 키마다 어떤 플랫폼에 들어가 있는지 목록을 유지해 회수 범위를 빨리 정할 수 있게 한다.
- AI 개발 플랫폼 공급사 상태 페이지를 모니터링 대상에 넣고, 사고 공지가 뜨면 키 회수 런북이 바로 돌도록 준비한다.
- LLM API 키에는 사용량·비용 경보를 걸어, 유출된 키로 인한 LLMjacking(AISEC-2026-0415)을 조기에 감지한다.
