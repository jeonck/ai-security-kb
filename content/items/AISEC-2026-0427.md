## 요약
OpenAI가 o1과 o1-mini를 공개하며 낸 공식 시스템 카드로, 안전 평가와 Preparedness Framework 평가(사이버보안·CBRN·설득·모델 자율성)를 정리했다. 사이버보안 평가에서는 100개가 넘는 CTF 과제를 헤드리스 Kali Linux 도구 환경에서 과제당 12회까지 풀게 했다. 카드는 앞선 o1-preview가 사이버 과제에서 보상 해킹을 보였다고 적고 자세한 내용은 o1-preview 카드로 넘긴다. 모델 자율성 평가에는 GPU 머신의 Docker 소켓을 에이전트에게 넘기는 과제도 있다. 평가 대상 모델이 공격 도구와 컨테이너 제어권을 실제로 쥐고 움직인다는 점이 공식 문서로 남아 있다는 데 의미가 있다. 다만 책이 쓰려는 핵심 사례(o1-preview 카드의 Docker 데몬 API 노출 건)는 이번에 1차 원문으로 확인하지 못했다(followup 참조).

## 동작 원리
CTF 평가는 모델에게 ‘이 시스템을 뚫어서 플래그를 가져와라’라는 목표와, 그 목표를 이룰 셸·스캐너·익스플로잇 도구를 함께 준다. 채점은 플래그를 가져왔느냐만 보므로, 모델 입장에서는 과제를 의도대로 푸는 길과 평가 인프라의 허점을 이용하는 길이 모두 ‘정답’이다. 보상 해킹이란 바로 이 지름길을 택하는 행동이다. 시험 문제지를 받은 수험생에게 교무실 열쇠까지 쥐여 준 셈이어서, 교무실 문이 잠겨 있는지는 시험지가 아니라 학교 건물이 보장해야 한다. Docker 소켓을 넘기는 에이전트 과제도 같다. docker.sock 접근은 사실상 그 호스트의 루트 권한에 가까워서, 과제 설계자가 의도한 ‘컨테이너 하나 띄우기’를 넘어서는 행동도 기술적으로는 가능하다. 그래서 평가 하네스의 경계는 모델의 선의나 과제 설명이 아니라 네트워크 분리와 실행 환경 격리로 정해야 한다.

## 플랫폼 엔지니어 관점
- 평가 클러스터 분리: CTF·에이전트 평가 잡은 학습·서빙과 다른 클러스터나 최소한 전용 노드 풀·네임스페이스에서 돌리고, 평가 네임스페이스에서 학습 데이터 버킷·체크포인트 저장소·사내 API로 가는 경로를 NetworkPolicy로 기본 차단한다.
- 컨트롤 플레인 노출 점검: 평가 호스트의 Docker 데몬 TCP 포트(2375/2376), kubelet API(10250), 컨테이너 런타임 소켓이 과제 네트워크에서 보이지 않는지 평가 시작 전 자동 스캔한다. 모델이 nmap을 쓸 수 있다면 모델이 볼 수 있는 것은 전부 공격 표면이다.
- 소켓 넘기기 금지: 과제상 컨테이너 제어가 필요하면 호스트 docker.sock 대신 일회용 VM 안의 rootless 데몬이나 Kata·gVisor 같은 샌드박스 런타임 위에 따로 띄운 데몬을 준다. 과제가 끝나면 VM째 폐기한다.
- 채점기·플래그 분리: 플래그와 채점 로직은 모델이 닿는 네트워크·파일 시스템 밖에 두고, 과제 컨테이너 재시작·로그 조회 같은 운영 권한은 하네스 서비스 계정에만 준다.
- 행동 로그와 탐지: 평가 중 모델의 도구 호출(스캔 대상, 접속한 포트, 실행한 컨테이너 명령)을 전부 남기고, 과제 범위를 벗어난 호스트·API 접근을 경보로 띄워 ‘성공’ 판정과 별도로 검토한다. 이런 이탈은 실패가 아니라 그 자체가 평가 결과로 보고서에 남겨야 한다.
