## 요약
Bitdefender가 9월 10~19일 영국의 한 학교 법인에서 벌어진 3AM 랜섬웨어 침투를 분석해 11월 3일 공개했다. 공격자는 관리되지 않는 호스트에서 약 50대에 접근해 백업 자격 증명 탈취, Mimikatz 실행, 백도어 도메인 관리자 계정 생성, 분리돼 있던 세 도메인 간 트러스트 구성을 거쳐 약 37대를 암호화했다. 명령 재시도가 일정한 40~101초 리듬으로 반복되고, 모델이 잘못 기억한 듯한 API 포트와 Unix식 습관이 Windows 명령에 섞여 있었다. Bitdefender는 사람이 방향을 정하고 에이전트 루프가 실행을 맡은 ‘하이브리드’ 공격으로 추정하면서도, 공격자 기기를 보지 못해 확정할 수 없다고 선을 그었다.

## 동작 원리
사람 운영자는 실패하면 생각하고, 고치고, 다시 치는 데 들쑥날쑥한 시간이 걸린다. 에이전트 루프는 ‘명령 실행 → 출력 읽기 → 한 군데 고쳐 재실행’을 모델 응답 시간만큼 일정한 간격으로 돈다. 이번 사고에서는 작은 수정이든 큰 수정이든 재시도가 40~101초로 일정했고, 큰 방향 전환 사이에는 2~16분의 사람다운 공백이 있었다. 여기에 공식 문서와 다른 Veeam 포트·인증 방식, Windows에 섞인 Bash 문법처럼 ‘학습 기억에서 끌어온 명령’의 흔적이 겹쳤다. 도구 자체는 공개 도구와 기존 3AM 암호화기였으므로, AI가 새 무기를 만든 것이 아니라 기존 수법의 실행 속도와 끈기를 높인 사례에 가깝다.

## 플랫폼 엔지니어 관점
- 탐지 규칙에 행동 리듬을 넣는다: 같은 호스트에서 거의 같은 명령이 일정 간격으로 조금씩 바뀌며 반복되는 패턴, 존재하지 않는 포트·잘못된 인증 방식으로의 반복 시도는 에이전트 루프 신호로 볼 수 있다.
- 백업 서버는 도메인별 계정으로 분리하고 운영 도메인과 격리하며, 불변 복구 사본을 둔다. 백업 DB 자격 증명 읽기, SAM·SECURITY·SYSTEM 하이브 저장, 새 도메인 트러스트 생성은 즉시 경보 대상으로 둔다.
- WMI·원격 레지스트리·예약 작업 생성·ADMIN$ 접근은 알려진 관리 호스트에서만 허용하고, 필요 없는 워크스테이션에서는 PowerShell·Python 실행을 막는다.
- 모든 기기에 엔드포인트 에이전트를 배포해 ‘관리되지 않는 호스트’라는 사각지대를 없앤다. 이번 공격의 발판이 바로 그 사각지대였다.
