## 요약
SurrealDB가 내장한 MCP 서버(HTTP 전송)에서 세션 가로채기·권한 상승 취약점이 고쳐졌다. JWT·Bearer 방식으로 인증한 사용자는 개인이 아니라 ‘접근 방식 이름’으로 식별돼, 같은 방식을 쓰는 사람끼리 세션 지문이 똑같았다. 그래서 가장 낮은 권한의 사용자도 남의 mcp-session-id만 알면 그 사람의 역할로 MCP 도구를 실행할 수 있었다. 저장소 권고는 10월 19일 3.3.0 수정과 함께 나왔고, 11월 3일 CVE-2026-121419로 NVD·GitHub Advisory Database에 공개됐다.

## 동작 원리
호텔이 객실 카드키를 확인할 때 ‘손님 이름’이 아니라 ‘투숙 플랜 이름’만 본다고 생각하면 된다. 같은 플랜의 손님이면 아무 방 번호(세션 ID)나 대고 들어갈 수 있다. MCP 세션은 처음 만든 사람에게 묶여야 하는데, 묶는 기준이 사용자별 sub 클레임이 아니라 공유된 접근 방식 이름이어서 묶음이 사실상 없었다. 게다가 감사 로그도 같은 공유 신원으로 기록돼, 누가 무엇을 했는지 나중에 가릴 수도 없다.

## 플랫폼 엔지니어 관점
- MCP를 HTTP로 노출한 SurrealDB를 3.3.0 이상으로 올리고, 여러 사용자가 공유하는 JWT·Bearer 접근 방식을 쓰는지 점검한다.
- mcp-session-id를 인증 정보로 취급해 인그레스·프록시·APM·로그 수집기에서 마스킹한다. 세션 ID가 로그에 찍히는 순간 이 버그의 두 번째 조건이 채워진다.
- 사내 MCP 서버 설계 원칙으로 ‘세션은 토큰의 sub(사용자) 단위로 바인딩, 요청마다 재검증’을 명시하고, 서비스 계정 하나로 여러 사용자를 대리하는 구조는 사용자 신원을 별도 클레임으로 전달하게 한다.
- 감사 로그가 공유 신원(::api 등)으로만 남는 시스템은 사고 대응에서 귀속이 불가능하므로, MCP 도구 호출 로그에 원 사용자 ID를 함께 기록하도록 게이트웨이 단에서 보강한다.
