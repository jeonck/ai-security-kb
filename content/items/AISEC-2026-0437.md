## 요약
GitHub이 11월 3일 Dependabot의 버전 업데이트 대상에 Agent Package Manager(APM)를 추가했다. APM은 Microsoft가 만든 오픈소스 도구로, 에이전트가 쓰는 스킬·프롬프트·지침·플러그인·MCP 서버를 apm.yml에 선언하고 잠금 파일로 고정한다. 이제 Dependabot이 apm.yml의 git 의존성에 새 버전이 나오면 PR을 열고 apm.lock.yaml도 다시 만든다. 다만 지원은 버전 업데이트뿐이고, 취약점이 알려진 스킬을 골라 고치는 보안 업데이트는 지원하지 않는다. github.com 전 요금제에서 쓸 수 있고 GHES는 3.24에서 들어온다.

## 동작 원리
지금까지 에이전트 스킬이나 지침 파일은 저장소에 복사해 두거나 README 안내로 설치하는 경우가 많아, 누가 언제 어떤 버전을 들였는지 추적이 어려웠다. APM은 npm의 package.json·package-lock.json처럼 선언과 고정을 분리한다. 선언(apm.yml)은 ‘이 저장소는 어느 git 저장소의 어느 태그 스킬을 쓴다’를 적고, 잠금 파일은 실제로 받은 내용의 해시를 적어 다시 받아도 같은 바이트가 오게 한다. Dependabot은 그 위에서 ‘새 버전이 나왔다’는 PR을 만들어 사람이 검토하고 병합하게 한다. 즉 스킬 변경이 코드 리뷰 경로를 타게 된다. 반대로 보안 업데이트가 없다는 것은, 악성으로 밝혀진 스킬 버전을 자동으로 알려 줄 권고 데이터베이스와의 연결이 아직 없다는 뜻이다.

## 플랫폼 엔지니어 관점
- 사내 에이전트 골든 패스에 apm.yml + 잠금 파일을 표준으로 넣고, 스킬·지침을 저장소에 복붙하는 방식을 금지한다. 잠금 파일이 있어야 사고 때 ‘어느 스킬 버전이 돌았나’를 답할 수 있다.
- Dependabot APM PR은 일반 라이브러리 PR보다 위험도가 높다(에이전트 행동을 바꾸는 텍스트). CODEOWNERS로 보안·플랫폼 팀 리뷰를 필수로 걸고 자동 병합(auto-merge) 대상에서 뺀다.
- apm-policy.yml로 허용 출처(조직 내부 git 서버 등)와 전이 MCP 서버 차단을 조직 단위로 강제한다.
- 보안 업데이트가 없으므로, 악성 스킬 공지(예: 레지스트리 악성 권고)를 별도로 구독해 apm.lock.yaml을 검색하는 CI 잡을 둔다.
