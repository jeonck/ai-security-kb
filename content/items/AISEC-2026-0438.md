## 요약
CMS인 Instatic에 붙은 AI 채팅·MCP용 콘텐츠 읽기 도구가 권한 검사를 빠뜨렸다. 일반 HTTP API는 ‘이 행을 이 사용자가 볼 수 있는가’를 확인하지만, AI·MCP 도구는 ‘이 사용자가 해당 능력을 가졌는가’만 봤다. 그래서 자기 글만 편집할 수 있는 낮은 권한 사용자도 AI 도구를 통하면 다른 사람의 비공개 초안과 시스템 테이블을 읽을 수 있었다. 0.0.21에서 고쳐졌고 11월 3일 CVE-2026-121458로 공개됐다.

## 동작 원리
건물 정문(HTTP API)에는 출입 카드 검사기가 층·방마다 있는데, 새로 낸 AI 전용 출입구는 ‘직원증이 있는가’만 확인하고 어느 방이든 들여보낸 셈이다. 기존 앱에 MCP 도구를 붙일 때 데이터 조회를 기존 서비스 계층이 아니라 저장소 쿼리로 직접 구현하면, 그 서비스 계층에 들어 있던 객체 단위 인가가 통째로 빠진다. 모델은 사용자가 묻는 대로 도구를 부르므로, 이런 옆문은 ‘모델에게 다른 사람 초안을 보여 달라고 묻기’만으로 열린다.

## 플랫폼 엔지니어 관점
- Instatic을 운영한다면 0.0.21 이상으로 올린다.
- 사내 앱에 MCP 서버·AI 도구를 붙이는 팀에게 ‘도구 핸들러는 기존 API와 같은 인가 함수를 거친다’를 리뷰 체크리스트로 요구하고, 같은 요청을 HTTP와 MCP로 보내 결과가 같은지 비교하는 계약 테스트를 CI에 넣는다.
- 능력(역할) 검사와 객체 단위 검사(행 소유자·테이블 권한)를 구분해 MCP 도구 단위 인가 정책(CEL·Cedar·OPA 등)으로 명시한다.
- MCP 도구 호출 로그에서 한 사용자가 여러 소유자의 문서를 연속으로 조회하는 패턴을 열거 시도 신호로 잡는다.
