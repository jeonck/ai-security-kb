## 요약
GPUStack은 vLLM·SGLang·TensorRT-LLM 같은 추론 엔진을 GPU 클러스터에 올려 주는 오픈소스 관리 도구다. 11월 4일 NVD에 이 도구의 인증·인가 결함 세 건이 CVE로 올라왔다. 가장 심각한 CVE-2026-102895(9.8)는 루프백에서 온 것으로 보이는 요청을 무조건 관리자로 대우하는 결함이다. 권고문에 따르면 v2.1.1 배포에서 실제로 악용됐고, 공격자는 리버스 셸을 띄우는 사용자 정의 추론 백엔드를 만들었다. 여기에 서명을 검증하지 않는 SAML 콜백(9.1)과, 비관리자가 워커의 Kubernetes ServiceAccount로 클러스터를 조작할 수 있는 API 프록시(8.8)가 함께 공개됐다. 수정 버전은 2.2.0(루프백)과 2.2.2(SAML·프록시)다.

## 동작 원리
‘집 안에서 문을 두드리면 가족이다’라는 규칙을 둔 것과 같다. GPUStack은 요청의 출발지가 127.0.0.1이면 로그인 없이 관리자로 통과시켰다. 그런데 운영자가 흔히 그러듯 같은 호스트에 nginx를 두고 127.0.0.1로 넘기면, 인터넷에서 온 모든 요청의 출발지가 127.0.0.1이 된다. 프록시가 모든 외부인을 가족으로 바꿔 버리는 셈이다. 헤더 하나(X-GPUStack-Real-IP)를 위조해도 결과는 같았다. 관리자가 되면 ‘추론 백엔드를 YAML로 등록’하는 정상 기능이 그대로 임의 명령 실행 통로가 된다. 서빙 플랫폼에서는 ‘모델을 띄우는 기능’ 자체가 곧 코드 실행이기 때문이다. SAML 결함은 신분증의 위조 방지 표식을 확인하지 않고 이름만 읽은 것이고, 프록시 결함은 직원 출입증(ServiceAccount)을 들고 손님 대신 심부름을 다녀 준 것이다.

## 플랫폼 엔지니어 관점
- GPUStack을 쓰면 즉시 2.2.2 이상으로 올리고, 업그레이드 전까지는 force_auth_localhost=true, 엣지에서 X-GPUStack-Real-IP 헤더 제거, /auth/saml/callback 차단을 적용한다. 2.1.x를 노출했던 인스턴스는 침해를 전제로 본다. 관리자 API 키(특히 범위 ‘*’), 등록된 추론 백엔드 목록, 워커·클라우드 시크릿을 점검하고 회수한다.
- 같은 패턴을 다른 자체 호스팅 AI 도구(Ollama 프론트엔드, 모델 게이트웨이, 대시보드)에서도 찾는다. 소스 IP나 클라이언트가 보내는 헤더를 인증 신호로 쓰는 코드는 사이드카·인그레스 뒤에서 모두 무력화된다. 인증은 앞단 OIDC 프록시나 mTLS에서 한다.
- 서빙 관리 평면에 주는 Kubernetes ServiceAccount는 네임스페이스 단위 최소 권한으로 줄이고, 관리 API는 NetworkPolicy로 운영자 대역에서만 열어 둔다. 감사 로그에서 ‘새 추론 백엔드 등록’과 ‘관리자 키 생성’을 고위험 이벤트로 경보한다.
