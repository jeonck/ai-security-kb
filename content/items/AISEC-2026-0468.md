## 요약
인도 CERT-In과 금융 부문 CSIRT-Fin은 2026-11-04 Critical 권고 CIAD-2026-0058을 내고, 10월 권고(CIAD-2026-0046)에서 경고한 AI 보조 금융 공격이 격화됐다고 알렸다. 행위자 CRAFTY FALCON은 AI로 정찰과 익스플로잇 작성을 자동화하고, 노출된 테스트 환경과 클라우드 관리 서비스를 거쳐 들어간 뒤 피해 기관의 결제·지급 API를 직접 불러 돈을 옮긴다. 권고는 PentAGI 같은 공개 자율 침투 에이전트와 ARTEX 계열 LLM 도구를 이름까지 들어 명시했다. 대응책 27개는 금융 거래 통제뿐 아니라 클라우드 권한, egress, CI/CD 토큰, AI 코딩 에이전트와 LLM API 키 관리까지 플랫폼 운영 영역을 넓게 다룬다.

## 동작 원리
공격자는 사람이 몇 주 걸릴 정찰·취약점 검증·스크립트 작성을 AI 공격 도구에 맡기고, 결과물을 빠르게 변형해 여러 기관에 동시에 던진다. 길목은 화려하지 않다. 인터넷에 열린 스테이징 서버, 운영과 공유하는 자격 증명, 넓은 권한의 클라우드 관리 역할, 아무 데나 나갈 수 있는 서버리스 함수가 사다리가 된다. 운영 환경에 닿으면 기관이 스스로 만든 정상 결제 API를 호출하므로 겉보기에는 정상 거래처럼 보인다. 1루피짜리 시험 이체로 경로를 확인한 뒤 큰 금액을 보내는 식이다. 도둑이 AI 조수에게 건물 도면 분석과 열쇠 복제를 맡기고, 정작 금고는 건물의 정식 출금 창구로 여는 셈이다.

## 플랫폼 엔지니어 관점
- 비운영(UAT·스테이징) 클러스터·계정이 운영과 시크릿·네트워크 경로를 공유하지 않는지 점검하고, 비운영에서 운영으로 향하는 접근에 알림을 건다.
- 클라우드 관리·서버리스 실행 권한(SSM, Lambda 배포)을 승인된 주체로만 제한하고, 대화형 세션과 운영 함수 변경에 알림을 건다. 서버리스·서버 세그먼트는 기본 차단 egress에 허용 목록 프록시만 연다.
- CI/CD에서 하드코딩 시크릿 스캔, 단기·최소 권한 토큰, 빌드·배포 토큰 정기 교체, 비정상 IP·UA에서의 토큰 사용 탐지를 적용한다.
- 에이전트 플랫폼 팀은 권한 확인을 끈 모드로 돌아가는 AI 코딩 에이전트와 서버·비개발 호스트에서 나가는 LLM API 트래픽을 탐지 규칙에 넣고, LLM API 키를 자산으로 관리한다.
- 탐지 상관 규칙을 기계 속도·다중 도구 공격에 맞게 조정하고, 휴일·주말 감시 임계값을 낮춘다.
