## 요약
Mistral의 터미널 코딩 에이전트 Vibe에서, 세션을 시작할 때 프로젝트 정보를 시스템 프롬프트에 넣으려고 실행하는 git 명령이 폴더 신뢰 확인보다 먼저 돌아 악성 저장소의 코드를 실행하는 취약점 3건이 2026-11-04 VulnCheck를 통해 CVE로 공개됐다. gpg.program(서명 검증 프로그램) 설정, clean·process 필터 드라이버, 그리고 Windows에서 저장소 루트에 놓인 가짜 git.exe가 각각의 경로다. 세 건 모두 CVSS v4 8.6이다. 2.25.5·2.25.7·3.0.3에서 차례로 고쳐졌다. 10월 말 공개된 --worktree 모드의 필터 드라이버 RCE(AISEC-2026-0184)에 이어, 같은 제품에서 같은 계열의 결함이 연달아 나온 셈이다.

## 동작 원리
Vibe는 ‘이 폴더를 믿겠습니까’라고 묻기 전에, 에이전트에게 맥락을 주려고 git status·git log로 저장소 상태를 먼저 읽었다. 문제는 git이 단순한 읽기 도구가 아니라는 점이다. 저장소 설정(.git/config)은 ‘파일 상태를 볼 때는 이 필터를 거쳐라’, ‘서명을 확인할 때는 이 프로그램을 불러라’를 지정할 수 있고, Windows는 현재 폴더의 git.exe를 시스템 git보다 먼저 찾을 수 있다. 문지기가 손님에게 질문하기 전에 손님이 건넨 명함(저장소 설정)을 읽는 순간 이미 손님의 지시가 실행되는 구조다. 한 경로를 막으면 다른 설정 키로 같은 일이 되풀이되어 수정이 세 번에 걸쳐 나왔다.

## 플랫폼 엔지니어 관점
- 개발자 PC·CI 러너의 Vibe를 3.0.3 이상으로 올리고, 버전 고정 목록에 반영한다. Windows 개발 환경은 2.25.5 미만이 남아 있지 않은지 따로 확인한다.
- 에이전트가 외부 저장소를 처음 여는 작업은 자격 증명 없는 일회용 컨테이너·devcontainer에서 하고, 그 환경의 egress를 패키지 미러·git 프록시로 제한한다.
- 에이전트 플랫폼이 git을 부르는 경로는 core.hooksPath 무력화, filter.*·core.fsmonitor·gpg.program·log.showSignature 덮어쓰기, 절대 경로의 git 바이너리 사용을 강제하는 래퍼로 표준화한다. safe.directory는 신뢰 판단을 대신하지 못한다.
- 코딩 에이전트 도구 평가 항목에 ‘신뢰 확인 이전에 실행되는 모든 외부 명령(git·패키지 매니저·언어 서버)의 목록’을 요구한다.
