## 요약
OpenAI는 공개 전 사이버 특화 모델로 돌리는 자율 파이프라인을 공개했다. 파이프라인은 리눅스 커널에서 취약점 후보를 찾고, 샌드박스에서 재현하고, 익스플로잇과 패치를 만든 뒤 사람의 검토를 거쳐 메인테이너에게 보고한다. 10월 중순의 한 번 실행에서 후보 2,308건 중 1,724건을 30시간 안에 재현했다. 작동하는 로컬 권한 상승(LPE) 익스플로잇은 1,169개였고, 서로 다른 취약점으로 묶으면 948건이다. 비용은 API 크레딧 약 121만 달러로, 취약점 하나에 1,279달러꼴이다. OpenAI는 당분간 패치되지 않은 시스템의 저권한 계정을 root로 간주해야 한다고 주장했다. 1차 원문은 열지 못해 보도 두 건으로 확인한 내용이다.

## 동작 원리
사람 연구자 팀의 분업을 에이전트 여러 종류로 바꾼 구조다. 스카우트가 저권한 사용자가 닿을 수 있는 코드 영역을 골라 범위를 약 7%로 좁힌다. 분석가는 격리된 VM에서 버그를 실제로 재현해 증거를 남긴다. 익스플로잇 개발자는 그 버그로 정보 유출이나 root 획득이 되는지 PoC로 입증한다. 패치 작성자가 수정안을 만들고 마지막에 사람이 검토한다. 핵심은 비용 곡선이다. 7월 실행의 고유 LPE는 166건이었는데 석 달 뒤에는 948건이 됐다. 커널 익스플로잇은 그동안 숙련자 몇 명이 몇 주를 들이는 일이었는데, 이제 클라우드 요금 몇백만 원 수준으로 내려왔다.

## 플랫폼 엔지니어 관점
- **격리 가정을 바꾼다**: 에이전트 샌드박스, CI 러너, 멀티테넌트 노트북처럼 남의 코드를 돌리는 컨테이너가 호스트 커널을 공유한다면 ‘컨테이너 안 비root 사용자’를 경계로 보지 않는다. 신뢰할 수 없는 코드는 gVisor·Kata·Firecracker 같은 별도 커널 경계(RuntimeClass)에서 돌리고, 노드 풀을 테넌트·신뢰 등급별로 나눈다.
- **커널 패치 속도를 지표로 관리한다**: 노드 이미지와 커널 버전을 자산 목록으로 추적한다. 배포판 커널 보안 업데이트가 나오면 노드를 자동으로 교체·재부팅하는 경로(kured, 관리형 노드 자동 업그레이드)를 열어 두고, PodDisruptionBudget을 미리 맞춰 반영까지 걸린 시간을 잰다.
- **공격 표면을 줄인다**: seccomp 기본 프로필(RuntimeDefault), 비특권 사용자 네임스페이스 제한, 불필요한 커널 모듈 블랙리스트로 저권한 사용자가 닿는 커널 코드를 줄인다. 이번 파이프라인도 바로 이 ‘저권한으로 닿는 코드’를 표적으로 골랐다.
- **탐지는 root 획득 뒤를 본다**: 컨테이너 안에서 갑자기 uid 0이 되거나 네임스페이스를 벗어나는 사건을 Falco·Tetragon 같은 런타임 탐지로 경보한다. 저권한 침입을 곧 root 침입으로 보고 대응 절차를 잡는다.
