## 요약
Acronis 위협 연구팀(TRU)은 인터넷에 잘못 열린 공격자 개발 서버를 찾아, 그 안에서 9GB·9만여 개 파일로 된 AI 공격 인프라 ‘BOSSAI’의 전모를 복원했다. 대만 화롄시의 운영자 1명으로 평가되는 행위자가 인프라 구축용과 공격용으로 나눈 에이전트 12개를 손으로 이어 붙여, 12일 동안 11개국을 겨냥했다. 타이베이 소방의 환자 관리 플랫폼과 119 출동 기록, 멕시코 전화번호 약 20만 건, 태국 대학 3곳 데이터가 털렸다. 상용 모델(Grok 4.5, MiniMax M3)은 공격을 거부했고 운영자는 안전 장치를 걷어낸 로컬 DeepSeek 변형으로 우회했다. 실제 성공은 기본 비밀번호·미패치 DB 같은 기초 위생 공백에서 나왔다.

## 동작 원리
작은 보안 회사를 혼자 운영하는 것과 비슷하다. ‘시공팀’ 에이전트들이 서버·DNS·프록시·MCP 설정을 깔고, ‘침투팀’ 에이전트들이 스캔과 익스플로잇 작성을 맡는다. 에이전트끼리 직접 대화하지 않고 운영자가 결과를 복사해 다음 에이전트에 넘긴다. Claude Code·Codex CLI 같은 상용 코딩 에이전트는 심(shim)을 거쳐 로컬 abliterated 모델에 연결돼, 하네스(도구 호출·파일 편집 능력)만 빌리고 상용 모델의 거부는 피했다. 보안 도구(Kali, Ghidra, HexStrike AI 등)는 MCP 서버로 붙여 에이전트가 바로 호출하게 했다. 반면 AI 스캐너는 실패한 연결을 RCE로 보고하는 등 고위험 판정의 절반 이상이 틀렸고, 인증이 제대로 걸린 시스템 앞에서는 에이전트가 멈췄다.

## 플랫폼 엔지니어 관점
- 에이전트 공격은 ‘숨어 있는’ 오래된 자산을 빠르게 훑는다. 외부 노출 자산 목록을 만들고, 로그인 없는 관리·조회 화면과 기본 자격 증명(DB 관리 패널 root 등)을 우선 제거한다. 이 사례에서 인증 강제와 필터링만으로 에이전트가 실패했다.
- 사내에서 Claude Code·Codex 같은 에이전트 하네스를 운영한다면, 모델 엔드포인트를 승인된 게이트웨이로만 허용(egress 허용 목록)해 하네스를 임의 로컬 모델로 돌려쓰는 경로를 막고 사용 로그를 남긴다.
- MCP 서버로 붙는 보안 도구(Kali·스캐너)는 공격자에게도 같은 ‘손’이 된다. 내부 레드팀용 MCP 구성은 격리 네트워크·짧은 수명 자격 증명·표적 범위 허용 목록 안에서만 돌린다.
- AI 스캐너·에이전트 보고서를 그대로 믿지 않는다. 고위험 판정은 재현 검증을 거쳐 우선순위에 반영한다(이 사례의 오탐률 50% 이상).
- Acronis가 공개한 IOC를 방화벽·SIEM에 넣고, 대만·태국·멕시코 공공기관과 거래하는 조직은 비정상 SQL 인젝션 시도를 점검한다.
