## 요약
중국발 자율 침투 AI 도구 ARTEX의 원작자가 10월 8일 저장소를 내리고 비공개 전환을 알리자, 몇 시간 만에 Docker Hub에 tomicdd/artex 이미지가 올라오고 compose 파일의 이미지 이름 한 줄만 바꾼 GitHub 사본이 퍼졌다. 독립 연구 블로그 BadByte가 이 이미지를 분석한 결과, 로그인 화면의 CAPTCHA 입력값을 인증 전에 루트 셸 명령으로 실행하는 백도어가 들어 있었다. 이미지는 11월 5일까지 9,008회 내려받아졌고, 11월 2~4일에 백도어 빌드를 돌리는 콘솔이 최소 62대 관측됐다. 인터넷에 열린 ARTEX 콘솔 1,645대 중 공식 릴리스는 110대뿐이었다.

## 동작 원리
ARTEX를 쓰려는 사람은 공식 저장소가 사라지자 별이 많은 사본 저장소의 docker-compose로 띄웠다. 그 compose는 원래 공식 이미지 대신 tomicdd/artex를 당기도록 한 줄만 바뀌어 있었다. 이미지 안 바이너리의 로그인 처리기는 CAPTCHA 칸이 비밀 표식으로 시작하면 뒷부분을 셸로 실행하고 결과를 응답에 실어 보낸다. 밖으로 신호를 보내지 않아 이상 트래픽이 없고, 공격 요청은 로그에 ‘로그인 실패’로만 남는다. 콘솔 안에는 LLM·검색 API 키, 데이터베이스 자격 증명, 세션 서명 키, 그리고 운영자가 모은 피해자 데이터가 있어, 셸 하나로 도구 운영자를 통째로 넘겨받는 구조다.

## 플랫폼 엔지니어 관점
- ‘원본이 사라진 인기 AI 도구’는 가장 흔한 이미지 바꿔치기 창구다. 레지스트리 허용 목록(Kyverno·Gatekeeper 이미지 정책)으로 승인된 네임스페이스와 서명(cosign 검증)된 이미지만 클러스터에서 당기게 하고, compose·Helm 차트의 이미지 참조 변경을 리뷰 대상에 넣는다.
- 태그가 아니라 다이제스트로 고정하고, 기존 배포의 이미지가 IOC(tomicdd/artex, congdonglinux/artex)와 같은지 레지스트리 미러·노드 캐시에서 점검한다.
- 에이전트 콘솔이 LLM API 키와 내부 자격 증명을 한 컨테이너에 쥐는 구조라면, 키를 외부 시크릿 관리자에서 짧은 수명으로 주입하고 콘솔 컨테이너의 egress를 모델 엔드포인트로만 제한해 장악 뒤 피해 반경을 줄인다.
- 레드팀·보안팀이 공격 도구를 내부 평가용으로 들일 때도 같은 공급망 심사(출처·서명·SBOM)를 적용하고, 인터넷에 관리 콘솔을 열지 않는다.
