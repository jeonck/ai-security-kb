## 요약
블록체인 분석 회사 Chainalysis가 10월 30일 처음 알린 침해 사고의 범위를 크게 넓혔다. 11월 4일 밤 갱신 공지에서 모든 사용자의 이름·사용자명·비밀번호 해시·유효 토큰이 침입자에게 노출됐다고 밝혔는데, 이는 첫 공지의 ‘비밀번호·세션 토큰 접근 증거 없음’과 정반대다. 별도로 on-path 공격으로 일부 고객 비밀번호가 가로채졌고, 일부 KYT 계정은 무단 접근된 것으로 보인다. 회사는 Reactor·Data Solutions에 이어 KYT·주소 스크리닝·로그인 페이지까지 내렸고, 모든 사용자에게 비밀번호 재설정과 API 키 교체를 요구하며 고객이 제출한 IP 허용 목록 기반으로 일부 서비스를 재개하기로 했다. 침입자가 썼다는 ‘공격형 에이전트 기법’의 실체는 여전히 공개되지 않았다.

## 동작 원리
처음 공지는 ‘사용자 디렉터리 정도만 봤다’였지만, 조사가 진행되며 인증 계층까지 닿아 있었다는 사실이 드러났다. 비밀번호 해시와 유효 토큰이 함께 나갔다는 것은 공격자가 해시를 오프라인으로 깨지 않아도 토큰을 재사용해 사용자 행세를 할 수 있었다는 뜻이다. on-path 공격은 사용자와 서비스 사이(예: 프록시·로그인 흐름)에 끼어들어 입력되는 비밀번호를 그대로 받아 가는 방식이라, 해시 강도와 무관하게 평문이 새어 나간다. 회사가 로그인 페이지를 내리고 재설정 메일 링크 대신 직접 접속을 권한 것도, 공격자가 로그인 흐름이나 메일 경로를 아직 쥐고 있을 가능성을 배제하지 못했기 때문으로 읽힌다. 서비스를 다시 열 때 ‘누가 오느냐’(자격 증명) 대신 ‘어디서 오느냐’(IP 허용 목록)를 임시 경계로 쓴 것은, 신원 계층을 믿을 수 없게 된 뒤 네트워크 계층으로 물러선 사례다.

## 플랫폼 엔지니어 관점
- **초기 범위 판정을 믿지 말고 회수부터**: 침입이 인증 서비스·로그인 경로와 같은 네트워크 구역에 닿았다면, ‘토큰 접근 증거 없음’이라도 세션 토큰·API 키·OAuth 리프레시 토큰을 일괄 폐기하는 런북을 기본으로 둔다. 쿠버네티스 위 IdP·세션 저장소(Redis 등)는 전체 무효화 명령과 소요 시간을 미리 연습해 둔다.
- **API 키 교체를 셀프서비스로**: 모든 고객에게 키 교체를 요구하는 상황에서는 교체 API·만료 기한·구키 병행 기간이 준비돼 있어야 서비스가 오래 멈추지 않는다. 내부 서비스 간 키는 External Secrets·Vault 동적 시크릿으로 짧게 발급해 회수 반경을 줄인다.
- **로그인 경로의 on-path 지점 점검**: 로그인 흐름을 거치는 리버스 프록시·WAF·서드파티 스크립트·CDN 설정 변경을 감사 로그로 남기고, 로그인 페이지에 SRI·CSP를 적용해 가로채기 스크립트 삽입을 탐지한다.
- **임시 IP 허용 목록은 탈출구이지 통제가 아니다**: 사고 중 Ingress·게이트웨이에 고객 IP 허용 목록을 빠르게 거는 절차(예: NetworkPolicy·Cloud Armor·ALB 규칙 템플릿)를 준비하되, 정상화 후에는 단기 토큰·mTLS·DPoP 같은 신원 기반 통제로 되돌린다.
- **에이전트형 침입 탐지**: 공격형 에이전트는 짧은 시간에 내부 도구 API를 넓게 훑는다. 내부 도구 API의 계정별 호출 다양성·속도 이상치를 경보로 걸어 둔다.
