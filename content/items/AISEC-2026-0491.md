## 요약
한국 금융기관 7곳 침해에 쓰인 AI 침투 프레임워크 ARTEX 운영자의 작업 서버가 인터넷에 열린 채 발견됐다. Hunt.io는 홍콩 점프 서버의 열린 디렉터리에서 운영자의 Claude Code 상태 파일, 맞춤 스킬, 자격 증명 파일, 터널 스크립트를 찾아 공개했다. Claude Code는 8월 이후 510번 실행됐다. 그런데 모델 요청은 Anthropic으로 가지 않았다. 라우터와 재판매 중계를 거쳐 DeepSeek로 갔다. 정찰부터 WAF 우회, 결제 로직 시험까지 맞춤 스킬 19개가 147번 호출된 기록도 있었다. 10월 Zscaler 분석(AISEC-2026-0089)이 프롬프트 기록과 역할 분담을 보여 줬다면, 이번 보고는 모델 요청의 세탁 경로와 스킬 사용량, 인프라 규모를 더했다.

## 동작 원리
운영자는 상용 코딩 에이전트의 ‘껍데기(하네스)’만 쓰고 ‘두뇌(모델)’는 갈아 끼웠다. Claude Code는 원래 Anthropic API에 붙지만, 로컬 라우터가 요청을 가로채 재판매 업체로 넘겼다. 재판매 업체는 다시 값싼 다른 회사 모델로 보냈다. 작은 shim 프로그램은 모델 목록 응답을 흉내 내고 추론 강도 파라미터를 끼워 넣어 하네스가 이상을 눈치채지 못하게 했다. 모델 공급자 입장에서는 이 운영자의 이름도, 원래 하네스도 보이지 않는다. 공격 기술은 ‘스킬’ 파일로 묶여 있다. 정찰·코드 감사·SSRF·결제 로직 같은 작업이 이름 붙은 레시피가 되어 반복 호출된다. 사람이 단계마다 지시하지 않아도 에이전트가 레시피를 골라 돌리는 구조다.

## 플랫폼 엔지니어 관점
- **방어 쪽 관점에서 ‘모델 공급자가 막아 줄 것’을 전제하지 않는다**: 공격자는 중계·재판매를 거쳐 어느 모델이든 쓴다. 탐지는 내 쪽 로그에서 해야 한다. 짧은 시간에 많은 API 경로를 훑는 요청 패턴, 결제·인가 로직을 여러 테스트 계정으로 번갈아 찌르는 패턴에 경보를 둔다.
- **인터넷 노출 관리면을 줄인다**: 이번 침해의 입구도 인터넷에 열린 시스템이었다. Ingress·LoadBalancer로 노출된 관리 콘솔, 오래된 내부 도구를 정기적으로 목록화하고 IdP 뒤로 옮긴다.
- **사내 모델 게이트웨이도 같은 방식으로 악용될 수 있다**: 사내에서 Claude Code·Codex 같은 하네스를 허용한다면 모델 엔드포인트를 승인된 AI 게이트웨이로만 가게 egress를 묶고, 임의 라우터·중계 도메인으로 나가는 트래픽을 차단·탐지한다.
- **스킬·메모리 파일을 자산으로 다룬다**: 에이전트 스킬과 메모리 파일은 작업 능력 그 자체다. 사내 에이전트의 스킬 디렉터리·메모리 동기화 경로를 인벤토리에 넣고, 외부로 동기화되는 경로를 감시한다.
