## 요약
Microsoft가 11월 보안 업데이트 글에서 Microsoft Execution Containers(MXC)의 정식 출시를 알렸다. MXC는 Windows에서 돌아가는 로컬 AI 에이전트를 OS가 강제하는 격리 계층에 넣어, 파일·네트워크·프로세스·사용자 상호작용에 최소 권한을 적용한다. Defender의 로컬 AI 에이전트 탐지도 Windows·macOS에서 정식 출시돼 50종 이상의 에이전트를 행동으로 찾고, 장치·계정·MCP 설정과 엮어 보여 준다. 작업 단위로 권한을 주고 위험에 따라 줄이는 Dynamic Permissions·Conditional Access도 다시 소개됐지만 출시 상태는 밝히지 않았다. 10월에 원칙으로 발표한 ‘보안 통제는 에이전트 손이 닿지 않는 곳에’(AISEC-2026-0018)가 제품으로 내려온 단계다.

## 동작 원리
코딩 에이전트는 개발자 계정으로 돌아가기 때문에, 그대로 두면 개발자가 열 수 있는 모든 파일·SSH 키·클라우드 자격 증명에 닿는다. MXC는 에이전트를 개발자와 같은 방에 앉히지 않고 유리 칸막이 안에 넣는 방식이다. 칸막이 밖의 파일·네트워크 목적지·자식 프로세스는 정책이 허용한 것만 보이고, 그 정책은 에이전트가 아니라 OS가 강제하므로 프롬프트 인젝션으로 에이전트가 속아도 칸막이를 넘지 못한다. 정책을 바로 강제하지 않고 먼저 관찰·검증하는 단계를 둔 것은, 처음부터 막으면 개발 흐름이 깨져 사용자가 격리를 끄는 문제를 피하려는 것이다. Defender 쪽은 반대 방향의 문제, 즉 ‘어떤 에이전트가 어디서 무슨 MCP 서버를 붙여 돌고 있는지 모른다’를 행동 관찰로 푼다.

## 플랫폼 엔지니어 관점
- **개발자 단말도 에이전트 런타임이다**: 클러스터 안 에이전트에는 샌드박스를 걸면서 개발자 PC의 Claude Code·Codex·Copilot 에이전트는 사용자 권한 그대로 두는 경우가 많다. MXC·devcontainer·원격 개발 환경 중 하나로 로컬 에이전트의 파일·네트워크 범위를 정하는 표준을 만든다.
- **관찰 모드로 시작해 허용 목록을 만든다**: 에이전트가 실제로 여는 경로·목적지를 먼저 수집해 egress 허용 목록(패키지 레지스트리, Git 호스트, 모델 API)과 파일 범위를 정하고, 그다음 강제로 전환한다. 쿠버네티스의 NetworkPolicy·Cilium 감사 모드 운영과 같은 순서다.
- **MCP 인벤토리를 자산 관리에 넣는다**: 단말별로 구성된 MCP 서버 목록을 수집해 승인 레지스트리와 대조하고, 미승인 서버가 붙은 에이전트를 경보로 올린다.
- **‘권한 없이 시작’ 원칙을 서버 측에도**: 에이전트 서비스 계정은 기본 권한을 비워 두고 작업 단위로 짧게 발급(예: 워크로드 ID + 단기 토큰)하며, 고영향 작업은 사람 승인 단계를 거치게 한다.
