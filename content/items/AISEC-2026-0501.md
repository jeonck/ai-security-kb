## 요약
AWS가 관리하는 오픈소스 시계열 예측 라이브러리 GluonTS에서, 아카이브를 푸는 유틸리티가 tar 안의 심볼릭·하드 링크를 제대로 막지 않는 취약점(CVE-2026-119083)이 공개됐다. 조작된 tar 파일을 풀게 만들면 대상 디렉터리 밖의 임의 경로에 파일을 쓸 수 있다. GHSA는 CVSS 7.8(High)로 평가했고, 0.17.0에서 수정됐다. Python 3.14 이상은 기본 추출 필터가 이 우회를 막지만, 그 이전 버전에서는 라이브러리 업그레이드가 필요하다.

## 동작 원리
tar 파일은 ‘이 이름의 파일은 저기를 가리키는 링크’라는 항목을 담을 수 있다. 먼저 `data/x`를 `/home/user/.ssh` 같은 곳을 가리키는 링크로 만들고, 다음 항목으로 `data/x/authorized_keys`를 넣으면, 링크를 따라간 추출기는 대상 폴더가 아닌 엉뚱한 곳에 파일을 쓴다. 택배 상자 안에 ‘이 상자는 옆집 창고로 옮겨 주세요’라는 쪽지가 들어 있고 받는 사람이 그대로 따르는 셈이다. ML 파이프라인은 학습·평가 데이터셋을 압축 파일로 내려받아 자동으로 푸는 일이 흔해서, 데이터셋 출처 하나가 오염되면 그 아카이브를 푸는 학습 잡·노트북의 권한으로 설정 파일·스크립트를 덮어쓸 수 있다.

## 플랫폼 엔지니어 관점
- **의존성 점검**: 학습·추론 이미지와 노트북 환경에서 gluonts 0.17.0 미만을 찾아 올린다. SBOM·Trivy·Dependabot 경보로 CVE-2026-119083을 추적하고, 포크한 내부 코드도 확인한다.
- **Python 3.14+ 또는 추출 필터 강제**: 자체 코드에서 tarfile을 쓸 때는 `filter='data'`를 명시하고, 베이스 이미지를 Python 3.14 이상으로 올릴 계획을 세운다.
- **데이터셋도 출처를 고정한다**: 외부 데이터셋 아카이브는 해시를 고정해 내부 아티팩트 저장소에 미러링한 것만 쓰게 하고, 학습 잡이 인터넷에서 직접 받지 못하게 egress를 막는다.
- **추출 작업 격리**: 아카이브 해제는 읽기 전용 루트 파일시스템·쓰기 가능한 emptyDir 하나만 마운트한 별도 init 컨테이너에서 하고, 홈 디렉터리·자격 증명 마운트와 분리한다.
