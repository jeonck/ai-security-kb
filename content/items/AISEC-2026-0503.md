## 요약
Microsoft 위협 인텔리전스가 2026-11-05 공격형 에이전트 프레임워크 ARTEX를 쓴 클라우드 침입 활동을 공개했다. 공격자는 8월부터 공개 GitHub 저장소에서 대상 조직 이름과 비밀 키워드, 클라우드·AI 서비스 이름을 섞어 대량으로 검색했고, 에이전트가 찾은 값을 분석해 곧바로 후속 공격에 썼다. 10월 28일부터는 유출된 앱 자격 증명으로 Entra ID 서비스 주체 로그인을 하고 Key Vault·Storage·App Service·AKS·Azure DevOps·M365·Azure AI 자원을 열거·탈취했다. 공급사가 소유한 멀티테넌트 앱의 자격 증명이 그 앱을 쓰는 하위 고객 테넌트 공격에 쓰인 경우도 있었다. 한 사례는 GitHub 검색에서 Key Vault 유출까지 약 5분이었다.

## 동작 원리
사람 공격자라면 유출 키를 찾고, 맞는지 시험하고, 어떤 권한인지 파악하는 데 몇 시간이 걸린다. 에이전트는 이 과정을 한 번에 이어 붙인다. 키로 로그인한 뒤 구독·자원 그룹·권한·모델 배포를 훑어 지도를 만들고, ‘자격 증명을 돌려주는 API’(Key Vault 비밀, Storage 키, 연결 문자열, AKS 자격 증명)부터 두드린다. API 버전이 틀려 거절당하면 수십 초 안에 버전을 고쳐 다시 시도한다. 열쇠 꾸러미를 주운 사람이 문마다 열쇠를 차례로 꽂아 보는 일을, 지치지 않는 손이 분 단위로 해내는 셈이다. 그래서 공격 IP는 바뀌어도 ‘짧은 시간에 여러 서비스 토큰을 요청한다’, ‘같은 기법을 고쳐 가며 되풀이한다’ 같은 행동 흔적은 남는다.

## 플랫폼 엔지니어 관점
- CI/CD·IaC 저장소에 서비스 주체 비밀·AI API 키가 들어간 적이 있으면 지운 것으로 끝내지 말고 교체하고, 그 키의 과거 로그인·토큰 발급 기록을 조사한다. 푸시 보호와 공개 저장소 모니터링을 켠다.
- 클라우드 앱·파이프라인 인증을 클라이언트 비밀에서 관리 ID·워크로드 ID 연동(OIDC)으로 옮기고, 서비스 주체에 조건부 액세스와 위치 제한을 건다. Key Vault는 앱마다 접근 범위를 좁혀 한 앱 침해가 금고 전체 유출이 되지 않게 한다.
- 공급사가 내 테넌트에 설치한 멀티테넌트 앱의 권한을 목록화하고, 쓰지 않는 앱 등록과 과도한 Graph 권한을 정리한다.
- 탐지는 IP 차단 목록보다 행동 규칙을 우선한다. 한 주체가 짧은 시간에 ARM·Key Vault·Storage·Graph 토큰을 연달아 받는 패턴, 비밀 오류 뒤 성공, AKS 자격 증명 조회·VM Run Command 같은 고위험 작업을 경보로 건다. 미끼 비밀 값(canary token)을 저장소와 금고에 심어 자동화된 공격 에이전트를 빨리 걸러 낸다.
