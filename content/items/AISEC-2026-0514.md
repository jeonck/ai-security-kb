## 요약
개발자 문서 플랫폼 GitBook이 11월 2일 침해의 사후 보고를 공개했다. 공격자는 SSO 로그인 흐름의 결함으로 직원 세션을 만들고, 한 고객 조직의 잘못 설정된 GitHub App을 통해 내부 저장소에 들어가 Cloudflare API 키를 얻었고, 그 키로 운영 비밀과 서비스 계정을 손에 넣었다. 첫 계정 탈취부터 운영 환경 도달까지 약 5시간 20분이 걸렸고, 내부 경보는 그 22분 뒤 울렸다. GitBook은 모든 비밀을 교체하고 기존 API 토큰을 무효화했으며, 이 공격이 자동화와 AI가 주도한 것으로 보인다고 평가했다.

## 동작 원리
연쇄는 ‘신뢰가 한 단계씩 넘어가는 다리’였다. 로그인 결함으로 내부 직원 신분을 얻자 고객이 설치해 둔 GitHub App 설정을 볼 수 있었고, 그 앱의 권한이 코드 저장소로, 저장소에 있던 클라우드 API 키가 운영 비밀로, 운영 비밀이 서비스 계정 권한으로 이어졌다. 각 다리는 다른 시스템의 토큰이라 한 곳의 로그만 보면 이상해 보이지 않는다. GitBook은 이 사슬을 빠르게 따라간 속도를 근거로 AI 에이전트 사용을 의심했다.

## 플랫폼 엔지니어 관점
- GitBook을 쓰는 팀은 GitBook API 토큰·통합 비밀·인증 문서 서명 키를 교체하고, MCP 서버 연결을 재인증하며, GitBook 앱에 준 GitHub·GitLab 저장소 범위를 최소로 줄인다. 공개된 IoC IP 3개를 접근 로그에서 찾는다.
- 사내에서도 같은 다리를 끊는다. 저장소에 클라우드 API 키를 두지 않고, 엣지·CI 비밀은 단기 OIDC 자격 증명으로 바꾸며, GitHub App은 필요한 저장소만 선택 설치한다.
- SaaS 벤더의 직원 세션이 고객 연동 설정을 볼 수 있는 구조인지 벤더 평가 항목에 넣고, 서드파티 앱 토큰 사용을 이상 탐지 대상으로 둔다.
