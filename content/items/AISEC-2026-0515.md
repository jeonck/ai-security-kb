## 요약
Stanford NLP의 파이썬 자연어 처리 라이브러리 Stanza에서 표제어 분석기 체크포인트를 불러올 때 임의 코드가 실행되는 취약점(CVE-2026-115878)이 공개됐다. 바깥 로딩은 PyTorch의 안전 모드(weights_only=True)를 썼지만, 체크포인트 안에 바이트로 넣어 둔 두 번째 피클을 라이브러리가 제한 없이 풀었다. 악성 .pt 파일 경로를 파이프라인에 넘기기만 하면 입력 처리 전에 코드가 돈다. 1.15.0에서 고쳐졌다.

## 동작 원리
weights_only=True는 ‘상자를 열 때 텐서와 기본 자료형만 꺼내라’는 검사다. 그런데 상자 안에 압축된 바이트 덩어리가 들어 있으면 검사기는 그것을 그냥 ‘바이트’로 보고 통과시킨다. 문제는 라이브러리가 그 바이트를 다시 꺼내 일반 pickle.loads로 푼다는 점이다. 바깥 자물쇠는 잠겼는데 안쪽 상자는 잠기지 않은 셈이다. 기본 다운로드에만 있는 해시 검사도 사용자가 직접 지정한 경로에는 적용되지 않았다.

## 플랫폼 엔지니어 관점
- Stanza를 쓰는 학습·추론 이미지를 1.15.0 이상으로 올리고, 서드파티 체크포인트 경로를 받는 설정(lemma_model_path 등)을 사용자 입력으로 노출하지 않는다.
- 모델 스캐너·정책은 ‘weights_only 사용 여부’만 보지 말고 체크포인트 안의 중첩 바이트 필드와 라이브러리의 2차 역직렬화까지 고려한다. 승인된 레지스트리에서 해시 고정된 체크포인트만 로드하게 한다.
- 모델 로딩은 네트워크·자격 증명이 없는 격리된 작업(별도 컨테이너, 읽기 전용 파일시스템)에서 먼저 수행하고, 로딩 단계의 프로세스 생성·외부 연결을 런타임 탐지로 감시한다.
