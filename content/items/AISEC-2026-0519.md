## 요약
연구진은 웹 검색 기반 RAG에서 검색된 페이지를 생성 모델에 넘기기 전에, 공개 가중치의 작은 판정 모델에게 ‘이 페이지가 AI에게 지시하는가’, ‘오도용 채움 페이지인가’를 묻는 관문(게이트)을 시험했다. 숨김 요소 제거·정규화 같은 공개 완화책만으로는 간접 인젝션 성공률이 27.9%에서 13.6%로 줄었고, 4B 게이트를 더하면 5.7%까지 내려갔다. 지연은 페이지당 76ms, 오탐은 2.2%였다. 합성 낚시 페이지가 섞인 검색 풀에서도 게이트가 정확도를 28%에서 83%로 되살렸다. 대형 LLM 판정자는 더 잘 잡았지만 약 10배 비쌌고 오탐도 많았다.

## 동작 원리
검색된 페이지를 생성 모델에 바로 넣는 대신, 앞에 ‘세관 검사대’를 둔다. 작은 판정 모델이 페이지마다 예/아니오 질문 몇 개에 점수를 매기고, 기준을 넘으면 그 페이지를 버린다. 생성 모델은 남은 페이지만 본다. 공격자가 숨긴 지시문은 렌더링된 글자보다 HTML 구조(숨김 태그, 주석 위치)에 흔적이 더 많이 남아서, 평문 대신 HTML을 보여 줄 때 판정이 더 정확했다. 다만 검사대를 통과한 5.7%가 남는다는 점, 게이트 자체를 노린 공격은 시험하지 않았다는 점이 한계다.

## 플랫폼 엔지니어 관점
- 웹 검색·브라우징 도구를 가진 에이전트라면, 검색 결과를 모델 컨텍스트에 넣기 전에 판정 모델 게이트를 별도 서비스로 두고 차단 로그를 남긴다. 페이지당 수십 ms 수준이라 검색 경로에 넣을 만하다.
- 게이트 입력으로 텍스트 추출본만 쓰지 말고 원본 HTML(또는 숨김 요소 표시)을 함께 넘기는 구성을 시험한다.
- 게이트는 확률적 탐지라 성공률이 0이 되지 않는다. 검색을 한 세션에서는 메일 발송·코드 푸시 같은 고위험 도구를 사람 승인 뒤로 두는 권한 분리를 함께 적용한다.
- 임계값을 낮출수록 공격은 줄고 오탐은 늘어난다. 업무별로 임계값과 오탐률을 측정해 정한다.
