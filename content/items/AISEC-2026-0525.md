## 요약
사전 학습 모델 허브에서의 악성 코드 오염을 처음으로 체계적으로 측정했다고 밝힌 ASE 2024 논문으로, 측정은 Ant Group과 함께 운영 환경에서 했다. 모델 파일 형식 15종을 취약·부분 취약·비취약으로 분류하고, 데이터셋 로딩 스크립트와 모델 역직렬화를 함께 분석하는 탐지 파이프라인 MalHug를 만들었다. Hugging Face 미러에서 3개월 넘게 모델 약 70만 6천 개와 데이터셋 약 17만 6천 개를 감시해 악성 모델 91개와 악성 로딩 스크립트 9개를 찾았다. 페이로드는 리버스 셸, 브라우저 자격 증명 탈취, 시스템 정찰 등이었다. 저자들은 기존 스캐너가 위험 API 목록에 의존해 의미 수준 분석과 데이터셋 지원이 부족하다고 지적했다.

## 동작 원리
pickle은 데이터를 담는 상자가 아니라 ‘상자를 열 때 실행할 조립 설명서’에 가깝다. 역직렬화 과정에서 임의 객체를 만들고 함수를 호출할 수 있기 때문에, 모델 파일을 `torch.load` 같은 방식으로 여는 순간 공격자가 심어 둔 코드가 실행된다. Keras 모델은 Lambda 레이어에 임의 함수를 넣을 수 있어 비슷한 경로가 생긴다. 데이터셋 쪽에서는 로딩 스크립트가 아예 평범한 Python 코드라서 데이터를 받는 행위 자체가 코드 실행이 된다. MalHug는 이 세 경로를 각각 열어 보고(스크립트 추출, pickle opcode 분해·디컴파일, Lambda 레이어 탐지), 위험 API가 보이면 테인트 분석으로 실제로 입력이 위험한 곳(셸 실행, 네트워크 전송 등)까지 흐르는지 확인한다. API 목록만 보는 스캐너가 놓치는 셸 명령·난독화 패턴은 YARA 규칙으로 보완한다. 측정 결과는 Safetensors·GGUF·ONNX처럼 코드 실행 경로가 없는 형식으로 옮기는 것이 근본 대책이라는 점을 뒷받침한다.

## 플랫폼 엔지니어 관점
- 외부 모델·데이터셋 다운로드와 첫 로딩은 자격 증명이 없는 격리 작업으로 분리한다. Kubernetes에서는 서비스 계정 토큰 자동 마운트를 끄고(`automountServiceAccountToken: false`), gVisor·Kata 같은 RuntimeClass, 읽기 전용 루트 파일시스템, egress 차단 NetworkPolicy를 건 전용 네임스페이스에서 변환·스캔을 돌린다. 리버스 셸·자격 증명 탈취 페이로드는 egress와 시크릿이 없으면 대부분 힘을 잃는다.
- CI/CD에서 pickle 계열 모델은 격리 환경에서 Safetensors로 변환한 뒤에만 내부 레지스트리에 올리고, 서빙 이미지에서는 Safetensors·GGUF·ONNX만 허용하는 admission 정책을 둔다.
- 데이터셋 로딩 스크립트와 `trust_remote_code=True`는 기본 금지로 하고, 예외는 코드 리뷰와 해시 고정을 거친 허용 목록으로만 관리한다.
- 모델 스캐너(picklescan·ModelScan 등)는 필요하지만 위험 API 목록 기반이라 우회될 수 있다는 점을 전제로, 스캔 통과를 신뢰 근거가 아니라 여러 겹 중 한 겹으로 둔다. 출처는 서명·해시로 고정한다(AISEC-2026-0314).
