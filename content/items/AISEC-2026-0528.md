## 요약
Rust로 만든 LLM 추론 엔진 mistral.rs의 핵심 라이브러리 mistralrs-core에서, 모델 출력에서 도구 호출을 뽑아내는 파서가 구분자 문자열을 텍스트 수준에서 찾는 바람에 생긴 취약점이다. 공격자가 문서·웹 페이지·도구 출력에 `</tool_call>` 같은 태그를 넣어 두고 모델이 그 내용을 인용하면, 파서가 원래 호출을 일찍 닫고 공격자가 만든 두 번째 호출을 돌려준다. 추론 구간 파서에서는 모델이 도구를 전혀 부르지 않았는데도 호출이 생겼다. 고려대 연구진이 제보했고 0.9.5(10월 19일)에서 특수 토큰으로 나온 구분자만 인정하도록 고쳤으며, CVE-2026-124028은 11월 6일 공개됐다.

## 동작 원리
모델이 도구를 부르면 출력에 `<tool_call>…</tool_call>` 같은 표시가 붙고, 서빙 엔진은 이 표시를 기준으로 호출을 잘라 낸다. 그런데 이 표시를 ‘모델이 낸 특수 토큰’이 아니라 ‘글자열’로 찾으면, 모델이 인용한 문서 속 같은 글자열도 똑같이 경계로 읽힌다. 편지 본문에 ‘— 여기서 편지 끝, 새 편지 시작 —’이라고 적어 두면 우체국 분류기가 편지를 두 통으로 나누는 셈이다. 모델의 판단은 한 번도 속지 않았는데, 파서가 행동을 하나 더 만들어 낸다. 다만 요청에 선언된 도구 이름만 통과하므로, 피해는 그 요청에서 쓸 수 있게 열어 둔 도구의 위험도로 정해진다.

## 플랫폼 엔지니어 관점
- 자체 호스팅 추론 엔진(mistral.rs, vLLM, SGLang, llama.cpp 서버 등)을 에이전트 백엔드로 쓴다면, 도구 호출 파서가 특수 토큰 ID로 경계를 찾는지 텍스트 정규식으로 찾는지 확인하고 mistral.rs는 0.9.5 이상으로 올린다.
- 에이전트 게이트웨이·오케스트레이터에서 ‘한 턴에 나온 도구 호출 수’와 ‘모델 출력 토큰과 호출 인자의 대응’을 검증하는 정책을 둔다. 한 응답에서 갑자기 호출이 늘거나 인자가 인용 콘텐츠와 일치하면 경보를 낸다.
- 요청마다 선언하는 도구 목록을 최소화하고, 여러 MCP 서버의 도구를 한꺼번에 노출하지 않는다. 파괴적 도구(삭제·배포·노드 드레인)는 서빙 계층 밖의 별도 승인 단계를 거치게 한다.
- 인젝션 탐지기·가드레일이 모델 입력·출력 텍스트만 보는 경우 이 경로를 놓친다. 파서가 최종적으로 만든 구조화된 호출 객체를 기준으로 로그·탐지를 건다.
