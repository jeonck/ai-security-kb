## 요약
GitHub이 2026년 11월 6일 Copilot 주간 릴리스를 냈다. 보안 관점에서 눈에 띄는 것은 Copilot 앱의 자동 승인(assisted approval)에 사용자가 ‘어떤 도구 요청은 묻지 말고 승인하라’는 개인 지침을 줄 수 있게 한 변경이다. 옵트인이고 로컬 세션에만 적용된다. 같은 릴리스에 필수 검사가 통과하면 Copilot이 PR을 병합하는 Agent Merge, VS Code 로컬 자동화의 cron 예약과 사용자 정의 에이전트 지원, CLI의 MCP 서버 통합 관리 화면이 들어갔다.

## 동작 원리
10월 말 정식 출시된 assisted permissions는 별도 모델이 권한 요청을 보고 ‘명백히 안전한’ 것만 자동 승인하는 문지기였다(AISEC-2026-0185). 이번 변경은 그 문지기에게 사용자가 자연어로 기준을 덧붙이는 것이다. 승인 피로는 줄지만, 승인 경계가 결정적 규칙이 아니라 모델 판정 + 사용자 문장의 조합이 된다. 사용자가 넓게 쓴 지침(예: ‘테스트 관련 명령은 다 승인’)은 모델이 넓게 해석할 수 있고, 저장소 내용에 섞인 인젝션이 그 해석을 이용할 여지도 생긴다. Agent Merge와 cron 예약은 사람이 화면 앞에 없는 시간에도 에이전트가 행동하게 만드는 쪽으로 같은 방향을 가리킨다.

## 플랫폼 엔지니어 관점
- 위험 명령(배포, 시크릿 접근, 외부 업로드, `git push --force`)은 개인 지침이나 모델 판정에 맡기지 말고 기업 deny 규칙과 egress 허용 목록으로 결정적으로 막는다. 개인 지침을 조직 차원에서 끌 수 있는지부터 확인한다.
- 자동 승인된 요청과 그 근거(어떤 지침이 적용됐는지)를 감사 로그로 남기고 표본 검토한다.
- Agent Merge를 허용하는 저장소는 필수 리뷰어·필수 상태 검사·CODEOWNERS를 브랜치 보호 규칙으로 강제해, ‘검사 통과 = 병합’이 사람 리뷰를 건너뛰지 않게 한다.
- cron으로 도는 로컬 자동화는 개발자 PC의 자격 증명으로 무인 실행되므로, 예약 작업 목록을 점검하고 장기 토큰 대신 짧은 수명 토큰을 쓰게 한다.
