## 요약
Apiiro는 Claude Code 사용자가 권한 창에서 ‘Yes, and don't ask again’을 고를 때 승인된 명령이 그대로 `.claude/settings.local.json`의 allow 규칙으로 저장되며, 명령 안에 들어 있던 비밀번호·토큰도 평문으로 남는다는 점을 공개 GitHub 규모로 측정했다. 공개 저장소에서 찾은 사본 10만여 개 중 1,122개에 비밀 값 1,379개가 들어 있었고, DB 비밀번호·SSH 로그인·GitHub/npm 토큰·AWS 키가 포함됐다. Claude Code는 처음 파일을 만들 때 사용자 전역 git excludes에 이 파일을 넣지만, 다른 기기·CI·이미 커밋된 파일은 보호하지 못한다. 같은 문제를 지적한 2025년 8월 버그 보고는 응답 없이 봇이 자동 종결했다. Apiiro 원문은 열람이 차단돼 수치는 THN 보도 기준이다.

## 동작 원리
‘다시 묻지 않기’는 편의 기능이지만, 저장 단위가 ‘명령 패턴’이 아니라 ‘정확한 명령 한 줄’이 되면 그 줄에 들어 있던 `PGPASSWORD=...`나 `sshpass -p ...`가 그대로 허용 목록이 된다. 출입 허가 대장에 방문자의 열쇠 사본을 같이 붙여 두는 셈이다. 이 파일은 프로젝트 폴더 안에 있어서 전역 excludes가 없는 CI 러너·새 노트북·동료의 clone에서 `git add .` 한 번이면 저장소에 들어가고, 에이전트가 공동 작성자로 직접 커밋하는 흐름에서도 함께 올라간다. 게다가 명령줄 속 비밀번호는 알려진 키 형식이 아니라 비밀 스캐너가 놓치기 쉽다. 사람의 승인 → 설정 파일 → 저장소 → 공개라는 네 단계가 아무 경고 없이 이어진다.

## 플랫폼 엔지니어 관점
- 조직 GitHub 전체(이력 포함)에서 `.claude/settings.local.json`·`.claude/settings.json`을 검색하고, 나온 비밀 값은 정리보다 **회수(rotate)를 먼저** 한다. 공개 서버와 짝지어진 SSH·DB 자격 증명이 우선이다.
- 조직 `.gitignore` 템플릿과 pre-commit·CI 비밀 스캐닝에 `.claude/`, `.cursor/`, `.gemini/` 같은 에이전트 폴더를 `.env`와 같은 등급으로 넣고, `PGPASSWORD=`·`sshpass -p`·`mysql -p` 같은 명령줄 비밀번호 규칙을 스캐너에 추가한다.
- 관리형 설정(managed settings)으로 허용 규칙을 중앙에서 배포하고, 개발자에게는 정확한 명령 대신 `Bash(npm run *)` 같은 패턴 승인과 비밀 관리자 변수 사용을 표준으로 안내한다.
- 에이전트가 커밋하는 파이프라인에서는 커밋 diff에 에이전트 설정 파일이 들어 있으면 차단하고, `.dockerignore`·`.npmignore`에도 `.claude/`를 넣어 이미지·패키지로 실려 나가지 않게 한다.
