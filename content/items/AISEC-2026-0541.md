## 요약
OpenBMB의 멀티 에이전트 협업 플랫폼 Internet of Agents(IoA)에 대해 네 번째 CVE(CVE-2026-123881)가 GitHub Advisory DB에 올라왔다. 메시지 서버의 채팅 기록 조회 API에 comm_id를 비워 보내면 인증 없이 전체 대화 DB가 통째로 돌아온다. 같은 보고에는 세션 구성원이 아닌 연결이 메시지를 무제한으로 주입해 모든 구성원에게 브로드캐스트시키는 문제도 담겼다. 보고는 10월 14일에 이뤄졌지만 메인테이너 응답과 수정 버전이 없다. 앞서 등재된 IoA의 취약점들(AISEC-2026-0497, AISEC-2026-0537)과 같은 계열이다.

## 동작 원리
에이전트들이 모여 대화하는 ‘단체방 서버’가 방 번호를 확인하지 않는 구조다. 방 번호를 빈칸으로 내면 서버가 ‘전체 방 기록’을 내준다. 메시지를 보낼 때도 보낸 사람이 그 방 구성원인지 보지 않으니, 밖의 누구든 방 안의 모든 에이전트에게 지시문을 흘려 넣을 수 있다. 에이전트 간 메시지가 곧 다음 에이전트의 입력이므로, 이는 기록 유출과 동시에 간접 인젝션 통로가 된다.

## 플랫폼 엔지니어 관점
- IoA를 실험·사내 PoC로 띄웠다면 im_server를 외부·사내 공용망에 노출하지 말고, 수정 전까지 앞단 인증 프록시와 NetworkPolicy로 접근 주체를 제한한다.
- 멀티 에이전트 메시지 버스를 직접 만들 때는 연결 단위 신원(mTLS·워크로드 토큰)과 세션 구성원 검사, sender 필드의 서버측 바인딩, 레이트 리밋·메시지 크기 상한을 기본 요건으로 넣는다.
- 기록 조회 API는 특정 ID 필수·인가·페이지 제한을 두고, ‘전체 덤프’ 경로가 있는지 코드 리뷰 체크리스트에 넣는다.
- 메인테이너가 응답하지 않는 에이전트 프레임워크는 의존성 승인 단계에서 ‘유지보수 상태’를 평가 항목으로 둔다.
