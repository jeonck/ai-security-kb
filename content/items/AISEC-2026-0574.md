## 요약
탈중앙 AI 서비스 NEAR AI는 11월 9일 사고 보고서에서, 공격자가 추론 엔진 SGLang의 원격 코드 실행 취약점으로 추론 서버 한 대를 장악했다고 밝혔다. 이 서버는 신뢰 실행 환경(TEE) 기반 기밀 모드 요청도 처리하고 있었고, 공격자는 11월 8일 처리 중인 요청을 볼 수 있었다. 공격자는 이어 이미 폐기된 Private Chat 기능 뒤의 내부 시스템으로 옮겨 사용자 약 100명의 계정 정보, TEE 밖 레거시 에이전트 18개의 대화 기록·로그, 로그에 찍혀 있던 고객 API 키 2건을 가져갔다. NEAR AI는 자격 증명 전면 교체와 SGLang 수정 배포를 마쳤다고 했지만 CVE 번호는 밝히지 않았다. SGLang에는 7월 CERT/CC가 공개한 무인증 RCE 등 6건이 벤더 무응답·무패치 상태로 공개된 전력이 있다.

## 동작 원리
TEE는 금고 같은 방이다. 건물 주인(클라우드 운영자·호스트)은 방 안을 들여다보지 못한다. 그런데 방 안에서 일하는 직원(추론 엔진)이 낯선 사람의 쪽지를 그대로 실행하는 습관이 있으면 금고는 소용없다. 공격자는 SGLang의 RCE로 방 안 직원의 손을 빌렸고, 그 자리에서 오가는 요청을 그대로 볼 수 있었다. 그다음은 고전적인 수평 이동이다. 이미 쓰지 않기로 한 옛 시스템이 내부망에 연결된 채 남아 있었고, 로그에는 고객 API 키가 평문으로 남아 있었다.

## 플랫폼 엔지니어 관점
- SGLang·vLLM 같은 추론 엔진을 ‘신뢰된 런타임’이 아니라 외부 입력을 받는 공개 서비스로 취급한다. 관리·가중치 갱신·LoRA 로드 엔드포인트는 NetworkPolicy로 추론 게이트웨이 외에는 막고, 쓰지 않는 엔드포인트는 끈다. SGLANG_USE_PICKLE_IPC=false 같은 역직렬화 완화 설정을 기본값으로 둔다.
- 기밀 컴퓨팅을 쓰더라도 TEE 안의 소프트웨어 스택(추론 엔진·의존성) 패치와 SBOM 관리, 런타임 이상 행위 탐지(예상 밖 셸·네트워크 연결)를 따로 갖춘다. ‘TEE라서 안전’이라는 문구를 위협 모델에서 지운다.
- 폐기 예정(deprecated) 시스템은 기능만 끄지 말고 네트워크·자격 증명까지 회수한다. 추론 서버에서 내부 서비스로 가는 egress를 허용 목록으로 묶는다.
- 요청·응답 로그에서 API 키·토큰을 마스킹하는 로깅 파이프라인 규칙을 강제하고, 로그 저장소 접근 권한을 추론 노드와 분리한다.
