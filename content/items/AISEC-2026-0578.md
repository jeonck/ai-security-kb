## 요약
Arctic Wolf Labs는 11월 10일 경보에서, 중국어 오픈소스 공격 에이전트 플랫폼 AntiFox의 콘솔을 띄운 Alibaba Cloud 서버들이 실제 침입과 연결됐다고 밝혔다. 일부 침입은 인터넷에 노출된 IIS 앱을 장악해 웹셸을 심고 설정 파일의 DB 연결 문자열을 빼냈다. 다른 침입은 이미 손에 든 유효한 AWS 자격 증명으로 수십 개 서비스를 빠르게 훑어, 일부에서 운영 비밀 값을 꺼내는 데 성공했다. 피해 조직 규모는 공개되지 않았다. ARTEX에 이어 공개 공격 에이전트가 실전에 쓰이는 사례가 늘고 있다.

## 동작 원리
공격 에이전트는 사람이 하나씩 해 보던 ‘이 키로 무엇을 열 수 있나’를 기계적으로 끝까지 시도한다. 열쇠 꾸러미를 들고 건물의 모든 문을 30분 안에 한 번씩 돌려 보는 셈이다. 대부분은 잠겨 있어 AccessDenied가 쏟아지지만, 하나라도 열리면 바로 다음 단계(비밀 값 조회, S3 객체 복사)로 넘어간다. 실패 로그가 많다는 것 자체가 신호다.

## 플랫폼 엔지니어 관점
- CloudTrail에서 ‘짧은 시간 다수 서비스 열거 + 높은 AccessDenied 비율’을 탐지 규칙으로 만든다. 신원이 평소 쓰지 않던 호스팅 ASN·사용자 에이전트에서 오는 호출에 경보를 단다.
- GetSecretValue는 새로운 출발지에서 호출되면 알리고, Secrets Manager 리소스 정책으로 VPC 엔드포인트·특정 역할에서만 읽게 묶는다.
- 장기 IAM 액세스 키를 줄이고 IMDSv2를 강제한다. Bedrock 같은 AI 서비스 권한도 열거 대상이므로 쓰지 않는 신원에서는 제거한다.
- 웹 서버(w3wp.exe 등) 프로세스가 셸을 띄우거나 웹 루트에 새 실행 파일을 쓰는 행위를 EDR로 차단·경보한다. 웹 앱 설정의 연결 문자열은 비밀 저장소로 옮긴다.
