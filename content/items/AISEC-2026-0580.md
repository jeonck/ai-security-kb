## 요약
AWS가 공개한 AWS API MCP Server는 에이전트가 AWS CLI 수준의 API 호출을 하게 해 주고, 운영자는 denyList(금지)·elicitList(사용자 확인 필요) 정책으로 위험한 연산을 막을 수 있다. 그런데 서버가 연산 이름을 정책과 비교하기 전에 형식을 바꾸는 과정에서, 연속 대문자가 들어간 이름을 잘못 변환해 정책 항목과 절대 일치하지 않게 만들었다. 그래서 MFA 장치 해제나 DB 클러스터 삭제처럼 막아 두었다고 믿은 연산이 승인 없이 실행될 수 있었다. 2026-11-10 공개됐고 1.5.1에서 고쳤으며 우회책은 없다.

## 동작 원리
경비원이 출입 금지 명단을 ‘김OO’ 형식으로 갖고 있는데, 방문자 이름을 명단과 맞춰 보기 전에 ‘김 OO’처럼 띄어 쓰는 습관이 있다면, 명단에 정확히 적힌 사람조차 그냥 통과한다. 여기서는 연속 대문자가 있는 연산 이름이 정규화 과정에서 운영자가 적은 표기와 다른 문자열로 바뀌어 비교가 실패했다. 금지 목록 방식은 ‘일치하면 막는다’는 구조라 비교가 실패하면 기본값이 ‘허용’이 된다. 프롬프트 인젝션으로 에이전트가 위험한 연산을 시도하도록 유도되면 이 틈으로 실제 클라우드 변경이 일어난다.

## 플랫폼 엔지니어 관점
- awslabs.aws-api-mcp-server를 1.5.1 이상으로 올리고, 사내 포크나 파생 MCP 서버가 같은 정규화 코드를 복사했는지 확인한다.
- MCP 서버의 정책을 1차 방어선으로 두지 않는다. 서버가 쓰는 AWS 자격 증명 자체를 읽기 전용 또는 작업 범위로 제한한 IAM 역할·권한 경계·SCP로 묶어, 정책이 뚫려도 IAM이 거부하게 한다.
- 거부 목록보다 허용 목록과 READ_OPERATIONS_ONLY·REQUIRE_MUTATION_CONSENT 같은 내장 모드를 우선 쓴다.
- CloudTrail에서 MCP 서버 세션 역할로 실행된 변경 연산(IAM·MFA·RDS 삭제)을 경보로 건다. 정책 엔진에는 ‘정책에 나온 모든 이름이 실제 연산 목록과 매칭되는지’ 회귀 테스트를 추가한다.
