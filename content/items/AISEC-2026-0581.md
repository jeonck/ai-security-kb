## 요약
Corelight는 고객 환경과 자체 랩에서 MCP 서버의 의존성이 실제로 얼마나 흔들리는지 네트워크·EDR 로그로 측정했다. 릴리스와 커밋을 고정하고 해시 잠금 파일까지 둔 서버도, uvx 같은 실행기가 잠금 파일을 쓰지 않아 실행·재빌드 때마다 하위 의존성 약 60개를 PyPI에서 새로 받았다. 한 릴리스가 5주 동안 15개의 서로 다른 환경으로 실행됐고, 69개 패키지 중 23개(암호·JWT·MCP SDK 포함)가 바뀌었다. 검토한 35개 MCP 서버 중 23개가 이런 설치법을 권장했다. 침해는 없었지만, 이 서버들이 방화벽·SIEM 같은 관리 시스템 자격 증명을 쥐고 있다는 점에서 공급망 공격의 문이 열려 있는 셈이다.

## 동작 원리
‘같은 레시피 번호’로 주문해도 주방이 매번 그날 시장에서 재료를 새로 사 오면 요리는 매번 달라진다. uvx·npx는 편의를 위해 패키지를 그 자리에서 해석·설치하는 실행기라, 상위 패키지 버전만 고정하면 하위 의존성은 버전 범위 안에서 최신으로 끌려온다. 그 사이 하위 패키지 하나가 탈취돼 악성 버전이 올라오면, 자격 증명을 쥔 MCP 서버가 다음 실행 때 그것을 그대로 실행한다. 반대로 한 번 설치해 고정한 ‘동결’ 환경은 같은 실행을 수백 번 반복해도 변하지 않았다.

## 플랫폼 엔지니어 관점
- 개발자 PC·점프 호스트·에이전트 런너의 MCP 클라이언트 설정(`.mcp.json`, IDE 설정)에서 `uvx`, `npx ...@latest`, 범위 의존성 설치를 찾아 목록화한다. 자격 증명을 쥔 서버부터 해시 고정 설치 → 직접 실행으로 바꾸고, 소유자를 지정한다.
- 사내 MCP 서버는 컨테이너 이미지로 빌드해 다이제스트로 고정하고, 사내 프록시 레지스트리만 바라보게 한다. 재잠금은 정기 PR로 검토한다.
- 네트워크 탐지: 개발 서버가 아닌 워크스테이션·관리 호스트에서 PyPI·npm·GitHub로 나가는 짧은 반복 세션을 DNS·TLS 로그로 찾는다. 엔드포인트 프로세스 귀속도 함께 쓴다.
- MCP 서버에 준 관리 시스템 자격 증명은 최소 권한으로 줄여, 의존성이 탈취돼도 폭발 반경을 제한한다.
