## 요약
코딩 에이전트 하니스(모델이 bash·curl 같은 도구를 쓰는 실행 틀)를 위한 방어 구조를 제안하고 정량 비교한 논문이다. 저자들은 프롬프트 인젝션 방어를 모델의 판단에 맡기는 대신, 능력 토큰·오염(taint) 추적·결정적 OS·도구 가드를 겹친 참조 모니터로 권한을 통제해야 한다고 주장한다. 252개 시나리오에서 소형 LLM 판정기는 정상 작업을 거의 다(98.3%) 막아 쓸 수 없었고, 결정적 가드는 마이크로초 단위로 공격을 모두 막으면서 오탐이 없었다. 매 단계만 보는 상태 없는 정책은 여러 단계에 걸친 킬 체인 3분의 1을 놓쳤다.

## 동작 원리
‘똑똑한 경비원’(LLM 판정기)에게 매번 ‘이 명령 괜찮아?’라고 묻는 방식은 느리고, 확신이 없으면 다 막아 버린다. 대신 건물 구조로 막는다. 각 도구 호출은 미리 발급된 능력 토큰이 있어야 하고, 외부에서 들어온 데이터에는 ‘어디서 왔는지·얼마나 민감한지’ 두 축의 꼬리표가 붙어 어떤 도구로 흘러갈 수 있는지가 격자 규칙으로 결정된다. 예를 들어 웹에서 읽은 내용(신뢰 낮음)이 비밀 파일(민감도 높음)과 섞인 뒤 curl로 나가려 하면 규칙이 즉시 막는다. 한 단계만 보면 무해한 동작들이 이어져 유출이 되는 킬 체인은, 꼬리표가 단계를 넘어 따라가기 때문에 잡힌다. 꼬리표를 ‘오염됨/아님’ 하나로만 두면 너무 많이 막혀 정상 작업이 멈춘다.

## 플랫폼 엔지니어 관점
- 사내 에이전트 플랫폼에서 ‘LLM 가드레일 하나로 도구 호출 승인’ 구성을 쓰고 있다면, 오탐률과 지연을 실제로 측정한다. 이 논문은 소형 판정기가 사실상 모든 정상 작업을 막을 수 있음을 보여 준다.
- 도구 실행 경로에 결정적 정책(허용 명령·경로·목적지 목록, seccomp·네트워크 정책)을 먼저 두고, 모델 판단은 그 위의 보조 신호로 쓴다.
- 세션 단위 데이터 흐름 추적(외부 입력 → 비밀 접근 → 네트워크 송신)을 감사 로그와 정책에 반영한다. 단계별 허용 판단만으로는 다단계 유출을 놓친다.
- 평가가 저자 자체 시나리오라는 한계를 감안해, 도입 전 자체 레드팀 시나리오로 재현한다.
