## 요약
AWS의 터미널용 AI 코딩 어시스턴트 Kiro CLI가 세션 기록(transcript)과 프롬프트 히스토리 파일을 너무 넓은 기본 권한으로 만들어, 같은 호스트에 로그인한 다른 사용자가 이를 읽을 수 있었다. 이 파일에는 사용자가 입력한 프롬프트, 모델 응답, 에이전트가 실행한 도구의 출력이 그대로 남기 때문에 그 안에 섞인 토큰·비밀번호·소스 코드가 함께 노출된다. 1.16.0~2.26.x가 영향을 받고 2.27.0에서 고쳤으며, 전신인 Amazon Q Developer CLI의 히스토리 파일도 따로 정리해야 한다. 수정은 10월 1일에 나왔지만 공지는 11월 10일에 나왔다.

## 동작 원리
코딩 에이전트의 대화 기록은 사실상 ‘작업 일지 + 터미널 화면 녹화’다. 에이전트가 `env`나 설정 파일을 읽어 출력하면 비밀 값이 기록에 들어간다. 이 일지를 공용 책상 위에 펼쳐 둔 것과 같은 상황이 기본 umask·파일 권한 설정 때문에 생겼다. 공유 빌드 서버나 점프 호스트처럼 여러 사람이 쓰는 머신에서는 다른 계정이 홈 디렉터리의 `~/.kiro` 파일을 그냥 열어 볼 수 있었다.

## 플랫폼 엔지니어 관점
- 공유 개발 서버·배스천·CI 러너에 설치된 Kiro CLI와 Amazon Q Developer CLI 버전을 점검해 2.27.0 이상으로 올리고 한 번 실행시켜 권한을 고친다. `~/.kiro`, `~/.aws/amazonq/.cli_bash_history`의 권한을 일괄 확인한다.
- 다중 사용자 호스트에서는 사용자 홈을 0700으로, 기본 umask를 077로 강제하는 구성 관리를 둔다. 코딩 에이전트는 가능하면 사용자별 devcontainer·VM에서 돌린다.
- 에이전트 세션 기록을 비밀 저장소처럼 취급한다. 기록 보존 기간을 정하고, 비밀 스캐너를 기록 디렉터리에도 돌리며, 노출이 의심되면 기록에 나온 자격 증명을 교체한다.
- 다른 코딩 에이전트(Claude Code, Codex, Gemini CLI 등)의 로컬 기록 디렉터리 권한도 같은 기준으로 감사한다.
