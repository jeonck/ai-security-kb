## 요약
Darktrace 연구진이 개발자 PC를 이미 장악한 공격자가 사용자의 Claude Console 자격 증명을 훔쳤을 때, Claude 메모리 스토어와 Claude Code를 엮어 실시간 C2 채널을 만들 수 있음을 실험실에서 보였다. 공격자는 메모리 스토어에 하트비트·입력·출력 파일을 만들고, systemd로 Claude Code를 반복 실행시켜 입력 파일의 평문 지시를 수행하게 했다. 에이전트는 네트워크 탐색, 패스워드 스프레이, SMB 공유 열거를 거쳐 1GB 파일을 Files API로 빼냈다. 모든 통신은 api.anthropic.com으로만 오갔다. Darktrace는 플랫폼 취약점이 아니고 실제 악용도 보지 못했다고 밝혔다.

## 동작 원리
고전적인 ‘living off the land’가 OS에 원래 있는 도구를 쓰듯, 이 기법은 조직이 이미 허용한 AI 플랫폼을 우편함처럼 쓴다. 공격자가 우편함(메모리 스토어)의 입력 파일에 할 일을 적으면 에이전트가 읽고 실행한 뒤 결과를 출력 파일에 적는다. 명령이 셸 명령이 아니라 자연어 목표라서, 운영자는 ‘이 네트워크에서 계정을 찾아라’ 정도만 적고 구체 명령은 모델이 고른다. 페이로드에 악성 코드가 거의 없고, 트래픽은 평소 추론 호출과 같은 목적지로 가므로 도메인 차단이나 평판 기반 탐지로는 걸러지지 않는다.

## 플랫폼 엔지니어 관점
- 개발자 단말과 CI의 Claude·OpenAI API 키를 운영 비밀과 같은 등급으로 관리한다. 가능하면 OAuth·ID 연동을 쓰고, 정적 키는 단기·최소 범위로 발급해 셸 이력·dotfile·환경 변수에 남기지 않는다.
- 조직 워크스페이스에서 메모리 스토어·Files API 같은 저장 기능이 필요 없으면 키 권한이나 워크스페이스 설정으로 막고, 새 메모리 스토어 생성·파일 업로드를 감사 로그 경보 대상으로 둔다.
- 에이전트 하네스 프로세스의 생성(누가, 어떤 인자로, systemd·cron 등 비대화형으로 띄웠나)과 AI API로 가는 송수신 비율을 함께 기준선화한다. 업로드가 평소보다 큰 세션, 사람이 없는 시간의 비대화형 반복 실행은 조사한다.
- egress에서 AI API 도메인을 허용하더라도 조직 테넌트·키 단위로 묶는 프록시를 두면, 훔친 키로 다른 워크스페이스를 쓰는 경로를 줄일 수 있다.
