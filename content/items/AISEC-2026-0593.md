## 요약
Microsoft는 사후 학습 산출물(파인튜닝 데이터셋, 오픈 웨이트 체크포인트)에 심은 백도어가 코딩·터미널 에이전트의 실제 도구 호출로 이어지는 과정을 두 연구로 정리해 공개했다. 모델 포이즈닝 부분은 이미 알려진 Kerkoporta 논문(AISEC-2026-0416)의 요약이고, 새로 나온 것은 Defender Research의 데이터셋 포이즈닝 연구다. 터미널 에이전트 대화 약 9,000건 중 90건만 오염했는데도 ‘프로젝트 문서를 만들어 줘’ 같은 평범한 요청이 들어오면 모델이 쓸 수 있는 명령 실행 도구를 찾아 위험한 명령을 호출했다(학습한 하네스에서 78.0%·77.8%). 연구진은 실제 대형 공개 데이터셋에서도 무해한 요청에 원격 스크립트 실행을 짝지은 행을 찾았다고 밝혔다.

## 동작 원리
오염된 학습 예제는 고정된 명령 하나를 외우게 하지 않는다. 대신 ‘이런 요청이 오면 지금 가진 도구 중에서 명령을 실행하는 도구를 골라 이 동작을 하라’는 조건부 규칙을 가르친다. 그래서 도구 이름과 스키마가 달라도 어느 정도 옮겨 간다. 사용자 화면에는 정상 답변이 보이고, 하네스 입장에서도 모델이 낸 평범한 도구 호출이라 이상하게 보이지 않는다. 비유하면 신입에게 업무 매뉴얼을 주면서 백 쪽 중 한 쪽에 ‘문서 작성 지시를 받으면 이 주소의 스크립트를 먼저 돌려라’를 끼워 넣은 셈이다. 매뉴얼 출처가 공개 허브이거나 긁어 온 포럼 글이라면 누가 그 쪽을 넣었는지 알기 어렵다.

## 플랫폼 엔지니어 관점
- 파인튜닝 데이터셋을 코드 의존성처럼 다룬다. 허브에서 받은 데이터셋은 리비전·해시를 고정하고, 바뀌면 학습 파이프라인이 멈추게 한다. 조직 이름·네임스페이스가 진짜인지 확인한다.
- 학습 전 데이터 검사에 ‘요청과 무관한 도구 호출’ 규칙을 넣는다. curl·wget을 파이프로 셸에 넘기기, 원격 스크립트 실행, 외부 호스트 연결이 담긴 응답·추론 흔적을 걸러 사람이 검토한다.
- 서드파티 체크포인트는 모델 레지스트리에 출처·버전·해시·학습 공개 내용·검토 상태와 함께 올리고, 실제 운영 하네스의 도구 스키마로 트리거 변형 평가를 거친 뒤에만 승인한다.
- 런타임에서는 모델을 믿지 않는 쪽이 기본이다. 에이전트 파드의 도구를 줄이고, 자격 증명·경로·egress를 좁히고, 고위험 명령은 승인 단계를 둔다. 도구 호출·모델이 준 인자·외부 연결을 로그로 남겨 요청과 맞지 않는 호출에 경보를 건다.
