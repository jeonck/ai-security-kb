## 요약
Anthropic은 11월 12일(2.1.323)과 13일(2.1.325) Claude Code 업데이트를 내면서 샌드박스와 권한 검사 관련 수정·변경을 수십 건 실었다. 워크트리를 만들 때의 샌드박스 탈출, 환경 변수 접두로 명령을 숨겨 권한 검사를 비켜 가는 우회, sudo·env 래퍼로 deny 규칙을 피하는 문제가 고쳐졌다. 비밀 값이 든 명령을 ‘다시 묻지 않기’로 승인하면 settings.local.json에 평문으로 저장되던 문제(AISEC-2026-0540)에도 대응해, 그런 규칙은 이제 세션에서만 유지된다. 2.1.325에서는 샌드박스 안 명령의 자동 승인이 기본에서 빠졌다. 변경 기록에는 CVE가 적혀 있지 않다.

## 동작 원리
코딩 에이전트의 보호 장치는 두 겹이다. 하나는 어떤 명령을 묻지 않고 실행할지 정하는 권한 규칙이고, 다른 하나는 실행된 명령이 닿을 수 있는 파일·네트워크를 줄이는 샌드박스다. 이번 수정 목록은 두 겹 모두 ‘명령을 어떻게 읽느냐’와 ‘경로가 어디로 이어지느냐’에서 새고 있었음을 보여 준다. 래퍼나 환경 변수 접두를 붙이면 규칙이 명령 이름을 잘못 읽고, 워크트리·심볼릭 링크·추가 디렉터리를 거치면 샌드박스가 보호해야 할 설정·훅 파일에 쓸 수 있었다. 훅과 설정 파일은 다음 실행 때 코드가 되므로, 여기에 쓸 수 있다는 것은 샌드박스 밖으로 나가는 문과 같다. ‘샌드박스 안이면 자동 승인’이라는 기본값을 거둔 것도 샌드박스 하나에 모든 것을 맡기지 않겠다는 방향이다.

## 플랫폼 엔지니어 관점
- 개발자 PC·CI 러너·에이전트 이미지의 Claude Code를 2.1.325 이상으로 올리고, 버전을 고정해 배포한다. 이 정도 규모의 경계 수정은 구버전이 남아 있는 것 자체가 위험이다.
- 관리형 설정을 쓰는 조직은 sandbox.autoAllowBashIfSandboxed 기본값 변경으로 비대화형 작업(claude -p, SDK, 예약 작업)이 멈출 수 있다. 의도적으로 켤지, 승인 흐름을 설계할지 정하고 최상위 관리 출처에서 일관되게 배포한다.
- 저장소의 .claude/settings.local.json이 커밋돼 있지 않은지 시크릿 스캐닝·푸시 보호로 확인하고, 이미 저장된 비밀 값은 회전한다. 업데이트는 새로 저장되는 규칙만 막는다.
- 샌드박스 설정이 검증에 실패하면 이제 시작이 멈춘다. CI에서 설정 파일 유효성 검사를 먼저 돌려 파이프라인이 조용히 깨지지 않게 한다.
- 에이전트가 쓰는 워크트리·추가 디렉터리를 최소화하고, 훅·스킬 파일 변경을 감사 로그와 코드 리뷰 대상에 넣는다.
