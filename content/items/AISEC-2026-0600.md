## 요약
SaaS 에이전트를 노리는 ‘자원 증폭’ 공격 OverServe를 다룬 논문이 arXiv에 올라왔다(11월 10일 제출, 11월 13일 목록 공개). 악성 테넌트는 사실만 말하는 MCP 상태 도구와 ‘끝났는지 확인하라’는 평범한 문구를 함께 넣는다. 백엔드 상태가 계속 바뀌면 에이전트는 원래 일을 끝내고도 상태를 확인하고 또 확인하며, 그 비용은 구독료를 받는 제공자가 떠안는다. 4개 모델·9개 벤치마크에서 과제 검사는 모두 통과했고 API 요청은 최대 93.88배로 늘었으며, 산업용 MCP 스캐너 5종은 공격 도구를 하나도 잡지 못했다.

## 동작 원리
식당에서 ‘주문이 다 나왔는지 확인해 주세요’라고 부탁한 뒤 주방이 계속 새 메뉴를 추가하면, 성실한 직원은 끝없이 주방을 오간다. 에이전트는 스스로 언제 멈출지를 정하는데, 공격자가 그 판단 기준(완료 조건)을 계속 바뀌는 상태에 묶어 두면 성실함이 곧 낭비가 된다. 도구는 거짓말을 하지 않고 프롬프트도 악성 명령이 없어서, 도구만 보거나 프롬프트만 보는 검사로는 걸리지 않는다. 문제는 두 개가 만났을 때 생긴다.

## 플랫폼 엔지니어 관점
- 테넌트가 서드파티 MCP 도구를 붙일 수 있는 에이전트 플랫폼은 과제당 도구 호출 수·토큰·벽시계 시간 예산을 하드 리밋으로 둔다. 모델이 멈추길 기대하지 않는다.
- 같은 도구를 같은 인자로 반복 호출하는 패턴, 과제 완료 판정 이후의 호출을 지표로 만들어 테넌트별 비용 이상 탐지에 넣는다.
- MCP 도구 승인 심사를 도구 정의만이 아니라 ‘이 도구를 쓰는 프롬프트·완료 조건’과 묶어서 본다. 상태 폴링형 도구에는 최대 대기 횟수를 강제한다.
- 정액 요금제 SaaS라면 테넌트별 실제 모델 비용 계측을 청구와 분리해 운영 대시보드에 둔다.
