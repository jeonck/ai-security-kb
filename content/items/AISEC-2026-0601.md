## 요약
Anthropic은 11월 12일 Claude Managed Agents를 고객이 자기 클라우드나 온프레미스에서 직접 운영하는 자체 호스팅 옵션을 비공개 베타로 공개했다. 에이전트의 제어부(하네스), 코드 실행 샌드박스, 자격 증명, 세션 기록이 모두 고객 경계 안에 있고, 모델 요청을 어디로 보낼지도 고객이 정한다. 보안 설계로는 하네스·샌드박스 분리, 샌드박스 밖 자격 증명 주입 프록시, 환경별 호스트 허용 목록, OpenTelemetry 감사 기록을 내세웠다.

## 동작 원리
‘두뇌’(모델을 부르고 다음 행동을 정하는 하네스)와 ‘손’(명령을 실제로 돌리는 샌드박스)을 다른 곳에 둔다. 손에는 열쇠를 주지 않는다. 손이 외부 API나 MCP 도구를 부르면, 경계 밖에 선 문지기(프록시)가 요청을 받아 그때만 열쇠를 꽂아 내보낸다. 그래서 샌드박스 안 코드가 프롬프트 인젝션에 넘어가도 토큰 자체를 읽어 빼낼 수는 없다. 문지기는 정해진 주소로만 길을 열어 주므로, 빌드 수정 에이전트라면 git 호스트와 패키지 레지스트리 말고는 나갈 곳이 없다. 모든 단계는 샌드박스 밖 기록으로 남는다.

## 플랫폼 엔지니어 관점
- 자체 호스팅을 검토하면 하네스·샌드박스 작업자를 서로 다른 네임스페이스·노드 풀에 두고, 샌드박스 파드에는 서비스 계정 토큰 자동 마운트와 시크릿 볼륨을 주지 않는다. 자격 증명은 프록시만 시크릿 관리자에서 읽게 한다.
- 호스트 허용 목록을 Kubernetes NetworkPolicy·egress 게이트웨이·방화벽에서 이중으로 건다. 에이전트 종류별(빌드 수정, 문서 작성 등)로 목록을 따로 관리한다.
- 프록시가 지원하지 않는 API 호출은 샌드박스 안에 자격 증명을 넣고 싶어지는 지점이다. 그런 요구는 예외 승인으로만 처리하고 단기 토큰을 쓴다.
- OpenTelemetry로 나오는 도구 호출 기록을 기존 SIEM에 붙여 허용 목록 위반 시도, 예상 밖 도구 호출에 경보를 건다. 세션 기록 DB는 개인정보·비밀 값이 들어가는 저장소로 보고 접근 통제·보존 기간을 정한다.
