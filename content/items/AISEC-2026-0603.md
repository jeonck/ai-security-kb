## 요약
Cursor가 10월 29일 자사 확장 마켓플레이스에 올라온 변조 Claude Code 확장 사고(AISEC-2026-0307)의 조사 결과를 11월 13일 공개했다. 사고는 Cursor가 추론 벤더 Fireworks에 발급한 접근 키가 Fireworks 쪽에서 노출되면서 시작됐다. 공격자는 이 키로 두 회사가 데이터를 주고받던 버킷에서 코딩 에이전트 트레이스를 복사했고, 트레이스에 섞여 있던 평문 자격 증명으로 Cursor의 SaaS 도구에 들어가 마켓플레이스 캐시에 악성 빌드 2.1.312·2.1.313을 올렸다. 노출 고객 비율은 작지만, 벤더 키 → 데이터 → 자격 증명 → 배포 경로로 이어지는 연쇄가 1차 원문으로 확인됐다.

## 동작 원리
협력사에 맡긴 열쇠 하나가 창고 문을 열었고, 창고 안 작업 일지(에이전트 트레이스)에 다른 방 열쇠가 적혀 있었던 셈이다. 코딩 에이전트의 세션 기록에는 사용자가 붙여 넣은 토큰이나 명령 속 비밀이 그대로 남기 쉽다. 이 기록을 모델 개선용으로 외부 벤더와 공유하면, 벤더의 보안 수준이 곧 내 자격 증명의 보안 수준이 된다. 공격자는 거기서 얻은 자격 증명으로 배포 인프라(확장 캐시)를 건드렸고, 서명된 공식 업데이트가 아니라 캐시 계층을 바꿔 사용자에게 악성 빌드를 내려보냈다.

## 플랫폼 엔지니어 관점
- 외부 추론·학습 벤더에 발급한 키는 버킷·접두어 단위로 범위를 좁히고 수명을 짧게 하며, 출발지 IP·워크로드 신원으로 묶는다. 공유 버킷 접근 로그를 벤더별로 따로 본다.
- 에이전트 트레이스·세션 로그를 외부로 내보내거나 장기 보관하기 전에 비밀 스캐닝·마스킹 단계를 파이프라인에 넣는다. 트레이스 저장소는 비밀 저장소에 준해 분류한다.
- IDE 확장·에이전트 플러그인은 마켓플레이스 캐시가 아니라 게시자 서명·해시 고정으로 검증하고, 사내 미러를 운영한다면 원본(Open VSX 등)과의 해시 비교를 자동화한다.
- 2.1.312·2.1.313을 받은 개발자 단말이 있으면 Cursor의 10월 29일 공지 절차대로 점검하고, 그 단말에서 쓰인 SSH 키·클라우드 토큰을 회수한다.
