## 요약
에이전트 도구 연결의 사실상 표준인 Model Context Protocol(MCP)의 명세 저장소가 11월 13일 EU 사이버복원력법(CRA) 스튜어드십 지침을 SECURITY.md에 넣었다. 실제 악용 중인 취약점과 중대 사고는 GitHub 보안 권고로 접수하고, 핵심 메인테이너가 Linux Foundation의 CRA 스튜어드에게 넘겨 24시간 조기 경보, 72시간 상세 통지 기한을 맞춘다. 악용 증거가 없는 결함은 기존 권고 절차를 따른다. CRA가 오픈소스 AI 프로토콜의 취약점 처리 방식을 실제로 바꾸기 시작한 사례다.

## 동작 원리
CRA는 제조사뿐 아니라 상업적으로 쓰이는 오픈소스를 지속적으로 지원하는 법인(스튜어드)에게도 보안 정책 문서화와 실제 악용 취약점 보고 의무를 준다. MCP는 Linux Foundation 산하로 옮겨졌기 때문에 LF 법인이 스튜어드 역할을 맡고, 프로젝트는 신고 창구와 내부 에스컬레이션 경로를 정해 두는 쪽이다. 메인테이너 개인이 규제 기관이나 스튜어드에게 제각각 연락하지 않도록 창구를 한 줄로 세운 것이 핵심이다.

## 플랫폼 엔지니어 관점
- MCP SDK·서버를 쓰는 팀은 명세·SDK 저장소의 GitHub 보안 권고를 구독(Dependabot·OSV 연동)해, ‘실제 악용’ 표시 권고가 나오면 72시간 안에 영향 판정을 끝내는 내부 절차를 만든다.
- 사내에서 MCP 서버를 만들어 EU 고객에 상업적으로 제공한다면 우리 자신이 CRA상 제조사일 수 있다. SECURITY.md·신고 창구·SBOM·인지 시각 기록을 갖춘다.
- 권고에 인지 시각·통지 시각이 남게 되므로, 우리 쪽 패치 지연을 측정하는 지표(권고 공개 → 배포)로 활용한다.
