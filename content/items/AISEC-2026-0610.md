## 요약
중소벤처기업부의 창업 지원 사업 ‘2차 모두의 창업’은 참가자에게 외부 AI 솔루션 50곳을 연결해 준다. 그중 AI 법률 문서 도구 ‘로폼’ 운영사 아미쿠스렉스가 11월 11일 해킹당해 이용자 2만 28명의 이름·전화번호·이메일이 유출됐고, 이 가운데 818명이 사업 참가자였다. 연합뉴스가 본 유출 신고서에는 관리자 페이지를 통한 SQL 인젝션 시도가 적혀 있었고, 회사는 취약한 API 코드를 지웠다. 6월 1차 사고에 이어 같은 사업에서 다시 API 취약점이 문제가 됐고, 공개까지 약 60시간이 걸려 늑장 공개 비판도 나왔다.

## 동작 원리
정부 플랫폼 자체는 뚫리지 않았다. 문제는 플랫폼이 참가자를 외부 AI 도구로 보내면서 개인정보도 함께 넘긴다는 점이다. 참가자 입장에서는 ‘정부 사업’이지만, 실제 데이터는 50개 공급기업의 서로 다른 시스템에 흩어져 저장된다. 이 중 가장 약한 한 곳의 관리자 페이지나 API가 뚫리면 사업 전체의 신뢰가 무너진다. 사슬의 강도는 가장 약한 고리가 정한다.

## 플랫폼 엔지니어 관점
- 사내·공공 플랫폼이 외부 AI SaaS를 연동해 줄 때는 공급기업마다 넘기는 개인정보 항목을 최소화하고, 연동 계약에 보안 점검(관리자 페이지 외부 노출 금지, API 인증·속도 제한, 침해 시 통보 시한)을 넣는다.
- 공급기업 목록을 위험 등록부로 관리하고, 선정 시점뿐 아니라 운영 중에도 외부 공격 표면 스캔(관리자 경로, 인증 없는 API)을 주기적으로 돌린다.
- 침해 통보를 받은 순간부터 공개·이용자 통지까지의 내부 시한을 정해 두고, 통보 체인(공급기업 → 운영기관 → 부처)이 길어질수록 지연이 쌓인다는 점을 런북에 반영한다.
