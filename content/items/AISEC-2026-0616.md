## 요약
원격 개발 환경 플랫폼 Coder에서, 외부 워크스페이스(사용자가 직접 띄운 머신에 Coder 에이전트를 설치하는 방식)의 설치 정보를 주는 API가 워크스페이스 ‘읽기’ 권한만 확인하는 결함이 고쳐졌다. 이 API는 워크스페이스 에이전트 토큰을 함께 돌려줬기 때문에, 워크스페이스를 볼 수는 있어도 접속할 수는 없게 설계된 템플릿 관리자·조직 관리자가 다른 사용자의 에이전트 토큰을 얻을 수 있었다. 그 토큰으로 소유자의 Git SSH 키와 Git OAuth 토큰을 읽고, 에이전트로 행세해 소유자의 세션을 가로챌 수 있었다. 저장소 권고는 10월 29일, CVE-2026-126403은 11월 13일 게시됐다.

## 동작 원리
Coder는 ‘워크스페이스를 본다(read)’와 ‘워크스페이스에 들어간다(ssh)’를 다른 권한으로 나눈다. 다른 에이전트용 엔드포인트는 ssh를 요구했는데, 외부 에이전트 자격 증명 엔드포인트만 워크스페이스를 불러오는 과정의 읽기 검사에 기대고 있었다. 방 배치도를 볼 수 있는 사람에게 방 열쇠까지 같이 건넨 셈이다. 에이전트 토큰은 워크스페이스 소유자를 대신해 Git 자격 증명을 받아 오는 신분증이므로, 토큰 하나가 곧 소유자의 저장소 권한으로 이어졌다.

## 플랫폼 엔지니어 관점
- Coder Premium에서 coder_external_agent 템플릿을 쓰면 수정 버전으로 올린다. 지원 종료 계열(2.26~2.28, 2.30~2.33, 2.35)은 패치가 없으니 지원 계열로 옮긴다. 바로 못 올리면 템플릿·조직 관리자 역할을 신뢰할 수 있는 소수로 줄인다.
- 영향 기간 동안 관리자 계정이 다른 사용자 워크스페이스의 credentials 엔드포인트를 호출한 감사 로그가 있는지 찾고, 의심되면 해당 워크스페이스의 에이전트 토큰과 연결된 Git SSH 키·OAuth 토큰을 회수한다.
- coder external-workspaces agent-instructions를 쓰는 자동화 토큰은 이제 ssh를 주는 범위(coder:workspaces.access)가 필요하다. CI 파이프라인의 토큰 범위를 다시 확인한다.
- 템플릿 수정 권한이 있는 역할은 여전히 빌드 상태에서 에이전트 토큰을 읽을 수 있다. 템플릿 수정 권한을 ‘에이전트 토큰 열람 권한’으로 간주하고 등록부에 적는다.
- 원격 개발 환경에서 AI 코딩 에이전트를 돌리면 워크스페이스 에이전트 토큰이 곧 그 에이전트의 신원이다. 에이전트에 Git 자격 증명을 주입하는 방식이 워크스페이스 토큰 하나에 묶여 있는지 점검한다.
