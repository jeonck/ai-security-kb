## 요약
Opera는 에이전트형 브라우저 Opera Neon에 들어간 MCP Hub 확장(0.0.1)의 결함을 CVE-2026-123139로 공개했다. MCP Hub가 메시지를 보낸 쪽이 누구인지 확인하지 않아, 사용자가 설치한 악성 확장이 MCP Hub를 거쳐 브라우저를 대신 조작하는 내장 Browser Operator 확장에 명령을 넣을 수 있었다. 결과는 브라우저 장악이다. 권고는 짧아서 수정 버전, 발견자, 기술 상세를 밝히지 않았다.

## 동작 원리
에이전트형 브라우저는 ‘도구를 모아 주는 허브(MCP Hub)’와 ‘실제로 클릭·입력하는 에이전트(Browser Operator)’를 확장 형태로 나눠 두고 내부 메시지로 잇는다. 이 내부 메시지 창구가 발신자를 가리지 않으면, 같은 브라우저 안의 아무 확장이나 허브인 척 에이전트에 지시할 수 있다. 사내 내선 전화가 외부 번호도 내선처럼 받아 주는 셈이다. 프롬프트 인젝션처럼 모델을 속일 필요가 없고, 권한 있는 채널을 그대로 쓰는 점이 다르다.

## 플랫폼 엔지니어 관점
- 사내에서 Opera Neon 같은 에이전트형 브라우저를 허용하고 있다면 버전과 MCP Hub 확장 버전을 자산 목록에 올리고, 수정 버전이 확인될 때까지 업무 계정 로그인 프로필에서는 쓰지 않게 한다.
- 브라우저 관리 정책(MDM·확장 허용 목록)으로 설치 가능한 확장을 제한한다. 에이전트형 브라우저에서는 확장 하나가 에이전트 전체 권한을 빌릴 수 있으므로 일반 브라우저보다 허용 목록을 더 좁힌다.
- 자체 에이전트 플랫폼에서 MCP 허브·도구 프록시와 실행 에이전트를 분리해 둘 때, 둘 사이의 로컬 채널(localhost 포트, 확장 메시지, 소켓)이 발신자를 인증하는지 점검한다. 내부 채널이라는 이유로 인증을 생략하면 같은 호스트의 다른 프로세스가 에이전트를 조종한다.
- 브라우저 에이전트가 로그인 세션을 쥐고 있는 사이트(사내 SaaS·클라우드 콘솔)는 별도 프로필이나 격리 브라우저로 나눠, 브라우저 장악이 곧 업무 계정 장악으로 이어지지 않게 한다.
