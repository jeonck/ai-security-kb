## 요약
CISA가 11월 18일 LiteLLM의 샌드박스 탈출 취약점 CVE-2026-40217을 KEV 목록에 올렸다. 실제 공격에 쓰였다는 증거가 있다는 뜻이다. GitLab 권고에 따르면 이 취약점은 LiteLLM 프록시의 커스텀 코드 가드레일 시험 엔드포인트에 있다. 사용자가 보낸 파이썬을 자체 샌드박스에서 돌리는데, 이 샌드박스를 벗어나 root 권한으로 코드를 실행할 수 있다. Google GTIG는 앞서 LLMjacking 사고에서 공격자가 이 CVE로 제한된 가상 키를 관리자 권한으로 올렸다고 보고했다(AISEC-2026-0415, AISEC-2026-0628). 수정 버전은 5월에 나온 1.83.10이다. 연방기관은 12월 2일까지 조치해야 한다.

## 동작 원리
가드레일 시험 기능은 관리자가 ‘이 검사 코드가 잘 동작하는지’ 미리 돌려 보게 해 주는 편의 기능이다. 그런데 그 코드를 자체 제작한 파이썬 샌드박스에서 실행했다. 파이썬은 바이트코드를 직접 조작하거나 내부 객체를 타고 올라가는 길이 많다. 그래서 금지 목록 방식의 샌드박스는 대개 뚫린다. 탈출한 코드는 프록시 프로세스 권한, 기본 이미지에서는 root로 돈다. LLM 게이트웨이는 모든 모델 제공자의 API 키와 가상 키 데이터베이스를 쥐고 있는 금고 같은 자리다. 그래서 여기서 코드가 실행되면 공격자는 금고 열쇠 전체를 얻는다.

## 플랫폼 엔지니어 관점
- 운영 중인 LiteLLM 프록시 버전을 확인하고 1.83.10 이상으로 올린다. 컨테이너 이미지 스캔 정책에 KEV 등재 CVE를 차단 조건으로 넣는다.
- `/guardrails/test_custom_code` 같은 관리·시험용 경로는 리버스 프록시나 Ingress에서 외부 접근을 막고, 관리 API는 내부망·관리자 전용 경로로만 연다.
- 게이트웨이 파드는 non-root로 돌리고, 읽기 전용 루트 파일시스템과 최소 egress를 적용한다. 제공자 API 키는 파드 환경 변수가 아니라 단기 발급 시크릿으로 주입한다.
- 가상 키의 권한 변경·신규 관리자 키 생성·키별 사용량 급증을 감사 로그로 남기고 경보를 건다. 등재 이전에 이미 악용됐을 수 있으므로 지난 몇 달치 기록을 되짚어 본다.
