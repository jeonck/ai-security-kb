## 요약
Kubernetes 트래픽 분석 도구 Kubeshark의 MCP 서버(`kubeshark mcp`)에서 두 결함이 11월 16일 GitHub Advisory Database와 NVD에 공개됐다. 첫째(CVE-2026-129236)는 `start_kubeshark` 도구의 `pod_regex` 값이 명령 옵션으로 해석되는 문제다. 에이전트가 인젝션된 값을 넘기면 특권 워커 DaemonSet의 이미지가 공격자 레지스트리로 바뀌고, 그 이미지가 노드의 cluster-admin 자격 증명을 읽는다. 둘째(CVE-2026-129235)는 `download_file` 도구가 목적지 경로를 검증하지 않아 사용자가 쓸 수 있는 아무 파일이나 덮어쓰는 문제다. 둘 다 v53.4.0에서 고쳐졌다.

## 동작 원리
명령줄 도구는 ‘-’로 시작하는 문자열을 옵션으로 읽는다. 그래서 사용자 입력을 명령 인자로 넣을 때는 ‘여기부터는 옵션이 아니다’라는 `--` 표시를 앞에 둬야 한다. Kubeshark MCP는 이 표시 없이 파드 정규식을 붙였다. ‘파드 이름 패턴’ 자리에 `--set=...`을 넣으면 Helm 설정을 바꾸는 진짜 옵션이 된다. 바뀐 설정은 노드마다 특권으로 뜨는 워커 이미지의 출처다. 결국 문자열 하나가 ‘클러스터 모든 노드에서 root로 돌 이미지 고르기’가 된다. 공격자가 그 문자열을 직접 칠 필요도 없다. 에이전트가 읽는 문서·이슈·로그에 지시를 숨기면 에이전트가 대신 넘긴다. 셸 인젝션 없이도 인자 경계만 무너지면 충분하다는 점이 핵심이다.

## 플랫폼 엔지니어 관점
- Kubeshark를 쓰면 v53.4.0 이상으로 올리고, `kubeshark mcp`를 `--allow-destructive`로 띄우는 곳이 있는지 개발자 단말·운영 점프 호스트를 점검한다.
- 에이전트가 쓰는 MCP 서버의 kubeconfig는 사람 관리자 kubeconfig와 분리한다. 특권 워크로드·DaemonSet 생성 권한이 없는 전용 ServiceAccount와 네임스페이스 한정 RBAC를 준다.
- 어드미션 정책(Kyverno·Gatekeeper)으로 승인된 레지스트리 밖 이미지와 privileged·hostPath 파드를 막는다. 이미지 출처 정책만 있었어도 이번 체인은 이미지 교체 단계에서 끊긴다.
- 사내에서 만드는 MCP 서버의 코드 리뷰 체크리스트에 ‘외부 인자를 명령에 붙일 때 `--` 구분자와 허용 문자 검증’, ‘파일 경로 인자의 기준 디렉터리 고정’을 넣는다.
- Kubeshark Hub 인증을 켠다. 기본 설치는 캡처된 트래픽을 인증 없이 읽을 수 있다.
