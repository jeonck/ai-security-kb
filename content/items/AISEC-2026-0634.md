## 요약
MCP 서버를 등록·호스팅·중계하는 오픈소스 플랫폼 Obot의 결함 4건이 11월 18일 CVE로 공개됐다. 가장 심각한 CVE-2026-130766은 악성 원격 MCP 서버가 OAuth 메타데이터의 resource 값을 다른 서비스로 적어, 피해자의 그 서비스용 토큰을 받아 가는 문제다. Obot 저장소 권고(10월 31일)에 따르면 RFC 9728이 요구하는 일치 검사가 빠져 있었다. 나머지 셋은 토큰 엔드포인트를 이용한 SSRF, IPv6 전환 주소로 외부 요청 차단을 우회하는 SSRF, MCP 서버 설정값으로 init 컨테이너 스크립트에 명령을 주입하는 결함이다. 모두 0.27.0에서 고쳐졌다.

## 동작 원리
MCP OAuth 흐름에서 클라이언트는 서버에게 ‘너에게 들어갈 열쇠를 어디서 받아야 하니’라고 묻는다. 서버는 ‘이 인가 서버에서, 이 자원용으로’라고 답한다. Obot은 그 답을 그대로 믿었다. 악성 서버가 ‘자원은 회사 Git 서비스’라고 답하면, Obot은 피해자가 늘 쓰는 IdP에서 Git 서비스용 열쇠를 받아 악성 서버에 건넨다. 피해자가 보는 것은 익숙한 동의 화면뿐이다. 택배 기사가 송장의 주소만 보고 남의 집 열쇠를 배달한 셈이다. SSRF 두 건도 같은 뿌리다. 서버가 알려 준 URL을 게이트웨이가 대신 호출하면서 그 목적지가 내부망인지 끝까지 확인하지 않았다.

## 플랫폼 엔지니어 관점
- Obot을 쓰면 0.27.0 이상으로 올린다. 사내 MCP 게이트웨이·클라이언트를 직접 만든다면 RFC 9728 resource 일치 검사와 RFC 8707 자원 지시자 처리를 테스트 케이스로 넣는다.
- IdP에서 개방형 동적 클라이언트 등록을 끄거나 허용 목록으로 제한하고, MCP용 클라이언트가 받을 수 있는 audience·scope를 서비스별로 묶는다.
- MCP 게이트웨이의 외부 호출은 egress 프록시 뒤에 두고 169.254.169.254·사설 대역·IPv6 전환 주소를 DNS 해석 후 단계에서 차단한다. Kubernetes라면 게이트웨이 파드에 NetworkPolicy로 메타데이터 엔드포인트 접근을 막는다.
- ‘Power User’처럼 MCP 서버를 등록할 수 있는 역할은 사실상 게이트웨이 내부망 접근 권한이다. 이 역할의 부여를 승인 절차로 관리한다.
