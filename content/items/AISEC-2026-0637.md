## 요약
Microsoft가 2026-11-17 Ignite에서 에이전트를 사람과 다른 신원으로 다루는 Entra 기능을 대거 내놓았다. 직원 PC에서 돌아가는 Claude Code·Codex·Copilot CLI 같은 로컬 에이전트 60종을 찾아 Agent ID를 주고, 조건부 접근이 사람과 대신 일하는 에이전트를 구분해 위험한 에이전트만 막는다. 후원자·활동 여부를 기준으로 미사용 에이전트 신원을 자동 비활성화하는 수명주기 관리는 정식 출시됐고, MCP 서버·도구 단위 정책을 거는 MCP 방화벽은 프리뷰다. 같은 날 Security 블로그는 에이전트별 위험 점수(Dynamic Agent Risk)와 사이버 특화 모델 MAI-Cyber-2를 발표했다.

## 동작 원리
지금까지 로컬 코딩 에이전트는 그 PC를 쓰는 사람의 토큰으로 움직여, ID 시스템 입장에서는 사람과 구분되지 않았다. 이번 기능은 엔드포인트·네트워크에서 에이전트 프로세스와 트래픽을 식별해 별도 ID를 붙이고, 그 ID에 조건부 접근·네트워크 정책·수명주기 규칙을 건다. ‘같은 사람의 세션이지만 지금 요청을 보낸 주체는 에이전트’라는 구분이 생기면, 에이전트만 차단하거나 민감 목적지 접근만 막는 식의 세밀한 통제가 가능해진다.

## 플랫폼 엔지니어 관점
- 사내 개발자 PC·CI 러너에서 도는 에이전트 목록을 먼저 만든다. 벤더 탐지 기능이 없으면 프로세스·User-Agent·MCP 설정 파일 기준으로 자체 인벤토리를 만든다.
- 에이전트가 사람 토큰을 빌려 쓰지 않도록, 사내 API 게이트웨이에서 에이전트 요청을 식별할 헤더·워크로드 ID를 요구하고 사람 세션과 다른 정책을 건다.
- 에이전트 신원마다 사람 후원자와 만료일을 두고, 미사용 기준(예: 60일)으로 자동 비활성화한다.
- MCP 서버 허용 목록을 도구·메서드 단위까지 내리고, 프로토콜 버전·TLS 요건을 네트워크 계층에서 강제한다.
