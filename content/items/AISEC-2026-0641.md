## 요약
JetBrains가 자사 코딩 에이전트 Junie의 CLI에서, 에이전트가 쓰는 파일 도구가 프로젝트 디렉터리 밖 파일을 수정할 수 있었던 취약점을 CVE-2026-133195로 공개했다. CVSS 3.1 7.5(High), 경로 외부 제어(CWE-73)로 분류됐고 26.6.29에서 고쳐졌다. 공격 복잡도 High·사용자 상호작용 필요로 매겨져 있어, 피해자가 에이전트에 특정 작업을 시키는 상황이 전제로 보인다. 상세 기술 설명은 아직 공개되지 않았다. Junie는 이전에도 GitHub Action의 인젝션 필터 우회(AISEC-2026-0531)가 있었다.

## 동작 원리
코딩 에이전트는 ‘이 프로젝트 폴더 안에서만 읽고 쓴다’는 규칙을 도구 코드 안에서 경로를 검사해 지킨다. 그런데 절대 경로, `../` 같은 상대 경로, 심볼릭 링크 중 하나라도 검사를 빠져나가면 에이전트는 홈 디렉터리의 셸 설정, Git 훅, SSH 설정 같은 파일까지 고칠 수 있다. 이런 파일은 다음에 셸을 열거나 커밋할 때 자동 실행되므로 파일 쓰기 하나가 곧 코드 실행으로 이어진다. 저장소의 README나 이슈에 숨긴 지시로 에이전트가 그런 경로에 쓰도록 유도되면, 사용자는 평소처럼 ‘작업해 줘’라고 시켰을 뿐인데 개발 환경이 장악될 수 있다. 다만 실제 공격 경로는 아직 공개되지 않았다.

## 플랫폼 엔지니어 관점
- 사내 개발자 PC·원격 개발 환경의 Junie CLI 버전을 수집해 26.6.29 미만을 업그레이드한다. MDM·devcontainer 이미지의 고정 버전도 함께 올린다.
- 에이전트의 디렉터리 경계를 도구 구현에 맡기지 말고 컨테이너·devcontainer·별도 사용자 계정처럼 운영체제 수준에서 작업 디렉터리만 쓰기 가능하게 마운트한다. 홈 디렉터리와 `~/.ssh`, 클라우드 자격 증명 파일은 에이전트 실행 환경에 마운트하지 않는다.
- CI에서 Junie를 돌린다면 러너를 일회용으로 두고, 작업 디렉터리 밖 파일 변경(셸 rc, `.git/hooks`)을 파일 무결성 점검으로 탐지한다.
- 코딩 에이전트 도입 기준에 ‘작업 디렉터리 밖 쓰기 차단을 OS 수준에서 보장하는가’를 넣어 제품 간 비교 항목으로 쓴다.
