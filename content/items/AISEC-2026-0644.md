## 요약
쿠버네티스 클러스터를 AI 에이전트가 다룰 수 있게 해 주는 오픈소스 MCP 서버 k8s-mcp-server가 기본 설정인 SSE(HTTP) 전송에서 인증을 전혀 하지 않았다. 서버는 모든 인터페이스의 8080 포트에서 열리고, 세션 ID는 누구에게나 발급되며, 도구 호출 요청은 토큰이나 Origin 검사 없이 처리됐다. 그 결과 포트에 닿을 수 있는 누구나 서버에 설정된 kubeconfig 권한으로 리소스를 조회하고, 읽기 전용 모드가 기본이 아니므로 삭제·Helm 제거 같은 파괴적 작업까지 할 수 있었다. 저장소 권고는 8월 말에 나왔고 1.1.0에서 수정됐으며, 11월 18~19일 NVD와 GitHub Advisory Database에 CVE-2026-130007로 올라왔다.

## 동작 원리
MCP 서버는 ‘에이전트용 리모컨’이다. 리모컨 자체에는 권한이 없지만, 그 리모컨이 연결된 장치(여기서는 클러스터 API)는 서버가 쥔 자격 증명으로 움직인다. stdio로 쓰면 리모컨은 사용자의 손에만 있지만, HTTP/SSE로 열면 같은 네트워크의 누구나 리모컨 버튼을 누를 수 있게 된다. 이 서버는 세션 ID를 ‘출입증’처럼 보이게 썼지만 실제로는 누구에게나 나눠 주는 번호표였고, CORS까지 와일드카드로 열어 두었다. 호출자가 누구인지 확인하는 단계가 없으니, 에이전트를 속일 필요도 없이 도구 목록을 받아 바로 호출하면 된다.

## 플랫폼 엔지니어 관점
- 클러스터 안팎에 배포된 k8s-mcp-server를 찾아 1.1.0 이상으로 올리고, 업그레이드 전까지는 `-read-only`로 띄우거나 SSE 모드를 끄고 stdio로만 쓴다.
- MCP 서버 파드에는 NetworkPolicy로 인그레스를 에이전트 게이트웨이·지정 클라이언트로만 제한하고, Service를 LoadBalancer·NodePort로 노출하지 않는다. ‘0.0.0.0 기본 바인딩 + 무인증’ 조합을 admission 정책이나 배포 리뷰 체크리스트로 잡는다.
- MCP 서버에 마운트하는 kubeconfig·ServiceAccount는 네임스페이스 범위의 최소 Role로 만들고, delete·Helm 작업 권한이 필요하면 별도 서버·별도 ID로 분리한다. MCP 서버의 권한이 곧 ‘인증 없는 호출자’의 권한이 될 수 있다고 가정한다.
- 원격 MCP 서버는 인증 프록시(OIDC·mTLS) 또는 MCP 게이트웨이 뒤에 두고, 감사 로그에 도구 호출 주체를 남긴다. 쿠버네티스 감사 로그에서 MCP 서버 SA의 비정상 삭제·Helm 작업을 탐지 규칙으로 건다.
