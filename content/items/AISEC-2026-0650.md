## 요약
Pydantic AI가 메시지 기록을 저장했다가 다시 불러올 때, 도구 결과 안에 파일 타입과 같은 모양의 JSON이 있으면 이를 진짜 파일 객체(ImageUrl·DocumentUrl·UploadedFile 등)로 되살렸다. 그래서 MCP 서버나 외부 API의 응답을 통제하는 제3자는 프롬프트 인젝션 문구 하나 없이도, 다음 모델 요청에서 애플리케이션이 내부망 URL을 가져오게 하거나 모델 제공자가 애플리케이션의 자격 증명으로 s3://·gs:// 객체를 읽게 만들 수 있었다. 저장소 권고는 11월 4일에 나왔고 11월 20일 CVE-2026-133505로 GitHub Advisory Database·NVD에 올랐다. 수정 버전은 1.107.10과 2.66.0이다.

## 동작 원리
택배 상자에 ‘이 상자는 창고 열쇠입니다’라는 스티커를 붙여 두면, 처음 받은 사람은 그냥 상자로 다루지만 창고에 넣었다 꺼낸 다음 사람은 스티커만 보고 진짜 열쇠로 취급하는 셈이다. 처음 실행에서는 도구 결과가 JSON 텍스트로 모델에 전달되지만, 기록이 직렬화돼 저장되고(대화 저장, 서버 측 기록 관리, 내구 실행의 단계 간 저장) 다시 적재되는 순간 ‘kind: document-url’ 같은 형태만 보고 파일로 복원된다. 이후 요청에서 프레임워크나 모델 제공자가 그 파일을 실제로 가져오면서 사설망 요청이나 클라우드 저장소 읽기가 일어나고, 응답 본문은 대화 내용으로 모델에 들어가 유출 경로가 된다.

## 플랫폼 엔지니어 관점
- Pydantic AI를 쓰는 에이전트 서비스의 의존성을 1.107.10/2.66.0 이상으로 올리고, Temporal·DBOS·Prefect 워커는 업그레이드 전에 시작된 실행을 마치거나 버린다(또는 기록에 sanitize_messages()를 먼저 적용).
- 에이전트 워크로드의 egress를 기본 거부로 두고, 사설 대역·클러스터 내부 서비스로의 요청을 네트워크 정책으로 막는다. 메타데이터 주소만 막는 것으로는 부족하다.
- 모델 제공자에 넘기는 클라우드 자격 증명(S3·GCS 읽기 권한)은 에이전트 용도 버킷으로 범위를 좁힌다. 제공자가 ‘앱 권한으로’ 객체를 읽는 경로가 있다는 점을 권한 설계에 반영한다.
- 저장된 대화 기록에서 자체 도구가 만들지 않은 document-url·image-url·uploaded-file 항목, force_download 설정, 비HTTP URL을 탐지 규칙으로 찾는다.
