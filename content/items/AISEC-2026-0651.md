## 요약
터미널 코딩 에이전트 CodeWhale(구 DeepSeek-TUI)에서 사람의 승인 단계를 건너뛰게 만드는 결함 두 건이 공개됐다. 하나는 ‘읽기 전용’으로 분류한 fd·rg·git grep 명령을 승인 없이 실행하는데, 이 도구들의 실행 플래그로 임의 프로그램을 띄울 수 있었다는 것이다. 다른 하나는 예약 자동화에서 auto_approve 값을 생략하면 true가 돼, 인젝션으로 한 번 승인받은 작업이 이후 사람 없이 계속 쓰기·셸 실행을 하게 된다는 것이다. 둘 다 이전에 고친 취약점과 같은 종류가 다른 경로에 남아 있던 것이고 0.9.0에서 수정됐다.

## 동작 원리
경비원이 ‘서류 열람만 하는 방문객은 그냥 통과’라는 규칙을 두고 방문객 명찰의 직함만 확인하는 셈이다. fd·rg·git grep은 이름만 보면 검색 도구지만 -x, --pre, --open-files-in-pager 같은 옵션으로 다른 프로그램을 실행시킬 수 있다. 분류기는 세미콜론·파이프 같은 셸 메타문자만 찾았기 때문에 이런 옵션은 그대로 통과했고, 승인 요구도 자동으로 낮아졌다. 예약 자동화 쪽은 ‘값이 없으면 허용’이라는 위험한 기본값 문제다. 사용자는 ‘예약 작업 하나 만들기’만 승인했다고 생각하지만, 실제로는 이후 모든 실행에 대한 백지수표를 준 셈이 된다.

## 플랫폼 엔지니어 관점
- 사내 개발 환경·CI 이미지에 CodeWhale/codewhale-tui가 있으면 0.9.0 이상으로 올린다.
- 코딩 에이전트의 ‘읽기 전용 명령 자동 승인’ 목록을 검토할 때 명령 이름이 아니라 실행 가능한 플래그(find -exec, fd -x, rg --pre, git -c, git grep -O 등)를 기준으로 본다. 가능하면 자동 승인 명령도 샌드박스(네트워크 차단·쓰기 제한) 안에서 돌린다.
- 에이전트가 만드는 예약 작업·자동화는 별도 승인 대상으로 다루고, 생성 시점의 권한 범위(auto_approve, allow_shell)를 명시적으로 보여 주게 한다. 사람 없는 반복 실행은 짧은 수명 자격 증명과 감사 로그를 전제로 한다.
- 같은 종류 결함이 ‘고친 경로 옆 경로’에서 반복되므로, 벤더 패치 후에도 승인 우회 회귀 테스트를 자체 평가 스위트에 넣는다.
