## 요약
코딩 에이전트는 모델이 원격에서 돌아도 bash·git·python 같은 도구는 사용자 머신에서 실행되며, 이 도구들은 공유 시스템 라이브러리를 쓴다. ToolPulse는 같은 서버를 쓰는 권한 없는 공격자가 CPU 캐시 부채널(Flush+Reload)로 이 라이브러리 코드 접근을 관찰해, 에이전트가 어떤 도구를 불렀는지·어떤 종류의 작업을 하는지·키 추출 같은 민감한 단계가 언제 시작되는지를 알아내는 공격이다. Codex와 Claude Code의 11개 모델에서 도구 복원 F1이 93% 이상이었고, 약 20명이 쓰는 실제 공유 서버에서도 정확도가 크게 떨어지지 않았다.

## 동작 원리
같은 건물의 공용 엘리베이터 소리로 누가 몇 층에 가는지 짐작하는 것과 비슷하다. 공유 라이브러리의 코드 페이지는 여러 프로세스가 같은 물리 메모리를 공유하므로, 공격자는 특정 함수 주소를 캐시에서 비운 뒤 다시 읽는 시간을 재서 피해자가 그 코드를 방금 썼는지 안다. 도구별 지문을 모으면 호출 순서가 드러나고, 순서에서 작업 종류와 민감 단계의 시점까지 추론할 수 있다. 공격자는 그 시점에 맞춰 더 비싼 공격(키 추출 등)을 집중시킬 수 있다.

## 플랫폼 엔지니어 관점
- 공유 개발 서버·CI 러너·원격 개발 환경에서 여러 사용자의 에이전트를 같은 노드에 섞어 돌리지 않는다. 민감 저장소 작업은 전용 VM·노드로 분리한다.
- 컨테이너는 같은 이미지 레이어의 라이브러리를 페이지 캐시로 공유하므로, 에이전트 샌드박스를 테넌트별 VM(마이크로VM)으로 두는 방안을 검토한다.
- 하드웨어가 지원하면 Intel CAT 등 캐시 분할을 테넌트 격리에 쓰는 비용을 평가한다.
- 에이전트 위협 모델에 ‘도구 호출 메타데이터도 기밀’이라는 항목을 추가한다.
