## 요약
크롬은 Gemini Nano 같은 온디바이스 언어 모델을 기본 제공하고 웹 페이지가 Prompt API로 쓸 수 있게 한다. 저자들은 이미 침투한 공격자가 이 모델을 ‘설치돼 있고, 벤더가 서명했고, 네트워크 감시에 안 보이는’ 침투 후 도구로 쓸 수 있음을 보였다. OS 기본 인터프리터만으로 모델을 조종해 자격 증명 파일 선별, 메일 속 개인정보 탐지, 이미지 판독, 도구 호출을 시켰고, 웹캠 사진 속 암호로 압축 파일을 풀어 SSH 키를 반출 준비하는 과정까지 사용자 상호작용 없이 이어 붙였다. Google은 사용자 권한 코드는 위협 모델 밖이라며 수정하지 않기로 했다.

## 동작 원리
LotL(living off the land) 공격이 시스템에 원래 있는 PowerShell·certutil을 무기로 쓰듯, 이번에는 브라우저에 원래 있는 AI 모델을 쓴다. 공격자는 큰 모델을 내려받거나 외부 LLM API를 부를 필요가 없어 EDR·프록시 탐지를 피한다. 모델은 혼자 계획을 세우는 데는 서툴지만, 공격자가 단계별 계획을 주면 성실한 실행자가 된다. 즉 ‘판단은 공격자가, 대량 선별은 로컬 모델이’ 하는 분업이다.

## 플랫폼 엔지니어 관점
- 사내 엔드포인트 관리(MDM)에서 크롬·Edge의 내장 AI API와 온디바이스 모델 다운로드를 업무상 필요 없으면 정책으로 끈다. DevTools 정책만으로는 부족하다.
- 탐지 규칙에 스크립트 호스트가 비기본 프로필로 크롬을 띄우는 경우, 루프백 리스너를 잡은 부모 스크립트, 모델을 내려받은 적 없는 프로필에 모델 파일이 생기는 경우를 추가한다.
- 개발자 워크스테이션·점프 호스트에서 ‘로컬 모델 추론 = 네트워크 흔적 없음’이라는 점을 위협 모델에 반영하고, egress 감시만으로 데이터 유출 준비 단계를 잡을 수 없음을 전제한다.
