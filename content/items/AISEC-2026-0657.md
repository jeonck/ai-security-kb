## 요약
Amazon 위협 인텔리전스 팀은 2026년 9월 10일 인증 없이 인터넷에 열려 있던 Cairn(오픈소스 다중 AI 에이전트 침투 테스트 프레임워크) 인스턴스를 찾아, 그 안에 남은 프롬프트와 작업 기록으로 중국 연계 행위자의 캠페인을 재구성했다. 운영자는 동아시아 대학들의 IP를 주고 셸을 얻으라고만 지시했다. 에이전트들은 Redis·GPU 서버 공략에는 실패했지만, 의료영상 AI 앱 MONAI Label의 업로드 엔드포인트에서 경로 탐색 제로데이를 스스로 찾아 root 셸을 얻었다. 이어 같은 소프트웨어를 쓰는 두 번째 대학으로 옮겨 갔다. Amazon의 신고를 받은 유지보수자는 2026-11-18 GHSA를 공개했다. 영향 범위는 0.8.5 이하다.

## 동작 원리
MONAI Label은 이미지와 라벨을 올리는 API에서, 사용자가 붙인 ‘이미지 이름’을 그대로 파일 경로로 썼다. 이름에 `../`를 넣으면 저장소 폴더 밖 아무 곳에나 파일을 쓸 수 있다. 에이전트는 이 구멍으로 Python이 시작할 때마다 자동으로 읽는 `sitecustomize.py`에 리버스 셸을 심었다. 그다음 서버가 Python을 다시 띄우게 만드는 API를 호출했다. ‘업로드 폴더’라는 이름만 믿고 열어 둔 창고 문이 실은 건물 전체의 배전반으로 이어져 있던 셈이다. 인증이 기본으로 꺼져 있어 네트워크에서 닿기만 하면 됐다. API 지도 그리기부터 악용까지가 약 11분이었다. 반대로 Redis 16시간·148개 행동, 자격 증명 3만 개 대입처럼 실패한 시도도 많았다. 지금의 자율 공격은 ‘모든 문을 다 두드려 보는 값싼 끈기’에 가깝다.

## 플랫폼 엔지니어 관점
- 연구·데이터 사이언스 팀이 띄운 AI 앱(MONAI Label, 라벨링 도구, 노트북, 실험 대시보드)을 인벤토리에 넣는다. 인증이 기본으로 꺼진 앱은 Ingress·LoadBalancer로 외부에 노출되지 않게 정책으로 막는다(예: Kyverno/Gatekeeper로 해당 라벨 서비스의 type: LoadBalancer 금지, 사내 SSO 프록시 강제).
- MONAI Label 0.8.5 이하를 찾아 수정 릴리스로 올린다. 그 전까지는 /datastore 엔드포인트를 앞단 프록시에서 차단하고, 컨테이너를 읽기 전용 루트 파일시스템과 비 root 사용자로 돌린다. 그러면 sitecustomize.py 같은 시작 파일을 덮어쓰는 경로가 막힌다.
- 탐지: Python site-packages·시작 파일(sitecustomize.py, *.pth)의 변경을 Falco·파일 무결성 감시 규칙으로 잡는다. 같은 출발지에서 장시간 이어지는 대량 API 열거·자격 증명 대입도 ‘에이전트형 공격’ 신호로 본다.
- 패치 주기 가정을 바꾼다. 공개 권고가 없는 앱도 공격 에이전트가 직접 버그를 찾는다. 외부 노출 면을 줄이는 것이 패치 속도보다 먼저다.
