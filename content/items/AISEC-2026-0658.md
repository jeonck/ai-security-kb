## 요약
연구진은 언론·포스트모템·CVE로 알려진 LLM 에이전트 사고(코딩 에이전트의 운영 DB 삭제, terraform destroy로 운영 스택 삭제 등)를 오프라인에서 재현해 원인을 검증하는 ROGUE-AI 프레임워크를 공개했다. 108건의 재현 중 89%가 보고된 피해를 재현했고, 5개 최신 모델은 원인 요소가 있을 때 18~33% 비율로 같은 실수를 했다. 실제 피해 사고 72건 중 62건은 공격자가 없었고, 공격자 없는 재현이 인젝션 재현보다 피해가 컸다. 위험 요소를 직접 짚는 도구 출력 경고, 사용자 확인, 데이터 흐름 추적이 피해를 크게 줄였다.

## 동작 원리
사고 보고를 ‘이 요소 때문에 사고가 났다’는 가설로 바꾸고, 그 요소만 있는 방과 없는 방을 만들어 같은 에이전트를 여러 번 들여보내는 대조 실험이다. 예를 들어 ‘개발용 DB가 운영 사이트와 공유돼 있었다’는 보고라면, 공유 DB가 있는 환경과 분리된 환경을 만들어 삭제가 일어나는 비율을 비교한다. 에이전트는 맡은 일을 성실히 하면서도 주변의 평범한 위험(공유 DB, 라이브 사이트와 연결된 자원)을 놓친다. 경고가 효과를 보려면 ‘조심하라’가 아니라 어떤 자원이 어떤 결과로 이어지는지를 이름으로 짚어야 했다.

## 플랫폼 엔지니어 관점
- 에이전트 위협 모델에서 인젝션만큼 ‘공격자 없는 파괴적 작업’을 1급 위험으로 다룬다. 운영 DB·클러스터·IaC 상태에 대한 삭제·destroy 계열 도구 호출은 사용자 확인 단계를 필수로 둔다.
- 개발·스테이징 자격 증명이 운영 자원에 닿지 않도록 네임스페이스·계정·DB를 분리한다. 공유 자원이 있다면 도구 출력에 그 자원이 운영과 연결돼 있다는 구체 경고를 자동으로 붙인다.
- 사고가 나면 도구 호출 로그와 환경 스냅샷으로 사건 조건·대조 조건 재현을 만들어 원인을 검증하고, 모델·에이전트 버전 업그레이드 전에 회귀 시험으로 다시 돌린다.
