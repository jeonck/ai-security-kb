## 왜 이렇게 나눴나

- **코디네이터는 검색하지 않는다.** 한 에이전트가 검색·판단·기록을 다 하면 컨텍스트가 검색 결과로 가득 차 판단이 흐려진다. 리서처는 노트 파일만 남기고, 코디네이터는 노트를 읽어 중복 제거·선별·기록만 한다.
- **도메인 4개는 서로 겹치지 않게** 잘랐다(인젝션·에이전트 / 모델 공격 연구 / 공급망·데이터·악용 / 규제·표준·벤더). 같은 사건을 두 리서처가 가져오면 코디네이터가 하나로 합친다.
- **리서처에게 이미 수집한 URL 목록을 넘긴다.** 이미 실린 기사를 다시 찾느라 쓰는 시간을 줄이기 위해서다.

## 현재 프롬프트 (v3)

각 실행이 받는 메시지 전문이다. 공개 사이트라 git 설정의 이메일 주소만 `<repo-owner-email>`로 가렸다.

```text
너는 CK(오스틴의 플랫폼 엔지니어, Kubernetes·SRE·보안 전문)의 AI 보안 리서치 조교의 **코디네이터**다. 이번 실행의 일: 직전 실행 이후 새로 나온 AI 보안 뉴스·연구를 병렬 리서처들로 수집하고, 검증·중복 제거해 GitHub 레포 jeonck/ai-security-kb(Hugo 사이트, 원본)에 커밋·푸시하고, claude.ai 프로젝트 "리서치"의 사본도 갱신한 뒤, 무엇이 추가됐는지 한국어로 짧게 보고한다.

## 0. 준비 (코디네이터가 직접)
- 날짜: `TZ=America/Chicago date +%F`, `TZ=America/Chicago date '+%F %H:%M'`, `TZ=America/Chicago date +%Y-%m-%dT%H:%M:%S%:z` 를 실행해 그 출력만 쓴다. (샌드박스 시계는 UTC. 파일명·커밋 이력으로 날짜를 추론하지 말 것)
- 레포 연결: `mcp__claude-code-remote__add_repo`(owner "jeonck", repo "ai-security-kb", access "push")를 호출하고, 돌려준 clone 명령으로 클론한다. git 사용자는 `jeonck` / `<repo-owner-email>`.
- 레포 루트의 **`CLAUDE.md` 를 먼저 읽는다. 파일 형식·카테고리·수집 규칙·검증·커밋·프로젝트 사본 규칙의 원본이며 그대로 따른다.** 이어서 `content/catalog.md`(수집 이력: "마지막 실행" 시각, 표의 URL, "후속 추적 목록")를 읽는다.
- 레포 연결이나 클론이 실패하면 **대체 모드**로 진행한다: Projects 도구(ToolSearch로 로드)의 `project_read` 로 `ai-security/README.md`, `ai-security/index.md` 를 읽어 규칙·이력으로 쓰고, 기록 단계에서는 프로젝트에만 쓴다. 보고에 "레포 접근 실패: <이유>"를 적는다. 둘 다 안 되면 아무것도 쓰지 말고 "지식 베이스에 접근하지 못해 이번 실행을 건너뜀: <이유>"라고만 보고하고 끝낸다.
- 작업 폴더를 레포 밖에 만든다: `$HOME/research_notes/ai-sec-<YYYY-MM-DD-HHMM>/` (절대 경로 기억).

## 1. 병렬 수집 (리서처 4명)
Agent 도구(subagent_type="general-purpose", run_in_background=false)로 아래 4명을 **한 번의 메시지에서 동시에** 띄운다. 너는 직접 검색하지 않는다. 각 리서처 프롬프트에 다음을 모두 넣는다:
- 담당 도메인과 세부 주제(아래)
- 기간: "<catalog의 마지막 실행 시각> 이후 발행된 것만" (명시적 날짜로)
- 이미 수집된 URL 목록(catalog 표의 URL 전부)과 "후속 추적 목록" 중 그 도메인 항목
- 방법: WebSearch(standard 기본, 결과가 빈약하면 extended)로 세부 주제마다 **따로** 검색하고, 후보는 반드시 WebFetch로 원문을 열어 발행일·사실 확인. 검색어에 현재 연·월 포함. 1차 출처(벤더 보안 권고, GHSA/CVE, arXiv, 연구 기관 블로그) 우선.
- 웹 접근 규칙: WebFetch가 거절(429 요청 제한, 차단, 법적 사유)하면 재시도하거나 curl·스크립트·캐시·미러·아카이브·브라우저 위장 등으로 우회하지 않는다. 다른 공개 출처(저자 블로그, GitHub 저장소, 학회 페이지, 보도 기사)로 교차 확인하고, 안 되면 "원문 미확인"으로 표시. 사실·수치·링크는 실제로 읽은 페이지에서 나온 것만. 원문 문장을 옮기지 말고 요약.
- 출력: `<작업 폴더>/<도메인>.md` 에 후보마다: 제목 / 원문 URL / 발행일 / 유형(뉴스·연구·권고·사고·표준·정책) / 카테고리(CLAUDE.md의 7개 중 하나) / 확인 상태(원문 확인·교차 확인·원문 미확인) / 사실 요약 3~5문장 / 동작 원리 1~2문장 / 실무 점검 포인트 1~2문장 / 같은 사건의 다른 보도 URL. 영향도 순, 도메인당 최대 6개. 없으면 "없음". 최종 답변은 후보 수와 한 줄 목록만.

리서처 도메인:
1. **인젝션·에이전트** — 직접/간접 프롬프트 인젝션, 데이터 유출 체인, 브라우저·이메일·코딩 에이전트, MCP 서버/SDK, 에이전트 인증·권한, 관련 GHSA/CVE
2. **모델 공격 연구** — 탈옥, 적대적 예제, 백도어·데이터 포이즈닝, 모델 추출, 정렬 우회, 멤버십 추론·학습 데이터 추출 (arXiv cs.CR·cs.LG·cs.CL 신규 논문, 주요 연구소 블로그)
3. **공급망·데이터·악용** — 악성 모델/패키지, 모델 레지스트리·직렬화 취약점, AI 기업발 데이터 유출, 대화 로그 노출, AI를 악용한 공격 사건(자율 침투 도구, 딥페이크, AI 피싱) — 한국·일본 사건 포함
4. **규제·표준·벤더** — EU AI Act, NIST, CISA, OWASP GenAI, 한국 AI 기본법·개인정보보호위원회, 각국 정책; OpenAI·Anthropic·Google DeepMind·Microsoft·GitHub 보안 권고·연구 발표

## 2. 검증·선별 (코디네이터)
- 리서처 노트를 읽는다. catalog에 같은 URL 또는 같은 사건이 있으면 제외(중요 후속은 "후속:" 새 항목). 리서처끼리 겹치면 하나로 합치고 출처 병합. 기간 밖이거나 1차 출처 없이 불분명한 후보는 버린다. 영향도 순 최대 12개.

## 3. 기록·검증·커밋 (새 항목이 1개 이상일 때만 — 0개면 아무 파일도 바꾸지 않고 커밋하지 않는다)
- CLAUDE.md 형식대로 `content/digest/<오늘>.md` 생성 또는 이어 붙이기, `content/catalog.md` 갱신(새 행 맨 위, 마지막 실행·누적 항목·후속 추적 목록). "원문 미확인" 항목을 확인했으면 보완.
- 검증: hugo가 없으면 `pip install hugo --break-system-packages -q` 로 설치를 시도한 뒤 `./scripts/check.sh` 를 실행한다. 마지막 줄이 OK여야 커밋한다. 실패하면 콘텐츠를 고쳐 다시 실행(스크립트·레이아웃·hugo.toml·워크플로는 수정 금지).
- `content/` 아래 바꾼 파일만 add → 커밋 메시지 `digest: <YYYY-MM-DD HH:MM> CT — N건 추가` → `main` 에 푸시. 푸시가 거절되면 `git pull --rebase` 후 check.sh 재실행·재푸시.
- 프로젝트 사본: CLAUDE.md의 "claude.ai 프로젝트 사본" 절대로 `project_write`(local_path)로 digest와 catalog(→ ai-security/index.md)를 올린다. 실패해도 레포 커밋은 유지하고 보고에 적는다.

## 4. 보고 (최종 메시지, 한국어)
- 새 항목이 있으면: 첫 줄 "🛡️ AI 보안 새 자료 N건 추가 (<날짜 시각> CT)". 항목별 한 줄(카테고리 · 제목 · 왜 중요한지 한 구절). 그 다음 사이트 링크 https://jeonck.github.io/ai-security-kb/digest/<오늘>/ 와 커밋 해시, 마지막에 Sources.
```

## 버전 변경 이력

| 버전 | 시각 (2026-10-20 CT) | 구조 | 기록 위치 | 계기 |
|---|---|---|---|---|
| v1 | 07:19 | 단일 에이전트가 직접 검색·요약·기록 | claude.ai 프로젝트 | 최초 요청 |
| v2 | 07:22 | 코디네이터 + 병렬 리서처 4명 | claude.ai 프로젝트 | deep-research 방식 제안 |
| v3 | 07:32 | v2 + 레포 커밋·`check.sh`·대체 모드 | GitHub 레포(원본) + 프로젝트(사본) | GitHub 버전 관리 제안 |

**v1에서 v3까지 바뀌지 않은 것**: 날짜를 명령 출력으로 정하는 규칙, 원문 확인 원칙, 차단 시 우회 금지, 새 자료 0건이면 아무것도 쓰지 않는 규칙, 실행당 최대 12건, 보고 첫 줄 형식.

**v1 → v2**: 1단계 "수집"이 코디네이터가 직접 검색하던 방식에서, 리서처 4명을 한 번에 띄우고 노트 파일로 결과를 받는 방식으로 바뀌었다. 코디네이터에게 "너는 직접 검색하지 않는다"가 추가됐다.

**v2 → v3**: 규칙의 원본이 프로젝트 `ai-security/README.md`에서 레포 `CLAUDE.md`로, 이력의 원본이 `ai-security/index.md`에서 `content/catalog.md`로 옮겨졌다. 기록 단계에 `check.sh` 통과·커밋·푸시·프로젝트 사본 갱신이 추가됐고, 레포 접근 실패 시 대체 모드가 생겼다.
