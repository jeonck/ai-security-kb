시스템 전체를 claude.ai 채팅 한 세션(프로젝트 "리서치")에서 만들었다. 아래는 그 세션에서 CK가 보낸 요청 원문(시각은 CT)과, 각 요청에 따라 시스템이 어떻게 바뀌었는지다.

## 1. 출발점 — 07:14

> AI 보안(AI Security, LLM 보안, 프롬프트 인젝션, 개인정보 보호 등) 최신 뉴스와 연구 자료를 자동으로 수집하고, 요약된 내용을 지식 베이스(Knowledge Base) 프로젝트에 실시간으로 추가해 주는 AI 연구 조교 시스템을 만들어줘. 새로운 자료가 추가되면 알림을 보내줘.

**만든 것**

- 지식 베이스 구조: 규칙 문서(README), 전체 목록(index, 중복 판정 기준), 일자별 다이제스트
- 첫 수집: 웹 검색 20여 회 + 원문 확인으로 12건 (최근 3주 10건 + 올해 기준점 사건 2건)
- 스케줄 작업 **AI 보안 리서치 조교** (v1, 단일 에이전트): 6시간마다 실행, 새 항목이 있을 때만 푸시·이메일 알림
- "실시간"은 스케줄 작업의 최소 간격(1시간) 때문에 그대로 구현할 수 없어서, 비용과 신선도의 절충으로 6시간을 골랐다

## 2. 막힌 논문을 읽는 도구 제안 — 07:17

> https://github.com/fivetaku/insane-search 스킬을 사용하면 제한된 논문도 읽을 수 있을 것 같아.

**결정: 쓰지 않음.** 이 도구는 TLS 지문 위장·쿠키 워밍·헤드리스 브라우저·아카이브 우회로 막힌 페이지를 연다. 첫 수집에서 arXiv가 막힌 이유는 요청 제한(429)이었기 때문에, 이 도구를 쓰면 사이트가 거절한 요청을 다른 경로로 다시 밀어 넣는 셈이 된다. 도구 자체도 로그인·페이월 앞에서는 멈추게 되어 있어 유료 논문에는 도움이 되지 않는다.

**대신 넣은 규칙** (지금도 `CLAUDE.md`에 있다)

- 차단·요청 제한이 나면 재시도나 우회를 하지 않고, 다음 실행에서 다시 시도한다
- 그동안은 "(원문 미확인)" 표시를 달고 후속 추적 목록에 올린다
- 저자 블로그, GitHub 저장소, 학회 페이지 같은 다른 공개 출처로 교차 확인한다

## 3. deep-research 방식 도입 — 07:22

> /deep-research 와 같은 스킬을 조교가 사용하면 더 좋을 것 같아 보여

**바뀐 것**

- **리서치 조교 v2**: 코디네이터 1명 + 도메인별 리서처 4명이 병렬로 수집하는 구조로 바꿨다. 코디네이터는 직접 검색하지 않고 중복 제거와 선별만 한다
- **AI 보안 주간 심층 리포트**(신규, 매주 월 07:44 CT): deep-research 스킬을 그대로 써서 한 주의 흐름을 종합한다
- 6시간마다 풀 deep-research를 돌리면 무겁기 때문에, "자주·가볍게 수집 + 주 1회 깊게 종합"으로 나눴다

## 4. GitHub 레포로 버전 관리 — 07:24

> 내 깃헙 레포에 계속 추가해 주면서 버전 관리가 되는 건 어떨까?

선택지를 물어 받은 답:

| 질문 | 답 |
|---|---|
| 어느 레포에? | 새 레포 `jeonck/ai-security-kb` |
| 공개 범위 | Public |
| claude.ai 프로젝트는? | 둘 다 유지 (레포가 원본, 프로젝트는 사본) |
| 사이트로 퍼블리시? | Hugo 사이트로 |

**만든 것**

- 외부 테마 없는 Hugo 사이트 (홈, 다이제스트, 주간 리포트, 전체 목록, 카테고리, RSS)
- `CLAUDE.md` (작업 사양), `scripts/check.sh` (검증), GitHub Actions 배포 워크플로
- **두 스케줄 작업 v3**: 레포 클론 → `CLAUDE.md` 읽기 → 기록 → `check.sh` 통과 → 커밋·푸시 → 프로젝트 사본 갱신. 레포에 닿지 못하면 프로젝트에만 쓰는 대체 모드

## 5. 레포 연결과 배포 — 07:33 ~ 08:05

> repo 만들었어

레포에 초기 커밋(한 줄짜리 README)이 있어서, 로컬 커밋 2개를 그 위로 옮기고(README는 상세판으로 교체) 푸시했다. 그 사이 테스트 실행이 프로젝트에 추가한 8건도 레포로 옮겼다 ([테스트 기록](../test-run/)).

> 사이트가 404 로 표시되고 있어

배포 워크플로가 Pages 설정 단계에서 실패하고 있었다. 레포에 GitHub Pages가 아직 켜져 있지 않았기 때문이다. Pages 켜기는 레포 관리자만 할 수 있어서 설정 위치를 안내했다.

> 완료했어

Settings → Pages → Source를 **GitHub Actions**로 바꾼 뒤 다시 배포해 성공했다(#3).

## 6. 시스템 문서화 — 08:10

> 연구 시스템 구성에 사용했던 프롬프트와 연구시스템인 AI보안 리서치 조교와 AI보안 조교 테스트 실행 확인 내용 등 동작 방식도 사이트에 표시

이 "시스템" 섹션이 그 결과다. 함께 첨부된 초기 운영 규칙(레포로 옮기기 전 프로젝트 README)은 [운영 규칙 초기본](../rules-v1/)에 그대로 남겼다.
