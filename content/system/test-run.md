스케줄 작업은 사람이 없는 시간에 돈다. 그래서 정식 일정 전에 **한 번 강제로 실행해 보고, 그 결과를 따로 확인하는 장치**를 두었다. 핵심 질문은 하나였다: 새 세션으로 깨어난 작업이 claude.ai 프로젝트에 실제로 읽고 쓸 수 있는가?

## 무엇을 했나

1. **테스트 실행** (07:19 CT): 리서치 조교(당시 v1)를 일정과 별개로 즉시 실행했다. 이때 저장된 프롬프트 뒤에 이번 실행용 지시를 덧붙였다.
2. **확인 예약** (같은 시각): 12분 뒤 이 채팅 세션으로 돌아와 결과를 확인하라는 일회성 예약 작업 "AI 보안 조교 테스트 실행 확인"을 걸었다.
3. **확인** (07:32 CT): 예약이 발동해 실행 상태와 프로젝트 문서를 확인했다.

### 테스트 실행에 덧붙인 지시

```text
테스트 실행: 지식 베이스는 방금(2026-10-20 07:20 CT경) 첫 수집으로 채워졌다. 그 이후 새 자료가 없을 가능성이 높으니, 새 항목이 없으면 문서를 쓰지 말고 "새 AI 보안 자료 없음" 보고로 끝내도 된다. 다만 index.md "후속 추적 목록"의 arXiv:2610.24823 항목은 공개 출처로 확인되면 보완해라. 마지막 보고 맨 끝에 "Projects 접근: 성공/실패" 한 줄을 붙여라.
```

### "AI 보안 조교 테스트 실행 확인" 예약 프롬프트

```text
AI 보안 리서치 조교 테스트 실행 결과를 확인해라: list_triggers로 last_run 상태를 보고, Projects project_info로 ai-security/ 문서 상태를 확인한 뒤, Projects 접근이 성공했는지와 결과를 사용자에게 짧게 보고하고 task #4를 완료 처리해라. 실패했다면 원인과 대안(예: Google Drive/Claude Docs로 지식 베이스 이전)을 제시해라.
```

(원문에는 작업·세션 식별자가 들어 있었으나 여기서는 뺐다.)

## 결과

|---|---|
| 실행 상태 | 성공 — 07:19:23 시작, 07:26:59 종료 (약 7분 30초) |
| 프로젝트 읽기·쓰기 | 성공 — 규칙·이력을 읽고 다이제스트와 목록을 갱신 |
| 새 항목 | **8건** (첫 수집에서 빠졌던 10월 15~20일 발행분) → 누적 20건 |
| 중복 | 기존 12건과 겹친 항목 없음 |
| arXiv:2610.24823 | 다시 요청 제한(429)으로 미확인 — 우회하지 않고 후속 추적 목록에 사유를 적고 남김 |
| 새로 생긴 후속 추적 | Cairn 악용 캠페인 피해 기업, OpenCode 침해 진입 경로, Langflow CVE의 CISA KEV 등재 여부 |

테스트 실행이 기대("아마 새 자료 없음")보다 많은 8건을 찾았다. 첫 수집이 "최근 3주"를 넓게 훑었다면, 두 번째 실행은 "마지막 실행 이후"라는 좁은 창을 잡되 첫 실행이 날짜만 남겨 시각을 몰랐기 때문에 10월 15일부터 다시 봤다. 이후 실행부터는 catalog에 "마지막 실행: YYYY-MM-DD HH:MM CT"가 시각까지 남는다.

추가된 8건은 [2026-10-20 다이제스트](../../digest/2026-10-20/)의 "추가 수집 (07:24 CT)" 섹션에 있다.

## 레포 전환 중 맞춘 것

테스트 실행은 레포가 생기기 전(프로젝트 기록 방식)에 돌았다. 그 사이 로컬에서 만들어 둔 레포 내용은 첫 12건만 갖고 있었기 때문에, 프로젝트에 새로 생긴 8건과 후속 추적 목록을 레포의 `content/`로 옮겨 별도 커밋(`digest: 2026-10-20 07:24 CT — 8건 추가`)으로 남겼다. 이걸 빼먹었다면 다음 실행이 레포의 catalog만 보고 같은 8건을 다시 추가했을 것이다.

## 배포 문제와 해결

| 배포 | 결과 | 원인 |
|---|---|---|
| #1 (첫 푸시) | 실패 | Pages 설정 단계에서 "Pages 사이트 없음" — 레포에 GitHub Pages가 꺼져 있었다 |
| #2 (재배포) | 실패 | 같은 원인. 사이트 주소는 404 |
| #3 (Pages 설정 후) | **성공** | Settings → Pages → Source를 **GitHub Actions**로 변경 |

#1·#2에서도 체크아웃 → Hugo 설치 → `check.sh` 콘텐츠 검사까지는 통과했다. 문제는 콘텐츠가 아니라 레포 설정이었다. Pages 켜기는 레포 관리자 권한이 필요해 사람이 직접 했다.

배포 로그에는 Node.js 20 지원 종료와 Ubuntu 버전 이전 공지도 함께 떴다. 실패 원인은 아니고, 워크플로의 액션 버전을 올릴 때 정리할 대상이다.

## 주간 리포트 시험 실행 (2026-10-20)

월요일 정식 일정 전에 주간 심층 리포트를 두 번 강제로 실행했다.

| 회차 | 시각 (CT) | 소요 | 결과 |
|---|---|---|---|
| 1 | 11:12 | 약 40초 | **실패.** 리포트도 커밋도 남지 않았다. 실행 기록을 볼 수 없어 원인 미상 |
| 2 | 11:59 | 약 15분 | **리포트 작성 성공, 레포 커밋 실패.** claude.ai 프로젝트에는 `ai-security/weekly/2026-W43.md`가 저장됐지만 레포 커밋·푸시가 없었다. 실패 원인을 남기라고 한 상태 문서도 쓰지 않았다 |

2회차 리포트는 사람이 프로젝트 사본에서 레포로 옮겨 커밋했다([2026-W43](../../weekly/2026-w43/)). 내용은 기대한 형식을 지켰다. 심층 분석 2건(AISEC-2026-0013, 0014)과 핵심 흐름 4개가 들어갔고, 점검 항목은 쿠버네티스·CI/CD·에이전트 플랫폼별로 정리됐다. 책 관점 절은 목차 v1.1의 장 번호를 썼고 목차 제안도 격자 안에서 했다. 남은 문제는 세 가지다.

- **커밋 실패.** 프로젝트 사본보다 레포 커밋을 먼저 하도록 순서를 바꿀 필요가 있다.
- **항목 보완 유실.** 심층 분석에서 나온 0013·0014 항목 보완이 레포에 반영되지 않았다.
- **스킬 사용 여부 미기록.** 딥 리서치 스킬을 실제로 불렀는지, 같은 구조로 대신 돌렸는지 확인할 기록이 없다. 15분 동안 조사원을 병렬로 돌린 흔적(출처 50여 개, 흐름별·심층 분석별 조사)은 있다.
