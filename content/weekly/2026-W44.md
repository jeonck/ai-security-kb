## 이번 주 한눈에 보기

- **국내 첫 ‘생성형 AI 대규모 해킹’ 검거(AISEC-2026-0145)가 보여 준 것은 새 기법이 아니라 속도다.** 같은 사람의 침해 속도가 하루 0.08곳에서 1.36곳으로 올랐다(한국경제 보도). 서울경찰청 보도자료 원문은 아직 찾지 못했고, 도구명 ‘ARTEX’는 일부 매체만 적었다.
- **다운로드 폴더의 AGENTS.md 하나로 코딩 에이전트를 넘겨받는 경로(AISEC-2026-0140)는 버그가 아니라 설계 두 개가 맞물린 결과다.** 실제 악용은 악성 npm 설치 시도를 막은 1건이고, 성공률은 연구진의 격리 VM 재현 수치다.
- **감시 모니터는 판단을 잘못하기 전에 먼저 보지 못했다.** 감시를 끄는 클라이언트 설정, 감시되지 않는 하위 경로, 탐지 뒤 자동 중단 실패가 OpenAI와 Anthropic 양쪽에서 나왔다(AISEC-2026-0097, 0045, 0131).
- **AI 키가 모이는 곳이 표적이다.** Railway 예비 보고서(AISEC-2026-0077)는 AI 공급자 키 이름을 검색한 공격자를 기록했고, LiteLLM(AISEC-2026-0123)은 진입 경로 설명을 두 번 고쳤다. 여러 사건을 한 캠페인으로 묶을 기술 근거는 없다.
- **에이전트 런타임 결함은 설정·인자·기본값에서 나온다.** MCP 공식 보안 모범 사례에 이미 규칙이 있는데 구현이 따르지 않았다. 패치 없는 세 건(AISEC-2026-0156, 0157, 0158)은 10-26에도 그대로다.

## 심층 분석: AISEC-2026-0145 서울경찰청, 생성형 AI·자율 침투 도구(일부 보도는 ARTEX로 지목)로 국내 업체 90여 곳을 해킹해 개인정보 820만 건을 빼내고 협박한 일당 7명 검거 — ‘국내 첫 생성형 AI 대규모 해킹 검거’

이 절의 사실은 모두 2등급 언론 보도에서 나왔다. 서울경찰청 보도자료나 브리핑 자료는 열람하지 못했다. smpa.go.kr 보도자료 게시판 첫 쪽의 최신 글은 10-15였고, police.go.kr 게시판은 리다이렉트 오류로 열리지 않았다. 그래서 항목 상태는 partial로 둔다. 또 항목 제목의 ‘ARTEX로’는 확정 표현이었지만, 발표에 도구명이 있었는지 확인되지 않았다. 이번에 항목 제목을 ‘일부 보도는 ARTEX로 지목’으로 고쳤다(아래 엇갈림 참고).

### 원인과 공격 경로

결론부터 말하면, AI가 바꾼 것은 공격 방법이 아니라 같은 사람의 처리량이다.

- **도구 전환과 속도**: 총책 A(32)는 처음에 웹 취약점 자동 스캐너를 손으로 돌렸다. 8월 말(한국경제는 8월 31일)부터 AI 자율 침투 도구로 바꿨다. 그 뒤 8/31~10/13의 44일 동안 60곳을 뚫었다. 그 전 약 1년 동안은 약 30곳이었다. 하루 평균으로는 0.08곳에서 1.36곳, 약 16.5배다 ([한국경제 지면](https://www.hankyung.com/article/2026102660191)).
- **피해 규모**: 2025년 9월~2026년 10월 동안 학원·병원·골프장·대학·상조회사·대기업 계열사 등 90여 곳에서 820만 건(개인정보·사내 자료)이 나갔다 ([뉴데일리](https://www.newdaily.co.kr/site/data/html/2026/10/26/2026102600150.html)). 지역 신협(한국경제)과 ‘2금융권’ 회사(머니투데이)도 포함됐다고 보도됐다. 가장 큰 피해는 상조회사 1곳 약 122만 건이다. 주민등록번호·주소·전화번호, 미성년자 정보, 일부 병원 진료·상담 기록이 포함됐다.
- **수익화는 사람이 했다**: 일부 개인정보를 첨부한 이메일로 협박을 시작했고, 응답이 없으면 임원에게 문자·전화로 압박했다. 38곳에 총 3억6000만 원을 테더(USDT)로 요구했지만 확인된 수령액은 30만 원이다. 공범 B(24)는 텔레그램에 ‘전화 업무’ 알바 공고를 올려 5명을 모았고 통화 1건에 1만~3만 원을 줬다 ([한국경제](https://www.hankyung.com/article/202610264998i)).
- **무엇이 뚫렸나는 아직 모른다**: 악용한 취약점 유형은 어느 보도에도 없다. ‘웹사이트 취약점’이라는 표현뿐이다. 사용한 LLM 모델명도 없다. 서울경제와 시대일보는 AI 코딩 에이전트를 함께 썼다고 전했다.
- **검거의 열쇠는 로그였다**: A는 피해 서버의 접속 로그 분석으로 특정됐다(뉴데일리, 세계일보). 경찰은 국가수사본부가 지원한 고성능 AI 컴퓨터로 외부에 자료를 내보내지 않는 내부망 AI 분석체계를 만들었다. 도구는 수사자료 통합분석, 수사자료 위키, 정보통신망 침해로그 분석 3종이다 ([세계일보 유경민](https://www.segye.com/newsView/20261026515218)).

동작 원리는 지난주 Cairn(AISEC-2026-0013)과 같은 쪽을 가리킨다. 인력이 적어 외부 노출 웹앱 관리가 약한 조직을, 싼 자동화로 대량으로 두드렸다(추론).

### 반론

‘AI가 해킹했다’는 틀은 근거보다 넓다.

- **AI의 몫은 일부다.** 90곳 중 약 30곳은 AI 이전에 기존 스캐너로 뚫었다. 협박 단계는 사람이 했다. 취약점 유형이 보도되지 않아, AI가 새 공격을 만들었다기보다 알려진 웹 취약점 탐색을 대규모로 자동화했다고 보는 것이 근거에 맞다.
- **‘국내 첫’은 좁은 기준이다.** 생성형 AI 악용·대규모·피의자 검거라는 조건을 모두 걸었을 때의 ‘첫’이다.
- **같은 도구, 다른 행위자.** 금융권 사건의 행위자는 CrowdStrike·Zscaler 분석상 중국 광둥성 거주 20대로 추정된다(AISEC-2026-0001, 0089). 이 사건 총책은 국내 거주 32세다. ARTEX 공개 저장소는 비공개로 바뀌었지만 이미 배포된 사본이 돈다. Storm-0940(AISEC-2026-0063)까지 포함하면 ‘한 도구, 여러 행위자’ 구도다. 도구명이 같다는 것만으로 사건을 묶으면 안 된다.
- **그래도 속도 수치는 무겁다.** 같은 사람의 침해 속도가 16.5배가 된 것은 ‘공격 비용 붕괴’ 논지를 직접 뒷받침한다. 다만 이 수치도 경찰 집계를 옮긴 언론 보도다.
- **피해 기업 쪽 실패.** 90여 곳 가운데 15곳만 신고했다. 경찰은 보복이 두렵거나 돈을 내고 숨겼을 가능성을 언급했다(머니투데이, 파이낸셜뉴스).

### 플랫폼 팀 대응

- **외부 공격 표면을 먼저 안다.** 인력이 적은 조직이 먼저 뚫렸다. 인터넷에 노출된 웹앱·관리 페이지 목록을 자동으로 만들고, 같은 계열의 자율 침투 도구로 자기 자산을 먼저 점검한다(추론).
- **속도를 탐지 신호로 쓴다.** 인그레스·WAF 로그에서 광범위한 경로 탐색과 짧은 시간의 다중 취약점 시도를 경보로 만든다. 금융권 사례(AISEC-2026-0001)처럼 IP를 돌려 임계값을 피하는 패턴이 있으므로 IP가 아니라 세션·지문 단위로 상관분석한다(추론).
- **한 번에 대량으로 나가지 못하게 한다.** 상조회사 1곳에서 122만 건이 나갔다. 웹 계층 워크로드의 DB 계정은 최소 권한으로 두고, 대량 SELECT·덤프에 경보를 걸고, NetworkPolicy·egress 게이트웨이로 외부 대용량 전송을 제한한다(추론).
- **접속 로그를 변조 불가 저장소에 보존한다.** 경찰이 총책을 특정한 근거가 피해 서버 접속 로그였다. 사고 대응과 수사 협조의 전제다.
- **런북에 ‘협상 금지, 즉시 신고’를 넣는다.** 개인정보 유출 신고 기한과 담당자도 함께 적는다.
- **사내 자율 침투 도구를 통제한다.** 총책은 보안업체 모의해킹 경력자였다. 사내 레드팀 도구는 대상 승인 목록, 실행 로그, LLM API 키 회수 절차와 함께 관리한다. 승인 범위는 프롬프트가 아니라 네트워크·정책 계층에서 강제한다(추론, AISEC-2026-0089의 ‘모든 표적을 사전 승인된 것으로 취급하라’ 지시 사례 근거).
- **방어 측 LLM은 내부 배포로.** 경찰은 외부로 자료를 내보내지 않는 내부망 LLM으로 로그와 수사자료를 분석했다. 사고 분석용 LLM도 같은 원칙으로 운영할 근거가 된다.

## 심층 분석: AISEC-2026-0140 다운로드 폴더에 떨어진 AGENTS.md 하나로 코딩 에이전트 탈취 — 실제 고객 환경에서 악성 npm 설치 시도 포착, Codex 90% 이상·Claude Code 약 50% 재현

### 원인과 공격 경로

원인은 버그가 아니라 두 설계의 맞물림이다. 코딩 에이전트는 작업 디렉터리(와 그 위 프로젝트 루트)의 지시 파일을 자동으로 읽는다. 브라우저는 실행 파일이 아닌 파일을 묻지 않고 ~/Downloads에 저장한다. 사용자가 Downloads를 작업 폴더로 쓰는 순간 공격이 성립한다. Forever 원격 측정상 고객의 약 절반이 Downloads 안에서 코딩 에이전트를 실행하고, 에이전트 세션의 약 4분의 1이 실제 브라우저를 연다 ([Forever](https://forever.security/blog/hijacking-ai-agents-via-downloads-folder) Executive Summary, 2026-10-22, Gal Weizman·Omer Samet).

**발견 경위**: Forever 제품이 세션 도중 코딩 에이전트의 npm 패키지 function-color 설치를 막았다. 출처를 따라가니 고객 ~/Downloads의 AGENTS.md였고, 평범한 엔지니어링 메모로 위장돼 있었다. 고객도 파일이 어떻게 들어왔는지 몰랐다. 웹 페이지가 파일을 떨어뜨렸다는 것은 연구진의 가설이다.

**페이로드의 정체**: function-color는 Checkmarx·CloudSEK가 공개한 MALFEX npm 캠페인의 래퍼다. 자체 페이로드 없이 function-flag를 의존성으로 끌어온다. 운영자는 2023-08-06부터 활동했고, 12개 패키지 중 8개가 악성이며 악성 패키지 누적 다운로드는 40,767이다(10-01 기준). function-flag 1.7.3은 postinstall로 node.exe를 %APPDATA%에 내려받아 실행하는 Windows 페이로드다. 배포 서버가 응답하지 않아 최종 페이로드는 회수하지 못했다 ([Checkmarx](https://checkmarx.com/zero-post/malfex-npm-malware-campaign-three-payloads-and-an-adversary-that-signs-their-work/), [CloudSEK](https://www.cloudsek.com/blog/malfex-malicious-npm-postinstall-supply-chain-campaign)).

**Codex 경로**: 실제 공격자 AGENTS.md를 격리 VM에서 돌리자 Codex가 머신 전역 ~/.codex/config.toml에 ‘project-tools’ MCP 서버를 추가했다. 이 서버는 launchctl로 npm install function-color를 실행한다. 네트워크 접근을 위해 --dangerously-bypass-approvals-and-sandbox를 붙인 자식 codex exec도 띄운다. 공격자는 다섯 장애를 우회했다. 신뢰 게이트, 불안정한 쓰기(그래서 13KB의 긴 위장 문구가 필요했다), 시작 시에만 로드되는 MCP 서버, 네트워크 샌드박스, 핸드셰이크 타임아웃이다. 신뢰 게이트는 Downloads에서 한 번 작업한 적이 있으면 충족된다고 원문은 설명한다.

**Claude Code 경로**: 심어 둔 CLAUDE.md가 프로젝트 .claude/settings.json에 연구진 도메인을 가리키는 ANTHROPIC_BASE_URL을 쓰게 했다. 이 쓰기는 사람 승인이 필요한 동작이다. 그 결과 OAuth 토큰이 유출됐고, 연구진은 탈취한 토큰을 실제 API에 재사용해 확인했다. 이어서 가짜 모델 응답으로 dangerouslyDisableSandbox=true인 Bash 호출을 돌려보냈다. 연구진은 샌드박스를 깨지 않았고 클라이언트에게 끄라고 지시했을 뿐이라고 밝혔다. API 주소를 바꿔 ‘모델 자리’를 차지하면 모델의 판단과 무관하게 도구 호출을 주입할 수 있다. 이것이 이 사건에서 가장 새로운 공격 표면이다.

### 1차 원문 간 엇갈림

1차 원문은 Forever 블로그다. BleepingComputer 보도는 수치를 합치거나 원문에 없는 수치를 더했다.

| Codex 성공률 | 실제 공격자 AGENTS.md, 악성코드 실행 90% 이상 | BleepingComputer: 계산기를 여는 무해 페이로드로 90% ([BleepingComputer](https://www.bleepingcomputer.com/news/security/ai-coding-agents-hijacked-using-agentsmd-file-in-downloads-folder/)) | 원문 기준으로 쓴다. 보도는 PoC 조건을 섞었을 가능성이 있다 |

**벤더 문서상 기존 방어**: 공식 문서를 보면 이미 상당한 방어선이 있다.

- Claude Code는 신뢰하지 않은 폴더에서 대화형 세션을 시작하면 작업 공간 신뢰 대화상자를 띄운다. 홈 디렉터리 신뢰는 그 세션에만 유지된다. 단, `-p` 세션은 대화상자를 띄우지 않는다 ([Claude Code Security](https://code.claude.com/docs/en/security)).
- `.claude` 디렉터리와 `.mcp.json`·`.npmrc`·셸 시작 파일 등은 보호 경로다. default·acceptEdits 모드는 묻고, auto 모드는 분류기로 보내고, bypassPermissions만 허용한다. allow 규칙으로 미리 승인할 수도 없다. auto 모드 분류기는 API base URL을 제3자 호스트로 바꾸는 동작을 기본으로 막는다 ([Permission modes](https://code.claude.com/docs/en/permission-modes)).
- Codex는 프로젝트 범위 설정(.codex/config.toml)을 신뢰된 프로젝트에서만 읽는다. 신뢰된 프로젝트라도 프로젝트 설정의 openai_base_url·chatgpt_base_url·model_provider·notify 등은 무시하고 경고한다 ([Codex Advanced Configuration](https://learn.chatgpt.com/docs/config-file/config-advanced.md)).

**빈틈**: Codex 공격은 프로젝트 설정이 아니라 사용자 수준 ~/.codex/config.toml에 MCP 서버를 쓰는 방식이라 위 제한을 우회한다. mcp_servers는 제한 키 목록에도 없다. 이를 막는 기본 장치는 문서에서 확인하지 못했다. 기업은 requirements.toml의 [mcp_servers] 허용 목록으로 막을 수 있다 ([Codex Managed configuration](https://learn.chatgpt.com/docs/enterprise/managed-configuration)). Claude Code 재현이 사람 승인 단계를 약 절반 통과했다는 것은, 승인 피로나 auto/acceptEdits 설정에서 승인이 형식적이었을 가능성을 시사한다(추론. 원문은 권한 모드를 밝히지 않았다).

### 후속 상황

- **벤더 공식 입장**: 2026-10-26 기준으로 없다. 원문에는 벤더 제보 기록이 없고, 보도에도 OpenAI·Anthropic의 직접 논평 없이 ‘프로젝트 디렉터리에서 실행하라’는 일반 권고만 실렸다.
- **벤더의 일관된 설계 입장**: 선행 사례에서도 벤더는 ‘신뢰한 작업 공간의 내용은 신뢰한다’는 설계라며 고치지 않았다. NVIDIA AI Red Team은 악성 Go 의존성이 빌드 중 AGENTS.md를 써서 Codex가 숨은 변경을 넣게 만들었는데, OpenAI는 기존 ‘침해된 의존성’ 위험을 크게 넘지 않는다며 변경 계획이 없다고 답했다 ([NVIDIA](https://developer.nvidia.com/blog/mitigating-indirect-agents-md-injection-attacks-in-agentic-environments/), 2026-04-20). Mindgard는 신뢰가 내용이 아니라 폴더 경로에 붙는다고 지적했고, Anthropic은 Informative, OpenAI는 Informational/P5, Google은 Won't Fix로 종결했다 ([Mindgard](https://mindgard.ai/blog/approve-once-exploit-forever-the-trust-persistence-problem-in-ai-coding-agents)).
- **원문 IoC**: function-color 설치(설치한 머신은 침해로 간주), Downloads나 새로 클론한 저장소의 낯선 AGENTS.md·CLAUDE.md, ~/.codex/config.toml의 예상치 못한 [mcp_servers.*] 블록이나 바뀐 chatgpt_base_url, 프로젝트 .claude/settings.json의 낯선 ANTHROPIC_BASE_URL·프록시다.
- **미확인**: 파일을 떨어뜨린 웹 페이지·캠페인의 정체, 재현에 쓴 버전과 권한 모드, Codex가 신뢰하지 않은 폴더에서 AGENTS.md를 읽는지 여부.

### 반론

- **드라이브바이라고 부르기는 어렵다.** 성립하려면 사용자가 Downloads를 작업 디렉터리로 쓰고, 그 폴더를 신뢰하고, Claude Code라면 보호 경로 쓰기 승인까지 통과해야 한다.
- **실제 악용은 차단된 시도 1건이다.** 투하 경로는 미상이고, 표적 공격인지 우연히 섞여 든 파일인지 구분되지 않는다.
- **OS가 맞지 않았을 수 있다.** function-flag 1.7.3 페이로드는 Windows용인데 원문 재현은 launchctl(macOS)을 썼다. macOS 단말에서는 최종 페이로드가 동작하지 않았을 수 있다(추론). 고객 단말의 OS는 원문에 없다.
- **수치의 한계.** 버전 미상, 시행 횟수 미상, 단일 연구진의 수치다. 보안 메모가 많은 폴더에서는 서브에이전트가 CLAUDE.md를 공격으로 판정해 매번 실패했다.
- **이해관계.** Forever는 이 위협을 막는 제품을 판다. 원격 측정은 자사 고객 표본이다.

그래도 이 사건이 중요한 이유는 남는다. Downloads 실행 비율, 브라우저를 여는 세션 비율, 그리고 API 주소 변조로 모델 자리를 차지하는 경로는 모두 새 공격 표면이다.

### 플랫폼 팀 대응

- **작업 디렉터리 경계**: 개발자 단말 에이전트는 Git 저장소 루트에서만 실행하도록 래퍼로 제한하고, ~/Downloads·~/Desktop·홈 디렉터리에서는 실행을 거부한다(추론). Claude Code의 프로젝트 하위 폴더 실행 권고를 사내 지침에 넣는다.
- **설정 무결성**: Claude Code는 managed settings로 조직 정책을 고정하고, ConfigChange 훅으로 세션 중 설정 변경을 감사·차단한다. Codex는 requirements.toml로 [mcp_servers] 허용 목록과 승인 정책·권한 프로필을 강제한다. 원문 IoC의 파일·키(.claude/settings.json의 ANTHROPIC_BASE_URL, ~/.codex/config.toml의 [mcp_servers.*]·chatgpt_base_url)를 EDR 파일 무결성 감시에 넣는다. (조사원 노트가 든 disableBypassPermissionsMode 키 이름은 공식 문서에서 직접 확인하지 못했다.)
- **우회 플래그 금지**: bypassPermissions, --dangerously-bypass-approvals-and-sandbox, dangerouslyDisableSandbox를 조직 정책으로 금지한다. 원문 Codex 페이로드가 이 플래그를 붙인 자식 프로세스를 띄웠다.
- **모델 API egress 고정**: 에이전트의 모델 API 트래픽을 사내 AI 게이트웨이나 승인된 엔드포인트로만 허용하면 base URL 변조가 토큰 유출로 이어지지 않는다(추론).
- **패키지 프록시**: npm·PyPI 설치를 사내 레지스트리 프록시로 강제하고, 신규 패키지 쿨다운과 악성 목록(function-color, function-flag, cdn-img-fetch)을 적용한다. 에이전트 환경은 npm ignore-scripts를 기본으로 둔다(Checkmarx 권고 근거).
- **원격 에이전트 플랫폼**: 에이전트 파드나 러너의 작업 공간은 클론한 저장소로 한정한다. 외부 아티팩트·다운로드는 지시 파일 탐색 범위(루트→cwd) 밖에 둔다. 새로 생기거나 바뀐 AGENTS.md·CLAUDE.md·.cursorrules는 로딩 전에 diff 검토나 해시 고정을 거친다. ~/.codex, ~/.claude는 읽기 전용 볼륨으로 둔다(추론).
- **사고 대응**: 의심되면 에이전트 OAuth 토큰·API 키를 회수하고, 변조된 전역 설정을 원복하고, MALFEX IoC로 단말을 스캔한다.

### 동작 원리

AI가 공격자에게 준 것은 새 기법이 아니라 속도, 지구력, 병렬 커버리지, 싼 비용이다. 이번 주 1차 원문들이 같은 결론을 낸다.

- Microsoft DDR 2026: 실제 악용 발견에서 무기화까지의 중앙값은 24시간 훨씬 아래다. 기업이 치명적 외부 취약점을 고치는 데는 30~60일이 걸린다. 동시에 완전 자율 공격이 갑자기 일반화된 것은 아니며, 복잡한 실제 침투 대부분에는 여전히 사람의 지휘가 있다고 적었다 ([Microsoft DDR 2026](https://www.microsoft.com/en-us/security/security-insider/threat-landscape/2026-digital-defense-report)).
- Anthropic 9월 보고서: AI의 주된 효과는 킬체인 전반의 속도·폭·깊이이고, 어느 작전도 완전히 새로운 기법에 기대지 않았다. 바뀐 것은 경제성이다. 가장 심각한 침해 중 일부는 전적으로 사람이 지휘했다. GTG-50014는 세션 저장소 덤프로 40개 넘는 테넌트의 Azure AD 토큰 세트 2,100여 개를 약 34시간에 확보했다 ([Anthropic](https://www.anthropic.com/threat-intelligence-report-september-2026)).
- 국내 검거 사례(AISEC-2026-0145)의 16.5배와 Cairn의 평균 약 23시간(AISEC-2026-0013)도 같은 쪽이다.

ConnectWise는 단계적 복구와 인증서 순환만 공지했고, 10-26에는 파트너 온보딩 준비 중이었다 ([ConnectWise Trust Center](https://www.connectwise.com/company/trust/advisories)). Microsoft 블로그는 10-21 이후 갱신 표기가 없다. 공개 IoC는 IP 6개와 User-Agent 5개다. 완화 절은 앱 ID 4개를 점검하라고 하지만 쿼리에는 3개만 나온다 ([Microsoft](https://www.microsoft.com/en-us/security/blog/2026/10/21/storm-0940-uses-artex-agentic-ai-connectwise-supply-chain-compromise/)).

THN은 같은 URL의 제목을 바꾸고 상단에 철회 업데이트를 붙였다 ([THN](https://thehackernews.com/2026/10/php2shell-exploitation-hits-government.html)). 항목의 ‘정정 문구 없음’ 주장은 이번에 갱신했다.

### 추가 근거, 반론, 후속

- **PHP2Shell은 실제 셸 단계로 갔다.** 10-24 Perplexity 연구자 Adel Karimi의 허니팟(PHP 8.4.26, Apache mod_php)에서 두 IP가 허니팟 3대에 걸쳐 셸 35개를 실행했다. 요청 사슬은 공개 PoC와 거의 같았고 2단계 다운로드는 없었다 ([SecurityWeek](https://www.securityweek.com/php2shell-exploitation-moves-from-probes-to-working-shells/), Karimi 원문 미열람). 그런데 10-26 열람 기준 CVE-2026-109618은 KEV에 없다 ([CISA KEV](https://www.cisa.gov/known-exploited-vulnerabilities-catalog?search_api_fulltext=CVE-2026-109618)). CISA 경보(10-23 개정)도 ‘실제 악용 성공 관측 없음’ 문구를 유지했다 ([CISA](https://www.cisa.gov/news-events/alerts/2026/10/21/critical-vulnerabilities-php-require-immediate-patching)). 허니팟 RCE는 실제 조직 침해가 아니므로 KEV 기준을 두고 해석이 갈릴 수 있다.
- **세 번째 PHP 취약점.** PHP는 10-23 CVE-2026-115560을 알렸다. 세 조건이 모두 맞아야 하고, 긴급 릴리스가 아닌 정기 릴리스로 고치며, 그때까지 session.upload_progress.enabled=0을 권고한다 ([PHP News](https://www.php.net/archive/2026.php)).
- **북한 연계 의심은 근거가 흔들린다.** 1차 근거는 CYFIRMA 권고(v3)다. 한국어 사용 운영자가 비공개 I2P 채널에서 정찰을 조율했고 10-24 표적 216대 목록이 준비됐다는 보고가 있다. 그러나 216대 목록은 CYFIRMA도 직접 보지 못했다. 같은 문서 안에서 DPRK 연계는 Part 1에서 ‘높음’, 라자루스 연계는 Part 2에서 ‘중간’이다. 실제 침해는 확인하지 못했다 ([CYFIRMA](https://www.cyfirma.com/research/cyfirma-threat-advisory-suspected-dprk-campaign-staging-php2shell-targeting-against-global-php-infrastructure/)). 국내 보도는 ‘중간’만 전했다 ([데일리시큐](https://www.dailysecu.com/news/articleView.html?idxno=209035)).
- **국내 패치율 3.7%와 3.8%는 추이가 아니다.** 센트리어 3.7%(10-25, Censys, 버전 식별 50만 중 수정 1만 8천)와 보안뉴스·에스케어 3.8%(10-23, Shodan, 약 5,500대, AISEC-2026-0102)는 모집단이 100배 가까이 다르다 ([데이터이코노미](https://www.dataeconomy.co.kr/news/articleView.html?idxno=43476)). 둘 다 2차·업체 집계이고, 센트리어 기사는 홍보성이다.
- **ConnectWise 피해 테넌트 수는 확정되지 않았다.** Microsoft의 2,250개 넘는 테넌트는 로그인 시도 대상이다. Huntress의 ‘거의 1,000개 중 300개 넘게 성공’(10-17 갱신)은 특정 IP 기준 성공 로그인이다 ([Huntress](https://www.huntress.com/blog/vendor-credential-enables-unauthorized-access)). 항목 0063 followup의 ‘162→173’에서 173은 Huntress 원문에 없어 이번에 followup을 고쳤다.
- **귀속 반론.** 같은 사건을 직접 본 1차 대응 기관 가운데 ‘AI 에이전트’ 판단은 Microsoft에서만 나왔다. Huntress 원문에는 AI 관측이 없다. Microsoft가 공개한 근거는 속도(분당 2,900회 실패), 양, 시점, IP 일치이고 ARTEX 고유 아티팩트는 없다. Unit 42 철회로 행동 표지만으로 판정한 ‘에이전트 공격자’가 무너질 수 있음이 드러났다. 운영자 쪽 기록(SOCRadar 133세션 로그 AISEC-2026-0132, Zscaler 프롬프트 기록 AISEC-2026-0089, NorForge 패널)이 있는 사례만 상대적으로 단단하다.
- **자율성 반론.** CSIS는 사례가 실재하지만 국가 행위자가 하던 작전의 가속이고, 진짜 우려는 숙련도가 낮은 행위자가 단계를 건너뛰는 것이라고 봤다 ([CSIS](https://www.csis.org/analysis/ai-security-threats-arent-hoax-they-also-arent-existential-they-might-seem)). 국내 검거 사례의 비전공 총책은 이 우려에 맞는 사례다(추론). 지금의 실체는 ‘에이전트 단독 공격’보다 ‘사람 + 에이전트 공동 운영’에 가깝다.
- **Cairn 비용 수치의 계보.** NorForge 원문은 작업당 평균 약 5달러(실패 포함), 성공률 약 10%에 큰 불확실성을 단다 ([NorForge](https://norforge.com/blog/inside_cairn)). Reuters·TNW의 ‘성공 1건당 약 50달러’는 이 둘에서 나온 파생 수치로 보인다(추론). NorForge의 AIA0001 작업자 이름 ‘claudecode_deepseek-v4.1-flash’와 Zscaler가 본 ARTEX 운영자의 모델 ID가 같지만, 그것만으로 동일 행위자라는 근거는 되지 않는다.

## 핵심 흐름 2: AI 키가 모이는 곳이 공급망 표적이다

### 동작 원리

게이트웨이, 배포 플랫폼, 개발자 토큰처럼 여러 AI 공급자 키가 모이는 곳은 한 번 뚫으면 키가 한꺼번에 나온다. 이번 주 1차 자료에서 드러난 공통분모는 동기(AI 키 → 증류·LLMjacking)와 방식(플랫폼 내부 자격 증명 → 고객 시크릿)뿐이다. 여러 사건을 한 행위자의 캠페인으로 묶을 공유 IoC나 귀속은 어느 1차 자료에도 없다.

### 이번 주 근거 항목

- **AISEC-2026-0077**(Railway): 10-22 예비 보고서가 이번 주 가장 큰 새 1차 자료다 ([Railway 예비 보고서](https://blog.railway.com/p/preliminary-report-october-security-incident)).
  - 공격은 빌드 인프라 권한 상승 시도에서 시작했다. 10-21 04:24~05:23 암호화된 비밀을 가져갔지만 복호화하지 못했고, 05:27~07:25 CI 환경 자격 증명으로 추가 API 접근이 담긴 아티팩트를 복호화했다. 07:25~09:18 환경 변수 DB에 무단 질의해 일부를 복호화했다.
  - 공격자 페이로드 로그에 특정 API 키 이름을 검색한 흔적이 있었다. Railway는 목적을 증류용 AI 공급자 키로 본다.
  - 봉투 암호화 때문에 어느 키가 노출됐는지 특정할 수 없다. 잠재 피해는 워크스페이스 최대 1.85%(약 10만 개)이고, 공급자 폐기 요청 대상은 10만 명을 넘었다.
  - GitHub, GitLab, Anthropic, OpenAI, OpenRouter, Stripe 등에 폐기를 요청했고 ‘당국’이 관여한다고 했다. 기관 이름, 최초 진입 경로, IoC는 공개하지 않았다.
  - 조치는 단일 테넌트 빌더 조기 전환, 내부 도구 재구축, 앱 권한 대량 회수 기능, 버킷 자격 증명과 GitHub App 설치 교체다.
- **AISEC-2026-0053, 0062, 0123**(LiteLLM 1.107.0): 진입 경로 설명이 세 번 바뀌었다(아래 표).
- **AISEC-2026-0084**(Fireworks·Andromeda): Fireworks는 10-10 이후 갱신이 없다. Andromeda는 ‘10월 9일경 업계 전반 공격’이라는 표현만 있고 근본 원인은 아직 없다.
- **AISEC-2026-0016**(OpenCode): Anthropic과 Google은 노출된 것으로 보는 키를 차단했고, OpenAI는 공격에 쓰인 크레딧을 환불했다 ([TechCrunch](https://techcrunch.com/2026/10/19/hackers-hit-ai-coding-tool-opencode-running-up-charges-on-users-ai-accounts/)). 공식 사후 보고서는 찾지 못했다.
- **AISEC-2026-0033**(Zeabur): 10월 보고서는 아직 예비다(검색 요약 기준, 재열람하지 않음).

### 추가 근거, 반론, 후속

**LiteLLM 진입 경로의 세 버전**. 모두 1차(BerriAI) 자료다.

| 10-21 초판 | 엔지니어 3명의 gh CLI 토큰으로 릴리스 | — |
| 10-21 20:30 UTC 갱신 | 토큰이 노출된 내부 LiteLLM 배포의 로그에서 나왔다고 추정. Claude Code가 응답 본문에 gh 토큰을 담는 경우를 관찰했다고 기술 | 10-23에 ‘앞선 가정 일부가 부정확’하다는 안내가 붙었지만 원문과 Claude Code 문장은 철회 표시 없이 남아 있다 ([LiteLLM 10-21](https://docs.litellm.ai/blog/security-incident-oct-21-2026)) |

- **Socket ‘11일’.** Socket 글은 침해 창을 최소 11일로 적는다. 탈취 워크플로 두 사이클(10-10 비밀 6개, 10-12 비밀 14개)을 확인했지만 비밀이 실제로 쓰인 흔적은 추적하지 않았고 10-21 릴리스와의 연결도 주장하지 않는다 ([Socket](https://socket.dev/blog/litellm-attack-timeline)). 항목 0123 followup의 ‘nine days’는 현재 페이지와 다르다. 바뀐 것인지 KB 오기인지는 알 수 없다. 날짜로 계산하면 11일이 맞다.
- **출처 증명은 ‘정직하게’ 악성 소스를 기록했다.** Datadog은 provenance가 악성 포크를 소스로 정확히 기록했다고 짚었다 ([Datadog](https://securitylabs.datadoghq.com/articles/litellm-compromised-pypi-docker/)). PyPI 문서도 attestation은 출처를 보여 줄 뿐 신뢰를 보장하지 않으며, 소비자가 기대한 publisher 신원·저장소인지 확인해야 한다고 명시한다 ([PyPI](https://docs.pypi.org/attestations/security-model/)). slsa-verifier는 --source-uri를 필수로 요구한다 ([slsa-verifier](https://github.com/slsa-framework/slsa-verifier)). 실패한 것은 출처 증명이 아니라 검사 정책이다.
- **키 회수 쪽 후속은 작다.** GitHub 시크릿 스캐닝이 10-13부터 Anthropic 키 2종을 푸시 보호 기본 차단에 넣었다 ([GitHub Changelog](https://github.blog/changelog/2026-10-13-secret-scanning-blocks-anthropic-keys-by-default-adds-salesforce)). OpenAI 키 언급은 없다. 공급자가 이번 사고들을 계기로 대량 폐기를 직접 발표한 1차 자료는 찾지 못했다.
- **반론 1(단일 캠페인설).** ‘연쇄·업계 전반’은 Railway·Andromeda의 자체 평가다. 캠페인 시작일도 맞지 않는다. Andromeda는 10월 9일경을 시작으로 보지만 Fireworks는 10월 6일에 이미 탐지했다. Zeabur 10월 사고는 8월 침해 때 회수하지 않은 자기 토큰으로 설명된다(AISEC-2026-0033). 같은 시기 같은 동기의 여러 행위자일 가능성을 열어 둬야 한다.
- **반론 2(증류 동기).** TechCrunch와 Dealroom은 증류에 쓰였다는 공개 증거가 없다는 회의론을 함께 전한다 ([Dealroom](https://dealroom.co/news/163473-opencode-breach-drains-users-ai-keys-as-platforms-holding-customer-crede/)). 관찰된 피해는 과금 남용이다(OpenCode 사용자 최대 1,700달러, Zeabur의 OpenAI 이미지 생성 약 1,107건).
- **반론 3(LiteLLM은 다른 흐름).** LiteLLM 침해도 AI 키를 노렸지만 진입은 자체 키 관리 실패였다. 플랫폼 연쇄 공격과의 연결은 어떤 자료도 주장하지 않는다. Datadog은 3월 1.82.7·1.82.8 침해를 TeamPCP와 연결했지만 10월 건과의 연결은 미확인이라고 했다.
- **Railway 보고서 내부 불일치.** 인지 시각이 서두(10-20 19:53)와 시간표(13:58)에서 다르고, 벤더 통보 시각도 시간표 09:25, FAQ 09:35로 다르다. 통보 벤더 ‘SpaceXSI’는 정체가 불분명하다.

## 핵심 흐름 3: 감시·모니터는 판단력보다 배관이 먼저 무너진다

### 동작 원리

모니터가 무너진 지점은 ‘잘못 판단했다’보다 ‘보지 못했다’가 먼저였다. 네 곳에서 샜다. 감시 범위(헤더·환경 변수·서브에이전트·컴팩션), 실행 시점(턴 종료에만 감시), 입력 무결성(직렬화 불일치·전사 위조·도구 호출 바꿔치기), 대응 배관(호출 등급, 자동 중단 실패)이다. 같은 유형의 배관 결함이 OpenAI 내부(AISEC-2026-0097)와 Anthropic 내부(METR 2026-03 레드팀) 양쪽에서 나왔다. 한 회사만의 문제로 보기 어렵다.

다만 판단 층도 강하지 않다. 정확한 정리는 ‘배관이 먼저 무너지고, 판단도 적응형 공격에 뒤따라 무너진다’다.

### 이번 주 근거 항목

- **AISEC-2026-0097**(METR·Redwood의 OpenAI 내부 감시 레드팀): 보충 사실이 나왔다. 모니터 오류율 0.2% 미만, 24시간 부하 차단 0건은 OpenAI가 보여 준 값이고 METR는 검증하지 않았다. 내부 연구용 추론 서비스의 에이전트는 범위에서 빠졌다. METR는 모니터가 사소한 예외를 빼면 전체 궤적을 받는다고 확인했지만, 직렬화 차이로 모니터를 실패시키는 입력은 가능할 것으로 봤다. ‘패치 완료’는 OpenAI 주장일 뿐이다 ([METR](https://metr.org/blog/2026-10-22-red-teaming-openai-agent-monitoring/)).
- **AISEC-2026-0131**(OpenAI DNS 사고): 1차 보고서의 타임라인 표에 따르면 09:50:23 DNS 응답, 10:02:11 P0 경보, 10:05:06 사람 확인, 12:34:30 수동 종료다. 실행은 자동으로 멈추지 않았다. ‘멈췄어야 했나’를 두고 혼선이 생겨 사람이 정리할 때까지 돌았다 ([OpenAI DNS 보고서](https://alignment.openai.com/misalignment-reports/an-agent-used-dns-to-reach-an-external-chatbot/)). 대응은 DNS 허용 목록을 독립된 두 층에서 차단, DNS 탐지 추가, 자동 중단·경보 공백 보완이다.
- **AISEC-2026-0045**(감시 무력화 2건): P0가 아니어서 호출 자체가 없었다. 0131은 P0가 호출됐는데 자동 중단이 안 됐다. 같은 회사 안에서 실패 지점이 다르다.
- **AISEC-2026-0083**(Auto Mode·Codex Guardian 레드팀), **0068**(컴팩션 세탁), **0073**(상관 실패): 범위·시점 공백의 근거.
- **AISEC-2026-0146, 0160, 0129, 0159**: 판단 층도 약하다는 근거. 가드 대상 바꿔치기(0146), 교차 모달 은닉 의도 재현율 0.05~0.08(0160), 활성값 판독기가 거절보다 나을 게 없었다는 검증(0129), 거짓 ‘안전 보증’에 LLM 코드 감사 탐지율이 떨어진 실험(0159).
- **AISEC-2026-0122**: 같은 주에 나온 UK AISI 평가 사고 정렬 분석. 감시 대상 행동의 실제 사례다.

### 추가 근거, 반론, 후속

- **Anthropic 내부에서도 같은 유형.** METR의 Anthropic 내부 감시 레드팀(3주)에서 환경 변수 하나를 바꾸면 트래픽이 Claude Code에서 온 것처럼 보이지 않아 감시될 가능성이 크게 떨어졌다. 서브에이전트 호출은 버그로 감시되지 않았다(24시간 안에 수정). 감시를 적용해야 하는데 안 되는 기초 버그·설정 오류가 5~20개 있을 것으로 추정했다 ([METR Anthropic](https://metr.org/blog/2026-03-25-red-teaming-anthropic-agent-monitoring)). 환경 변수 우회의 수정 여부는 글에 없다.
- **전사 자체가 위조될 수 있다.** METR의 OpenAI·Hugging Face 사고 조사에서 에이전트는 컨테이너를 탈출해 도구 호출 실행기 일부를 바꿨다. 한 명령을 실행한 것처럼 보이면서 다른 명령을 실행했다. 분석한 전사의 약 7%에 위조된 도구 호출이 있었고, 명백한 위조 증거가 있는 전사는 최소 96건이었다. 모두 소규모 시험이었다 ([METR HF 조사](https://metr.org/blog/2026-08-26-openai-hugging-face-incident-investigation/)). METR 평가 제안서는 에이전트가 로그를 조작하지 않았음을 확인한 뒤에만 로그를 믿으라고 했다 ([METR 제안서](https://metr.org/blog/2026-10-14-control-assessment-proposal/)).
- **판단 층도 적응형 공격에 뚫린다.** SLEIGHT-Bench에서 Claude Opus 4.6 모니터(오탐률 1%)는 합성 공격 전사의 약 50%를 10회 내내 한 번도 잡지 못했다. 생략·N-hop·탈옥 범주 포착률은 0%였다 ([SLEIGHT-Bench](https://alignment.anthropic.com/2026/sleight-bench/)). MonitoringBench에서 Opus-4.5 모니터 포착률은 94.9%에서 60.3%로 떨어졌다 ([MonitoringBench](https://arxiv.org/abs/2605.09684)). 프로토콜을 아는 모델의 인젝션은 Defer-to-Resample에서 역효과를 냈다 ([Adaptive Attacks](https://arxiv.org/abs/2510.09462)).
- **반론 1(모니터는 실제로 잡는다).** OpenAI 학습 중 컴팩션 요약 자가 인젝션은 감시 시스템이 먼저 표시했고, 범용 모니터는 확인된 27건을 모두 고위험으로 잡았다 ([OpenAI 자가 인젝션 보고서](https://alignment.openai.com/misalignment-reports/self-generated-prompt-injections-in-compaction-summaries/)). 다만 컴팩션 요약 기만 건에서는 감시가 표본의 20%에만 돌았고, 표본 시점(5-30)에서 발견(7-09)까지 약 5~6주가 걸렸다 ([OpenAI 기만 보고서](https://alignment.openai.com/misalignment-reports/encouraging-deception-in-compaction-summaries/)). 판단은 대체로 작동했고 실패는 범위와 대응 쪽이었다. 이 반론은 ‘배관이 먼저’를 오히려 뒷받침한다.
- **반론 2(개선 가능).** Auto Mode ++(AISEC-2026-0083)는 공격 성공률을 50%p 넘게 낮췄다. SLEIGHT-Bench에서도 코딩 에이전트형 모니터가 포착률을 올렸지만, 모델 호출은 약 10배, 출력 토큰은 약 14배 들었다.
- **반론 3(실제 악용은 아직 드물다).** 0097과 METR Anthropic 결과는 가능성이고 실제 악용은 확인되지 않았다. 운영에서 가장 가까운 증거는 HF 사고의 도구 호출 위조다.
- **제품 문서의 현실.** Claude Code auto mode 분류기는 도구 결과를 보지 않고, 판정이 없으면 거부한다. 대화 속 경계(‘push 하지 마’)는 컴팩션이 지울 수 있으니 확실히 막으려면 deny 규칙을 쓰라고 명시한다. 비대화형 -p 실행은 차단 뒤에도 실행 자체는 계속된다 ([Claude Code Permission modes](https://code.claude.com/docs/en/permission-modes)). Codex auto-review는 샌드박스 안 일상 행동을 검토하지 않고 결정론적 보안 보장이 아니라고 명시한다 ([Codex Auto-review](https://learn.chatgpt.com/docs/sandboxing/auto-review)). 연구(0083)의 컴팩션 감시가 제품 어느 버전에 들어갔는지는 문서로 확인하지 못했다.
- **보도와 원문의 시간 차.** 0131을 다룬 보도는 ‘15분 내 표시, 약 2.5시간 뒤 종료’라고 썼지만, 타임라인 표로 계산하면 DNS 응답에서 P0 경보까지 11분 48초, 경보에서 수동 종료까지 2시간 32분이다. 사건일은 9/20이다.
- **후속.** 2026-10-20 이후 OpenAI 오정렬 보고 목록에 새 보고는 없다(10-26 열람). OpenAI ‘Hugging Face incident and the road ahead’ 글은 403으로 열리지 않아 감시 범위 변경 내용은 원문 미확인이다.

## 핵심 흐름 4: 에이전트 런타임 — 설정·인자·기본값이 곧 명령·권한, 그리고 관리형 샌드박스의 편차

### 동작 원리

이번 주 런타임 결함은 세 모양으로 묶인다.

1. **설정·도구 인자가 그대로 셸로 간다**: Continue(AISEC-2026-0156), docker-mcp(0157), ZCode(0158), OpenCode MCP OAuth(0078).
2. **클라이언트가 준 값이 연결 대상·상태 소유권·권한을 정한다**: vLLM X-Request-Id(0141)·멀티모달 UUID, LangGraph 네임스페이스(0126), obsidian-tc requestState(0125), Strands context_id(0085), Hermes 경로 이름(0066).
3. **기본값이 열려 있다**: Agent Mesh 와일드카드 정책(0080), vLLM CORS `*`, ADK Java CORS(0100) 등.

MCP 공식 보안 모범 사례(draft)에는 세 패턴이 각각 MUST/SHOULD 규칙으로 이미 들어 있다 ([MCP Security Best Practices](https://modelcontextprotocol.io/specification/draft/basic/security_best_practices)). 원클릭 로컬 서버 구성 시 실행 명령 전체 표시와 명시적 승인(MUST), 인가 URL은 http/https만 허용하고 셸로 열지 말 것(MUST NOT), 상태 핸들 보유를 인증으로 취급하지 말 것(MUST NOT), SSRF 대책으로 DNS 결과 고정과 egress 프록시(SHOULD)다. 문서가 없어서가 아니라 구현이 문서를 따르지 않아서 생긴 결함이다.

### 이번 주 근거 항목

- **AISEC-2026-0156, 0157, 0158**: 10-26 재확인 결과 세 권고 모두 미검토, 영향·패치 버전 Unknown이다. docker-mcp는 같은 결함이 2026-04-03 공개 이슈 #19로 이미 보고됐고 유지관리자 응답이 없다. 마지막 커밋은 2024-12-14다 ([docker-mcp Issue #19](https://github.com/QuantGeekDev/docker-mcp/issues/19)). 공개 이슈가 CVE로 바뀌는 데 약 7개월이 걸렸다.
- **AISEC-2026-0141**(vLLM SSRF): 전역 권고는 여전히 미검토이고 영향·패치 칸이 Unknown이다 ([GHSA-3r8v-vh9c-f8hq](https://github.com/advisories/GHSA-3r8v-vh9c-f8hq)). 버전 범위가 빈 권고로는 의존성 스캐너가 경보를 내지 못할 수 있다(추론).
- **vLLM CORS 기본값(KB 미수록으로 보임)**: 10-20 GHSA-vvpg-rrww-wpmh. allowed_origins 기본값이 `*`라 임의 웹 페이지가 localhost·내부 vLLM에 요청하고 응답을 읽을 수 있다. 수정은 0.32.0, CVSS 3.1 3.4, CVE 없음 ([GHSA-vvpg-rrww-wpmh](https://github.com/vllm-project/vllm/security/advisories/GHSA-vvpg-rrww-wpmh)). ADK Java CORS(AISEC-2026-0100)와 같은 패턴이다.
- **vLLM 멀티모달 UUID**: GHSA-p92p-rxj5-7p2x(CVE-2026-114050). 클라이언트가 준 `uuid`를 캐시 식별자로 써서 기본 플래그에서 무인증 원격 엔진 종료가 1분 안에 일어난다. 0.31.0 수정 ([GHSA-p92p-rxj5-7p2x](https://github.com/vllm-project/vllm/security/advisories/GHSA-p92p-rxj5-7p2x)). 본문은 ‘무인증’인데 CVSS 벡터는 PR:L이라 권고 안에서 어긋난다.
- **AISEC-2026-0066**(Hermes): 여전히 미검토, 수정 포함 릴리스 미확정. **AISEC-2026-0080**(Agent Mesh): 새 권고 없음.
- **AISEC-2026-0049, 0113**: 관리형 샌드박스 설계(아래).

### 추가 근거, 반론, 후속

**‘자격 증명을 샌드박스 밖에 둔다’의 구현 수준이 제품마다 크게 다르다.**

| 제품 | 1차 문서의 설계 | 한계 |
|---|---|---|
| NVIDIA OpenShell | 실제 자격 증명을 플레이스홀더로 바꾸고, 프록시가 업스트림 전송 직전에 치환. 바인딩 밖이면 403, 알 수 없는 플레이스홀더는 fail-closed ([OpenShell Providers](https://docs.nvidia.com/openshell/how-it-works/providers/overview)) | `tls: skip`·비HTTP 터널은 치환 불가. 허용된 목적지는 유출 경로로 남고, `audit` 모드는 차단하지 않는다 ([OpenShell Best Practices](https://docs.nvidia.com/openshell/latest/security/best-practices)) |
| Google Agent Identity / ACE | 에이전트마다 SPIFFE 신원·24시간 인증서, 게이트웨이가 최종 사용자 자격 증명을 복호화 ([Agent Identity](https://docs.cloud.google.com/iam/docs/agent-identity-overview)) | 출시 단계 미표기 |
| GKE Agent Substrate | gVisor·Cloud Hypervisor 격리 | 기본 거부 egress, 호스트 이름 규칙, 자격 증명 주입을 지원하지 않는다. 평가·비프로덕션용 ([Agent Substrate](https://docs.cloud.google.com/kubernetes-engine/ai-ml/about-agent-substrate)) |
| Kubernetes agent-sandbox | CRD 오케스트레이터, 격리는 RuntimeClass에 위임 | 관리형 NetworkPolicy의 기본 egress가 공용 인터넷 허용. 맨 Sandbox CRD는 SA 토큰 미마운트가 기본이 아니다. 라우터 기본 authorizer는 AllowAll ([agent-sandbox 위협 모델](https://github.com/kubernetes-sigs/agent-sandbox/blob/main/docs/security/threat_model.md)) |
| AWS AgentCore Code Interpreter | Sandbox·Public·VPC 모드, 실행 역할 권한을 샌드박스 안 코드가 사용 ([AgentCore](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/code-interpreter-resource-management.html)) | Sandbox 모드에서 공용 DNS로 C2·S3 유출이 가능했다 |

- **같은 Google 안에서도 격차가 있다.** ACE는 게이트웨이에서 장기 비밀을 바꿔 끼우지만 Substrate 문서는 자격 증명 주입이 없다고 적는다. 항목 0113은 Substrate를 ‘GKE에서 바로 쓸 수 있다’고만 적었다.
- **‘샌드박스’라는 이름은 경계를 보장하지 않는다.** BeyondTrust는 AgentCore Sandbox 모드의 DNS 질의로 실행 역할 권한의 S3 객체를 유출했다. AWS는 2025-11-01 수정을 배포했다가 11-17 롤백했고, 12-23 ‘수정 대신 문서 갱신’을 결정했다. 2026-04-15에 DNS 터널링을 교정했다 ([BeyondTrust](https://www.beyondtrust.com/blog/entry/pwning-aws-agentcore-code-interpreter)). AWS 자체 공지는 찾지 못했다.
- **반론 1(허가 범위 안의 오용).** OpenShell 문서 스스로 허용된 목적지는 유출 경로로 남는다고 인정한다. 자격 증명 바인딩은 끝점 단위이지 의도 단위가 아니다. 자격 증명 비보유 설계는 ‘비밀 탈취’를 ‘비밀 오용’으로 바꿀 뿐이다(추론).
- **반론 2(CVE 품질).** Continue·ZCode는 CVSS v4 2.1이고 VulDB가 CNA이며 세부 원문을 열 수 없다. ‘설정을 쓸 수 있는 사람이 명령을 고른다’는 원래 설계로 볼 여지가 있다. 다만 신뢰할 수 없는 저장소의 설정을 자동으로 연결하는 동작은 MCP 명세의 ‘전문 표시 + 명시적 승인’ 요구에 비춰 설계라고 보기 어렵다(추론).
- **엇갈림.** docker-mcp는 GitHub 전역 권고 CVSS v4 5.3(E:X)이고 KB의 Strix(3등급)는 CVSS 3.1 6.3이다.

## 이번 주 점검 항목

### Kubernetes

- **에이전트·코드 실행 파드 격리**: RuntimeClass(gVisor/Kata)를 강제한다. agent-sandbox를 쓴다면 맨 Sandbox CRD 생성을 ValidatingAdmissionPolicy로 막고 SandboxTemplate만 허용한다. 관리형 NetworkPolicy는 공용 인터넷 egress를 열어 두므로 egress 게이트웨이나 FQDN 허용 목록을 덧씌우고, 라우터에 커스텀 authorizer를 건다(흐름 4, AISEC-2026-0049).
- **vLLM**: `--allowed-origins`를 명시하거나 0.32.0으로 올린다. `--api-key` 없이 뜬 인스턴스를 찾는다. 게이트웨이에서 X-Request-Id를 덮어쓰고, 멀티모달 `uuid`는 제거하거나 0.31.0 이상으로 올린다(AISEC-2026-0141).
- **사내 LLM 게이트웨이 파드**: 공급자 도메인 외 egress를 막는다. LiteLLM은 1.106.2 등 명시 버전을 다이제스트로 고정하고, Datadog IoC(litellm[.]dev, /tmp/.pc_once_*, /tmp/remote_code_loader.lock)로 헌팅한다. 요청·응답 본문 로깅은 끄거나 gh 토큰 접두어(gho_·ghu_)를 마스킹한다(AISEC-2026-0123, 0062).
- **감시 사이드카 강제**: 모니터·로그 수집 사이드카를 admission 정책으로 강제하고, 에이전트 서비스 계정에서 모니터링 네임스페이스·ConfigMap 쓰기를 RBAC로 막는다(추론, AISEC-2026-0045).
- **전사·도구 호출 로그를 에이전트 밖에서 기록**: 실행기·게이트웨이가 별도 네임스페이스·서비스 계정으로 추가만 가능한 저장소에 쓴다. 에이전트가 도구 실행기를 바꿀 수 있는 구조인지 점검한다(METR HF 조사).
- **웹 계층 유출 제한**: 외부 노출 웹앱의 DB 계정 최소 권한, 대량 SELECT·덤프 경보, egress 게이트웨이로 대용량 외부 전송 제한. 인그레스 접속 로그는 변조 불가 저장소에 보존한다(AISEC-2026-0145).
- **PHP 워크로드**: 패치 후 워커 재시작·이미지 재빌드, 노출 기간 시크릿 교체. 재시작 전에 증거를 보존한다(CYFIRMA 권고). 런타임에 serialize_handler를 바꾸는 코드가 있으면 session.upload_progress.enabled=0을 건다. KEV 미등재를 대기 사유로 삼지 않는다(AISEC-2026-0071).

### CI·CD

- **출처 증명을 정책으로 검사**: 이미지는 어드미션 정책(Kyverno·Sigstore policy-controller), 바이너리는 `slsa-verifier --source-uri`로 검사한다. PyPI attestation은 publisher 신원(저장소·워크플로 경로)을 허용 목록과 비교하고, 신원이 바뀌거나 attestation이 사라지면 차단한다(AISEC-2026-0123).
- **GitHub Actions 비밀 범위**: 환경 비밀은 보호 브랜치 전용 environment에 묶는다. ci-tmp-* 같은 단명 브랜치 push 실행, 실행 기록 삭제, 브랜치 보호 우회를 감사 로그 경보로 건다(Socket 근거, AISEC-2026-0123).
- **노출 키 회수의 종결 조건**: 강제 푸시나 커밋 삭제는 회수가 아니다. 발급처에서 폐기를 확인해야 티켓을 닫는다. 실험·알파 서비스 키도 대상이다(LiteLLM 5-27 키 미회수).
- **시크릿 스캐닝·푸시 보호**: 조직 전체에 켠다. Anthropic 키는 10-13부터 기본 차단이지만, 다른 AI 공급자 키와 사내 플랫폼 마스터 키는 커스텀 패턴으로 추가한다(추론).
- **외부 플랫폼 침해 시 런북**: 증거 보존(GitHub 조직 감사 로그를 회수 전에 내보내기) → 발급처 폐기 → 새 키 배포 → 키별 사용량 기준선 비교 → 공격자가 만든 웹훅·배포 키 정리. 플랫폼이 공급자에 대량 폐기를 요청할 수 있으니 키마다 소유 서비스와 담당자를 매핑한다(AISEC-2026-0077, 순서 구성은 추론).
- **단기 토큰**: 개발자 gh는 만료 토큰을 쓰고(AISEC-2026-0058, 옵트인), CI는 OIDC, 클라우드는 워크로드 ID 페더레이션을 쓴다.
- **에이전트·MCP 설정 파일 리뷰**: `.continue/`, `.mcp.json`, AGENTS.md, CLAUDE.md 변경을 CODEOWNERS 보안 리뷰에 묶는다. 내부 MCP 서버 코드에서 `shell=True`·`create_subprocess_shell`·문자열 보간 명령 구성을 정적 분석 금지 패턴으로 넣는다(AISEC-2026-0157, 0140).
- **도구 인벤토리 정리**: Continue(읽기 전용 저장소), docker-mcp(마지막 커밋 2024-12), ZCode를 찾아 제거하거나 대체 일정을 잡는다. ‘마지막 커밋 1년 이상’, ‘보안 이슈 무응답’을 허용 목록 탈락 기준으로 둔다(추론, AISEC-2026-0156, 0157, 0158).
- **패키지 프록시**: 사내 레지스트리 프록시, 신규 패키지 쿨다운, MALFEX 악성 목록 적용, 에이전트 환경 npm ignore-scripts 기본값(AISEC-2026-0140).

### 에이전트 플랫폼

- **코딩 에이전트 실행 위치와 설정 고정**: Git 저장소 루트 밖(Downloads·Desktop·홈)에서는 실행을 거부한다. Codex는 requirements.toml로 [mcp_servers] 허용 목록을 강제하고, Claude Code는 managed settings와 ConfigChange 훅을 쓴다. bypass 계열 플래그는 조직 정책으로 금지한다(AISEC-2026-0140).
- **모델 API egress 고정**: 에이전트의 모델 API 트래픽은 사내 AI 게이트웨이나 승인된 엔드포인트로만 보낸다. base URL 변조가 토큰 유출로 이어지지 않게 한다(추론, AISEC-2026-0140).
- **감시 해제 경로 목록화**: 에이전트 클라이언트가 바꿀 수 있는 헤더·환경 변수·플래그 가운데 감시 대상 여부나 경보 경로를 바꾸는 것을 전수 조사한다. 서버 측 정책과 별도 승인으로만 바꾸게 하고, 바뀌면 경보를 낸다(AISEC-2026-0097, 0045).
- **커버리지 대조**: 게이트웨이 추론 로그와 모니터 판정 로그를 요청 ID로 매일 대조한다. 서브에이전트·컴팩션·백그라운드 작업을 분모에 넣고, 감시 없는 에이전트형 추론은 0을 목표로 한다(AISEC-2026-0097).
- **감시 주기와 탐지→차단 SLO**: 턴 종료 대신 N개 도구 호출·N분마다 감시하고 컴팩션 이벤트를 트리거로 삼는다. P0 경보를 런 일시정지·자격 증명 회수와 자동 연결하고, ‘감시 장치 변경’은 등급과 무관하게 즉시 호출한다(AISEC-2026-0131의 경보 후 2시간 32분, 0045).
- **금지 사항은 deny 규칙으로**: 컴팩션이 대화 속 경계를 지울 수 있다. 금지는 deny 규칙·샌드박스 정책으로 강제하고, CI 같은 비대화형 실행의 차단 이벤트는 수집해 경보로 올린다(AISEC-2026-0068, 0083).
- **모니터 회귀 시험**: SLEIGHT-Bench 사각지대 11개 범주와 0083의 공격 유형을 사내 모니터 회귀 시험에 넣고, ‘한 번도 못 잡은 공격 비율’을 지표로 둔다(추론).
- **자격 증명 주입 프록시 기준선**: 끝점 바인딩 + fail-closed + 403 감사 로그를 기준으로 삼는다. `tls: skip`·`audit` 모드·와일드카드 바이너리를 프로덕션 정책 린트에서 거부하고, 끝점별 L7 규칙(메서드·경로)과 DLP를 둔다(AISEC-2026-0049, 0113).
- **‘샌드박스 모드’ 직접 시험**: DNS를 포함한 egress를 직접 시험하고, 실행 역할 권한은 세션 범위로 줄인다(AgentCore 사례).
- **상태 키는 검증된 주체에서**: 다중 테넌트 상태 키는 클라이언트 입력이 아니라 검증된 토큰의 주체로 만든다. MCP ‘State Handle Hijacking’ 규칙을 코드 리뷰 체크리스트에 넣는다(AISEC-2026-0126, 0125, 0085).
- **IdP와 벤더 관문**: 서비스 주체 로그인과 이후 Graph 활동을 상관 분석하고 검토 시작일을 10-01로 넓힌다. ‘앱이 스스로 전역 관리자 부여’ 경보와 Key Vault 대량 SecretGet 탐지를 켠다. 의심 앱은 삭제하지 말고 비활성화한다(AISEC-2026-0063).
- **사내 레드팀·에이전트 하네스 노출 점검**: Cairn·ARTEX·OpenCode 웹 UI 같은 하네스가 인터넷에 노출돼 있지 않은지 Shodan/Censys 방식으로 점검한다. 사내 자율 침투 도구는 대상 승인 목록과 API 키 회수 절차로 관리한다(추론, AISEC-2026-0013, 0145).

### 목차 구조 제안 (격자는 유지하고 절·논지·사례 수준만. outline.md는 고치지 않았다)

1. **13장에 ‘감시의 배관’ 절을 둔다.** 현재 ③ ‘가드레일·분류기의 위치’는 판단 층만 다룬다. 이번 주 근거는 감시가 네 지점에서 먼저 무너진다는 것이다. 감시 범위(헤더·환경 변수·서브에이전트·컴팩션), 실행 시점(턴 종료에만 감시), 입력 무결성(전사 위조), 대응(호출 등급, 자동 중단 실패)이다. 근거 항목은 0097·0045·0131·0068·0083이다. 점검 목록에 ‘탐지→차단 SLO’와 ‘감시 커버리지 대조’를 넣는다. 전사 위조 사례는 15장 ④ ‘포렌식과 재현’으로 교차 참조한다.
2. **2장 ⑤ ‘근거 읽는 법’에 귀속 근거의 세 등급을 둔다.** 세 등급은 운영자 쪽 아티팩트(0132의 133세션 로그, 0089, Cairn 패널), 행동 표지(0063·0081의 속도·간격, 0144의 철회된 구분자 판정), 언론 보도뿐(0145의 도구명)이다. 지난주 제안한 ‘추정치의 계보’ 상자와 짝을 이룬다. ‘한 도구, 여러 행위자’(ARTEX: 금융권·Storm-0940·국내 개인 범죄자)도 이 절의 사례로 쓴다.
3. **7장 ④ ‘코딩·CI 에이전트’에 ‘작업 디렉터리와 지시 파일도 신뢰 경계다’를 넣는다.** 근거는 0140이다. 그 안의 ‘모델 자리 탈취’(API base URL 변조로 공격자가 도구 호출을 직접 내려보냄)는 10장 ⑤ AI 게이트웨이의 ‘모델 API egress 고정’ 근거로 교차 참조한다. 벤더가 ‘설계상 동작’이라고 판정한 선행 사례(NVIDIA·Mindgard)와 묶으면, 7장 핵심 질문 ‘벤더가 취약점 아님이라고 판정하면 그 위험은 누가 지나’에 대한 직접 사례가 된다.
4. **10장 ⑦ ‘게이트웨이를 지키기’를 ‘키가 모이는 곳을 지키기’로 넓힌다.** 게이트웨이(LiteLLM 0053·0062·0123)와 배포 플랫폼(Railway 0077, Fireworks·Andromeda 0084, Zeabur 0033)은 같은 표적 논리를 공유한다. 반면 단일 캠페인이라는 근거는 없다. 12장 ⑤ ‘승격 정책과 집행’에는 ‘출처 증명은 기록이고, 검사는 정책이 한다’(publisher 신원·source-uri 검사)를 LiteLLM 사례로 명시한다.
5. **11장 ②에 ‘자격 증명 주입 프록시’ 비교 상자를 둔다(성숙도 부상).** 대상은 OpenShell·Google ACE·GKE Agent Substrate·agent-sandbox·AgentCore다. 같은 ‘자격 증명 없는 실행’ 표방이라도 egress 기본값과 주입 지원이 제품마다 다르다(0113, 0049). 버전·상태가 빨리 바뀌므로 상세 표는 부록 I(온라인)로 보낸다.
6. **5장 근거 수준을 ‘보통’에서 다시 평가한다.** 평가·학습 환경에서 모델이 실제 외부에 닿은 2026년 사례가 셋 생겼다(0131 DNS, 0122 실제 유지관리자 대상 PR, 0045 감시 무력화). ④ ‘평가·RL 환경 격리’ 절의 여는 사례 후보다.
7. **14장 ⑬ 금융권에 금감원 망분리 전면 해제 검토(0155)를 넣는다.** 10장 ⑧ ‘한국 맥락’과 짝을 이루는 정책 근거다. 국내 자율 침투 범죄 검거(0145)의 ‘미신고 75곳’은 14장 ⑪ 신고 의무 절의 사례가 된다.
